# 2609.0014 Local images in markdown doc cards

**Date:** 2026-09-15
**Status:** accepted
**Author:** EP Lin

## Context

`tarmac open README.md` shows both README images as empty broken-image boxes
([#164]). Two independent defects cause it.

1. **Load.** `desktop/src/cards/DocCard.tsx:82` assigns `marked.parse(markdown)`
   to `.doc-prose`'s `innerHTML` in the main app document, so `<img src>`
   resolves against the app origin (`http://localhost:1420` under `make run`,
   `tauri://localhost` bundled). That URL hits the frontend's SPA fallback, gets
   `200 text/html`, and the image fails. Doc-relative, absolute-path and
   `file://` sources all break. `https:` and `data:` load.
2. **Size.** Prose is laid out at `--oversample-k: 3` and down-scaled by
   `scale(zoom/K)` (`desktop/src/kit/docZoom.ts`, `.doc-prose` in
   `desktop/src/theme/card.css`), and no rule targets `img`. At 100% zoom a
   `width="160"` image is ~53 screen px, and a 1920 px image is drawn 640 px wide
   and clipped by `.doc-prose-sizer`.

Nothing serves local image bytes to the main document today. `read_doc`
(`desktop/src-tauri/src/commands.rs:128`) returns text only. The
`tarmac-card://doc/` handler (`desktop/src-tauri/src/card_protocol.rs`) answers every
successful request as `text/html` with a script shim prepended.

**Measured before writing this spec** (spike code deleted):

- **Load path.** A throwaway `tarmac-card://img/<encoded-path>` branch in the
  scheme closure served `docs/images/logo.png` as `image/png`. In the `make run`
  dev app, an `<img>` pointing at it rendered, and the handler logged the request
  with host and percent-encoding intact. A relative-`src` control beside it
  stayed broken.
- **Sizing.** Playwright WebKit (`webkit-2336`, the WKWebView family) rebuilt
  `.doc-prose-scaler > .doc-prose > img` at K = 3 and card width 392 px. The rule
  `.doc-prose img { zoom: var(--oversample-k); max-width: 100% }` measured:

| image | 100% zoom (screen px) | 200% zoom |
|---|---|---|
| `width="160"`, natural 400×400 | 160 × 160 | 320 × 320 |
| no attrs, natural 100×50 | 100 × 50 | 200 × 100 |
| no attrs, natural 1920×1037 | 348 × 187.95 (capped to content width 392 − 44) | 696 × 375.91 |
| `width="600"`, natural 1920×1037 | 348 × 187.95 | 696 × 375.91 |
| `width="160" height="80"` | 160 × 80 | 320 × 160 |
| `height="80"` only | 80 × 80 | 160 × 160 |
| `width="50%"` | 174 × 174 | 348 × 348 |

  Adding `height: auto` dropped the explicit `height="80"` (160 × 160). The rule
  therefore sets no height.
- **Decoding.** A headless WKWebView harness (macOS 26.6.2, WebKit
  21624.5.1.11.3) loaded real samples, each identified by `file`, ImageIO or ffprobe, through a custom scheme
  whose responses carried `Content-Security-Policy: sandbox` and
  `X-Content-Type-Options: nosniff`:
  - **Load at their natural size:** PNG, APNG, JPEG, GIF, WebP, BMP, TIFF, ICO,
    AVIF, HEIC, and a HEIC sequence holding one frame plus a cover image. WebKit
    sniffs these, so they load under every declared type tried, including
    `application/octet-stream`. SVG loads only when declared `image/svg+xml`. The
    harness recorded the load and the natural size only. It read no pixels, did
    not check that the APNG animates, and tried no multi-frame HEIC sequence.
  - **Fail to load under every declared type tried**, though each sample is a
    valid file that ImageIO or ffmpeg decodes: JPEG 2000 (`jp2`, `j2k`),
    OpenEXR, DPX, FITS, KTX, PBM/PGM/PPM/PNM, PCX, Radiance, PSD, Sun raster, SGI,
    WBMP, XBM, XPM and XWD.
  - **Not measured:** every other Appendix A format. For plain HEIF, JPEG XL,
    PICT, EMF, WMF and DjVu, no non-GUI tool here writes a sample; the rest, such as
    KTX2, were not tried.
  - A control run of the PNG, JPEG, ICO and PSD samples without the two headers
    gave the same outcomes, as expected, since neither header applies to an `<img>`
    load.
  - The harness page and its images shared one origin. Loading across schemes, as
    Tarmac's page does, was exercised by the load-path spike above (dev build),
    and S25 covers the bundled build.

## Motivation

Doc cards are how an agent's written output reaches the user. READMEs, design
docs and reports routinely embed screenshots and diagrams that sit beside the
markdown. Today every one of them renders as an empty box, including Tarmac's own
README. The user has to leave the board to see what the doc is about.

## Proposed Solution

### Overview

Serve local images through a new **`img` host on the existing `tarmac-card://`
scheme**. It is a sibling Rust module that returns file bytes with an
image-only `Content-Type` and never HTML. `DocCard` parses marked's output into a
detached `<template>`, rewrites every `<img src>` through a pure kit resolver, and
only then inserts the nodes, so the broken app-origin URL is never fetched. One
CSS rule sizes images in the K× layout, so `width="N"` is N screen px at 100% zoom
and every image is capped to the prose width.

### Key Components

- **`desktop/src/kit/docImage.ts`** (new, pure; paired `docImage.test.ts`):
  - `localImagePath` resolves an image `src` to the absolute on-disk path it
    names, or `undefined` when the `src` is not a local file reference.
  - `docImageSrc` returns the `src` a doc-card `<img>` should carry.
- **`desktop/src-tauri/src/image_protocol.rs`** (new; inline `#[cfg(test)]`)
  serves `tarmac-card://img/<encoded-abs-path>?v=<mtime_ms>`. It takes an
  extension allowlist, sets `Content-Type`, and returns 403/404/400 as
  `text/plain`. Its module header states the same "raw path, no
  canonicalization, no jail" trust model as `card_protocol.rs`.
- **`desktop/src-tauri/src/card_protocol.rs`**: the percent-decoding in
  `decode_card_path` moves into a new
  `pub(crate) fn decode_scheme_path(uri: &str, prefix: &str) -> Result<String, String>`,
  and `text_response` becomes `pub(crate)`, so the image module reuses both
  instead of duplicating them. `decode_card_path` keeps its signature and
  behaviour, and its body only delegates to the new function. No other existing
  item in the file changes.
- **`desktop/src-tauri/src/lib.rs`**: the `tarmac-card` registration calls a new
  `respond_card_scheme(uri)`, which routes a `uri` that starts with
  `tarmac-card://img/` to `image_protocol::respond` and everything else to
  `card_protocol::respond`. It is tested in `lib.rs`'s `mod tests`.
- **`desktop/src/cards/DocCard.tsx`** (wiring, §1.3 exception 2): parse into a
  `<template>`, rewrite each `img[src]` by passing its `src` *attribute*
  (`getAttribute("src")`, not the resolved `.src` property) to
  `docImageSrc(src, model.path, props.lastChangedMs)` and writing the result back
  with `setAttribute`, then move the content into
  `.doc-prose`. No marked renderer override is needed: raw `<img>` HTML comes
  through marked as an `html` token, and the template walk covers it and `![]()`
  alike.
- **`desktop/src/theme/card.css`** (presentation, §1.3 exception 1):
  `.doc-prose img { zoom: var(--oversample-k); max-width: 100%; }`.
- **Docs**: add one sentence to the *Doc cards* paragraph of
  `docs/architecture.md`, and one to *Markdown cards* in
  `core/crates/tarmac-cli/src/SKILL.md`, on how local images resolve. The
  SKILL.md sentence names no repo path and no relative link: the inline test in
  `core/crates/tarmac-cli/src/skill.rs` fails on either.

### Data Flow

1. The markdown changes and `DocCard`'s layout effect runs.
2. `marked.parse` output is written into a detached `<template>`. Template
   content has no browsing context, so no image fetch starts.
3. Each `img[src]` in the template gets `docImageSrc(src, model.path, lastChangedMs)`.
   A local `src` becomes `tarmac-card://img/…`; anything else is left untouched.
4. The template content replaces `.doc-prose`'s children, and WebKit fetches the
   images.
5. `respond_card_scheme` routes the request to `image_protocol::respond`, which
   checks the extension, reads the file, and answers with the bytes and an image
   `Content-Type`.
6. As each image loads, `.doc-prose` grows. The existing `ResizeObserver` on it
   re-measures `proseNatH` and calls `relayout()`. No new observer is needed.

### Interface Contract

```ts
// desktop/src/kit/docImage.ts

/** Absolute on-disk path a doc image `src` names, or undefined when `src` is not
 *  a local file reference (the caller leaves it unchanged). `docPath` is the
 *  doc's absolute path (DocCardModel.path). Never throws. */
export function localImagePath(src: string, docPath: string): string | undefined;

/** The src a doc-card <img> should carry. Local → tarmac-card://img/ URL;
 *  otherwise `src` itself, returned unchanged. Pure. */
export function docImageSrc(src: string, docPath: string, mtimeMs: number | undefined): string;
```

`localImagePath` decision table. It first trims ASCII whitespace (tab, LF, FF,
CR, space) from both ends of `src`, then takes the first row that matches, top to
bottom (`docPath = /r/README.md` unless stated):

| trimmed `src` | result |
|---|---|
| empty | `undefined` |
| has a URL scheme (`^[A-Za-z][A-Za-z0-9+.-]*:`) whose name is not `file` (compared case-insensitively) — e.g. `http:`, `https:`, `data:`, `blob:`, `mailto:`, `tarmac-card:`, and a bare `x:y.png` | `undefined` |
| starts with `//` (protocol-relative) | `undefined` |
| `file://` URL (scheme case-insensitive) whose host — the text between `file://` and the next `/` — is empty or `localhost` | the path from that `/` on |
| `file://` URL, any other host | `undefined` |
| any other `file:` form (`file:/path`, `file:path`; scheme case-insensitive) | `undefined` |
| starts with `/` | that path |
| anything else | a relative path, joined in step 3 |

A local result's path then goes through these steps, in this order:

1. **Query and fragment.** Everything from the path's first `?` or `#` onward is
   dropped. This runs before decoding, so `%23` and `%3F` survive as a literal `#`
   or `?` in the file name. If nothing is left (`src="#top"`), the result is
   `undefined`.
2. **Percent-decoding.** The path is decoded with `decodeURIComponent`
   semantics: every `%XX` escape, including `%2F`, `%23` and `%3F`, decodes as
   UTF-8. If decoding fails anywhere (a stray `%` as in `100%.png`, or invalid
   UTF-8), the whole path is kept undecoded, including any valid escapes in it.
3. **Joining.** A relative path is appended to the doc's directory: `docPath` up
   to and including its last `/`. The directory is taken literally and is never
   decoded or cut at `?`/`#`.
4. **Normalization.** `.` and `..` segments of the resulting path are resolved,
   and `..` never climbs above `/`. Empty segments are kept (`/r//x.png`).

Non-ASCII whitespace around `src` is outside the tested domain.

Address format, the `img` host of `cardSrcUrl` in `desktop/src/kit/docKind.ts`:

```
tarmac-card://img/${encodeURIComponent(path)}?v=${mtimeMs ?? 0}
```

`v` only busts the cache: the handler ignores it and serves the current bytes.

```rust
// desktop/src-tauri/src/image_protocol.rs
pub fn image_content_type(path: &str) -> Option<&'static str>;
pub fn respond(uri: &str) -> tauri::http::Response<Vec<u8>>;

// desktop/src-tauri/src/lib.rs
fn respond_card_scheme(uri: &str) -> tauri::http::Response<Vec<u8>>;
```

`image_content_type` reads the file name's extension with
`std::path::Path::extension` semantics: the text after the last `.` of the file
name. A name with no `.` and a name whose only `.` is its first character
(`.png`) have no extension; a name ending in `.` (`x.`) has an empty one, which
matches no row. It matches case-insensitively against **Appendix A**: 128
extensions derived from all 115 image types listed on mimes.info/image as of
2026-09-15. 95 of those types are sent; Trade-offs lists the rest. An extension not in Appendix A, or no extension, is `None`.

Appendix A was built by this rule, and any later change to it follows the same
rule:

1. **Extension source.** A type's extensions come from its "Related File
   Extensions" on mimes.info. For a type listed there with none, they come from
   the `File extension(s)` field of its IANA registration template. `vnd.dxf`'s
   template has no such field but states that `.DXF` identifies the format, so
   `dxf` counts as its extension. An extension the field assigns to named subtypes
   only (`hif (for subtypes heif and heic)`) goes to those subtypes only.
   Extensions are kept lowercase, without the leading `.`, once per type. A
   deprecated alias with no registration template of its own (`x-emf`, `x-wmf`)
   gets no extension from IANA.
2. **Collisions.** When several types claim one extension, the tiers run in
   order, each on the types the tier before left, and the first tier that leaves
   a single type decides:
   1. An IANA-registered type (one with a row in IANA's `image.csv`) beats an
      unregistered one. If none is registered, all stay.
   2. A type whose whole subtype equals the extension wins; failing that, one
      whose last `.`-separated segment does.
   3. The five ties left are named: `heifs` → `image/heif-sequence`, `hif` →
      `image/heif`, `pgm` → `image/x-portable-graymap`, `ras` →
      `image/x-cmu-raster`, `xwd` → `image/x-xwd`.
3. **Spelling.** A type is sent as mimes.info spells it (`image/jxrA`).

`respond(uri)` returns:

| condition, checked in this order | status | headers | body |
|---|---|---|---|
| URI doesn't decode (wrong prefix, empty path, invalid UTF-8) | 400 | `Content-Type: text/plain; charset=utf-8` | error message |
| `image_content_type(path)` is `None` | 403 | `Content-Type: text/plain; charset=utf-8` | `{path}: not a supported image type` (the file is never opened) |
| file can't be read | 404 | `Content-Type: text/plain; charset=utf-8` | `{path}: {io error}` |
| otherwise | 200 | Appendix A's `Content-Type`, `Content-Security-Policy: sandbox` and `X-Content-Type-Options: nosniff` | the file's bytes, unmodified |

No response carries `Access-Control-Allow-Origin`, and none is ever `text/html`.

## Alternatives Considered

### Tauri's asset protocol (`convertFileSrc`)

Stock, and it brings MIME inference and Range support. It was rejected for four
reasons:

- It needs the `protocol-asset` cargo feature kept in lockstep with
  `app.security.assetProtocol` in `tauri.conf.json`; tauri-build fails on a
  mismatch.
- Its scope glob excludes dot-directories by default (`requireLiteralLeadingDot`
  is true on unix), so `/**` misses `~/.dev/x.png` without an override.
- It serves any file type, and its unknown-type fallback is `text/html`.
- `convertFileSrc` lives in `@tauri-apps/api`, which `kit/` must not import.

### A separate `tarmac-img://` scheme

This works equally well, but it needs a second registration and a second copy of
the async glue. A host on the existing scheme keeps one registration and one
dispatch point.

### Read bytes over IPC and swap in `blob:` URLs

This was rejected on three counts:

- The swap happens after insertion, so either the broken URL is fetched first or
  the images must be held back and patched in asynchronously.
- Blob URLs need revoking on every re-render.
- Whole image files would cross the IPC boundary per render.

### A marked `renderer.image` override

It can't see raw `<img>` HTML, which marked emits as an `html` token; the README
logo is exactly that case. The template walk covers both forms.

### Size images in JS (attribute width or `naturalWidth` × K, applied on load)

Measured to produce the same layout as the CSS rule. It was rejected because it
adds a load listener per image plus a decision table for something one
declarative rule already does. Typed CSS `attr()` (`attr(width px)`) would be
cleaner still, but it is not in Safari 26 (Technology Preview only).

## Security Considerations

- **Filesystem reach is not widened.** The main webview can already read any path
  as text through `read_doc` with no scope check, and `card_protocol.rs` serves any
  path. This change adds image-typed bytes, which page script still cannot read:
  the response has no CORS header, so the cross-origin image taints canvases.
- **Why the handler must never answer HTML.** Tauri treats pages from app-registered
  schemes as local and skips the command ACL for them (tauri 2.11.3
  `webview/mod.rs`). marked passes raw `<iframe>` through, so a markdown doc can
  frame a `tarmac-card://img/` URL. The allowlist guarantees such a frame can only
  ever receive an image type, never `text/html`.
- **Framed or navigated responses can't run script or be re-read as HTML.** SVG is
  scriptable when framed or navigated to, and many Appendix A formats are ones
  WebKit can't decode. Every 200 therefore carries
  `Content-Security-Policy: sandbox`, which gives a framed or navigated response
  an opaque origin with scripts disabled, and `X-Content-Type-Options: nosniff`,
  so a file WebKit can't decode is never re-sniffed as HTML. S22 checks that the
  formats WebKit renders still render with both headers.
- **Pre-existing, not widened, not fixed.** Raw HTML in markdown already runs in
  the main document (for example `<img onerror=…>`). That surface predates this
  change and is out of scope.

### Resolution — happy path
- **S1 [K]:** Given a relative `src`, when resolved, then it is joined onto the
  doc's directory with dot segments normalized:
  - `docs/images/logo.png` → `/r/docs/images/logo.png`
  - `./x.png` → `/r/x.png`
  - `../x.png` → `/x.png`
  - `a/./b/../c.png` → `/r/a/c.png`
  - `./x:y.png` → `/r/x:y.png` (the `./` keeps the colon out of scheme position)
- **S2 [K]:** Given an absolute `src`, when resolved, then the result is that
  path, normalized:
  - `/abs/dir/x.png` → `/abs/dir/x.png`
  - `/abs/../x.png` → `/x.png`
- **S3 [K]:** Given a `file://` URL, when resolved, then its path goes through the
  same steps as any local path:
  - `file:///abs/x.png`, `file://localhost/abs/x.png`, `FILE:///abs/x.png` →
    `/abs/x.png`
  - `file:///abs/my%20pic.png#x` → `/abs/my pic.png`
  - `file:///abs/../x.png` → `/x.png`

### Resolution — edge cases
- **S4 [K]:** Given a non-local `src`, when resolved, then `localImagePath` is
  `undefined` and `docImageSrc` returns the input string unchanged. The inputs:
  - `https://h/x.png`, `HTTPS://h/x.png`, `http://h/x.png`, `ftp://h/x.png`,
    and `" https://h/x.png"` (trimming runs before the scheme check)
  - `data:image/png;base64,AAAA`, `blob:http://localhost/u`
  - `mailto:a@b.c`, `tarmac-card://img/x`, `x:y.png`
  - `//h/x.png`, `file://example.com/x.png`, `file:/abs/x.png`, `File:/abs/x.png`,
    `file:abs/x.png`
  - `""`, `"   "` and `"#top"`
- **S5 [K]:** Given `x.png?raw=true#top` or `/abs/x.png#frag`, when resolved,
  then the query and fragment are gone: `/r/x.png` and `/abs/x.png`.
- **S6 [K]:** Given a percent-encoded `src`, when resolved, then it is decoded,
  and a malformed escape falls back without throwing:
  - `my%20pic.png` → `/r/my pic.png`
  - `%E5%9C%96.png` → `/r/圖.png`
  - `a%23b.png` → `/r/a#b.png` and `a%3Fb.png` → `/r/a?b.png` (the strip ran
    before decoding)
  - `100%.png` → `/r/100%.png`
  - `my%20pic%.png` → `/r/my%20pic%.png` (the fallback keeps the whole path
    undecoded)
  - `%2Fx.png` → `/r//x.png`: the row is picked before decoding, so it is
    relative, and the empty segment stays. POSIX reads `//` as `/`.
- **S7 [K]:** Given a doc directory containing URL-significant characters, when
  `img/x.png` is resolved, then the directory is kept byte-for-byte, neither
  decoded nor cut at `#`/`?`:
  - `docPath` `/tmp/my docs 100%#?/圖表/README.md` →
    `/tmp/my docs 100%#?/圖表/img/x.png`
  - `docPath` `/tmp/a%20b/README.md` → `/tmp/a%20b/img/x.png`

  The second directory must hold only valid escapes. With the first one's stray
  `%`, decoding the directory fails, the S6 fallback keeps it literal, and a
  mutant that decodes the directory still passes.
- **S8 [K]:** Given `"  x.png  "` or `"\tx.png\n"`, when resolved, then the result
  is `/r/x.png`. A vertical tab is not one of the trimmed characters:
  `"\vx.png"` resolves to `/r/\vx.png`.
- **S9 [K]:** Given a `src` that climbs past the root, `../../x.png` (one level
  past) and `../../../x.png`, when resolved, then both results are `/x.png`. The
  one-level case matters: in the deeper input, a `..` wrongly kept at the root
  is popped again by the next `..`.

### Addressing
- **S10 [K]:** Given `src` `img/x.png` and S7's first `docPath`, when
  `docImageSrc` builds the URL with `mtimeMs` 1234 and again with `undefined`,
  then it matches all of the following. Compute expected values from
  `encodeURIComponent`; do not hard-code them.
  - With 1234 it equals
    `` `tarmac-card://img/${encodeURIComponent("/tmp/my docs 100%#?/圖表/img/x.png")}?v=1234` ``.
  - It is `tarmac-card://img/`, then one segment, then `?v=<mtimeMs>`.
  - The segment contains no `/`, `#` or `?`.
  - `decodeURIComponent(segment)` equals `localImagePath(src, docPath)`.
  - A missing `mtimeMs` gives `?v=0`.
- **S11 [K]:** Given the same `(src, docPath, mtimeMs)`, when `docImageSrc` is
  called twice across a fake-timer tick, then both URLs are identical. This is a
  purity guard, the same shape as the `cardSrcUrl` guard in `docKind.test.ts`.

### Image handler
- **S12 [R]:** Given a readable temp file named `*.png` whose bytes are not valid
  UTF-8 (the PNG signature `89 50 4E 47 0D 0A 1A 0A` and a few more bytes), when
  its `tarmac-card://img/<encoded path>?v=1` URI is served, then:
  - status is 200 and the body is byte-identical to the file
  - `Content-Type` is `image/png`, `Content-Security-Policy` is `sandbox` and
    `X-Content-Type-Options` is `nosniff`
  - there is no `Access-Control-Allow-Origin` header and no shim bytes
  - a readable `*.svg` file is served the same way with
    `Content-Type: image/svg+xml`, so the type comes from Appendix A, not a
    constant
- **S13 [R]:** Given every row of Appendix A, when `image_content_type` is called
  with `/d/x.<extension>`, then it returns exactly that row's type. The test
  holds its own literal copy of all 128 `(extension, type)` pairs, because a test
  that iterates the production table passes however wrong the table is, and
  asserts the production table has exactly 128 rows, so an extra row fails. It
  also checks `x.PNG`, `x.JpEg`, `x.HEIC`, `x.X-PNG` and `x.Svg` for
  case-insensitivity. `/d/x.png.txt`, `/d/README`, `/d/.png`, `/d/x.` and
  `/d/x.cgm` return `None`.
- **S14 [R]:** Given an existing, readable file named `*.html`, `*.md`, `*.png.html`
  or with no extension, when served, then the response is 403 with
  `Content-Type: text/plain; charset=utf-8` and the body does not contain the
  file's contents.
- **S15 [R]:** Given a `*.png` path that doesn't exist, when served, then the
  response is 404 with `Content-Type: text/plain; charset=utf-8` and the body
  names the path. A missing `*.html` is 403, because the type check comes first.
- **S16 [R]:** Given each of `tarmac-card://img/?v=1` (empty path),
  `tarmac-card://img/%FF?v=1` (invalid UTF-8) and `tarmac-card://doc/x.png?v=1`
  (wrong prefix), when passed to `image_protocol::respond`, then the response is
  400 with `Content-Type: text/plain; charset=utf-8` and nothing panics.
- **S17 [R]:** Given a `*.png` whose name contains spaces, CJK, `%`, `#` and `?`,
  percent-encoded as one segment and followed by `?v=1`, when served, then the
  response is 200 with the file's bytes.
- **S18 [R]:** Given `respond_card_scheme`, when called, then:
  - a `tarmac-card://img/…` PNG URI returns 200 `image/png` bytes
  - a `tarmac-card://doc/…` HTML URI returns what `card_protocol::respond` returns:
    200 `text/html; charset=utf-8`, shim first, `CARD_CSP` header
  - `tarmac-card://other/x` returns 400

## Trade-offs and Limitations

- **Not rewritten:** `srcset`, `<picture><source>`, `<video>`/`<audio>` and CSS
  `url()`. Only `img[src]` is.
- **Many served types don't render.** WebKit decodes only some formats; Context
  (*Decoding*) lists the ones measured to render and not to render, and the rest
  are unmeasured. A format WebKit can't decode is still served with its Appendix A
  type and shows WebKit's broken-image placeholder, just as a 403 would.
- **Coverage is a 2026-09-15 snapshot of two outside lists.** mimes.info is not
  versioned. A type mimes.info adds later, or an extension either source changes,
  is not reflected until Appendix A is re-derived by the same rule. An
  IANA-registered type mimes.info doesn't list (such as `image/jaii`) is not
  served.
- **Eight listed types have no extension in either source, so no file can reach
  them:** `cgm`, `example`, `pwg-raster`, `vnd.cns.inf2`, `vnd.mix`, `vnd.svf`,
  `x-emf`, `x-wmf`. `.cgm` files are common, but the IANA
  registration names no extension.
- **Twelve spellings are never sent**, because the collision rule gives all their
  extensions to another type: `pjpeg`, `vnd.mozilla.apng`, `vnd.net-fpx`,
  `x-dwg`, `x-icon`, `x-pcx`, `x-portable-greymap`, `x-tiff`, `x-windows-bmp`,
  `x-xbitmap`, `x-xbm`, `x-xwindowdump`.
- **The rule makes some picks that common practice wouldn't:**
  - `.ico` is sent as `image/vnd.microsoft.icon`, not the common `image/x-icon`.
  - `.pic` is sent as `image/vnd.radiance`, though Mac PICT files also use `.pic`.
  - `.svf` is sent as `image/vnd.dwg`, because only mimes.info names it.
  - `.sgi` is sent as `image/vnd.sealedmedia.softseal.gif`, though SGI images also
    use `.sgi`.
  - `.hsj2` is sent as `image/hsj2`, though IANA marks that registration obsolete.
  - `.sub` (a DVB subtitle), `.pm`, `.x-png` and `.jfif-tbnl` are served because
    a source lists them.
- **No live refresh for image-only changes.** An image changed on disk shows up
  only when the doc's own text next changes: the render effect runs on markdown
  changes, and the cache-buster follows the doc's mtime. The refresh control
  re-reads the same text, so it does not re-fetch images. Tarmac watches only
  opened docs; there is no image-file OS fact to key on.
- **A literal `#` or `?` in a local image's own filename can't be written as-is**
  (URL semantics, same as GitHub). Percent-encoded as `%23` or `%3F` it resolves
  (S6), and both are fine in the doc's directory (S7).
- **A relative `src` whose first segment contains `:`** (`x:y.png`) reads as a URL
  scheme and is left unchanged (S4); `./x:y.png` resolves (S1).
- **Protocol-relative `//host/x.png` stays broken**, as today.
- **HTML cards are unchanged.** Their CSP (`img-src data: blob:`) still forbids
  local images, and SKILL.md's hard rule for them stays true.
- **Capped images with both attributes distort.** An image with both `width` and
  `height` that the prose width caps keeps its explicit height, matching GitHub's
  `max-width: 100%`.
- **`zoom` scales every length on the image.** An inline `style` margin or border
  on an `<img>` scales with it, which keeps it proportional to the prose.
