# 2611.0034 The app compares doc paths as bytes

**Date:** 2026-11-25
**Status:** accepted (spec-evaluator + advisor, 2026-11-25)
**Author:** EP Lin
**Issue:** #314

## Context

The daemon keys each doc by the path that `std::fs::canonicalize` gives (`core/crates/tarmacd/src/reader.rs`), and its registry compares those paths as bytes. The app keeps the same paths as Swift `String`s and uses them as dictionary keys and with `==`. A Swift `String` compares by canonical equivalence, so `/v/\u{e9}/a.md` (NFC) and `/v/e\u{301}/a.md` (NFD) are one key in the app and two keys in the daemon.

The app keys or compares doc paths as `String` in these places:

- `CardID.doc(String)` (`app/Sources/TarmacApp/BoardModel.swift`): the key of `BoardView.cards`.
- `DocStore` (`app/Sources/TarmacKit/DocStore.swift`): `indexByPath: [String: Int]` and the `seen` set of `applyRestore`.
- `BoardRestore.plan` (`app/Sources/TarmacKit/BoardRestore.swift`): `recordedOwner: [String: String?]`, which joins a layout tile to its doc.
- `Board.docOwner: [String: String]` (`app/Sources/TarmacApp/Board.swift`).
- `CardDataRegistrations` (`app/Sources/TarmacKit/CardDataRegistrations.swift`): `Card.path` is a hashed `String`, and `cards(reading:)` compares the data file with `==`.
- The dev driver (dev builds only), where a doc card's id is its path: `DevRouting.onCard` (`$0.id == id`) and the `borrow` flag of `.focusHTML` (`context.borrowedCard != card.id`) in `app/Sources/TarmacKit/DevRouting.swift`; the `focused` and `borrowed` fields of a card in `app/Sources/TarmacKit/DevSnapshot+JSON.swift` (`card.id == input.selectedCard`, `card.id == input.borrowedCard`); and `cardView(_:)` in `app/Sources/TarmacApp/Dev/DevVerbs.swift` (`$0.id.wireID == id`). `DevUntil` already compares a `cards[<id>]` id by its scalars.

Not in this list: `app/Sources/tarmac-smoke/main.swift` compares `doc.path == canonical`, where `canonical` comes from `FileBytes.resolved`, which is out of scope. `LayoutTiles.build` sorts doc tiles by UTF-16 code unit, which is an order and not an equality. `CardDataPath` and `CardProtocol` already compare bytes.

The owner's decision of 2026-11-25 (#314 comments): the daemon decides whether two paths are one doc, and the app does not. There is no normalisation and no `(dev, inode)` join, on any volume.

## Motivation

On a volume that keeps the two forms as two files (NFS, SMB, FUSE, ext4), the daemon has two docs and the app shows one card. A `file_event`, a `doc_event` or a data-file change of one doc then goes to the card of the other doc. The app takes a decision that belongs to the file system and the daemon.

## Proposed Solution

### Overview

A new TarmacKit value, `DocPath`, holds one doc path. Its `==` and its hash use only the UTF-8 bytes of the path. Each place in the Context list keys or compares by `DocPath`, so two paths are one doc in the app exactly when they are one doc in the daemon. The wire protocol, `state.json` and the daemon do not change.

### Key Components

- **`DocPath`** (`app/Sources/TarmacKit/DocPath.swift`, tests in `app/Tests/TarmacKitTests/DocPathTests.swift`, as `make arch-check` requires) — a value type that wraps the path `String`. `==` and `hash(into:)` use `string.utf8` only.
- **`DocStore`** — keys `indexByPath` and the `seen` set of `applyRestore` by `DocPath`.
- **`BoardRestore.plan`** — keys `recordedOwner` by `DocPath`.
- **`CardDataRegistrations`** — `Card` hashes its path as a `DocPath`, and `cards(reading:)` compares the data file as a `DocPath`.
- **`CardID.doc`** (`TarmacApp`) — carries a `DocPath`. `CardID` keeps its synthesized `Hashable`, so the shell holds no comparison rule of its own.
- **`Board.docOwner`** (`TarmacApp`) — `[DocPath: String]`.
- **The dev driver** — `DevRouting`, `DevSnapshot+JSON` and `DevVerbs.cardView` compare a doc card's id as a `DocPath`. The implementing agent may compare every card id by bytes: a term id is ASCII, so the result for it does not change.

The public kit APIs may take `String` or `DocPath`. The implementing agent chooses. The rule is that no doc-path key or doc-path comparison in the Context list uses `String` `==` or `String` hashing.

### Data Flow

1. A daemon message (`restore`, `doc_opened`, `file_event`, `doc_event`, `doc_closed`) gives a path as a msgpack `str`. The Swift codec decodes it to a `String` with the same scalars.
2. The receiver makes a `DocPath` from it and looks up or stores by that key.
3. A request back to the daemon (`doc_close`, `doc_refresh`, `data_file`, and the doc tiles and the `dock` list of `layout`) sends `DocPath.string`, which has the same bytes the daemon sent.

### Interface Contract

```swift
public struct DocPath: Hashable, Sendable {
    public let string: String
    public init(_ string: String)
    // ==         : lhs.string.utf8 elementsEqual rhs.string.utf8
    // hash(into:): hashes the bytes of string.utf8
}
```

No wire key, message type or persisted field changes.

## Alternatives Considered

### Normalise paths in the app

Swift `String ==` already is this. On a volume that keeps two forms apart, it joins two files. Only the file system knows its rule.

### `(dev, inode)` join in the daemon

The investigation for #314 (2026-11-25, re-checked by a second agent) found three problems. An atomic save gives the path a new inode. `st_ino` can collide on SMB and FUSE, which joins two files. Hard links, which show as two cards today, would join into one. The owner rejected it.

## Trade-offs and Limitations

- **Case (b) shows two cards of one file.** A doc file is deleted while it is open, the file is made again under the same name in the other form, and `tarmac open` names it again. On APFS, `canonicalize` then gives the new stored bytes, the daemon has two docs, and the app shows two cards. Both cards refresh. Today the app shows one card. The owner accepted this.
- **An old `state.json` with two entries for one file shows two cards.** The owner accepted this.
- **A push that names the new spelling of a case-(b) doc still fails** with `not an open doc`, as it does today.
- `FileBytes.resolved` (`String(cString:)`, U+FFFD) is out of scope.

## Acceptance Scenarios

Below, NFC is `"/v/\u{e9}/a.md"`, NFD is `"/v/e\u{301}/a.md"`, HTML-NFC and HTML-NFD are the same two forms with `a.html` in place of `a.md`, and a data file adds `/data.json` in the same form. "The doc (or card) NFD" is the one whose path has the bytes of NFD. Each Then that names a path compares UTF-8 bytes (see *For the Implementing Agent*).

### Happy Path

- **Two forms of one name are two doc paths:** Given NFC and NFD, when each is made a `DocPath`, then the two are not equal, and a `Set` of both has two members.
- **Same bytes are one doc path:** Given two `String`s built separately with the same bytes, when each is made a `DocPath`, then they are equal and have the same hash.
- **Doc path keeps its string:** Given NFD, when it is made a `DocPath`, then `.string.utf8` equals the bytes of NFD.
- **Restore keeps both forms as two docs:** Given a restore list with an NFC doc and an NFD doc, when `DocStore.applyRestore` takes it, then `docs` has two entries, `doc(for:)` with NFC returns a doc with the bytes of NFC, and `doc(for:)` with NFD returns a doc with the bytes of NFD.
- **Restore still drops an exact repeat:** Given a restore list with the same path twice in the same bytes, when `DocStore.applyRestore` takes it, then `docs` has one entry.
- **Open in the other form is a new doc:** Given a `DocStore` with the NFC doc, when `applyDocOpened` takes the NFD doc, then it returns true, and `docs` has two entries.
- **File event goes only to its own form:** Given a `DocStore` with the NFC doc and the NFD doc, when `applyFileEvent` names NFD, then the NFD doc has the new `lastChangedMs`, and the NFC doc keeps its old `lastChangedMs`.
- **Close removes only its own form:** Given a `DocStore` with the NFC doc and the NFD doc, when `remove` names NFD, then `docs` has one entry, and its path has the bytes of NFC.
- **Restore plan joins a tile only to its own form:** Given terminal tiles for terms A and B, both in `liveTerms`, an NFC doc whose `termID` is A, an NFD doc whose `termID` is B, and a doc tile for each, when `BoardRestore.plan` runs, then the placed doc with the bytes of NFC has owner A, and the placed doc with the bytes of NFD has owner B.
- **Restore plan drops a tile with no doc of its form:** Given only the NFC doc and a doc tile for NFD, when `BoardRestore.plan` runs, then `droppedDocPaths` holds one path with the bytes of NFD, and `docs` of the plan is empty.
- **Data registrations keep two forms apart:** Given, on one board, card NFC registered for the NFC data file and card NFD registered for the NFD data file, when `cards(reading:)` names the NFD data file, then it returns one card, with the path bytes of NFD, and `resent` holds two `data_file` messages.
- **Clearing one form keeps the registration of the other form:** Given, on one board, card NFC and card NFD each registered for a data file, when `set(nil, for:)` names card NFD, then `resent` holds one `data_file` message, and its doc path has the bytes of NFC.
- **Dev focus goes to the card of the same bytes:** Given a `DevRouting` context with HTML cards HTML-NFC and HTML-NFD, both inside the view and not culled, where HTML-NFC is the borrowed card, when a `focus` request names HTML-NFD, then the route is `.focusHTML` with the card bytes of HTML-NFD and `borrow` true.
- **Snapshot marks only the card of the same bytes:** Given a dev snapshot input with doc cards NFC and NFD, where NFD is the selected card and the borrowed card, when the snapshot is made JSON, then card NFD has `focused` true and `borrowed` true, and card NFC has `focused` false and `borrowed` false.

### Edge Cases

- **Two forms that Unicode calls one are two doc paths:** Given `"/v/\u{c5}.md"` (A with ring above) and `"/v/\u{212b}.md"` (Angstrom sign), when each is made a `DocPath`, then the two are not equal.
- **Combining mark after a slash stays a slash:** Given `"/v/\u{301}a.md"` and `"/v/a.md"`, when each is made a `DocPath`, then they are not equal.
- **Recreated name in the other form shows a second card:** Given the dev app with an open doc `café.md` named in NFC on APFS, when the file is deleted, made again under the NFD name, and `tarmac open` names it again, then the dev snapshot lists two doc cards, one whose id has the bytes of the NFC path and one whose id has the bytes of the NFD path (read with `cards[<id>]`, which compares scalars). After an edit to the file, both cards show the new text. (QA against a `make run` app. `make qa` checks the two card ids. No dev verb or snapshot fact reads a doc card's text, so the refresh of both cards is checked by hand: a screen capture of the dev window after the edit, recorded in the PR body. If only one card refreshes, stop and report to the owner before the PR: the owner accepted case (b) on the basis that both cards refresh.)

A **two-form** test fails when its key or comparison goes back to `String`. A **guard** still holds when `DocPath` compares as `String`, because `String` gives the same answer for its inputs; it is kept so that a wrong `DocPath` fails (one that drops or merges a combining mark, one whose `==` or hash does not agree for the same bytes, one that changes its string, a `DocStore` that no longer drops a repeat). Every new test fails on the unmodified tree: the `DocPathTests` guards do not compile before `DocPath` exists, and "Restore still drops an exact repeat" is an existing test. TDD applies with no exemption.

`CardID`, `Board.docOwner` and `DevVerbs.cardView` are `TarmacApp` wiring. `TarmacApp` has no unit tests by design (`docs/coding-style.md` §1.2); their comparison is `DocPath`'s. The PR names exception 2 of §1.3 (thin wiring) for them, and the QA scenario is its verification statement.

## For the Implementing Agent

> **Your job:** make every acceptance scenario above pass with tests that would *fail if the behavior were wrong*. A green suite that passes for the wrong reason does not satisfy this contract — `/verify` will hunt for vacuous tests by asking, of each behavior, "what is the smallest change that breaks this, and would any test catch it?"

Implement however you work best. Only the result is checked. Write tests to the project's conventions (`docs/coding-style.md`; TDD: watch each new test fail on the unmodified tree) and to these principles:

- **Behavioral over structural** — assert observable output and effects, not internals.
- **Every test can fail** — no copy-pasted expected values, no asserting a constant, no tautologies. Each two-form test must fail when `DocPath` (or the key) compares as `String`.
- **Assert paths as bytes** — an assertion that names a path compares `.utf8` bytes or `DocPath`s. Never `XCTAssertEqual` on two path `String`s, `contains` on a `[String]`, or `==` on a value that holds a path `String` (for example `RestoreDoc` or `BoardRestore.Plan`): `String ==` passes when the other form comes back, so the test cannot fail.
- **Deterministic, isolated, readable** — AAA structure with inline setup.
- **Name each test after its scenario title** — for example `testTwoFormsOfOneNameAreTwoDocPaths`. The one exception is the existing test that the table names for "Restore still drops an exact repeat".
- **Pass the repo's own checks** — `make test`, `make lint ONLY=swift`, `make lint ONLY=swiftc`.

Safety for the QA scenario: run it only against a `make run` dev app (`.claude/skills/dev-channel/SKILL.md`). Make the files only under a scratch folder. NFC and NFD names are valid UTF-8. Never make a name that is not UTF-8 (#316).
