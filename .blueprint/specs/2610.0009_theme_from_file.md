Decisions the draft made, which the user accepted at the gate:

- **G1. The config directory's rule.** `TARMAC_CONFIG_DIR` when it is set and not empty; or else `$XDG_CONFIG_HOME/tarmac` when that variable is an absolute path; or else `$HOME/.config/tarmac`. A debug build adds `/dev` to the last two, as `ChannelPaths.channelDir` does. Only the app reads it, so the rule has no Rust twin.
- **G2. The id of a file theme is `file:` and then the file's name. Its title is the file's name.** A Ghostty theme file has no extension, and its name is the theme's name.
- **G3. Which files are read.** A regular file directly in the folder (a symbolic link to one is followed), at most 65,536 bytes, whose name does not start with `.`, does not end with `~` and holds no control character. A subfolder is not read.
- **G4. The grammar is that of Ghostty 1.3.1 for the lines, and narrower for the values.** A colour is `#rrggbb`, `rrggbb`, `#rgb` or `rgb`. An X11 colour name and a `palette` index that is not plain decimal are not read (see *Trade-offs and Limitations*).
- **G5. A used key with a value that cannot be read refuses the file.** Ghostty skips such a line and goes on with its default. A theme with one colour that the user did not write is worse than a line in the pane that names the bad line.
- **G6. A file with fewer than 16 `palette` entries is offered.** A missing entry is the one of the standard theme of the file theme's variant (Breeze Light or Breeze Dark).
- **G7. The Tarmac keys** (see *The file's keys*): `tarmac-` and then the token's name in lower case with hyphens, and `tarmac-repo = N=colour`. The scroll thumb has no key (#209).
- **G8. The selection of a file theme is its `agent` at 0.3,** as every built-in theme has it (2610.0008 G5). `selection-background`, `selection-foreground` and `cursor-text` are not read.
- **G9. The rule that derives the chrome** (see *The derived colours*): the fills and the lines are fixed mixes of the terminal background and foreground; the text and the marks start from the foreground and from ANSI 6, 3, 2 and 1, the repo colours from ANSI 3, 2, 4 and 5, and each is moved towards white (a dark theme) or black (a light theme) in steps of 1/16 until it passes its floor on the three fills. `faint` and `prose` are not moved. Measured on the 463 files of Ghostty 1.3.1: one theme is left with a chrome finding.
- **G10. The order of the list:** the eight built-in themes, and then the file themes by title, with no regard to letter case.
- **G11. The caption of a file theme** is `light theme, from a file` or `dark theme, from a file`.
- **G12. The contrast note also counts chrome colours,** in a second sentence, when there is one. No built-in theme has one, so their notes do not change. The note's tooltip lists each finding. This replaces 2610.0008 G14.
- **G13. A line under the list tells what was read,** with a button *Open Themes Folder*. A file that was refused is named in that line's tooltip, with the reason.
- **G14. A saved id is kept when no theme has it** (the issue's second comment, point 2). Any id that is not empty, holds no control character and is not the standard id of its appearance is read and written. It is resolved when it is used, as a font family is. This replaces 2610.0008 G9.
- **G15. A theme is compared by value** where "did the theme in effect change" is the question (`ThemeSettings`), and by id where "is this the chosen theme" is the question (`ThemeBrowser`).
- **G16. When the themes change, the shown theme keeps its id.** If no theme has that id any more, the shown theme is the theme in effect. This adds to 2610.0008 G19.
- **G17. The list has the height of eight rows and scrolls.** The window keeps one size. This replaces 2610.0008 G21. *(After the gate: the height is not less than eight rows, and does not depend on the number of rows. See "Changed after the gate".)*
- **G18. The snapshot's `theme` gains four members:** `folder`, `available`, `refused` and `findings`.
- **G19. The QA verbs:** `show` also takes an id, `rows` prints the id of each row, the frame of the list and the new lines for the tooltips and the line under the list, and `open-themes` presses the button.
- **G20. A byte-order mark at the start of a file is dropped.** Ghostty 1.3.1 does not drop it for a theme file: the mark is then part of the first key, and Ghostty reports an unknown field for that line. Tarmac ignores a key that it does not use, so by that rule the first line would be lost with no word. That is the silent wrong colour that G5 is against.
- **G21. The quote rule is for the value of a line only, and a hex digit is an ASCII one.** `palette = "1=#fff"` is read, and `palette = 1="#fff"` refuses the file, as in Ghostty.
- **G22. The list scrolls its selected row into view** when the Settings window opens and when the themes change.
- **G23. A title that is longer than its room is cut at its end,** in a row and in the showcase. The window's size does not depend on a title.
- **G24. The watch is an `FSEventStream` on the folder's path,** with a latency of 0.2 s (see *Measured*). Every callback makes one read of the whole folder.

## Context

2610.0008 gave Tarmac eight built-in themes, a list of them with a showcase, and a choice for each appearance. A user whose palette is not one of the eight cannot have it.

The Ghostty theme format is the source: `mbadolato/iTerm2-Color-Schemes` exports each scheme to it, and a Ghostty install carries hundreds of files.

### Read at `17b54fe`

- `ThemeCatalog.all` is a static list of eight `Entry` values (`id`, `title`, `palette`). `ThemeCatalog.entry(_:for:)` and `inEffect` look an id up in it.
- `ThemeCatalog.saved(_:for:)` keeps only an id of the catalogue. `AppPrefs` calls it at decode and at encode, and `encode` writes the id raw.
- `ThemeSettings.resolve` returns early when `entry.id == Theme.entry.id`. `ThemeBrowser.box` and `marks` compare ids. `PageTheme` compares palettes.
- `ThemeBrowser.marks(of:themes:)` takes the raw ids. `ThemeSettings.themes` has one caller, `ThemePane`, which feeds `marks`.
- `ThemeList` reads `ThemeCatalog.all` once, at `init`, and sets its height to that of all its rows. `SettingsWindowController` takes the window's size once, from the fitting size of the panes.
- `Palette` has 18 chrome tokens, 4 repo colours and a `Terminal` (foreground, background, cursor, one selection colour with an alpha, 16 ANSI colours). `scrollThumb` is `181b1d` and `scrollThumbLine` is `696b6c` in all eight palettes.
- `AppPrefs.path(besideSocket:)` puts `app-prefs.json` beside the daemon socket. No code of the app or of the Rust workspace reads `XDG_CONFIG_HOME` or `~/.config` for Tarmac.
- `FontRole.isFamilyName` is the precedent for G14: a name is kept when it is not empty and has no scalar under `0x20` and no `0x7f`.

### Measured on 2026-10-07

**The files of Ghostty 1.3.1** (`/Applications/Ghostty.app/Contents/Resources/ghostty/themes`, 463 files). Every file has exactly 22 lines with a value: 16 `palette = N=#rrggbb` lines for 0 to 15, and `background`, `foreground`, `cursor-color`, `cursor-text`, `selection-background`, `selection-foreground`. Every value is `#rrggbb`. 385 themes are dark and 78 are light by the rule of `Palette.variant`.

**The grammar**, read in the source of Ghostty at the tag `v1.3.1` (`332b2ae`): `LineIterator.next` and `parseIntoField` in `src/cli/args.zig`, `Color.parseCLI`, `TerminalColor.parseCLI` and `Palette.parseCLI` in `src/config/Config.zig`, `Config.loadTheme`, and `src/config/theme.zig`.

| Point | Ghostty 1.3.1 | This spec |
| --- | --- | --- |
| A line | Trimmed of space, tab and `\r`. Empty, or with `#` first: skipped. Split at the first `=`; key and value trimmed of space and tab. No comment after a value. | The same |
| Quotes | A value of 2 characters or more that starts and ends with `"` loses them | The same |
| A colour | `#rrggbb`, `rrggbb`, `#rgb`, `rgb`, in any letter case; an X11 colour name | The hex forms. A name refuses the file |
| `palette` | `N=colour`, split at the first `=` of the value, both parts trimmed. `N` is 0 to 255, decimal or with `0x`, `0o`, `0b`, `+`, `_` | `N` is decimal digits only. Another form refuses the file. 16 to 255 are read and not used |
| `cursor-color` | A colour, or `cell-foreground`, or `cell-background` | A colour. The two words read as "not set" |
| An empty value | Sets the key back to its default; `palette =` sets back all entries | The key is as if no line gave it |
| A key given twice | The last line wins; `palette` by index | The same |
| Another key | Any config key is valid in a theme file | The line is ignored, whatever its value |
| A bad line | A diagnostic; the line is skipped | The file is refused (G5) |
| Where a theme is found | `$XDG_CONFIG_HOME/ghostty/themes` (or `~/.config/ghostty/themes`), then the app's resources. The file's name is the theme's name, with no extension | `themes/` of Tarmac's config directory only (D1) |

**The fit of the derived fills.** For each of the eight built-in palettes, the mix factor `t` that gives each fill and line from the terminal background `B` and foreground `F` (`B + (F − B) · t`) was computed. For the four dark palettes `bg1` is at −0.030 to −0.038 and `bg0` at −0.059 to −0.090: the fills that are darker than the terminal are on the far side of `B` from `F`. For the four light ones `bg1` is at 0.032 to 0.056 and `bg0` at 0.078 to 0.113. Of the 16 factors of G9, 14 are within 0.02 of the middle of their token's range. The two that are not are those of `liftBorder`: 0.40 for a dark theme, in a range of 0.28 to 0.66, and 0.55 for a light one, in a range of 0.48 to 0.69. One factor is outside its range: `bg1` for a dark theme is −0.04, and its range ends at −0.038.

| --- | --- | --- |
| The mixes, and ANSI 6, 3, 2, 1 as they are | 251 | 1172 |

The one theme is *Hot Dog Stand* (white on red, 4.20): white itself has less than 4.5 on its fills. For Catppuccin Latte the rule gives `agent` `148086`, `amber` `a76b16` and `ok` `388c26`; the built-in palette, tuned by hand, has `148187`, `a26715` and `358423`. **The watch**, measured with a stand-alone Swift 6 program on macOS 26 (Darwin 25.6), each step timed against the callback.

| Interface | A file made, changed in place, replaced by a rename, removed | The folder made after the stream | The folder removed and made again |
| --- | --- | --- | --- |
| `FSEventStream` on the folder's path, with `FileEvents` and `WatchRoot` | Each one gives a callback | A callback for the folder (`RootChanged`), and then for each file | Callbacks go on, with no new stream |
| `DispatchSource` on a descriptor of the folder | No event for a change in place | It cannot be made: there is nothing to open | No event after the folder is removed |

- **The delay** from a write to the callback, with a latency of 0.2 s: 14 to 217 ms without `NoDefer` (median 53), and 6 to 26 ms with it. Twenty files made in one burst gave one callback without `NoDefer`, and two with it.
- **The stream follows the path, not the folder.** After `mv themes themes.old` and a new `themes`, a change in `themes.old` gave no event, and a change in the new folder did.
- **A watched path that is a symbolic link** gives its events with the real path, not the link's.
- **A file in the folder that is a link to a file outside it:** a change of the target gave no event.
- **The flags of an event are a history, not a kind.** An append reported `Created|Modified`, and a removal `Removed|Renamed`. `sed -i` made a file `.!<n>!<name>` for a moment, and a save through a second file made `<name>.tmp`.
- **Swift 6.** The `@convention(c)` callback with an `info` pointer compiles in the Swift 6 language mode with no diagnostic, on a stream whose dispatch queue is the main queue.

## Motivation

The eight themes cover eight palettes. With this change a user copies one file into a folder and has that palette in every card, with no restart. A user or an agent who wants a palette of their own writes one file, sees it live, and reads in the pane which colours are too faint.

## Proposed Solution

### Overview

Tarmac ships no theme file (G25). It reads every theme file that the user put in `themes/` of its config directory. Each file that can be read is a theme: it is one more row of the Theme pane's list, after the eight built-in themes, and it can be applied to the light appearance, the dark appearance or both, as a built-in theme can.

A file gives the terminal colours in the Ghostty keys. It can give each chrome colour in a Tarmac key. Each colour it does not give is derived by a fixed rule, so a plain Ghostty file is a whole theme.

The folder is watched. A file that is added shows in the list. A file that is changed draws again everything that has its colours, at once. A file that is removed, damaged or without a `background` or a `foreground` is not a theme: an appearance that had it has its standard theme, and `app-prefs.json` keeps the id, so the theme is back in effect when the file is.

A line under the list says how many themes came from files and how many files were not read, and a button opens the folder.

### Key Components

New, in `TarmacKit`, each with its paired test file:

- **`ChannelPaths.configDir` and `themesDir`** (`ChannelPaths.swift`) — where the config directory and the folder are.
- **`ThemeFile`** (`ThemeFile.swift`) — the text of a file to the colours it gives, or the reason it is refused; and those colours to a whole `Palette`.
- **`ThemeLibrary`** (`ThemeLibrary.swift`) — a value: the built-in themes and the themes of a set of files, in the order of the list, the files that were refused, and the rules that were `ThemeCatalog.entry` and `ThemeCatalog.inEffect`.
- **`ThemeFolder`** (`ThemeFolder.swift`) — the one thin file operation: the files of a folder, by name, with their bytes.

Changed, in `TarmacKit`:

- **`ThemeCatalog`** — keeps `Entry`, `all` (the eight) and `standard(for:)`. `entry(_:for:)` and `inEffect` are removed: the library has them. `saved(_:for:)` keeps any well-formed id (G14). `Entry` gains `isFromFile`.
- **`AppPrefs`** — writes a theme id through `JSONValue.string`.
- **`ThemeBrowser`** — `marks(of:chosen:)`, the contrast note with chrome, `contrastDetail`, the caption of a file theme, `filesNote`, `toolTip`, and `shown(_:in:inEffect:)`.
- **`DevSnapshot.Theme`** — the four new members.

Changed, in the shell (`TarmacApp`), which is wiring:

- **`ThemeSettings`** — holds the library, reads the folder at `init` and at each report of the watch, and compares the entry in effect by value.
- **`ThemeFolderWatch`** (new) — tells of each change of the folder.
- **`ThemeList`** — is given its themes, and takes them again.
- **`ThemePane`** — the line under the list and its button; draws again when the themes change.
- **`AppDelegate`** — resolves the folder and gives it to `ThemeSettings`.
- **`Makefile`** — `DEV_ENV` pins `TARMAC_CONFIG_DIR`.
- **`scripts/qa/settings-window.swift`** — G19.

`TarmacTerm`, the daemon, the CLI and the wire protocol do not change.

### Data Flow

Launch:

1. `AppDelegate` resolves the folder: `ChannelPaths.themesDir(configDir: ChannelPaths.configDir(…))`, from the environment and `ChannelPaths.Channel.build`.
2. `ThemeSettings` reads it: `ThemeLibrary(files: ThemeFolder.files(at: folder))`.
3. `library.inEffect(choice:themes:systemIsDark:)` gives the entry. Steps 1 to 3 are done before the first view is made, so a file theme that is the saved choice is in effect at the first paint.
4. `ThemeSettings` starts the watch of the folder. The launch writes nothing: it does not make the folder.

The folder changes:

1. The watch tells `ThemeSettings`.
2. `ThemeSettings` reads the folder again and makes a new library.
3. A library equal to the one it holds changes nothing, and nothing is drawn again.
4. Or else it holds the new library, and resolves the entry in effect. **If the entry differs by value** from the one in effect (another id, or the same id with another palette), it sets the entry on `Theme`, sets `NSApp.appearance`, and calls `onChange`: the walk of 2610.0007 runs.
5. It tells the pane that the themes changed. The pane gives the list its themes again, keeps or replaces the shown theme (`ThemeBrowser.shown`), and draws its tiles, marks, boxes, note and the line under the list again.
6. Nothing is saved. `app-prefs.json` is not written.

A box set or cleared: as in 2610.0008, with `library.entry` in the place of `ThemeCatalog.entry`.

### Interface Contract

**The config directory.**

```swift
extension ChannelPaths {
    /// Tarmac's config directory. `override` is `TARMAC_CONFIG_DIR` and
    /// `xdgConfigHome` is `XDG_CONFIG_HOME` (`nil` when not set).
    public static func configDir(
        override: String?, xdgConfigHome: String?, home: String, channel: Channel
    ) -> String
    /// `configDir` and then `/themes`.
    public static func themesDir(configDir: String) -> String
}
```

- `override` wins verbatim when it is not `nil` and not empty, in both channels. Nothing is added to it.
- Or else the base is `xdgConfigHome` when it is not `nil` and starts with `/`, and `home` joined with `.config` in every other case (an empty or a relative `XDG_CONFIG_HOME` is not used, as the XDG specification says).
- The directory is the base joined with `tarmac`, and for `.dev` joined then with `dev`.
- A join puts exactly one `/` between its parts, as `channelDir` does: a `home` of `/` gives `/.config/tarmac`, and a base with a `/` at its end gives no `//`. An empty `home` adds no `/` and stays relative, as in `channelDir`: it gives `.config/tarmac`.
- `themesDir` joins `configDir` with `themes` by the same rule.
- `make run` sets `TARMAC_CONFIG_DIR` to `<worktree>/.dev/config`, in `DEV_ENV`. So `make run`, `make qa` and `make qa-quit` name the same directory.

| `override` | `xdgConfigHome` | `home` | channel | `configDir` |
| --- | --- | --- | --- | --- |
| `nil` | `nil` | `/Users/u` | release | `/Users/u/.config/tarmac` |
| `nil` | `nil` | `/Users/u` | dev | `/Users/u/.config/tarmac/dev` |
| `nil` | `/x/cfg` | `/Users/u` | release | `/x/cfg/tarmac` |
| `nil` | `/x/cfg/` | `/Users/u` | dev | `/x/cfg/tarmac/dev` |
| `nil` | `""` or `cfg` | `/Users/u` | release | `/Users/u/.config/tarmac` |
| `""` | `nil` | `/` | release | `/.config/tarmac` |
| `/w/.dev/config` | `/x/cfg` | `/Users/u` | release or dev | `/w/.dev/config` |
| `nil` | `nil` | `""` | release | `.config/tarmac` |

**The file's keys.** The reader uses these keys and no other. A key is compared exactly, letter case too.

| Key | Value | Gives |
| --- | --- | --- |
| `background` | a colour | `terminal.background`. The file must have it |
| `foreground` | a colour | `terminal.foreground`. The file must have it |
| `cursor-color` | a colour, `cell-foreground` or `cell-background` | `terminal.cursor`. Not set, or one of the two words: the foreground |
| `palette` | `N=colour`, `N` from 0 to 255 | `terminal.ansi[N]` for 0 to 15. An entry for 16 to 255 is read and not used |
| `tarmac-bg0`, `tarmac-bg1`, `tarmac-bg2`, `tarmac-bg3` | a colour | `bg0`, `bg1`, `bg2`, `bg3` |
| `tarmac-line`, `tarmac-line-soft`, `tarmac-lift-border`, `tarmac-prime-header-bg` | a colour | `line`, `lineSoft`, `liftBorder`, `primeHeaderBg` |
| `tarmac-text`, `tarmac-muted`, `tarmac-faint`, `tarmac-prose` | a colour | `text`, `muted`, `faint`, `prose` |
| `tarmac-agent`, `tarmac-amber`, `tarmac-ok`, `tarmac-console-error` | a colour | `agent`, `amber`, `ok`, `consoleError` |
| `tarmac-repo` | `N=colour`, `N` from 0 to 3 | `repoColors[N]` |

`selection-background`, `selection-foreground`, `cursor-text`, `tarmac-scroll-thumb` and every other key are not used keys: their lines are ignored, whatever the value.

**The file's grammar.**

```swift
public enum ThemeFile {
    public enum ChromeKey: String, CaseIterable, Sendable {
        case bg0, bg1, bg2, bg3, line, lineSoft, liftBorder, primeHeaderBg
        case text, muted, faint, prose, agent, amber, ok, consoleError
        public var fileKey: String              // "tarmac-bg0", … "tarmac-console-error"
    }

    /// What a file gave. A colour it did not give has no entry.
    public struct Colours: Equatable, Sendable {
        public var background, foreground: UInt32
        public var cursor: UInt32?
        public var ansi: [Int: UInt32]          // keys 0...15 only
        public var chrome: [ChromeKey: UInt32]
        public var repo: [Int: UInt32]          // keys 0...3 only
    }

    public enum Refusal: Error, Equatable, Sendable {
        case unreadable
        case tooLarge
        case notText
        case value(line: Int, key: String)
        case missing(key: String)
        public var reason: String
    }

    public static let sizeLimit = 65_536
    public static func parse(_ text: String) -> Result<Colours, Refusal>
    public static func palette(from colours: Colours) -> Palette
    /// UTF-8, then `parse`, then `palette(from:)`.
    public static func palette(of contents: Data) -> Result<Palette, Refusal>
}
```

- `parse` drops one byte-order mark (U+FEFF) at the very start of its text (G20).
- The text is cut into lines at each `\n`. Line numbers start at 1 and count every line.
- A line is trimmed of space, tab and `\r` at both ends. An empty line, and a line whose first character is `#`, is skipped.
- A line is cut at its first `=`. The key is the part before it, and the value the part after it, each trimmed of space and tab. A line with no `=` has the whole line as its key and no value.
- A value of two characters or more that starts and ends with `"` loses those two characters, and is trimmed of space and tab again. This rule is for the value of a line only. The colour of an entry does not lose its quotes: `palette = "1=#fff"` is read, and `palette = 1="#fff"` is not.
- A line whose key is not a used key is ignored.
- **A colour** is an optional `#` and then exactly six or exactly three ASCII hexadecimal digits (`0` to `9`, `a` to `f`, `A` to `F`). Three digits `rgb` are `rrggbb`.
- **A used key with an empty value** takes away what earlier lines gave for that key. For `palette` and for `tarmac-repo` it takes away every entry.
- **`cursor-color`** with exactly `cell-foreground` or `cell-background` takes away the cursor colour, as an empty value does. No other key reads those words.
- **`palette` and `tarmac-repo`**: the value is cut at its first `=`. The index is the part before it and the colour the part after it, each trimmed of space and tab. The index is one or more ASCII digits, read as a decimal number, and is at most 255 for `palette` and at most 3 for `tarmac-repo`. A `palette` entry from 16 to 255 must still be a valid line, and gives nothing.
- A later line wins over an earlier one for the same key, and for the same index.
- **A refusal.** The first line, from the top, with a used key and a value that these rules do not read gives `.value(line:key:)`, and the file is refused. This includes: a used key with no `=`; a text that is not a colour; an index that is empty, is not all digits, or is over its limit, however many digits it has; an entry with no `=`; an entry with an empty colour.
- Only when every line is read: with no `background` the result is `.missing(key: "background")`, or else with no `foreground` it is `.missing(key: "foreground")`.
- `palette(of:)` gives `.notText` for bytes that are not valid UTF-8.
- `reason`, the words for a person:

  | Refusal | `reason` |
  | --- | --- |
  | `.unreadable` | `cannot be read` |
  | `.tooLarge` | `is larger than 64 KiB` |
  | `.notText` | `is not UTF-8 text` |
  | `.value(line: 12, key: "palette")` | `line 12: the value of palette cannot be read` |
  | `.missing(key: "background")` | `has no background` |

**The derived colours.** `palette(from:)` gives a whole `Palette`. It never fails, and it changes no colour that the file gave.

In this section `B` is the background, `F` the foreground, and:

- `mix(a, b, t)` is, for each of the three channels, `a + (b − a) · t` computed on the 8-bit values as `Double` in the order written, rounded to the nearest whole number (a half goes away from zero), and then held to 0…255.
- The **variant** is dark when the luminance of `B` is less than that of `F`, and light in every other case: the rule of `Palette.variant`.
- The **pole** is `ffffff` for a dark theme and `000000` for a light one.
- The **three fills** are the `bg0`, `bg1` and `bg2` of the result, given or derived.
- `lift(c, floor)` is the first of `mix(c, pole, k / 16)` for `k` = 0, 1, … 16 whose `Contrast.ratio` with each of the three fills is `floor` or more. When none is, it is the pole (`k` = 16).

- `reads` is false for an empty name, a name that starts with `.`, a name that ends with `~`, and a name with a scalar under `0x20` or equal to `0x7f`. It is true for every other name: `Dracula`, `Catppuccin Mocha`, `theme.conf`.

- `entry(id, for: variant)` is the entry of `all` whose id is exactly `id`, whatever its variant, or `ThemeCatalog.standard(for: variant)`. `inEffect` is `entry(themes[v], for: v)` with `v` as `choice.inEffect(systemIsDark:)`.

## Alternatives Considered

### Read Ghostty's own folders in place

No copy step. Rejected by D1: the list would gain 463 rows on a Mac with Ghostty, and the pane would name 463 contrast notes for themes the user did not choose. A user who wants them all can link them into the folder (S54 is that run).

### Refuse a theme with a finding

Rejected by D6. Of the 463 files, 1 would be refused for its chrome and many for their terminal colours (ANSI 0 of most dark themes is near the background). The user's other terminals show those colours as they are.

### Derive with no lift

The mixes alone, and the ANSI colours as they are. Measured: 251 of 463 themes have a chrome finding. The lift leaves 1, and for Catppuccin Latte it gives values near the ones that were tuned by hand (*Measured*).

### Skip a bad line, as Ghostty does

Ghostty writes a diagnostic and uses its own default colour. Tarmac has no default that is right for a file of another palette, and the user would see a theme with one wrong colour and no word about it. Rejected by G5.

### The whole grammar of Ghostty

X11 colour names need a table of some 750 names, and the index forms `0x0f`, `0o17`, `0b1111`, `+5` and `1_0` need a number reader of their own. No file of the 463 uses either. Rejected by G4, and named in *Trade-offs and Limitations*.

### Tarmac's keys in comments

`# tarmac: bg0 = #101010` would let Ghostty read the same file with no diagnostic. Rejected: a comment that is data is a surprise to a person who reads the file, and the proposal in the issue's first comment is "optional keys in the same `key = value` form". A file with Tarmac keys is for Tarmac's folder.

### Copy the colours into `app-prefs.json` when a file theme is chosen

Then a removed file would not change the theme. Rejected: the issue's acceptance says the default is in effect when the file is gone, and an edited file would not be seen (D5).

### Read the folder only when the Settings window opens

Smaller. Rejected by D5.

### Move `app-prefs.json` in this change

Rejected by D1: it is a released file, and 2609.0016 puts it beside the socket on purpose.

## Migration & Rollback

No migration. A Mac with no `themes/` folder has the eight themes, as today, and the launch makes no folder.

Release 0.16.0 has no theme setting. The keys `theme`, `theme_light` and `theme_dark` are on `main` and are not released. A build of `17b54fe` that reads `"theme_dark":"file:Dracula"` reads Breeze Dark, and leaves the key out at its next save.

Rollback is a revert. The folder and its files stay, and nothing reads them.

## Security Considerations

- **A theme file is text of the user, and can be text of another person** (a file from a collection). It is read as bytes, one byte over the limit of 65,536 at most, and a file with more is refused. It is decoded as UTF-8 and cut into lines. It gives `UInt32` colours and nothing more. No value of it is put into a page, a script, a command or a path.
- **The file's name** becomes an id and a title. It is shown in AppKit labels, which read no markup. It is written to `app-prefs.json` and to the snapshot through the JSON string escape. It is never joined to a path again after the folder is listed: an id from `app-prefs.json` is compared with the ids of the library and opens no file. A name with a control character is not read.
- **A named pipe or a device in the folder is never opened** (it would block the app). A symbolic link is followed: the folder is the user's own, and a link there is the user's choice.
- **`TARMAC_CONFIG_DIR` and `XDG_CONFIG_HOME`** name where files are read from. They are read from the app's own environment, as `TARMAC_SOCKET` is.
- **The button** makes one folder at the resolved path and opens it. It runs no file.

## For the Implementing Agent

> **Your job:** make every acceptance scenario above pass with tests that would *fail if the behavior were wrong*. A green suite that passes for the wrong reason does not satisfy this contract — `/verify` will hunt for vacuous tests by asking, of each behavior, "what is the smallest change that breaks this, and would any test catch it?"

Implement however you work best. Only the result is checked. The repository's own rules still bind (`docs/coding-style.md`): red first and observed red; the smallest correct diff; no line-noise comments; do not run `cargo fmt`; verify with `make`, not the editor.

Points that are easy to get wrong:

- **The values of the vector table were computed by a program that is not the implementation.** Do not copy a failing value from the test's output into the table. A difference is a difference of rule: find it. The nearest decisions are 3.006 and 3.010 against the floor 3 in the vector table, and 4.496 against 4.5 in S18 (the step before the chosen one): all far from the noise of a `Double`. Compute `mix` as `Double` in the order the contract writes it, `a + (b − a) · t`: another order can round another way at a half.
- **`mix` is on the 8-bit channel values, not on linear light,** and rounds a half away from zero. A negative `t` goes under 0 for a dark background and is held at 0.
- **The lift measures against the three fills of the result.** Derive the fills first. A given `tarmac-bg2` changes every lift (S17).
- **A given colour is never changed,** also when it fails its floor. The detector tells; nothing refuses (D6, S17).
- **`selection` is the final `agent`,** given or lifted, not ANSI 6.
- **The missing ANSI entries need the variant, and the variant needs only `B` and `F`.**
- **A line is cut at the first `=` only.** `palette = 3 = #abc` has the value `3 = #abc`, which is cut again.
- **Trim space and tab, not all white space,** and `\r` only at the ends of a line.
- **Keys are compared exactly.** `Background` is not a used key, so its line is ignored and not refused (S6).
- **An empty value is not a refusal for a plain key** (S7), and is one for the colour of an entry (`palette = 1=`, S9).
- **`String(data:encoding:)` is the strict UTF-8 read.** `String(decoding:as:)` repairs bad bytes and never fails (S12).
- **Never open what is not a regular file.** Examine the entry first, following a link. The test has a named pipe: a reader that opens it blocks the suite (S27).
- **`ThemeCatalog.entry` and `inEffect` are removed, not kept beside the library's.** The compiler then finds each caller. Tests that held their rules ask `ThemeLibrary.shipped` (S42).
- **`ThemeSettings.resolve` compares entries with `!=`.** With the id guard an edited file never draws again (S47). `Palette` and `Entry` are already `Equatable`.
- **`ThemeList.select` finds its row by id.** After a file's change the entry it is given is not equal to the one it holds.
- **The list's height has a floor of eight rows, and never follows its row count:** the window is measured once (S44, S54).
- **The pane and its list are made at launch** (`SettingsWindowController.init`); only the pane's view and the window are made later. A list that reads the themes when it is made holds the themes of the launch. It must be given the themes at each change, with a view or with none, and the view that is made later must show the library of that moment (S55).
- **Measure first what the Accessibility API gives for a row that is scrolled out of view.** S54 and S62 read rows of a list of 471. If a row out of view has no title or no id there, `rows` and `show` must scroll the list to read it, and the record says so.
- **Nothing is saved when the folder changes.** `app-prefs.json` is written only for a choice of the user (S47, S49, S50).
- **The launch makes no folder** (S44). Only the button does.
- **The watch decides nothing.** The flags of an event are a history (an append reports `Created|Modified`), and for a folder that is a symbolic link the paths are the real ones. Do not read them: every callback is one read of the folder.
- **Make the stream on the path also when the folder is not there.** The stream follows the path. Do not open the folder and watch a descriptor: that misses a change in place and ends when the folder is removed (*Measured*).
- **The callback is a C function with an `info` pointer.** Keep the object it points to alive for as long as the stream, and stop, invalidate and release the stream when the watch ends. Put the stream on the main queue, or hop to it: the read and everything after it are on the main actor.
- **The watch must outlive a removed folder** (S52) and must see a folder that is made after the launch (S45). See *The watch and `ThemeSettings`*.
- **`rows` prints the id last on its line,** because a title and an id can both hold spaces.
- **`TARMAC_CONFIG_DIR` in a QA run.** A fresh channel that replaces `DEV_ENV` must set it too, to a folder of the run's own. Never write a test file into `~/.config/tarmac`.
- **Never launch `dist/Tarmac.app`** and never kill a daemon by name. All live QA is against `make run`; stop its daemon with `make kill-daemon`.

Test principles, the ones `/verify` scores against:

- **Behavioral over structural** — assert observable output, not internals.
- **Every test can fail** — S9 names the exact refusal of each bad line; S15 and S17 name the wrong rule they fail; S31 fails for a raw write; S36 fails for a count of findings.
- **Deterministic, isolated, readable** — a temp folder for each test of `ThemeFolderTests`, no shared state, no read of the real config directory or of an installed Ghostty: every file text is in the test.

## Trade-offs and Limitations

- **Not every Ghostty file is read.** A file with an X11 colour name, or with a `palette` index in a form that is not plain decimal, is refused, and the line under the list names the line. None of the 463 files of Ghostty 1.3.1 has either.
- **A bad line refuses the whole file** (G5), where Ghostty goes on.
- **The selection colours of the file are not used** (G8). `Palette.Terminal` holds one selection colour with an alpha.
- **`cursor-text` is not used,** and `cell-foreground` and `cell-background` for the cursor read as the foreground: the terminal card has one cursor colour.
- **Terminal colours 16 to 255 and the scroll thumb do not come from the file** (#209, #217).
- **A derived theme is not a designed one.** The fills are mixes of two colours. With a background near black, `bg0`, `bg1` and the terminal body are the same colour or nearly (48 of the 463), and a card is told from the board by its border. The Tarmac keys are the remedy.
- **`amber` and the first repo colour both start from ANSI 3,** and `ok` and the second from ANSI 2, so in a derived theme they are equal.
- **A theme can be left with a chrome finding** when its foreground is too near its background for any lift (1 of the 463). It is offered, and the note tells.
- **A file that is written in place can be read half-written.** For that moment it can be refused, and the standard theme is in effect until the next report. A write of a new file that is renamed over the old one does not have this.
- **A file that lives for a moment can be a row for a moment.** A save through `<name>.tmp` that is then renamed can show a row `<name>.tmp` until the next report, at most some 0.2 s later. A name that starts with `.` or ends with `~` is never read.
- **A file that starts with two byte-order marks has no rule.** `parse` drops one, and the read of the bytes can drop one more.
- **A list that was scrolled before the window was closed opens where it was,** moved only as far as the selected row needs. The rows above that row can then be out of view.
- **A link's target is not watched.** A change of a file outside the folder that a link in the folder names is seen at the next change in the folder, or at the next launch.
- **The folder is read on the main actor.** S54 gives the time for 463 files.
- **Two rows can have one title** (D4). The caption tells them apart, and the built-in one is first.
- **A file named `Old~` or `.name` is never a theme,** so an editor's backup file is not one.
- **An agent can read the findings only in a dev build** (`tarmac dev snapshot`, `findings`) or in the pane's tooltip. A release build has no command that prints them.
- **`app-prefs.json` and the themes folder are in two places** until the separate issue of D1 moves the first.
- **A debug build with no `TARMAC_CONFIG_DIR`** (a bare `swift run`) reads `~/.config/tarmac/dev/themes`, not the folder of the installed app.
- **The rule of the config directory is in the app only.** If the daemon or the CLI needs it later, it becomes a fourth place to keep in sync, as the socket path is.
