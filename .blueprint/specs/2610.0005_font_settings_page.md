## Context

Tarmac draws text in three places, and each has a fixed face today.

| Role | Where | Face today | Source |
| --- | --- | --- | --- |
| Terminal | terminal cards | `JetBrainsMonoNFM-Regular`, bundled | `TerminalFonts.preferredNames` |
| Interface, native | card headers, status bar, board switcher, zoom control, toasts, off-screen hints, the HTML card console | IBM Plex Mono, bundled | `Theme.mono` |
| Interface, in doc cards | the chrome and code of doc cards | the system monospaced face (see below) | `--chrome-font` in `DocTemplate.html` |
| Document | the prose of markdown doc cards | the system UI font | `.doc-prose` in `DocTemplate.html` |

`--chrome-font` names `"IBM Plex Mono"` first, but the bundled files are
registered for the app's process only and the page has no `@font-face`. In a
plain `WKWebView` with the two files registered in the host process, the
stack measures the same as `ui-monospace, monospace`. So doc cards most
likely draw the system monospaced face already, and this change does not
alter them. This was not checked inside the app's own web view.

The two bundled families are four files in
`app/Sources/TarmacApp/Resources/Fonts/`. `BundledFonts.register()` registers
them for the process in `main.swift`. `NOTICE` and `THIRD-PARTY-LICENSES`
carry their notices, the notices of the thirteen icon sets in the Nerd Fonts
patch, and the texts of the SIL OFL 1.1 and CC BY 4.0, which apply to nothing
else in the bundle.

The app has one preference, `warn_before_quit`, in `app-prefs.json` beside the
daemon socket (`AppPrefs`). `AppPrefs.encode` writes that one key as a literal.
There is no settings window.

Facts measured on 2026-10-05 (macOS 26, this repository's dev machine):

- `NSFont.monospacedSystemFont` is SF Mono: family
  `.AppleSystemUIFontMonospaced`, face `.AppleSystemUIFontMonospaced-Regular`.
  It has bold and italic faces. The family is hidden: it is not in
  `NSFontManager.availableFontFamilies`.
- A CoreText descriptor made from that hidden family name alone resolves to
  the *Light* face. `CTFontCreateWithName("SFMono-Regular")` and the CSS names
  `"SF Mono"` and `".AppleSystemUIFontMonospaced"` do not resolve at all. The
  hidden PostScript name does resolve, but the API call is the definition of
  the default and is what the code uses. In CSS the system face is reached
  only through the keyword `ui-monospace`.
- The 16 pt cell, by the `TerminalFonts.metrics` rule, in points:

  | Face | at 1× | at 2× |
  | --- | --- | --- |
  | system monospaced | 10 × 19 | 10 × 19 |
  | Menlo | 10 × 19 | 9.5 × 19 |
  | Monaco | 10 × 22 | 9.5 × 21.5 |
  | JetBrains Mono (bundled today) | 10 × 22 | 9.5 × 21.5 |

  Menlo and the system face have the same cell at 1×, and the system face
  has the same cell at both scales. The dev machine's main display is 1×.
  Every scenario that must see a cell change uses Monaco.
- Family lookup is not case-sensitive: `availableMembers(ofFontFamily:
  "menlo")` gives Menlo's members, and CSS `"menlo"` resolves to Menlo.
  `availableMembers` is also not `nil` for the hidden families
  `.AppleSystemUIFontMonospaced` and `.SF NS Mono`.
- Monaco has one member: no bold, no italic. `font(withFamily: "Monaco",
  traits: .boldFontMask, weight: 9, size:)` gives `Monaco`, not `nil`.
- Osaka has two upright members of weight 5: `Osaka` (not fixed pitch),
  listed first, and `Osaka-Mono` (fixed pitch).
- In a `WKWebView`, `font-family: "Fira Code"` resolves a family installed in
  `~/Library/Fonts`. `ui-monospace` and `monospace` are different faces.
- `NSFontManager.font(withFamily:traits:weight:size:)` with weight 5 gives the
  regular upright face of every family tried (Menlo, Monaco, Fira Code,
  JetBrainsMono Nerd Font Mono, MesloLGS NF, PT Mono) and `nil` for an
  unknown family. A family-only CoreText descriptor gives `Helvetica` for an
  unknown family.
- In a fresh process, listing the 254 installed families and reading each
  one's members (`availableFontFamilies`, then `availableMembers(ofFontFamily:)`)
  takes about 190 ms. Reading the members of one named family takes 0 to
  8 ms, and gives `nil` for a family that is not installed.
- Neither SF Mono nor Menlo has the Powerline glyph U+E0B0.

## Motivation

The user cannot change a font. The app carries two third-party font families
only to supply fixed faces, and their licence notices are the largest part of
`NOTICE`. With fonts taken from the Mac, the user gets the choice and the
repository and the bundle stop carrying font files and font licences (#204).

## Proposed Solution

### Overview

A **Settings** window, opened from the app menu (`Settings…`, ⌘,), has one row
for each role: Terminal, Interface, Document. Each row is a pop-up list of
installed families with *System Default* first, and a sample line set in the
face in effect. A choice applies at once to every open card and is saved in
`app-prefs.json`.

The bundled fonts, their registration and their notices are removed. With no
choice saved, Terminal and Interface use the system monospaced font and
Document uses the system UI font.

### Key Components

- **`AppPrefs.Values`** (`app/Sources/TarmacKit/AppPrefs.swift`) — the whole
  file as one value: the quit guard and the three font choices. One decode,
  one encode. Replaces the single-key `encode(warnBeforeQuit:)` so that a save
  of one preference keeps the others.
- **`FontRole`** (`app/Sources/TarmacKit/FontRole.swift`) — `terminal`,
  `interface`, `document`; each knows its JSON key, whether it takes only
  fixed-pitch families, and the pure rule for the family in effect: the saved
  one, or none when the Mac does not have it or the role cannot take it.
- **`FontMenu`** (`app/Sources/TarmacKit/FontMenu.swift`) — the pure rule that
  turns the installed families and the saved choice into the list a row shows
  and the entry it selects.
- **`FontCSS`** (`app/Sources/TarmacKit/FontCSS.swift`) — the pure rule that
  turns a chosen family into a CSS `font-family` value for doc cards.
- **`TerminalFonts`** (`app/Sources/TarmacTerm/TerminalFonts.swift`) —
  resolves a family name instead of a list of PostScript names.
  `TerminalView` gains a settable `fontFamily`.
- **The shell** (`app/Sources/TarmacApp/`) — `SettingsWindowController` (the
  window), `InstalledFonts` (the `NSFontManager` adapter), `AppPrefsStore` (the
  one owner of the saved values), `FontSettings` (resolves the family in
  effect for each role and tells the views), `Theme.mono` (reads the
  Interface family), `MainMenu` (the menu item), `DocWebView` (hands the two
  CSS values to the page).
- **`DevSnapshot.fonts`** (`app/Sources/TarmacKit/DevSnapshot.swift`) — an
  additive `fonts` object in `tarmac dev snapshot`, so a run can state the
  faces in effect as facts.
- **Removal** — `Resources/Fonts/`, `BundledFonts.swift`, the `Fonts` resource
  in `app/Package.swift`, the `Fonts` entry in `scripts/bundle.sh`, the font
  parts of `NOTICE` and `THIRD-PARTY-LICENSES`, `ShippedFonts.swift` in the
  tests.

### Data Flow

Launch:

1. `FontSettings` loads `AppPrefs.Values` from `app-prefs.json`.
2. For each role with a saved family, `InstalledFonts` reads that one family
   from the Mac, and `FontRole.familyInEffect` gives the family in effect or
   `nil`. The whole font list is not read at launch (see Context: 190 ms).
3. `Theme` takes the Interface family in effect before the first view is
   built. Today `AppDelegate` builds `RootView()` first and reads the prefs
   path later from `controller.client.socketPath`; the status bar takes its
   font at `init`. So the prefs path is resolved before `RootView()`.
4. Each terminal card is created with the Terminal family in effect.
5. Each doc card, after its page loads, is given the two CSS values, made
   from the Interface and Document families in effect.

Every consumer is given a family in effect, never a saved value.

A change in the window:

1. The row's pop-up reports an index. `FontMenu.choice(at:)` gives the family,
   or `nil` for System Default.
2. `FontSettings` stores it in its `Values`, saves the file, and applies it:
   - Terminal: sets `fontFamily` on every `TerminalView`. Each view rebuilds
     its renderer, lays its grid out again, and reports the new columns and
     rows, which go to the PTY as they do after a card resize.
   - Interface: sets the family `Theme.mono` reads, then every chrome view
     takes its font again and lays out. Doc cards get a new `--chrome-font`.
   - Document: doc cards get a new prose family and measure again.
3. The row's sample line takes the face now in effect.

The *Warn Before Quitting* menu item reads and writes the same `Values`
through `AppPrefsStore`, the one owner of the file, so neither writer can
drop the other's keys (S5, S47).

A card made after a change takes the fonts in effect at that moment: a new
terminal card is created with the Terminal family, and a new doc card is
given the two CSS values when its page loads. A change reaches the cards of
every board, not only the active one (S48).

### Interface Contract

**The file.** `app-prefs.json`, same path rule as today
(`AppPrefs.path(besideSocket:)`). Keys:

| Key | Type | Absent means |
| --- | --- | --- |
| `warn_before_quit` | boolean | `true` |
| `terminal_font` | string, a family name | system default |
| `interface_font` | string, a family name | system default |
| `document_font` | string, a family name | system default |

```swift
public enum FontRole: String, CaseIterable, Sendable {
    case terminal, interface, document
    public var prefsKey: String        // "terminal_font", "interface_font", "document_font"
    public var fixedPitchOnly: Bool    // true for terminal and interface
    /// `installed` is what the Mac says of the saved family; nil when it has none.
    public func familyInEffect(saved: String?, installed: InstalledFamily?) -> String?
}

extension AppPrefs {
    public struct Values: Equatable, Sendable {
        public var warnBeforeQuit: Bool            // default true
        public var fonts: [FontRole: String]       // no entry = system default
        public init(warnBeforeQuit: Bool = true, fonts: [FontRole: String] = [:])
    }
    public static func decode(_ contents: Data?) -> Values
    public static func encode(_ values: Values) -> Data
    public static func load(from path: String) -> Values
    public static func save(_ values: Values, to path: String) throws
}
```

Decode rules:

- Missing, unreadable, rejected by `StrictJSON`, or a top-level value that
  is not an object: `Values()`, all defaults. The existing strictness rules
  do not change.
- Each key is read on its own. A key of the wrong type reads as that key's
  default and does not change how any other key reads.
- `warn_before_quit` is `false` only for the JSON literal `false`.
- A font key reads as a choice only when it is a string that is not empty and
  holds no control character (below U+0020, or U+007F). Anything else is no
  entry. The string is judged after its JSON escapes are read: `"a\nb"` holds
  U+000A and is no entry. A raw U+000A in a string is a different case:
  `StrictJSON` rejects the whole file.
- Unknown keys are ignored and are not written back.

Encode rules:

- `{"warn_before_quit":<bool>` first, then one member for each role that has
  an entry, in the order terminal, interface, document, then `}`. No
  whitespace. With no font entry the bytes are exactly
  `{"warn_before_quit":true}` or `{"warn_before_quit":false}`, as today.
- A family name is a JSON string: `"` and `\` escaped, every other character
  written as UTF-8.
- An entry whose name the decode rule rejects (empty, or with a control
  character) is not written. So the bytes pass `StrictJSON.isValid` for every
  `Values`, and a bad name can never make the next load read
  `warn_before_quit` as its default.
- `decode(encode(v)) == v` for every `v` whose names pass the decode rule.
- `save` keeps the temp-file-then-rename write.

`AppPrefs.warnBeforeQuit(from:)` stays, with the same answers.
`AppPrefsStrictnessTests` passes unedited. `AppPrefsTests` passes unedited
apart from its `encode`, `save` and `load` calls, which change shape: `load`
now returns `Values`, not `Bool`.

**The list.**

```swift
public struct InstalledFamily: Equatable, Sendable {
    public let name: String
    public let fixedPitch: Bool
}

public struct FontMenu: Equatable, Sendable {
    public static let systemDefaultTitle = "System Default"
    public let families: [String]      // the entries after System Default, in order
    public let selected: Int           // 0 = System Default; n = families[n - 1]
    public init(role: FontRole, installed: [InstalledFamily], saved: String?)
    public var titles: [String]        // [systemDefaultTitle] + families
    public func choice(at index: Int) -> String?   // nil for 0 and for an index out of range
}
```

- `families` holds every installed name that does not begin with `.` and,
  when `role.fixedPitchOnly`, is fixed pitch. Each name appears once.
- Order: ascending by `caseInsensitiveCompare`; two names equal under it are
  ordered by `<`. The order does not depend on the user's locale.
- `selected` is the entry equal to `saved`, compared exactly; `0` when `saved`
  is `nil` or is not in `families`.
- A family is fixed pitch when its regular upright face reports the
  fixed-pitch trait: of its members that are not italic, the one whose weight
  is nearest 5, and on a tie the first in `availableMembers` order. A family
  whose members are all italic is judged by them. The rule is
  `InstalledFamily.init?(name:faces:)`, which gives `nil` for no member
  (S51). On the dev machine it agrees with `font(withFamily:traits: [],
  weight: 5, size:).isFixedPitch` for all 254 families. `InstalledFonts`
  (the adapter) reads the members from `availableMembers(ofFontFamily:)`,
  for one family or for all of them, by the same code.
- `InstalledFamily.name` is the family's own name as the Mac spells it (the
  resolved font's `familyName`), never the string that was asked for. The
  lookup is not case-sensitive, so a saved `menlo` finds `Menlo`; the exact
  compare in `familyInEffect` then gives `nil`, and the row shows *System
  Default* (S34).

**The family in effect.** One rule for all three roles, and one place for it:

```swift
role.familyInEffect(saved:installed:)
```

- `nil` when `saved` is `nil` or begins with `.` (a hidden system family,
  which no list shows).
- `nil` when `installed` is `nil` (the Mac has no such family) or its `name`
  is not `saved`, compared exactly.
- `nil` when `role.fixedPitchOnly` and `installed.fixedPitch` is false.
- Otherwise `saved`.

`nil` means the role uses its system default. The saved value stays in the
file; nothing rewrites it until the user makes a choice. The row a
`FontMenu` selects and the family in effect always agree: both come from the
same `InstalledFamily` facts (S26, S50).

`TerminalFonts`, `Theme.mono` and `FontCSS` do not judge fixed pitch. Each
is given a family in effect. `TerminalFonts` and `Theme.mono` keep one guard
of their own, for a family that is removed while the app runs: a name that
does not resolve gives the system default (S30).

A family in effect is used for every weight of its role. When it has no bold
face, a bold request gives its regular face, never the system default: the
terminal does this today (`TerminalFonts.variant`), and `Theme.mono` does the
same from `.semibold` up.

The Interface role has two consumers, `Theme.mono` and `--chrome-font` in doc
cards. Both take the family in effect. When the saved Interface family is not
installed or is not fixed pitch, that is `nil`, so doc-card chrome and code
use the monospace stack and not the saved family (S34).

| Role | System default | A family resolves through |
| --- | --- | --- |
| Terminal | `NSFont.monospacedSystemFont(ofSize:weight: .regular)` | `NSFontManager.font(withFamily:traits: [], weight: 5, size:)`, not a family-only CoreText descriptor (which gives a Light or W3 face for some families); bold and italic as `TerminalFonts.variant` derives them today |
| Interface | `NSFont.monospacedSystemFont(ofSize:weight:)` | `NSFontManager.font(withFamily:traits:weight:size:)`: regular below `.semibold`, bold from it |
| Document | the page's current stack | CSS, by family name |

```swift
// TarmacTerm
struct TerminalFonts {
    init(size: CGFloat, pixelsPerPoint: CGFloat, family: String? = nil)
}
public final class TerminalView: NSView {
    public init(frame:, theme:, fontSize:, fontFamily: String? = nil, scrollbackLines:, backingScale:) throws
    public var fontFamily: String?   // a new value rebuilds the renderer and lays out; the same value does nothing
}
```

`TerminalFonts.preferredNames` and the `names:` parameter are removed. The
system default is taken from the API, never from a family name (see Context).

`TerminalFonts` is internal to `TarmacTerm`, and the shell needs the Terminal
role's face name for the dev snapshot. This change adds one public member to
`TarmacTerm` that gives the PostScript name of the regular face a family
resolves to (pass `nil` to ask for the system default's). Its form is the implementer's
choice. It gives the same name as the `TerminalFonts` regular face in S10,
S11 and S30, and those scenarios assert it too.

**CSS for doc cards.**

```swift
public enum FontCSS {
    public static let monospaceStack = "ui-monospace, monospace"
    public static let proseStack = #"-apple-system, "SF Pro Text", system-ui, sans-serif"#
    public static func interface(_ family: String?) -> String   // for --chrome-font
    public static func document(_ family: String?) -> String    // for the prose
}
```

- `nil` gives the stack alone.
- A family gives the family as a CSS string, a comma and a space, then the
  stack: `"Fira Code", ui-monospace, monospace`.
- In the CSS string, `\` and `"` are each written with a `\` before them.
- A name the `AppPrefs` decode rule would reject gives the stack alone.

`DocTemplate.html` holds the two stacks as custom properties, with the
defaults above and no name of a removed font. `tarmacDoc` gains
`fonts(chrome, prose)`, which sets the two properties and measures again.
`DocWebView` passes the values as `callAsyncJavaScript` arguments, as
`render` passes markdown, so no value is spliced into script text.

**The window.**

- App menu, in order: `About`, separator, `Settings…` with key equivalent ⌘,,
  separator, `Services`, then the existing items after `Services`, unchanged.
- One window, titled `Settings`, dark like the main window, not resizable.
  `Settings…` while it is open brings it to the front; it never makes a
  second one. ⌘W and its close button close it. Closing it does not hide or
  quit the app.
- Three rows in the order Terminal, Interface, Document. Each has its name, a
  pop-up whose titles are `FontMenu.titles`, and a sample line set in the face
  in effect for the role. The words of the sample line are not part of this
  contract; its face is.
- Under the Terminal row: `Prompt and Powerline icons need a Nerd Font.`
- The installed families are read each time the window opens.
- A choice that cannot be saved still applies for the session; the failure is
  logged with `Log.stderr`, as the quit toggle does.

**The dev snapshot.** `tarmac dev snapshot` gains, additively:

```json
"fonts": {
  "terminal":  {"saved": "Menlo", "face": "Menlo-Regular"},
  "interface": {"saved": null,    "face": ".AppleSystemUIFontMonospaced-Regular"},
  "document":  {"saved": null,    "css": "-apple-system, \"SF Pro Text\", system-ui, sans-serif"}
}
```

`fonts` is always an object with the three roles. `saved` is the role's entry
in the `Values` the app holds: what it loaded, or the last choice made. It is
JSON `null` when there is no entry, never an absent key and never `""`.
`face` is the PostScript name of the regular face the role resolves to: for
Terminal at `Theme.termFontSize`, for Interface the font of `Theme.mono(10.5)`
(the status bar's size). `css` is `FontCSS.document` of the Document family
in effect. No CLI change: the driver prints the app's reply as it is.

Two existing tests in `DevSnapshotTests` pin the shape and both change:
`testS1TheSnapshotCarriesExactlyTheDocumentedTopLevelKeys` gains `fonts`, and
`testTheSnapshotSerialisesAsCompactJSON` pins the whole byte string. No other
key changes. The one caller of `build` is `Dev/DevSnapshotReader.swift`.

**No wire-protocol change.** Nothing here reaches `tarmacd` except the
terminal resize a new cell size causes, which is the existing message.

### The shell, which is wiring

What stays in `TarmacApp` with no unit test, under exceptions 1 and 2 of
`docs/coding-style.md` §1.3:

- `InstalledFonts`: reads `NSFontManager` into `InstalledFamily` values, one
  named family (at launch and on a change) or all of them (when the window
  opens).
- `AppPrefsStore`: holds `Values` and saves all of it on every change.
  `WarnBeforeQuit` takes its value from it and no longer reads or writes the
  file itself.
- `FontSettings`: asks `FontRole.familyInEffect` for each role, puts the
  answers in `Theme.fontFamilies`, and tells the views.
- `SettingsWindowController`: builds the rows from `FontMenu`, forwards a
  selection.
- `Theme.mono`: resolves the Interface family. The fonts
  `BoardSwitcherView` keeps in `static let` become values read after a
  change, and every chrome view that set a font at `init` takes it again:
  `CardHeaderView`, `HeaderButton`, the owner chip, `StatusBar`,
  `ZoomControl`, `HTMLCardChrome` (also a `static let`), `ChromeLabel` users
  (`Toasts`, `OffscreenHints`).
- The app-wide event monitors in `AppController+Keys.swift`. `takeKey`
  already ignores a key from another window. `handlePress` checks that the
  main window is key; it does not check the event's window. `routeScroll`
  and `routeMagnify` check neither, and hit-test the event's point against
  the board. So a wheel or a pinch over the Settings window, and possibly a
  click on a Settings window that is not yet key (not measured), can reach
  the board. The rule: an event whose window is not the main window must not
  select or deselect a card, pan the board or zoom it (S35 checks both
  window states).

## Alternatives Considered

### Keep the fonts bundled and add the picker on top

The user can then pick, and the default look does not change. It keeps the
font files and every notice in the repository, which the issue sets out to
remove.

### The first installed fixed-pitch family as the default

It is the literal reading of "the system's first one". On the dev machine it
is Andale Mono, and it differs from Mac to Mac. Rejected by the user in
favour of the system monospaced font, which every Mac has and which is the
first entry of every list.

### `userFixedPitchFont` (Menlo) as the default

Also on every Mac. Rejected by the user in favour of SF Mono.

### An overlay panel or a card on the board

Either needs its own list, keys and focus rules; a card needs a new card
kind. A standard window with standard controls needs none of that. Chosen by
the user.

### Store a PostScript face name

It names one face exactly, but the Interface role needs a regular and a bold,
the terminal needs four styles, and CSS needs a family. A family name serves
all three and is what the list shows.

## Migration & Rollback

### Migration Steps

1. None for the file. A file written by 0.15.2 holds only
   `warn_before_quit` and decodes with no font entry.
2. On the first launch after the upgrade every terminal card changes from
   JetBrains Mono Nerd Font to SF Mono. The cell size changes, so each
   terminal reports a new grid to its program once.
3. Prompt and Powerline icons stop rendering until the user picks an
   installed Nerd Font in Settings. The release note must say so.

### Rollback Plan

An older app ignores the font keys when it reads the file, and drops them the
next time *Warn Before Quitting* is toggled. No other data is touched.

## Security Considerations

A family name is user-controlled text that reaches two sinks: a CSS value in
doc cards and a JSON file. `FontCSS` writes it only as an escaped CSS string
and rejects control characters; `DocWebView` passes it as a script argument,
never as script text; `AppPrefs.encode` escapes it as a JSON string. The
doc-card content rules and the HTML-card sandbox are not changed, and no
font is fetched: every face is one the OS already has.

## For the Implementing Agent

> **Your job:** make every acceptance scenario above pass with tests that would *fail if the behavior were wrong*. A green suite that passes for the wrong reason does not satisfy this contract — `/verify` will hunt for vacuous tests by asking, of each behavior, "what is the smallest change that breaks this, and would any test catch it?"

Implement however you work best. Only the result is checked. The repository's
own rules still bind (`docs/coding-style.md`): red first and observed red;
the smallest correct diff; no line-noise comments; do not run `cargo fmt`;
verify with `make`, not the editor.

Points that are easy to get wrong here:

- **Tests that leaned on the shipped face.** `TerminalRendererTests` and
  `TerminalViewTests` drew with the bundled JetBrains Mono through the
  default. After this change the default is the system face. Where a test
  pins a number that came from the old face's metrics, derive the new
  expectation from the layout rule and say so in the PR; do not adjust a
  number until the test is green. A test that needs a known face names
  `Menlo` or `Monaco`, which are system fonts.
- **One existing test breaks by its premise.**
  `testAnUnwindowedViewMeasuresItsGridAtTheGivenBackingScale`
  (`TerminalViewTests`) asserts that the default face's cells at 1× and 2×
  differ. The system face's do not (see Context). It must name a family
  through `fontFamily:`; Menlo and Monaco both differ across the two scales.
- **Menlo cannot prove a cell change.** Its cell equals the system face's at
  1×, which is the dev machine's display and may be the CI runner's. Use
  Monaco wherever a scenario needs the grid to change.
- **The adapter gives the Mac's spelling of a family name.** If
  `InstalledFonts` builds `InstalledFamily(name: saved, …)`, a saved `menlo`
  is in effect while its row shows *System Default*. S34's second file is
  the check.
- **The system face is never resolved by name.** See Context. S30 is the test
  that fails if a family-only descriptor is trusted: it gives `Helvetica`.
- **S10's comparison is against the platform call**, which is the definition
  of the default, not a copied constant. Its fixed-pitch and italic checks
  are what make it fail for a wrong face.
- **`AppPrefs` strictness is load-bearing** (spec 2609.0016). Do not loosen
  `StrictJSON`. Per-key reading happens after the bytes pass it.
- **One owner of the file.** If `WarnBeforeQuit` keeps its own copy of the
  flag and its own `save`, S5's bug comes back in the shell where no test
  sees it. S47 is the manual check.
- **The Interface fallback has two consumers.** CSS takes any installed
  family, fixed pitch or not, so `--chrome-font` is right only when the shell
  hands `FontCSS.interface` the family in effect, the same value `Theme.mono`
  gets. S34's code block is the check.
- **Do not read the whole font list at launch.** It costs about 190 ms on
  the main thread. Launch reads one family for each saved role.
- **A family with no bold face.** Monaco has one face. A bold request must
  give Monaco, not the system face (S16's switcher footer).
- **Cards that are not on screen.** A change reaches the terminals and doc
  cards of every board, and a card made later starts on the fonts in effect
  (S48).
- **Chrome fonts cached at `init` or in `static let`** will show the old face
  until relaunch. S16 lists every surface; capture each one.
- **`scripts/bundle.sh` fails hard on a missing `Fonts` entry** and `make
  test` does not run it. S44 is not optional.
- **Never launch `dist/Tarmac.app`** and never kill a daemon by name. All
  live QA is against `make run`; stop its daemon with `make kill-daemon`.

Test principles, the ones `/verify` scores against:

- **Behavioral over structural** — assert observable output, not internals.
- **Every test can fail** — no copied expected value, no tautology.
- **Deterministic, isolated, readable** — temp directories per test, no
  shared state, no dependence on which fonts a developer added beyond Menlo,
  Monaco, Helvetica and the system faces.

## Trade-offs and Limitations

- **The default look changes for every user**, and Nerd Font icons need one
  step in Settings. This is the cost of bundling no font.
- **Family, not face.** A user cannot pick *Fira Code Retina* over *Fira Code
  Regular*; the role takes the family's regular face.
- **No font size setting.** `Theme.termFontSize` and the chrome sizes stay
  fixed. The window is built so a later row can be added.
- **A fixed-pitch family is judged by its regular face.** *Osaka* has a
  fixed-pitch member (*Osaka-Mono*) and a proportional regular, so it is not
  listed for Terminal or Interface.
- **Some CJK families report the fixed-pitch trait** (*BIZ UDGothic*,
  *PCMyungjo*) and are listed. The list reports the OS fact; it does not
  judge whether a face suits a terminal.
- **A font installed while the Settings window is open** appears the next
  time the window opens. A font removed while it is in use: a view that
  already holds the face keeps drawing with it; a card made later, or a
  renderer rebuilt for a new display scale, gets the system default. At the
  next launch the whole role falls back.
  No scenario covers the re-read on open: a check would install a font file
  on the tester's Mac.
- **Opening the Settings window reads the whole font list**, about 190 ms
  once for each open.
- **HTML cards are not affected.** They are the author's page and keep their
  own font stacks. Only the native console chrome follows Interface.
- **The quit notice** uses the system UI font and has no row.
- **A toast already on screen** takes the new face in the box it was
  measured for, until it leaves a few seconds later.
- **`fonts` in the snapshot reports what the app resolved**, not what each
  view drew. A view that missed the change is found only by S16's captures.
- **An older app drops the font keys** when it next saves the file.
