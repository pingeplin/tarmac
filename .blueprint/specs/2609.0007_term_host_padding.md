# 2609.0007 `.term-host` padding from a `--rs` custom property

**Date:** 2026-09-07
**Status:** draft
**Author:** EP Lin
**Issue:** [#117](https://github.com/pingeplin/tarmac/issues/117) `refactor(terminal): drive .term-host padding from CSS, not an imperative write`
**Related:** [#87](https://github.com/pingeplin/tarmac/issues/87) / PR [#115](https://github.com/pingeplin/tarmac/pull/115), spec [2609.0005](2609.0005_new_terminal_card_zoom_scale.md) (S5), QA sheet `desktop/qa/new-card-zoom-scale-qa.md`

> House-numbered `2609.0007` (`2609.0006` is taken in a sibling branch); the issue is #117.

## Context

`.term-host { padding: 8px 10px 16px }` (`desktop/src/theme/app-only.css:73`) never governs a
live element. `TerminalCard` creates the host div (`desktop/src/cards/TerminalCard.tsx:80`),
appends it (`:108`) and writes `host.style.padding = termHostPadding(rs)` (`:216`) inside the
same synchronous mount-effect body — no paint in between — and the rasterScale settle
`useLayoutEffect` writes it again (`:363`). This holds at every `rasterScale`, including 1.

The consequence is a test pinning a corpse: `desktop/src/kit/termHostPadding.test.ts:16-22`
reads the rule off disk and compares it with `termHostPadding(1)`. It is weaker than the house
precedent it copies (`desktop/src/kit/termZoom.test.ts:18-23`, where both sides are live), and
it goes red when someone edits a declaration that affects nothing.

This is a cleanliness issue, not a correctness bug. The global `* { box-sizing: border-box }`
(`desktop/src/theme/tokens.css`) means `FitAddon` already measures a host width that includes
the padding, so the padding has **no `cols × rows` effect** — it buys the visual gutter alone.

> **Note (spec 2609.0011, issue #130):** that observation is correct and was the bug. Because
> the padding had no `cols × rows` effect, the grid was counted against a box `24·rs` px taller
> than the one `.xterm` paints in, and the surplus row fell outside the card. The terminal card
> no longer uses `FitAddon`; `kit/termGrid.ts` subtracts the padding explicitly.

## Motivation

Two copies of the same three constants (JS `kit/termHostPadding.ts`, CSS `app-only.css`) are
held in sync by a test that cannot detect a real regression. Route (b) below deletes one copy
by making the other live, removing the duplication instead of deleting one side of it.

## Decision

**Route (b) — `--rs` custom property.** Chosen at the issue gate over (a) "delete the CSS
declaration and drop the test", which removes the tripwire rather than repairing it and leaves
the constants live only in JS.

`(a)` is the fallback, taken **only** if (b) demonstrably breaks under the `scale(1/rs)`
counter-scale. Concrete trigger: at `rs = 2`, devtools computed `padding-left` on a live
`.term-host` is not `20px`, **or** `stty size` changes *grossly* (≈ `rs ×`) across the zoom
ladder. A drift of **±1 column** — and of ±1 row — is pre-existing `FitAddon` behavior, not a
trigger: `DEFAULT_SCROLL_BAR_WIDTH = 14 px` does not scale with `rs`, so
`cols(rs) = floor((rs·W − 14) / (rs·c))` creeps upward (QA sheet §S4's ±1 pre-authorisation,
plus its *Incidental observations*, where rows moved 15 → 14 across a 1.0 → 1.5 settle). If the
fallback is taken, record the observed measurement and the reason in this section before
implementing (a).

## Proposed Solution

### Overview

Set `--rs` on the raster wrapper's JSX style object and let the stylesheet compute the padding.
`.term-host` is a descendant of `.term-raster-wrapper` (wrapper → `.term-host-slot` → host), so
the property inherits.

### Key components

- **`desktop/src/theme/app-only.css:73`** — replace the literal with
  ```css
  .term-host {
    padding: calc(8px * var(--rs, 1)) calc(10px * var(--rs, 1)) calc(16px * var(--rs, 1));
  }
  ```
  Carry one `why` comment naming `.term-raster-wrapper` in `TerminalCard.tsx` as the source of
  `--rs` — the coupling is cross-file and invisible from here.

- **`desktop/src/cards/TerminalCard.tsx:406-414`** — the wrapper's style object emits `--rs`
  **unconditionally** (at `rs = 1` too), while `width` / `height` / `transform` /
  `transformOrigin` stay conditional on `rasterScale !== 1` exactly as today. Follow the house
  custom-property pattern — a `... as React.CSSProperties` cast, as in
  `desktop/src/board/Board.tsx:177` with `docCardVars`. Emit the value as a **string**
  (`String(props.rasterScale)`), matching `docCardVars`, so React's unitless-number handling
  for custom properties is not load-bearing.

  Rationale for unconditional: it keeps React's custom-property *removal* semantics on an
  `rs 2 → 1` transition off the load-bearing path. The `var(--rs, 1)` CSS fallback stays as
  belt-and-braces for any `.term-host` outside a wrapper.

- **Deletions** — `host.style.padding` at `:216` and `:363`, the `termHostPadding` import
  (`:46`), `desktop/src/kit/termHostPadding.ts`, `desktop/src/kit/termHostPadding.test.ts`.

- **`desktop/qa/new-card-zoom-scale-qa.md`** — its header (`:5-10`) states in the present tense
  that "the one automated scenario, **S5**" is a drift tripwire living in
  `desktop/src/kit/termHostPadding.test.ts`. That file is deleted here, so amend those lines to
  record that #117 removed the tripwire and the padding contract is now QA-only. **Do not touch
  the run records, observation table, or sign-off below the header** — they are a frozen log of
  what was observed. Nothing else is renamed: spec `2609.0005_new_terminal_card_zoom_scale.md`
  is a frozen historical record and keeps its `termHostPadding` references as-is.

  **Allowlist.** After the change, `grep -rn termHostPadding` repo-wide is expected to hit
  exactly: spec `2609.0005_new_terminal_card_zoom_scale.md` (frozen), this spec, and the QA
  sheet's S2 preamble (`:139`) and *Run conditions* (`:249-250`) — both frozen log, below the
  header. Any other hit is a defect.

- **Comments to update** — three sites describe the imperative write: the file header
  (`:16-21`), the mount-effect comment near `:112-115` ("so fontSize and padding can never
  disagree"), and the settle `useLayoutEffect` comment at `:349-356` ("Setting fontSize +
  padding SYNCHRONOUSLY"). The substance they explain — why the padding scales, and why the
  settle effect must be a layout effect for `fontSize` — remains true and must survive; only
  the claim that padding is written imperatively goes.

### Invariants

1. **`cols × rows` is unchanged at `rs` 1, 1.5, 2 and 3**, to within the ±1 column / ±1 row of
   pre-existing `FitAddon` scrollbar drift documented under **Decision**. Border-box sizing
   makes `FitAddon` measure a width that already includes the padding, so padding is
   `cols × rows`-neutral by construction. This must remain observably true (S2).
2. **The padding resolves before the settle `fit()`.** The wrapper's style prop — `--rs`
   included — is applied in React's mutation phase, the same DOM commit as the `rs ×`
   width/height, which runs *before* `useLayoutEffect`. At mount, `--rs` is present in the
   initial render, and the host is appended and `fit()` in the passive effect, inheriting it.
   So the padding is resolved no later than today's imperative write.
3. **`padding` is layout; `transform` is post-layout.** The counter-scale cannot alter the
   computed padding, only its on-screen size — identical to the current behavior.

## Interface Contract

- **No wire-protocol, daemon, or public API change.** Nothing in `core/` or
  `desktop/src-tauri/` is touched; no `Msg` variant, no Tauri command, no persisted state key.
- **The one new internal contract:** `.term-raster-wrapper` sets the custom property `--rs` to
  the numeric `rasterScale` (unconditionally, at every value including `1`);
  `.term-host` is its only consumer, via `var(--rs, 1)`. `--rs` is read nowhere else, and no
  module exports or imports it.
- **Breaking change for callers: none.** `desktop/src/kit/termHostPadding.ts` is deleted; its
  only importer is `TerminalCard.tsx`, which stops needing it in the same change.

## Testability

**Automated tests: none.** This is deliberate and must not be "fixed" by adding one.

- The app layer (React/Tauri shell) is not unit-tested in this repo; only pure `kit/` logic and
  Rust are (`desktop/qa/new-card-zoom-scale-qa.md`, repo testing convention).
- jsdom resolves neither `calc()` nor custom properties, so a "computed padding equals 20px"
  test would be vacuous by construction.
- After (b) there is no kit-side value left to pair with the CSS. A `termZoom.test.ts:18-23`
  style tripwire needs **both sides live**; here it would pin the literals 8/10/16 against
  nothing — the exact corpse pattern this issue exists to kill. A one-sided text pin is
  explicitly out of scope.

Every scenario below is therefore `[Q]` (manual QA, to be listed in the PR body) except the
`[G]` build gate.

## Acceptance Scenarios

- **S1 [Q]** — Given a terminal card on a board settled at `rs = 2`, when its `.term-host` is
  inspected in devtools, then the element carries **no inline `padding`** and its computed
  padding is `16px 20px 32px`; and when the *same card* is then zoomed back down to `rs = 1`,
  its computed padding is `8px 10px 16px`, still with no inline `padding`.
- **S2 [Q]** — Given a terminal card, when the board is zoomed through `rs` 1 → 1.5 → 2 → 3 → 1
  (readouts per `desktop/qa/new-card-zoom-scale-qa.md`: 100 % / 120 % / 173 % / 299 % / 100 %),
  then `stty size` in that shell reports the same `rows cols` at every step **to within ±1
  column and ±1 row** (the pre-existing `FitAddon` scrollbar drift recorded under **Decision**);
  no step shows a gross, ≈ `rs ×` change. (Invariant 1.)
- **S3 [Q]** — Given a reference terminal card spawned at 100 % and a card under test spawned
  after the board settles at `rs = 2`, when the two are compared side by side, then their left
  gutters are visually equal (≈ 17 px at the 173 % readout) — the only tell for the padding
  half, per the QA sheet's "three tells".
- **S4 [Q]** — Given a card at `rs = 2`, when the board is zoomed back to `rs = 1` and up to
  `rs = 2` again, then there is no one-frame grid blow-up and no spurious PTY resize: `stty
  size` stays within ±1 column / ±1 row of its starting value throughout, and never jumps by
  ≈ `rs ×`. A transient blow-up self-corrects and is invisible to a post-hoc `stty size`, so
  arm the shell first with `trap 'echo WINCH' WINCH`, pace the presses ≥ 500 ms apart
  (> `RASTER_SCALE_SETTLE_MS` = 150 ms), and count: the 173 % → 100 % → 173 % round-trip crosses
  four `rs` buckets (2→1.5, 1.5→1, 1→1.5, 1.5→2), so expect **≤ 4 `WINCH`** — one per bucket
  change. A settle that blows up and self-corrects emits two. The trap sees only the PTY half;
  the one-frame *visual* blow-up stays an eyeball tell.
  (Guards Invariant 2 across the removal path.)
- **S5 [Q]** — Given a board at 100 % (`rs = 1`), when the `.term-raster-wrapper` element is
  inspected, then `--rs` is present with value `1` and no `width` / `height` / `transform`
  inline keys are set. (S1 and S5 read the DOM: right-click → *Inspect Element* in the
  `make run` dev window opens the WKWebView inspector.)
- **S6 [G]** — Given the worktree after the change, when `make app` and `make test` are run,
  then both pass — `make app` type-checks and bundles the frontend (this is what catches a
  dangling `termHostPadding` import; bare `make` builds only the Rust workspace and would prove
  nothing here), and `make test` runs the vitest suite green after the test file's deletion,
  with `docs-check` as its first step. And `grep -rnE 'termHostPadding|host\.style\.padding'
  desktop/src` returns **zero hits**.

## QA ladder

The written hand-over for S1–S5 — a human presses ⌘T and reads the tells. Cite this section
verbatim in the PR body and fill in the readings.

Setup: `make kill-daemon` (never `pkill tarmacd`), then `make run`. Spawn the **reference**
terminal card with ⌘T at 100 % *before* any zooming. Zoom readouts to use: **100 % / 120 % /
173 % / 299 % / 100 %** (→ `rs` 1 / 1.5 / 2 / 3 / 1). Devtools: right-click → *Inspect Element*
in the dev window opens the WKWebView inspector.

- **S1 — computed padding, both directions.** Settle a card at 173 % (`rs = 2`), inspect its
  `.term-host`: expect **no inline `padding` attribute** and computed padding `16px 20px 32px`.
  Zoom the *same card* back to 100 % (`rs = 1`): computed padding `8px 10px 16px`, still no
  inline `padding`. *(This is the route-(b) trigger check: if computed `padding-left` at
  `rs = 2` is not `20px`, stop and take route (a).)*
- **S2 — `stty size` across the ladder.** In the card's shell, run `stty size` at each of
  100 → 120 → 173 → 299 → 100 %. Record every `rows cols`. Expect the same values throughout
  **to within ±1 column and ±1 row** (pre-existing `FitAddon` scrollbar drift:
  `DEFAULT_SCROLL_BAR_WIDTH = 14px` does not scale with `rs`). Any gross ≈`rs ×` change is a
  failure.
- **S3 — gutter comparison.** With the reference card (spawned at 100 %) and a card spawned
  *after* the board settles at 173 %, compare side by side: left gutters must be visually equal
  (≈17 px at the 173 % readout). This is the only tell for the padding half. *(Open question
  below: decide beforehand whether to measure this with a screenshot + pixel ruler rather than
  eyeball — the QA sheet records that this tell has never had a recorded observation.)*
- **S4 — round-trip, no blow-up.** Arm the shell first: `trap 'echo WINCH' WINCH`. Then press
  the zoom keys **≥ 500 ms apart** (> `RASTER_SCALE_SETTLE_MS` = 150 ms) for
  173 % → 100 % → 173 %. That round-trip crosses four `rs` buckets (2→1.5, 1.5→1, 1→1.5,
  1.5→2), so expect **≤ 4 `WINCH`** lines — one per bucket change; a settle that blows up and
  self-corrects emits two. `stty size` must stay within ±1 col / ±1 row of its start and never
  jump ≈`rs ×`. Watch the screen for a one-frame grid blow-up (the trap only sees the PTY half).
- **S5 — wrapper inline style at rest.** At 100 % (`rs = 1`), inspect the
  `.term-raster-wrapper` element: `--rs` is **present with value `1`**, and there are **no**
  inline `width` / `height` / `transform` keys.

## Trade-offs and Limitations

- The padding contract becomes QA-only. That is a truthful downgrade from a test that was
  already evidence of nothing — it passed on a completely unfixed build (QA sheet, S5 note).
- `--rs` is a new cross-file coupling: a rename in `TerminalCard.tsx` silently degrades the
  padding to its `var(--rs, 1)` fallback (gutter shrinks to `1/rs`; `cols × rows` unaffected,
  so `stty size` stays blind to it). Mitigated only by the CSS comment.
