# 2607.0004 HTML/JS Doc Cards in a Sandboxed Iframe

**Date:** 2026-07-02
**Status:** accepted
**Author:** EP Lin
**Design doc:** [2607.0004](../../docs/designs/2607.0004_html_js_doc_cards_sandboxed_webview.md)
**Issue:** [#49](https://github.com/pingeplin/tarmac/issues/49)

## Context

`tarmac open <path>` surfaces any file as a doc card, but the frontend treats every doc as Markdown: `Board.tsx` renders one `DocCard` per `kind: "doc"` card (`desktop/src/board/Board.tsx:188-220`), and `DocCard` pipes the content through `marked.parse()` into `innerHTML` (`desktop/src/cards/DocCard.tsx:80-87`). An agent-written HTML dashboard renders as escaped text soup. The main webview has no CSP (`security.csp: null` in `desktop/src-tauri/tauri.conf.json`) and holds Tauri invoke rights, so HTML content cannot simply be trusted into the host DOM.

The design doc (linked above) chose: render `.html`/`.htm` docs in a **sandboxed `<iframe>`** served by a new **`tarmac-card://` Tauri custom URI scheme** whose Rust handler attaches a strict CSP response header and prepends a console-capture/escape shim. Routing is a frontend-only extension check. Daemon, CLI, and wire protocol change **not at all**. Interaction is **shield-by-default**: the card is look-don't-touch until the user explicitly borrows it (double-click), and Esc always goes home.

## Motivation

The file-as-pipe model stops exactly where it gets most interesting: live, agent-generated UI (D3, Canvas, WebGL). Without this, agents have no way to show interactive output; with a naive implementation, machine-written HTML would run with the host's privileges. This feature ships live HTML cards while keeping the sandbox guarantee absolute and legible.

## Proposed Solution

### Overview

A pure `docKind()` extension check routes each `kind: "doc"` card to either the existing `DocCard` (markdown) or a new `HtmlCard` (html). `HtmlCard` renders a sandboxed iframe (`sandbox="allow-scripts"`, no `allow-same-origin`, `allow=""`) whose `src` is `tarmac-card://doc/<url-encoded-abs-path>?v=<mtime_ms>`. The Rust handler reads the file, prepends the shim, and serves it with a strict CSP header. A transparent shield overlay keeps the card behaving like every other card until borrowed. Console output relays via `postMessage` into a per-card ring buffer surfaced in the card chrome. `file_event` bumps `?v=`, causing a full reload.

**Milestone 0 is a gate (spike-first):** before any card UI work, build the protocol handler plus a throwaway iframe and run the probe card (below). Three outcomes: (1) header CSP enforced → proceed; (2) header CSP not enforced but meta CSP is → switch delivery to the `srcdoc` fallback (frontend seams identical) and re-probe; (3) neither enforced → **stop**; the feature is blocked (do NOT substitute shim-level `fetch` monkeypatching). Independently: if Tauri IPC is reachable from the sandboxed frame → stop.

### Key Components

- **`docKind()`** — new pure function in `desktop/src/kit/` (suggested `docKind.ts`): `docKind(path: string): "markdown" | "html"`. Case-insensitive `.html`/`.htm` → `"html"`; everything else → `"markdown"`. Derived, never stored — `DocCardModel` (`desktop/src/board/model.ts:79-97`) is untouched; do not add a `CardModel.kind` variant.
- **`cardSrcUrl()`** — new pure function in `kit/` (may share a module with `docKind`): `cardSrcUrl(path: string, mtimeMs: number | undefined): string` → `tarmac-card://doc/<encodeURIComponent(path)>?v=<mtimeMs ?? 0>`. The whole absolute path is one percent-encoded segment.
- **`card_protocol.rs`** — new flat module in `desktop/src-tauri/src/` (declared `mod card_protocol;` in `lib.rs`, following the existing one-file-per-concern layout). Registers `tarmac-card` on the `tauri::Builder` chain in `run()` (`desktop/src-tauri/src/lib.rs:18-47`) via `register_uri_scheme_protocol` (verify sync vs. `register_asynchronous_uri_scheme_protocol` against the resolved tauri 2.11.3 API). Pure helpers (URI decode, response composition, header constants) kept separate from registration glue so they unit-test inline, per the `bridge.rs:531-738` precedent. Same filesystem trust model as `read_doc` (`desktop/src-tauri/src/commands.rs:106-112`): no canonicalization, no jail — a deliberate non-goal, not an oversight.
- **The shim** — a static JS file (suggested `desktop/src-tauri/src/card_shim.js`, embedded via `include_str!`). Overrides `console.log/info/warn/error` (still invoking the originals), hooks `window.onerror` + `unhandledrejection`, relays each event via `window.parent.postMessage({tarmac:"console", level, args: safeSerialize(args)}, "*")`, and posts `{tarmac:"escape"}` on Escape keydown. `safeSerialize` degrades non-cloneable values (functions, cycles, DOM nodes) to strings rather than throwing. *Deviation from the design doc:* the design placed the shim string builder in `kit/`; since composition happens in the Rust handler, the shim lives Rust-side and its ordering guarantee is unit-tested where it is enforced (Rust inline tests). Host-side pure logic (message parsing, ring buffer) lives in `kit/` and is Vitest-tested.
- **`HtmlCard`** — new component `desktop/src/cards/HtmlCard.tsx`, mirroring `DocCard`'s `CardShell` wiring (`className`, `inWrapper`, `header` ReactNode, move/resize/grab/close props — `DocCard.tsx:139-198`). Renders the sandboxed iframe, the shield overlay, the console strip, and the header badge. Does **not** consume `docContents` — it needs only `path` + `lastChangedMs`.
- **Console buffer** — pure ring-buffer + message-validation logic in `kit/` (suggested `cardConsole.ts`): `CARD_CONSOLE_BUFFER_CAP = 500`, a push function that drops oldest beyond cap, and `parseCardMessage(data: unknown)` returning a typed console/escape event or `null`. Buffer state is component-local in `HtmlCard` (the `DocCard` refs/`useState` precedent) — it dies on unmount, matching "reload loses state". React `key={id}` keeps it stable across drags/resizes.
- **Borrow state** — `borrowedCardId: string | null` in App state (the `selectedId` precedent, `App.tsx:184-186`). App-level because the Esc ladder must see it.
- **Zoom sizing** — two pure helpers in `kit/` (suggested `cardZoom.ts`, sibling to the existing `docZoom.ts`) so the iframe-sizing math is unit-testable rather than inline in `HtmlCard`: `cardIframePx(frame: {w, h}, zoom)` → `{ w: round(frame.w × zoom), h: round(frame.h × zoom) }` (the settled real-px box) and `cardGestureScale(zoom, settledZoom)` → `zoom / settledZoom` (the mid-gesture transform scale). Formulas are exactly the Data Flow zoom rule; `HtmlCard` consumes both, and the settle timing (`RASTER_SCALE_SETTLE_MS`) stays in `rasterScale.ts`. Note this cannot reuse `docZoom.ts`'s CSS-`calc()` downscale mechanism — a foreign iframe document cannot be oversample-then-downscaled the way prose is — hence the JS-computed px box.

### Data Flow

1. **Open:** daemon `doc_opened` → `landDoc()` (unchanged) → `Board.tsx` doc branch calls `docKind(c.path)`; `"html"` mounts `HtmlCard` inside the same `docWrapperBox()` wrapper, `"markdown"` mounts `DocCard` as today.
2. **Load:** iframe `src = cardSrcUrl(path, lastChangedMs)` → Rust handler percent-decodes the path, reads bytes, responds `200` with body = shim + file bytes and headers below. The `?v=` query is a cache-buster only; the handler ignores it and always serves current bytes.
3. **Console:** card JS logs → shim `postMessage` → `HtmlCard`'s `window` `message` listener (none exist today — no collision), filtered by `event.source === iframe.contentWindow`, validated by `parseCardMessage`, pushed to the ring buffer → header badge count + toggleable strip in the card body.
4. **Live reload:** daemon `file_event` → `App.tsx` `handle()` (`App.tsx:1119-1122`) → `stampDocChange()` (unchanged; updates `docMeta.lastChangedMs`) → `HtmlCard` sees a new `lastChangedMs` prop → swaps iframe `src` to the new `?v=` → full reload, all in-page JS state lost by design. `refreshDoc`/`fetchDoc` (markdown plumbing) must be **gated by `docKind()`** — including the unconditional `fetchDoc` in `applyRestore` (`App.tsx:811-886`) — so `.html` docs never trigger `read_doc`.
5. **Interaction:** shield overlay (transparent div above the iframe inside `.card-body`) does not `stopPropagation`/`preventDefault`/capture — pointerdown bubbles to `CardShell`'s existing `onBodyPointerDown` (select/raise) and native wheel listener (`CardShell.tsx:153-166`) for free. Double-click on the shield borrows: shield unmounts/hides, borrow ring shows, `borrowedCardId` set. Esc → un-borrow + `focusTerm(prime)` — via the shim's `{tarmac:"escape"}` relay when focus is inside the iframe, via a **new rung in the App Esc ladder** (`App.tsx:1453-1485`) when the host has focus; both consume the event.
6. **Zoom:** the iframe is sized in real screen px (`round(frame.w × zoom)` × `round(frame.h × zoom)`), untransformed at rest, inside the existing translate-only `docWrapperBox()` wrapper. During a pan/zoom gesture the iframe keeps its px size and takes `transform: scale(zoom/settledZoom)`; when zoom is stable for `RASTER_SCALE_SETTLE_MS` (150ms, `kit/rasterScale.ts`) the iframe is resized to the new px box and the scale resets to 1 — one `resize` event per settle, not per frame. Note: `DocCard`'s zoom-change detection (MutationObserver on `.board`'s `style`, `DocCard.tsx:89-121`) is the available signal; `BoardEngine.onRasterScaleSettle` fires only on rasterScale *step* changes and is insufficient alone. Doc cards receive no `rasterScale` prop today — any needed wiring through `Board.tsx`'s doc branch is new.

### Interface Contract

```
// kit (Vitest-tested, node env)
docKind(path: string): "markdown" | "html"
cardSrcUrl(path: string, mtimeMs: number | undefined): string
CARD_CONSOLE_BUFFER_CAP = 500
parseCardMessage(data: unknown): { kind: "console", level: "log"|"info"|"warn"|"error", args: unknown[] } | { kind: "escape" } | null
// ring-buffer push: order-preserving, drops oldest beyond cap
cardIframePx(frame: { w: number, h: number }, zoom: number): { w: number, h: number }  // { round(w × zoom), round(h × zoom) }
cardGestureScale(zoom: number, settledZoom: number): number                              // zoom / settledZoom

// wire: shim → host postMessage payloads
{ tarmac: "console", level: "log"|"info"|"warn"|"error", args: <serialized>[] }
{ tarmac: "escape" }
// uncaught errors and unhandled rejections arrive as level "error"

// Rust handler: tarmac-card://doc/<url-encoded-abs-path>?v=<mtime_ms>
200 → body: shim + file bytes (shim strictly first)
      Content-Type: text/html; charset=utf-8
      Content-Security-Policy: default-src 'none'; script-src 'unsafe-inline';
        style-src 'unsafe-inline'; img-src data: blob:; font-src data:;
        media-src data: blob:
404 → file unreadable; text/plain body naming path + error; no shim
400 → malformed/undecodable URL; text/plain

<iframe sandbox="allow-scripts" allow="" src="tarmac-card://doc/...">
```

CSP is byte-exact as above: `connect-src` is covered by `default-src 'none'` (fetch/XHR/WebSocket/sendBeacon blocked); external `<script src>` blocked — agents inline everything. No capability file names `tarmac-card://`; `capabilities/default.json` stays `windows: ["main"]` only.

### Probe card (permanent QA artifact)

`desktop/qa/sandbox-probe.html` — a self-contained page whose script attempts `fetch()` (http + custom scheme), XHR, `WebSocket`, `sendBeacon`, dynamic `import()`, reads `window.__TAURI__` / `__TAURI_INTERNALS__`, calls `window.ipc?.postMessage`, and touches `localStorage`/`document.cookie` (opaque-origin checks) — reporting every result through `console.log` so outcomes land in the host buffer. All escape attempts must fail. The probe stays in the repo as the permanent QA checklist for this sandbox and gates Milestone 0.

## Alternatives Considered

Argued in the design doc; summarized: **`srcdoc` + meta CSP** — weaker enforcement point; retained as the designated fallback (identical frontend seams) if the spike falsifies header enforcement. **Child webview per card** — Tauri multiwebview is `unstable` with open positioning/z-order/rendering bugs; worst case is exactly this board. **Sanitized static HTML** — no JS, fails the point of #49.

## Security Considerations

- Isolation is **iframe origin boundary + CSP + Tauri's iframe-injection exclusion** (GHSA-57fm-592m-34r7; resolved tree: tauri 2.11.3 / wry 0.55.1, well past the ≥2.0.0-beta.20 fix), not a process boundary. Threat model: the user's own agent wrote a file onto the user's own disk. A stronger malicious-content model is out of scope.
- `Cargo.toml` pins `tauri = "2"` (unpinned minor); the GHSA claim holds per `Cargo.lock` today. The probe card is the regression net for dependency bumps.
- The handler reads any user-readable path, mirroring `read_doc` — deliberate non-goal (no docs-root concept exists).
- A runaway card can burn CPU/GPU in the shared process — accepted for MVP.

## Acceptance Scenarios

Verification tags per repo convention (only pure `kit/` + Rust logic is unit-tested; the shell is QA'd): **[kit]** Vitest, **[rust]** `cargo test` in `desktop/src-tauri`, **[QA]** runnable probe card / manual checklist.

### Happy Path

- **S1** [kit] Given paths `a.html`, `B.HTM`, `x.htm`, when `docKind()` is applied, then each returns `"html"`; given `a.md`, `a.html.bak`, `README`, `a.htmlx`, then each returns `"markdown"`.
- **S2** [kit] Given path `/Users/me/my dash.html` and mtime `1234`, when `cardSrcUrl()` builds the URL, then the result is `tarmac-card://doc/` + `encodeURIComponent` of the full path + `?v=1234`; given `undefined` mtime, then `?v=0`.
- **S3** [rust] Given an existing HTML file, when the handler serves its `tarmac-card://doc/...` URL, then the response is 200 with `Content-Type: text/html; charset=utf-8`, the byte-exact CSP header above, and a body equal to shim + original file bytes with the shim strictly before the first file byte.
- **S4** [kit] Given a `{tarmac:"console", level:"warn", args:[...]}` message, when `parseCardMessage()` runs, then a typed console event with that level and args is returned; given `{tarmac:"escape"}`, then an escape event.
- **S5** [kit] Given a ring buffer at `CARD_CONSOLE_BUFFER_CAP` (500) entries, when one more entry is pushed, then the oldest entry is dropped, length stays 500, and remaining order is preserved.
- **S6** [QA] Given an agent writes a self-contained `dashboard.html` (inline D3/Canvas) and runs `tarmac open` from a Tarmac terminal, when the card lands, then an animating card appears next to that terminal with a provenance edge, live at every zoom, crisp at rest after settle, and no `read_doc` markdown fetch is ever issued for the file (fresh-open gating, the counterpart to S14's restore gating).
- **S7** [QA] Given card JS that logs during initial script execution and later, when the card runs, then every `console.*` call, uncaught error, and unhandled rejection appears in the host per-card buffer **in order**, including the initial-execution calls (proves shim-before-content), the header badge count matches the number of buffered entries, and toggling the strip open reveals those entries in the same order.

### Edge Cases

- **S8** [rust] Given a file path containing spaces, non-ASCII (e.g. CJK), and `%`/`#`/`?` characters, when it round-trips `cardSrcUrl` encoding → handler decoding, then the handler reads exactly the original path.
- **S9** [rust] Given a file that already begins with `<!DOCTYPE html>` or a BOM, when served, then the shim still precedes the first file byte (composition is unconditional; no content sniffing).
- **S10** [kit] Given a card frame and zoom, when `cardIframePx()` computes the settled iframe size, then it is `round(frame.w × zoom)` × `round(frame.h × zoom)` px (verify rounding at a non-integer product, e.g. `w=100, zoom=1.005` → `101`); and given a mid-gesture zoom `z` with settled zoom `s`, `cardGestureScale(z, s)` returns `z/s`.
- **S11** [QA] Given a **shielded** HTML card, when the user presses on it, drags its header, resizes a handle, or scrolls the wheel over it, then it selects/raises, moves, resizes, and plain-wheel does **not** scroll or reach the iframe content (ctrl+wheel still zooms the board) — identical to DocCard parity — and typing still goes to the prime terminal; `⌥Tab` cycles terminals only, never the card.
- **S12** [QA] Given a borrowed card (double-click dropped the shield, borrow ring visible), when the user presses Esc — whether focus is inside the iframe (shim relay) or in the host (Esc-ladder rung) — then in **one keypress** the shield restores, borrow chrome clears, and the prime terminal has keyboard focus.
- **S13** [QA] Given an open HTML card, when the file is rewritten on disk, then within the existing daemon 100ms-debounce path the card fully reloads with the new `?v=<new mtime_ms>` and all prior in-page JS state is gone; markdown cards keep their existing scroll-fraction behavior, HTML cards get none.
- **S14** [QA] Given an app restart with a persisted `.html` doc tile, when the board restores, then the card mounts as a live `HtmlCard` (extension routing applies on restore) and no `read_doc` markdown fetch is issued for it.

### Error Scenarios

- **S15** [rust] Given a `tarmac-card://doc/...` URL naming a nonexistent/unreadable file, when the handler serves it, then the response is 404 `text/plain` naming the path and error, with no shim.
- **S16** [rust] Given a malformed URL (undecodable percent-encoding or empty path), when the handler serves it, then the response is 400, not a panic.
- **S17** [kit] Given `message` data that is not a Tarmac payload (random objects, strings, `{tarmac:"bogus"}`, console payload with unknown `level` or missing `args`), when `parseCardMessage()` runs, then it returns `null` and the buffer is untouched.
- **S18** [QA] **Sandbox probe:** given the probe card loaded as a normal HTML card, when its script attempts every escape (fetch http + custom scheme, XHR, WebSocket, sendBeacon, `import()`, `__TAURI__`/`__TAURI_INTERNALS__` reads, `window.ipc?.postMessage`, storage/cookie access), then **0 attempts succeed** — no outbound request observed (verifiable with a local listener), `__TAURI__` undefined, IPC rejected — and every failure is reported into the host buffer.
- **S19** [QA] Given card JS that logs a non-cloneable value (a function, a circular object, a DOM node), when the shim's `safeSerialize` prepares it for `postMessage`, then the relay does not throw, that entry still lands in the host buffer as a string placeholder, and subsequent `console.*` calls continue to arrive (one bad argument does not wedge the channel).

## For the Implementing Agent

> **Your job:** make every acceptance scenario above pass — [kit]/[rust] scenarios with tests that would *fail if the behavior were wrong*, [QA] scenarios via the probe card and the QA checklist they define. A green suite that passes for the wrong reason does not satisfy this contract — `/verify` will hunt for vacuous tests by asking, of each behavior, "what is the smallest change that breaks this, and would any test catch it?"

**Sequencing constraint (the one prescribed order):** Milestone 0's spike gate comes first. Do not build card UI until the probe confirms header-CSP enforcement and IPC unreachability on this Tauri version; on outcome (2) switch to `srcdoc` delivery; on outcome (3) or reachable IPC, stop and report.

Implement however you work best otherwise. Write tests to the project's conventions (kit: `<module>.test.ts` siblings, node-env Vitest, `describe`/`it` citing scenario IDs; Rust: inline `#[cfg(test)] mod tests` in the new module) and to these principles (the same ones `/verify` scores against):

- **Behavioral over structural** — assert observable output/effects, not internals; the suite must survive refactoring.
- **Every test can fail** — no copy-pasted expected values, no asserting a constant, no tautologies.
- **Deterministic, isolated, readable** — no `Date.now()` in kit (pass timestamps in), no cross-test state, AAA structure.

Repo cautions that bite here: don't `cargo fmt` the Rust crates; `make` is the compile source of truth; kill any installed `tarmacd` before QA; native (non-React-synthetic) listeners are the established pattern where event timing matters (`CardShell.tsx:153-156`) — the double-click borrow listener likely needs the same treatment; no borrow/`.edit` CSS exists in the codebase — the borrow ring is **new CSS**, and it must read visually distinct from the existing `.border-focus` selection ring and `.fresh` ring (the v4c crib, `docs/v4c/visual-crib.md`, is an old design sketch — reference if useful, not a contract to follow).

## Definition of Done

Done is when `/verify` passes against this spec:

- [ ] Milestone 0 spike outcome recorded (header CSP enforced + IPC unreachable), probe card committed at `desktop/qa/sandbox-probe.html`.
- [ ] Test suite is green (`make test`).
- [ ] Every [kit]/[rust] scenario maps to at least one test; every [QA] scenario maps to a probe-card check or a written QA-checklist item in the PR.
- [ ] No covered-but-vacuous scenarios — each tested scenario's test fails under the smallest break of its behavior.
- [ ] Tests meet the Desiderata bar (behavioral, structure-insensitive); no anti-pattern violations.
- [ ] No implementation-quality blockers (stubs, dead code, stale docstrings); daemon/CLI/protocol diff is empty.

## Trade-offs and Limitations

- Process-shared isolation (origin boundary + CSP + injection exclusion), not OS isolation; runaway-CPU cards accepted for MVP.
- No external resources ever — agents must inline libraries (~280 KB D3, etc.).
- Shielded cards are look-don't-touch (no scroll/hover); borrowing is a mode to learn.
- Reload loses all in-page state; HTML cards have no scroll persistence.
- Shim lives Rust-side (`include_str!`), not as a kit string builder — a deviation from one design-doc sentence, made so the ordering guarantee is tested where it's enforced.
- `HtmlCard` DOM behavior (shield, borrow, message relay) is not unit-testable under the node-env Vitest config — QA'd per repo convention.

## Out of Scope

Unchanged from the design doc: network opt-in, console forwarding to agents/daemon, non-md/html doc kinds, multi-file HTML apps, any `doc_kind` protocol field, v4c editable docs. Additionally: peek/shelf HTML placeholder chips — recon confirmed no peek or shelf UI exists in the React app at all (legacy shelf tiles are dropped in `parseTiles`), so there is nothing to placeholder.
