## Context

Three card kinds scroll in three engines, and nothing Tarmac draws says where
any of them is scrolled to:

- a terminal card shows nothing, though `TerminalEngine.scrollbar` has the
  numbers (`TerminalScrollbar {total, offset, visible}`, in rows);
- a markdown card (`DocWebView`) shows WebKit's scrollbar on `.doc-scroll`, at
  native width;
- an HTML card (`HTMLCardView`) shows WebKit's scrollbar on its document,
  scaled by `zoom/3` with the document.

Both web scrollbars follow the system's *Show scroll bars* setting. Measured
with legacy scrollbars forced: at board zoom 0.25 a markdown card's track is
15 pt wide and a magnified HTML card's about 1 pt.

A card is a `CardView`: a header and a body container (`bodyHost`) inside a
clip. `CardBox.screen` lays the chrome out on screen through `CardScale`; the
body keeps its world size and is scaled. The wheel router
(`AppController.routeScroll`, `BoardWheel.route`) gives a card the wheel only
over the body of the selected card.

## Motivation

One scroll indicator for every card kind was asked for with the unified wheel
(2610.0002). A terminal left in its scrollback gives no cue at all today, and
the two web kinds disagree with each other and with the system setting.

## Proposed Solution

### Overview

Each card kind reports one value, `ScrollMetrics {offset, visible, total}`, in
whatever unit its content has. `CardView` draws one thumb from it, as chrome,
with a frame `TarmacKit` computes. The thumb shows from a wheel routed to the
card until one second after the last, then fades; deselecting the card hides
it at once. WebKit's own root scrollbar is hidden in both web kinds. The dev
snapshot reports each card's metrics and whether its thumb is shown.

### Key Components

- **`ScrollMetrics`** (new, `app/Sources/TarmacKit/ScrollMetrics.swift`, with
  `ScrollMetricsTests`) — the value, its validation, and the parser of a web
  card's report.
- **`ScrollIndicator`** (new, `app/Sources/TarmacKit/ScrollIndicator.swift`,
  with `ScrollIndicatorTests`) — the thumb on a track, its frame on screen, and
  `Visibility`, the rule's clock.
- **`CardConsole.Message.scrolled`** and **`HTMLCardSession.Effect.scrollChanged`**
  — an HTML document's report, parsed and passed through. The session holds no
  scroll state.
- **`TerminalView.onScrollChanged`** (`TarmacTerm`) — the engine's scrollbar,
  whenever it changes. `TarmacTerm` cannot see `ScrollMetrics`; the shell copies
  the three fields.
- **`card_shim.js`** — posts the root's numbers and hides the root scrollbar.
  **`doc-render.js`** and **`DocTemplate.html`** — the same for a markdown card.
- **`DocCardBody`** — gains `onScrollChanged`, `scrollCover` and
  `onScrollCoverChanged`.
- **`CardBox.Screen.shownBody`** (`TarmacKit`, `CardBoxTests`) — the part of
  the body's container the content area shows: what the thumb is laid against.
- **`CardView`** — owns the indicator view (a sibling of `bodyHost` in the
  clip), the card's metrics and its `Visibility`.
- **`AppController.routeScroll`** — tells the card it was given a wheel.
- **`DevSnapshot`** — `cards[].scroll`.

### Data Flow

1. A source reports:
   - terminal: after each frame read and each relayout, `TerminalView` compares
     `engine.scrollbar` with the last value it reported and calls
     `onScrollChanged` when it differs;
   - markdown: `doc-render.js` posts
     `{offset: scrollTop, visible: clientHeight, total: scrollHeight}` of
     `.doc-scroll` to the `docScroll` handler after every `relayout()` and on
     every `scroll`;
   - HTML: the shim posts
     `{tarmac: "scrolled", offset: window.scrollY, visible: <root>.clientHeight, total: <root>.scrollHeight}`
     to its parent — `<root>` is `document.scrollingElement`, read as it
     posts — when a `ResizeObserver` on `document.documentElement` fires, on a
     `scroll` whose target is the document, and on `resize`. The host page
     carries it (it is small); `CardConsole.parse` reads it;
     `HTMLCardSession.handle` returns `.scrollChanged`.
2. The body calls `onScrollChanged` with the `ScrollMetrics`, or with nil when
   what it reported is gone: an HTML reload (`loadDocument`), a page reload, a
   web content process that terminated.
3. `CardView` keeps the value and lays the indicator out at
   `ScrollIndicator.frame(metrics, body: box.shownBody, covered: scrollCover, scale: scale)`
   — hidden when that is nil.
4. `AppController.routeScroll`, on `BoardWheel.Route.card`, tells the card:
   `Visibility.wheeled(atMs: Uptime.nowMs)`. The card puts the thumb at full
   alpha, and once `Visibility.holdMs` has gone by with no other wheel fades it
   to 0 over `Visibility.fadeMs`.
5. `CardView.setSelected(false)` calls `Visibility.reset()`: the thumb is gone
   at once.
6. `DevSnapshotReader` hands `DevSnapshot` each card's metrics, whether its
   thumb is laid out and its alpha; `DevSnapshot` reports the metrics and
   `shown`.

### Interface Contract

```swift
// TarmacKit — ScrollMetrics.swift
/// Where a card's content is scrolled to, in any one unit of that content.
public struct ScrollMetrics: Equatable, Sendable {
    public let offset: Double    // of the first visible unit, from the start
    public let visible: Double
    public let total: Double
    public init?(offset: Double, visible: Double, total: Double)
    public init?(report: Any)
    public var overflows: Bool { get }
}

// TarmacKit — ScrollIndicator.swift
public enum ScrollIndicator {
    public static let width: CGFloat = 6        // world units
    public static let inset: CGFloat = 2
    public static let minLength: CGFloat = 24

    public struct Thumb: Equatable, Sendable { public var y: CGFloat; public var length: CGFloat }
    public static func thumb(_ metrics: ScrollMetrics?, track: CGFloat) -> Thumb?
    public static func frame(_ metrics: ScrollMetrics?, body: CGRect, covered: CGFloat, scale: CardScale) -> CGRect?

    public struct Visibility: Equatable, Sendable {
        public static let holdMs: UInt64 = 1000
        public static let fadeMs: UInt64 = 200
        public init()
        public mutating func wheeled(atMs now: UInt64)
        public mutating func reset()
        public func alpha(atMs now: UInt64) -> CGFloat
    }
}

// TarmacKit — CardConsole.swift, HTMLCardSession.swift
//   CardConsole.Message gains   case scrolled(ScrollMetrics)
//   HTMLCardSession.Effect gains case scrollChanged(ScrollMetrics)

// TarmacKit — DevSnapshot.swift
//   DevSnapshot.Card gains `scroll: Scroll?`, and DevSnapshot gains
//   public struct Scroll: Equatable, Sendable {
//       public var metrics: ScrollMetrics
//       public var laidOut: Bool      // the card's ScrollIndicator.frame is not nil, and the card is not culled
//       public var alpha: CGFloat     // its Visibility.alpha at the time of the snapshot
//       public init(metrics: ScrollMetrics, laidOut: Bool, alpha: CGFloat)
//   }

// TarmacTerm — TerminalView.swift
//   public var onScrollChanged: ((TerminalScrollbar) -> Void)?

// TarmacApp — DocCardBody
//   var onScrollChanged: ((ScrollMetrics?) -> Void)? { get set }
//   var scrollCover: CGFloat { get }             // world units hidden at the body's bottom by its own overlay
//   var onScrollCoverChanged: (() -> Void)? { get set }
```

**`ScrollMetrics.init?(offset:visible:total:)`** — nil unless all three are
finite, `visible > 0` and `total >= visible`. `offset` is clamped into
`0...(total − visible)`. `overflows` is `total > visible`.

**`ScrollMetrics.init?(report:)`** — `report` is a script message's body. It
must be a dictionary whose `offset`, `visible` and `total` are numbers — not
booleans, strings or null — and is then `init(offset:visible:total:)` of them.
Other keys are ignored. Anything else is nil. A number is what
`JSONValue.init(foundation:)` takes for one: an `NSNumber` that is not a
`CFBoolean`. So the 0 and the 1 a page sends are numbers and its `true` is
not, though all three bridge to `Bool`; a Swift `Int` or `Double` in the
dictionary is a number too.

**`ScrollIndicator.thumb`** — nil when `metrics` is nil, when it does not
overflow, or when `track < minLength`. Otherwise
`length = max(minLength, track × visible / total)` and
`y = (track − length) × offset / (total − visible)`, both in the track's units.

**`CardBox.Screen.shownBody`** — `body` cut to the content area: its width the
lesser of the body's and the content's, its height the lesser of the body's
and the room under the header. A border held at one device pixel
(`CardScale.line`: below zoom 1 on a 1× display, below 0.5 on a 2× one) leaves
the body less room than its container takes, and the clip cuts the rest off;
a thumb laid against the whole container would sit under the border, or
outside the clip. The container can also be the lesser — where the border
rounds down far enough, as at zoom 1.5 — and is then what shows.

**`ScrollIndicator.frame`** — `body` is the body's on-screen rect as it
shows, `CardBox.Screen.shownBody`: screen points in the card's content area,
where the indicator view lies beside `bodyHost`. The result is in the same
coordinates. `covered` is in world units, as `width`, `inset` and `minLength`
are.

```
H     = body.height / scale.zoom                           // the shown body's height, in world units
track = H − inset − max(CardBox.cornerRadius, covered + inset)
thumb = thumb(metrics, track: track)                       // nil → nil
frame = ( x:      scale.aligned(body.maxX − scale.length(inset) − scale.snapped(width)),
          y:      scale.aligned(body.minY + scale.length(inset + thumb.y)),
          width:  scale.snapped(width),
          height: scale.snapped(thumb.length) )
```

So the track starts `inset` below the body's top, and ends clear of the
card's rounded bottom corner or `inset` above the overlay, whichever is higher;
the thumb's right edge is `inset` in from the body's. `x`, `y`, `width` and
`height` are each on a whole device pixel (`CardScale.aligned`: a tie goes away
from zero), and `x` leaves room for the snapped width, not the exact one.

**`ScrollIndicator.Visibility`** — never wheeled, or reset: `alpha` is 0 at
every time. After `wheeled(atMs: t)`: 1 for `now ≤ t + holdMs` (and for a
`now` before `t`), then linear to 0 at `t + holdMs + fadeMs`, and 0 after.
Every call of `wheeled` replaces `t`, and one after a `reset` starts again.
No `t` and no `now` traps, `UInt64.max` included.

**`CardConsole.parse`** — a payload whose `tarmac` is `"scrolled"` is
`.scrolled(metrics)` when `ScrollMetrics(report: payload)` is not nil, and nil
otherwise, as for any message it cannot read.

**`HTMLCardSession.handle(.scrolled(m), borrowed:)`** — `[.scrollChanged(m)]`,
whatever `borrowed` is, and the session is unchanged.

**The shim** — one `scrolled` message a trigger, posted as the event happens:
it requests no animation frame and sets no timer for a report, paused or not,
and remembers nothing between posts, so two triggers with the same numbers
post twice. The numbers are read as it posts, not when it loads. A `scroll`
whose target is not the document posts nothing. While
`document.scrollingElement` is null a trigger posts nothing and throws nothing
(a throw would reach the shim's own `error` relay and land in the card's
console). A window with no `ResizeObserver` does not stop it loading or
posting on the other two triggers. By the time it posts `ready` it has set
`document.documentElement.style.scrollbarWidth = "none"`.

**`TerminalView.onScrollChanged`** — called with `engine.scrollbar` whenever it
differs from the value last passed to it, and not otherwise. It is checked
after each frame read and each relayout, one that changes no grid included.
Nothing has been passed while the callback was unset, so the first check after
it is set calls it.

**Snapshot** — every card object gains `"scroll"`: `null` when the card has no
metrics, else `{"offset", "visible", "total", "shown"}`. `shown` is
`laidOut && alpha > 0`, and `DevSnapshot` decides it: the reader hands over
whether a thumb is laid out — the card's `ScrollIndicator.frame` is not nil
and the card is not culled, since a culled card's view is hidden with
everything in it — and its `Visibility.alpha` at the time of the snapshot. So
a card culled inside its hold reads `shown` false.

**Breaking-change rule.** All additive: a new message kind documents may post,
a new snapshot key, three new protocol requirements on `DocCardBody` (both
implementers are in the tree). A document that styled its own root scrollbar
keeps doing so unless the shim's inline `scrollbar-width` wins.

### The shell, which is wiring

- `CardView`: the indicator view takes `ScrollIndicator.frame`'s rect; it
  answers no hit test, so a wheel or a press over the thumb reaches the body
  under it; a dark fill with a light hairline, both opaque, so the thumb is
  the same fill and the same hairline on every page (S37). New metrics and a changed `scrollCover`
  each ask for a layout; a wheel asks for none — it puts the view at full
  alpha and arms the timer, and the frame stays the last layout's (the layout
  knockouts of S19 and S36 lean on that). One timer, the card's, armed by a
  wheel for `Visibility.holdMs`, starts an animation of `Visibility.fadeMs`
  to 0; a later wheel cancels both. The view so draws the rule from
  `Visibility`'s two durations and does not read `Visibility.alpha`, which is
  the snapshot's (S15): the two agree for as long as the main queue is on
  time, and S19 and S28 check the drawing by capture. `reset` puts the view at
  0 with no fade.
- Terminal cards: `TerminalScrollbar`'s `offset`, `visible`, `total` are copied
  into a `ScrollMetrics` in `AppController.makeTerminalView`, beside the view's
  other callbacks; the card is found by term id when the callback runs, on
  whichever board holds it.
- `DocWebView`: a `docScroll` message handler, main frame only; a report
  `ScrollMetrics(report:)` refuses is dropped — the card keeps what it had —
  and never sent on as nil; nil is sent when its page is loaded again
  (`loadPage()`, which a terminated process comes to);
  `.doc-scroll { scrollbar-width: none }` in `DocTemplate.html`. The page posts
  every time, an unchanged report included.
- `HTMLCardView`: forwards `.scrollChanged`; sends nil in `loadDocument()` and
  on process termination; `scrollCover` is the open console's height, 0 when it
  is closed; `onScrollCoverChanged` fires when that changes.
- A culled card keeps its metrics and takes any report that still arrives. A
  cull does not touch its `Visibility`: the hold runs out by itself, and it is
  `laidOut` that says nothing shows.
- `DevSnapshotReader` reads `CardView.scrollFacts`: `laidOut` is the thumb's
  frame not being nil and the card's view not being hidden, `alpha` its
  `Visibility.alpha(atMs: Uptime.nowMs)`.

## Alternatives Considered

Argued in the design doc: restyling WebKit's scrollbar; always on the selected
card; hover-gated; cause-tagged reports; any change of the metrics; a
persistent mark on a terminal scrolled back; the indicator inside each body.

**`shown` read off the view** (`alphaValue`, `isHidden`). Under an animated
fade the view's model alpha is already 0 while the thumb is still on screen;
`Visibility.alpha` at the snapshot's time is the same fact with no animation
in it. The price: `shown` is the rule's word, not the view's, and cannot say
the view followed. Wherever a `[Q]` scenario leans on it, a capture says so.

**`shown` handed to `DevSnapshot` as a `Bool`.** The two-term rule would then
sit in the reader, untested. `DevSnapshot` takes the two facts and decides, as
it does for the quit notice's alpha.

## Security Considerations

- An HTML card's metrics come from its untrusted document, which can forge the
  message. `ScrollMetrics.init?` bounds what it can say; the worst case is one
  wrong thumb on its own card. No rate cap: a document can already post
  `escape`, `ready` and console messages without one.
- A document can bring WebKit's scrollbar back (`!important`, or clearing the
  inline style) and then shows both.

## Acceptance Scenarios

Unit scenarios name their test home. `[Q]` scenarios run against a live
`make run` app, driven by `scripts/qa/wheel-gesture.swift` and read off
`tarmac dev snapshot` and captures; each names a **knockout** — a one-line
temporary change that must make it fail — or says why it has none. Record
them in `qa/scroll-indicator-qa.md`; revert the line, never the file.

**Setup, for every `[Q]`**, as in `qa/native-wheel-qa.md`: the probe
(`qa/wheel-travel-probe.html`) and the two markdown fixtures this change adds
(`qa/scroll-indicator-long.md` — 300 numbered one-line paragraphs, then a last
line `END OF DOCUMENT` — and `qa/scroll-indicator-short.md`, one line) opened
with `env -u TARMAC_TERM_ID … tarmac open`; each card brought to the middle of
the board by a wheel posted over an unselected card; `tarmac dev focus board`
before a `--select`. A terminal is given history with
`tarmac dev type <term> $'seq 1 300\n'` after `tarmac dev focus <term>`.

**Timing.** The poster returns about 220 ms after its last event (320 with
`--lines`), and the thumb is up for a second after that event. A capture of a
shown thumb is taken straight after the poster returns, or while a long
gesture runs in the background (`--events 120 &` is about 2 s of wheel). Where
a scenario depends on being inside the hold, time the commands and record it:
a run that was not is inconclusive, not a pass.

- **S17 [Q] a terminal's metrics are its engine's.** Given a terminal with 300
  lines of history that has taken no wheel since the app was launched, then
  `scroll.visible` equals the snapshot's `term.rows` and
  `offset + visible = total`; when the poster posts
  `--select --lines --dy 3 --events 1` (three rows into history), then
  `offset` is 3 less and `visible` and `total` are what they were. The notched
  event has to be that terminal's first wheel: `TerminalView` keeps the part
  of a row a precise gesture leaves over (`scrollRemainder`), and after one
  the same event can move two rows — so S17 runs before S19 gestures on that
  terminal, or after a relaunch. The click lands on blank cells — `seq`
  prints at the left — so it opens no link, and a shell at its prompt gets no
  mouse report. *Knockout:* the shell copies `total` into `offset` → `offset`
  reads `total`, which `ScrollMetrics` clamps to `total − visible`, before and

## For the Implementing Agent

> **Your job:** make every acceptance scenario above pass with tests that would *fail if the behavior were wrong*. A green suite that passes for the wrong reason does not satisfy this contract — `/verify` will hunt for vacuous tests by asking, of each behavior, "what is the smallest change that breaks this, and would any test catch it?"

Implement however you work best; only the result is checked. This repo adds:

- **TDD is mandatory** (`docs/coding-style.md` §1): each unit test first,
  against a stub, watched failing. S27 is the one exception — a pin of
  existing behaviour, labelled as such.
- **The shell is wiring** (§1.2, §1.3 exception 2): every coordinate is
  `ScrollIndicator.frame`'s, every time `Visibility`'s, and `shown` is
  `DevSnapshot`'s. What the views owe is the `[Q]` record in
  `qa/scroll-indicator-qa.md`.
- **`CardShimTests`' stand-in** has no `ResizeObserver`, `scrollingElement` or
  `scrollY`, and its `h.fire` reaches only the window's listeners; S12 and
  S23–S25 add what they need to the stand-in, not to the shim:
  - a `ResizeObserver` on the window before the shim runs, as the six
    scheduler natives are, that records its callback and what it observes, so
    a test can call the one and read the other; the page's `omitNative`
    argument leaves it out for S25;
  - a `scroll` delivered, with its `target`, to the `scroll` listeners of both
    the document and the window — where the shim listens is its own business.
    The document itself is the root's target;
  - `scrollY` and `document.scrollingElement` are plain properties a test sets
    once the shim has loaded.
  A throw fails a test through the stand-in's `exceptionHandler`.
- **Existing tests this breaks, to update on purpose:** the card key-set
  tests in `DevSnapshotTests` (`"scroll"` joins both lists) and
  `testTheSnapshotSerialisesAsCompactJSON` (`"scroll":null` after
  `"screen_rect"`); its two card factories too, if `Card.init` takes `scroll`
  with no default.
- **Left to you**, with nothing observable riding on it: whether the shim sets
  `scrollbarWidth` when it loads or at `DOMContentLoaded`; whether the card
  skips a layout for a report equal to the metrics it holds; how the fade is
  drawn between the hold's end and the fade's end.
- **A `TerminalView` test** reads a frame with `viewportCells()`; a wheel is
  `wheel(lines:)`; a 3-row view is a frame of three cell heights and the
  padding.
- **Docs in the same change:** `docs/architecture.md` (the terminal, doc and
  HTML card sections, the shim bullet, the driver's `snapshot` paragraph);
  `.claude/skills/dev-channel/SKILL.md` (`cards[].scroll`); the agent guide
  `core/crates/tarmac-cli/src/SKILL.md` — let the document's root scroll (its
  test, `skill.rs`, forbids a repo path, a non-http link and `Doc status` in
  that file); flip the design's banner to HISTORICAL and its status to
  implemented.
- **Do not `cargo fmt`.** No Rust code changes.
- **Dev-channel rules:** never kill by name; the poster moves the cursor.

Write tests to these principles (the ones `/verify` scores against):

- **Behavioral over structural** — assert observable output, not internals.
- **Every test can fail** — no copy-pasted expected values, no tautologies.
- **Deterministic, isolated, readable** — the clock is an argument
  (`atMs:`); no cross-test state.

## Trade-offs and Limitations

From the design: the thumb is not draggable, and the web kinds lose the
scrollbar they can drag; an HTML card's thumb is its document's word; only the
root scroller is indicated; a scroll that is not a wheel shows nothing; the
system's *Show scroll bars* setting stops applying; a web card's thumb trails
its content by a frame or two.

- A wheel that scrolls something else — a nested scroller, an open console, a
  document that cancels it — shows the thumb unmoved.
- At the zoom floor, 0.1, a wheel over the middle of a selected card of the
  size a card opens at pans the board: the wheel router does not take it for
  the body's, so no thumb shows. At 0.125 it does, one pixel wide (S37's
  record).
- The thumb is opaque, so that it is the same on every page: for the second it
  shows, it hides the 6 points of content under it.
- `[Q]` scenarios are not in `make qa`.
- Nothing in the tool set ends a web content process, so the nil a body sends
  then — an HTML card's and a markdown card's — is reviewed, not run. So is a
  wheel that lands inside the 200 ms of the fade, and so is the hairline's
  width after the window moves to a display of another density
  (`ScrollThumbView.viewDidChangeBackingProperties`): the machine the record
  was made on has one display.
- The nil a magnified HTML card sends as it reloads does not last, except at
  zoom 3: the outgoing document reports once more when its frame is resized
  for the reload, so for as long as the new document takes to load the card
  carries the old one's numbers (S31). A wheel in that time shows a thumb for
  a document that is about to go.

## Open Questions

- **A root pinned to the viewport** (`html { height: 100% }`) changes no box
  when its content grows, so its `total` is stale until its next `scroll` or
  `resize`. Not measured; the design accepts it.
- **Thumb latency** for the web kinds is not measured and has no scenario.
- **`document.scrollingElement` before the body is parsed.** The shim's
  `<script>` precedes the document's doctype (`CardProtocol.respond`), which
  by the HTML standard puts every card's document in quirks mode, where
  `scrollingElement` is the body, and null until there is one. The contract
  holds either way — the element is read as the shim posts, and a null posts
  nothing (S12, S25) — and what it rests on is measured in a real card
  document: after load the scrolling element's `scrollTop` equals `scrollY`,
  its `clientHeight` equals `innerHeight`, and a `ResizeObserver` on
  `documentElement` fires when the zoom lands and when content grows
  (2610.0002's spike), and `document.compatMode` reads `BackCompat` in a card
  (S16's record).
