## Gate

The owner approved the direction on 2026-11-21: the shim draws list markers itself, with `::before` and the list counter, so that a magnified card shows them where they belong. These bind this spec:

- **G1.** A plain `ul`/`ol` in a magnified card shows its marker, its first line and its wrapped lines where they are at zoom 1. "Plain" = every item meets D3.
- **G2.** `ol` keeps `start`, `reversed`, `li value` and nesting.
- **G3.** An item never shows two markers. An author who asks for no marker gets no marker.
- **G4.** Markdown cards are out of scope.

**Two deviations from the board, raised by the advisor (2026-11-21), for the owner's brief (the advisor ruled that G3 and the measurements force both, so they do not wait for the owner):** (a) Tarmac writes an attribute on the author's `li` elements; (b) the rule that removes the native marker is `!important`, not zero-specificity. The board sketched a pure-CSS `:where()` sheet; D2 below records why that cannot meet G3.

## Context

- `card_shim.js` `applyZoom(z)` sets `document.documentElement.style.zoom = z`. The shim posts one `ready` per load (at `DOMContentLoaded`), and the host answers each `ready` with one zoom, only in magnify mode: `z` is the frozen K (3, `CardZoom.swift:23`). A reveal card gets no zoom message (`ZoomMode.ready` → `magnify: false`; `app/Sources/TarmacKit/HTMLCardSession.swift:102`). A zoom that arrives before `ready` is held and applied in `postReady`, through the same `applyZoom`. The shim applies every zoom it gets after `ready`, not only the first (`CardShimTests` `test2609_0003S9`).
- The shim already adopts one constructed stylesheet for the user's fonts (spec 2610.0010), only when fonts are given. `GUIDE.md` tells authors "Tarmac adds one stylesheet, last in `document.styleSheets`".
- `CardShimTests` runs the shim in JavaScriptCore with a stand-in page. It has no cascade and no layout.

### Facts measured before this spec (2026-11-21, system WebKit, macOS 26, offscreen `WKWebView`, root zoom like the shim)

- **The bug.** At zoom 3, 14px text, first line left in zoomed px (expected 300): `ul` 268, `ol` 215.8, `ol start=10` 164.3; 22px `ol type=I start=8` 76.5. Wrapped lines stay at 300. The same page in a `WKWebView` inside `swift test` shows it too (112 against 144).
- **Ruled out:** `li { display: flow-root list-item }`, `contain: layout`, `overflow: hidden`, `transform`, `text-indent: 0`, `zoom: 1`, `unicode-bidi: isolate`; `ul { zoom }`; an empty `li::before`; earlier: `::marker` rules, `list-style-position: inside`, `pageZoom`, zoom on `body`/`ul`.
- **The list counter.** With `list-style-type: none`, `content: counter(list-item)` in `li::before` gives `start=5` → 5, 6; `reversed` → 3, 2, 1; `value=10` → 1, 10, 11; `start=3 reversed` → 3, 2; nested `ol` restarts at 1; `counter(list-item, upper-roman)` → I, II…
- **The author's intent is readable before Tarmac acts.** Computed style of an `li` with no Tarmac rule: plain `ul` → `disc`; nested `ul` → `circle`, then `square`; `ol type=I` → `upper-roman`; `ol type=a` → `lower-alpha`; author `list-style: square` → `square`; `list-style: none` → `none`; `list-style-type: "→ "` → `"→ "`; `list-style-position: inside` → `inside`; author `li::before { content: "✓ " }` → `::before` content `"✓ "`, else `none`.
- **Marker geometry.** Four candidates, each at zoom 3: first line of a plain item, `ol start=998` (`1000.`), `<li><p>`, `<li><div>`, `<li><h3>`, a list in a scrolled `overflow: auto` box, the same under a `position: sticky` header with a background, and a scrolled `body` under `html { overflow: hidden }`.
  - **Zero-width float (chosen):** `li::before { float: left; box-sizing: content-box; width: 0; margin-left: -.5em; padding-right: .5em; display: flex; justify-content: flex-end; white-space: nowrap }`. Its margin box is 0 wide, so the text does not move; the content overflows to the left and ends .5em before the text. First line at 300; `1000.` clear of its text; marker on the first line of `<li><p>`, `<li><div>` and `<li><h3>`; it scrolls with its item in a scroller and in the body; the sticky header paints over it.
  - **Absolute at its static position** (`position: absolute; transform: translateX(-100%)`): good in an unscrolled page, but in a scrolled `overflow: auto` box the markers stay still while the text moves, so each marker sits on the wrong line. Rejected.
  - **`inline-block` with a fixed width and a negative margin:** overlaps the text at `1000.` and sits on a line of its own before a block child. Rejected.
  - **Float with `direction: rtl`:** shows `.998` and pushes the first line by the gap. Rejected.

## Proposed Solution

### Decisions

- **D1 (when).** The shim runs a marking pass each time `applyZoom` applies a numeric zoom other than 1 (both the direct path and the held-zoom path of `postReady`), right after it sets the zoom (so a failed pass never blocks the zoom). A reveal card (no zoom message), a zoom of 1 and a document before its zoom are not touched. The host posts one zoom per load, so the pass runs once per load, plus D6. A repeat zoom other than 1 runs the pass again: marked items are skipped (D4), and no second sheet (D5) or second observer (D6) is made. A later zoom of 1 removes no mark and does not stop the observer of D6.
- **D2 (why JS, not a pure-CSS sheet).** A zero-specificity sheet that sets `list-style: none` and draws `::before` cannot tell an author's `list-style: none` (wants no marker) or `list-style: square` (keeps the native marker, which the author rule restores) from the default: the first gets an unwanted bullet, the second two markers. G3 forbids both. So the shim reads each item's computed style first, while no Tarmac rule applies to it, and marks only items whose marker it can reproduce.
- **D3 (which items).** An `li` is marked when all hold: computed `display` is `list-item`; `list-style-position` is `outside`; `list-style-image` is `none`; `direction` is `ltr`; `writing-mode` is `horizontal-tb`; `list-style-type` is in the supported set; `getComputedStyle(li, "::before").content` is `none` or `normal`. Supported set: `disc`, `circle`, `square`, `decimal`, `decimal-leading-zero`, `lower-roman`, `upper-roman`, `lower-alpha`, `upper-alpha`, `lower-latin`, `upper-latin`, `lower-greek`. Every other `li` keeps its native marker: still shifted, but single and of the author's type. Only `li` elements are looked at; another element with `display: list-item` is not.
- **D4 (how an item is marked).** The shim sets `data-tarmac-marker="<type>"` on the `li`, `<type>` being the computed `list-style-type`. Reads come first for all candidates, then all writes, then one check per marked item: if its computed `list-style-type` is not `none` (an author `!important` rule beat the sheet), the attribute is removed again. An `li` that already has the attribute is skipped.
- **D5 (the sheet).** A second constructed stylesheet, appended to the end of `document.adoptedStyleSheets` the first time an item is marked (a page with no markable item gets none). The font sheet, when there is one, stays where it is. Adopted sheets come after the page's own sheets in the cascade order. There is at most one marker sheet per document. Its first rule is the `!important` rule below, so a test can find the sheet by that rule's `selectorText`. Its rules:
  - `li[data-tarmac-marker] { list-style-type: none !important; }`
  - `:where(li[data-tarmac-marker])::before { float: left; box-sizing: content-box; width: 0; margin-left: -.5em; padding-right: .5em; display: flex; justify-content: flex-end; white-space: nowrap; font-variant-numeric: tabular-nums; }` (the geometry of *Facts*: in flow, not positioned, not transformed, so it scrolls and paints with its item)
  - one rule per supported type: `:where(li[data-tarmac-marker="disc"])::before { content: "\2022"; }`, `circle` `"\25E6"`, `square` `"\25AA"`, and for each counted type `content: counter(list-item, <type>) ".";`.
  The drawing rules are zero-specificity, so an author rule on `li::before` that is added later (after marking) still wins for the properties it sets.
- **D6 (later items).** After the first marking pass (D1), also when that pass marked nothing, one `MutationObserver` on the root (`childList`, `subtree`) runs the same pass over each added `li` and each `li` inside an added element. It observes no attributes, so the shim's own writes do not wake it. A class or style change on an existing item is not observed (limit, see *Trade-offs*).
- **D7 (never break the page).** Every path is in `try`/`catch`, as the rest of the shim, and the pass never relays an error to the console (no post: `test2609_0003S9` pins that a zoom adds none). The pass first checks that all five natives below exist, and does nothing when one is missing; so the observer and the sheet are made only from the zoom path, never at load. A document without `CSSStyleSheet`, `adoptedStyleSheets`, `MutationObserver`, `querySelectorAll` or `getComputedStyle` gets its zoom as today, posts `ready` as today, no exception reaches the page, and no item is marked.
- **D8 (author guide).** `GUIDE.md` "Zoom: design for magnify" gains a short paragraph: in a magnified card, Tarmac draws the marker of a plain list item itself and marks the item `data-tarmac-marker`; a custom marker (`list-style: none` plus your own `li::before`) is left alone; a marker type outside the set, an image marker, an inside marker, a right-to-left list or a vertical list keeps WebKit's own marker, which WebKit draws too far left at the frozen zoom. The sentence "Tarmac adds one stylesheet" becomes "up to two stylesheets" with the same `ownerNode` caveat. To colour Tarmac's marker, style `li::before` (no `content`) as well as `li::marker`: a `::marker` rule does not reach a marked item.

### Trade-offs

- An author rule that changes an item's marker after it was marked (a class toggle) is not seen: the item keeps Tarmac's marker of the old type.
- Tarmac's bullet is a text glyph (`•`, `◦`, `▪`), not WebKit's drawn disc: its size and exact place differ a little from the native marker (seen by eye in the snapshots, not measured).
- The marker is a float at the start of the item. An author float or `clear` inside the item can move it, and with a non-collapsing top margin on the first child (the `li` has top padding or a border) the marker sits at the top of the item, not on the child's first line.
- A page that copies `innerHTML` of a marked item, or reads `attributes`, sees `data-tarmac-marker`.
- A marked item that a script moves or clones keeps its attribute (D4 skips it), so it keeps Tarmac's marker of the type read at marking time.
- An `li` that already carries `data-tarmac-marker` in the source is not read (D4). Once the marker sheet exists, it gets Tarmac's marker of the type the attribute names.
- An author `li::marker` rule (colour, size, font) has no effect on a marked item: the native marker is gone, and Tarmac's `::before` takes the item's own colour and font, or an author `li::before` colour (S21). (The `::marker` loss is not measured; it follows from the cascade.) Accepted by the advisor.
- The shown numbers (G2) come from WebKit's `list-item` counter. No automated check reads them, because a pseudo-element's text is not in the DOM: S3 checks that the marker uses that counter, and Q1 checks the numbers by eye.

## Scenarios

Automated in a new suite `app/Tests/TarmacKitTests/CardListMarkerTests.swift`, which runs the shipped `card_shim.js` in a real `WKWebView` (offscreen, in the test process) inside a page that posts the zoom to itself (at the top level `window.parent === window`, so the shim's source check passes). Terms:

- "First line" = left edge of the item's first text; "wrapped" = left edge of its second line. Both from `getBoundingClientRect`/`Range.getClientRects`, in zoomed px.
- "Zoom-1 left" = the same left, read from the same page loaded with a zoom of 1 posted (no item is marked there), times 3.
- "Mark" = the value of the item's `data-tarmac-marker` attribute; "no mark" = the item has no such attribute.
- "The marker sheet" = the one entry of `document.adoptedStyleSheets` whose first rule's `selectorText` is `li[data-tarmac-marker]`.
- "Control" = a plain `ul` with two items on the same page. Each "no mark" scenario also asserts that the control's items are marked `disc`, so the scenario fails on the unmodified tree.

Layout (G1):

- **S1.** Given a page with a two-line `ul` item at 14px, when zoom 3 is applied, then the first line's left equals the wrapped line's left, and both equal the zoom-1 left (±1 px).
- **S2.** Same as S1 for `ol`, `ol start=10` at 14px, and `ol type=I start=8` at 22px.
- **S22.** Given a two-line `ul` item inside a non-positioned `overflow: auto` box of 150px that is scrolled by 120px, when zoom 3 is applied, then the item's first line left equals its zoom-1 left (±1 px) and the item is marked (the marker is a float in the item, D5). The scroll and sticky-header behaviour of *Facts* is also in Q3.
- **S14.** Given a `ul` with `<li><p>…</p></li>` and an `ol` with `<li><div>…</div></li>`, when zoom 3 is applied, then the `ul` item is marked `disc`, the `ol` item `decimal`, and in each the child's first line left equals its zoom-1 left (±1 px).

Which items are marked (D3, D4, G2, G3):

- **S3.** Given `ol start=5`, `ol reversed` (3 items), an `ol` with `li value=10`, and `ol start=3 reversed`, when zoom 3 is applied, then each item is marked `decimal`, its computed `list-style-type` is `none`, and its computed `::before` `content` contains `counter(list-item` and names no other counter. (The shown numbers are not readable from the DOM; see *Trade-offs* and Q1.)
- **S4.** Given `ul` inside `ul` inside `ul`, when zoom 3 is applied, then the marks are `disc`, `circle`, `square`, outer to inner.
- **S5.** Given `ol type=I` and `ol type=a`, when zoom 3 is applied, then the marks are `upper-roman` and `lower-alpha`, and each `::before` `content` contains the same type name.
- **S6.** Given author `ul.chips { list-style: none }`, when zoom 3 is applied, then its items have no mark and their computed `::before` `content` is `none` or `normal`. Control marked.
- **S7.** Given author `ul { list-style: square }`, when zoom 3 is applied, then the items are marked `square` and their computed `list-style-type` is `none` (one marker, Tarmac's square).
- **S8.** Given author `ul.ticks li::before { content: "✓ " }`, when zoom 3 is applied, then those items have no mark, their `::before` `content` is still `"✓ "`, and their computed `list-style-type` is still `disc`. Control marked.
- **S9.** Given one `ul` each with author `list-style-type: "→ "`, `list-style-position: inside`, `list-style-image: url(<data URI>)`, `direction: rtl`, `writing-mode: vertical-rl`, `list-style-type: hebrew`, and `ul.blocks > li { display: block }`, and a `div` with `display: list-item`, when zoom 3 is applied, then none of them has a mark, and each keeps its computed `list-style-type`. Control marked.
- **S10.** Given author `ul.keep > li { list-style-type: square !important }` (specificity 0,1,2, above the sheet's 0,1,1), when zoom 3 is applied, then those items have no mark after the pass (D4 check) and their computed `list-style-type` is `square`. Control marked.
- **S17.** Given author `li { list-style-type: square !important }` (specificity 0,0,1, below the sheet's rule), when zoom 3 is applied, then the items are marked `square` and their computed `list-style-type` is `none` (one marker, Tarmac's square).
- **S23.** Given one `ol` (or `ul`) per supported type, set by `list-style-type`, when zoom 3 is applied, then each item's mark is its type, and its computed `::before` `content` contains the type name (counted types; for `decimal`, `counter(list-item)`, since WebKit leaves the default style out when it writes the value — seen when S23 first ran) or the glyph of D5 (`disc`, `circle`, `square`).
- **S21.** Given author `li::before { color: rgb(200, 0, 0) }` with no `content`, when zoom 3 is applied, then the items are marked `disc` and their computed `::before` `color` is `rgb(200, 0, 0)`.
- **S18.** Given a page whose items are marked, when a `<style>` with `li::before { content: "– " }` is added after the pass, then the item is still marked `disc` and its computed `::before` `content` is `"– "` (D5: the drawing rules have zero specificity).

When (D1, D5, D6):

- **S11.** Given a page with a plain `ul`, when no zoom is posted, and again when a zoom of 1 is posted, then no item has a mark and there is no marker sheet. (Regression guard: passes on the unmodified tree.)
- **S19.** Given a page with no `li`, when zoom 3 is applied, then there is no marker sheet and `document.adoptedStyleSheets` is as before the zoom. (Regression guard.)
- **S12.** Given a page after zoom 3, when a script appends a new `ul` with two items, and appends one `li` to an existing `ul`, then all three new items are marked `disc` when a task queued with `setTimeout(…, 0)` right after the appends runs.
- **S13.** Given a page after zoom 3 with marked items, when a second `ul` is appended and a second zoom 3 is posted, then each first-list item still has the one mark `disc`, the new items are marked, and there is exactly one marker sheet.
- **S20.** Given a page loaded with the user's fonts (a filled shim), when zoom 3 is applied, then the font sheet is still adopted with its values and there is one marker sheet beside it.

In `CardShimTests` (JavaScriptCore stand-in, no cascade, no layout):

- **S15.** Given a stand-in page with a head, one stand-in `li` (attributes, `localName`) that `querySelectorAll("li")` returns, and a cascade-aware `getComputedStyle` stub (a plain `disc` item; `list-style-type` `none` once the `li` has the attribute and a sheet whose first rule is `li[data-tarmac-marker]` is adopted): when nothing is removed and zoom 3 is posted after `ready`, the `li` is marked `disc` (positive control). When one native is removed instead (one case each: the global `CSSStyleSheet`, `document.adoptedStyleSheets`, the global `MutationObserver`, `document.querySelectorAll`, the global `getComputedStyle`), then the root's zoom is 3, `ready` was posted, nothing more was posted, no exception reaches the page, the `li` has no mark and no sheet or observer was made (D7).
- **S16.** Given the stand-in of S15, when a zoom of 1 is posted after `ready`, then no `MutationObserver` beyond the colour-scheme one is made and no sheet is made (regression guard). When zoom 3 is posted after `ready` instead, one more `MutationObserver` is made (two in all), observing the root with `childList` and `subtree`; when a second zoom 3 is posted, no further `MutationObserver` or sheet is made (D1, D6).

Manual QA (dev app, `make run`):

## Out of scope

- Markdown cards (the owner is still choosing that design).
- Image and SVG sizing, and the guide's layout template (separate issue).
- Filing a WebKit bug: a draft is written; filing is the owner's call.

## Interface Contract

What a card's author can see, and what the guide (D8) documents:

- In a magnified card, after the zoom, each `li` that meets D3 and passes D4's check carries `data-tarmac-marker="<list-style-type>"`.
- One more constructed sheet in `document.adoptedStyleSheets` (D5), only when an item was marked. It has no `ownerNode`.
- One more `MutationObserver` on the root, in a magnified card only (D6).
- No wire change, no new message, no change for a reveal card or a markdown card.

## Alternatives Considered

- **A pure-CSS `:where()` sheet** (the board's sketch): breaks G3 (D2).
- **Layout fixes on `li`, `ul` or the root**, and `::marker` or `list-style-position` rules: none moves the first line back (*Facts*, "Ruled out").
- **An `inline-block` marker with a fixed width and a negative margin:** overlaps `1000.` and drops below a block child (*Facts*, "Marker geometry").
- **A counter of the shim's own:** would repeat `start`, `reversed`, `value` and nesting by hand; WebKit's `list-item` counter already gives them (*Facts*, "The list counter").

## Decided questions (Fable advisor, 2026-11-21)

- **Deviations (a) and (b):** accepted; G3 and the measurements force them. They lead the owner's brief.
- **G3 scope:** G3 binds at marking time. The *Trade-offs* limits stay; an `li` that already has the attribute is skipped.
- **Vertical writing:** excluded in D3 (`writing-mode: horizontal-tb`), with an S9 case.
- **`::marker` styling:** the loss is accepted; S21 pins that an author `li::before` colour reaches Tarmac's marker, and D8 tells authors so.
- **CI:** `CardListMarkerTests` runs in CI with no skip. Push once S1 is red then green and read the `app (swift test)` job before writing the other scenarios. Drive the page with the run-loop form (`RunLoop.main.run(until:)`) that worked in the spike; the two `async` forms failed.
