## Gate

The owner made these decisions on 2026-11-19 (issue #424). They bind this spec:

- **G1. Pane.** Fixed at the panel's foot, between the list and the footer. It shows the selected item: kind tag, title, age, a `go ↵` button, then the text, then the place. A bell or exit item shows `no text` and its place. With nothing selected it says so.
- **G2. Markdown in the pane.** Paragraphs, headings (semibold at body size, never larger than the row title), lists, code blocks and inline marks. No images, no click targets. The text keeps its quote marks as a claim, at the top-left and bottom-right corners, so a code block does not break them.
- **G3. Long text** scrolls inside the pane.
- **G4. Click selects and previews; it does not fly.** Fly = the `go ↵` button (on the hovered row, the selected row and in the pane header), a double-click on a row, or ↵. A fly closes the inbox, as `jump(to:)` does today.
- **G5. No tool tip** on rows.
- **G6. Resize.** A drag bar between the list and the pane. The pane keeps a minimum height (~72 pt) and the list keeps about two rows. A double-click on the bar resets the default height (~236 pt). The bar takes ↑↓ when it has keyboard focus.
- **G7. The pane height is saved** in `app-prefs.json` and restored at launch.
- **G8. Row states.** Selected = `bg3` plus a 1 px inset `focus-border` outline. Hover = a quieter lift than `bg3` (prototype `#383e44` in Breeze Dark), in each of the eight themes.
- **G9. Out of scope:** answering from the inbox (#423).

## Context

- **Panel.** `InboxPanelView` (`app/Sources/TarmacApp/InboxPanelView.swift`) stacks a header (`bg1`), a scrolling list of `InboxRowView`s on `bg2`, and a footer (`bg1`). It holds first responder while open (`KeyHoldingView`); every key goes to `AppController.handleInboxKey`, which runs `InboxKeys.handle`. A click on a row calls `onPick`, which today jumps.
- **Rows.** `InboxRowView: OverlayRowView`. `OverlayRowView.paint` fills `bg3` for selected **or** hovered. `BoardSwitcherRow` is the other subclass; the switcher's list is also on `bg2` (`BoardSwitcherView.swift:129`).
- **Tool tip.** `InboxRow.toolTip` (`InboxCopy.toolTip`) is set on the row view (`InboxRowView.swift:61`).
- **Markdown.** `InlineMarkdown.line` (`app/Sources/TarmacKit/InlineMarkdown.swift`) parses blocks privately and flattens them to one line. `InlineTextLabel` draws one line of runs; it does not wrap.
- **Prefs.** `AppPrefs.Values` / `encode` / `decode` (`app/Sources/TarmacKit/AppPrefs.swift`); the app saves through `AppPrefsStore.update`.
- **Refresh.** `openInbox` starts a timer that calls `renderInbox()` each `ReportChip.refreshInterval`, so the age text changes while the panel is open.
- **Interface size.** Chrome design sizes go through `Theme.chrome(_:)`.

### Facts checked before this spec (2026-11-19)

- **Hover colour.** The prototype's list is on `#353b41`, which is Breeze Dark `bg2`; selected is `#3e444b` = `bg3`. `#383e44` is exactly one third of the way from `bg2` to `bg3` per channel, with the rounding of `ThemeFile.mix`.
- **Read state.** In the prototype, a click (select) does not mark an item read; only `go` does. The app marks an item read when a jump lands (`touchInbox`), so a preview changes no read state.
- **Wrapped markdown in AppKit** (offline spike, PNG checked by eye): an `NSTextView` on a TextKit 1 `NSLayoutManager` subclass that draws in `drawBackground(forGlyphRange:at:)` gives (a) a rounded bordered box behind each line fragment of a code span, also when the span wraps, and (b) one full-width filled box behind a code block. A `\n` inside the block adds paragraph spacing between its lines; `U+2028` (line separator) does not.
- **QA S35** (`scripts/qa/smoke.mjs`) jumps with ↵ only, so G4 does not break it.

## Proposed Solution

### Overview

The kit gets the rules: the block model of a report's text, the pane's copy, the split's sizes, the pointer effects, the grip's focus and keys, the saved height and the hover colour. The shell gets a grip view, a preview view and a TextKit view for the blocks, and rewires the row click.

### Decisions

- **D1 (block model).** `InlineMarkdown.blocks(_ text: String) -> [MarkdownBlock]` becomes public, with
  `enum MarkdownBlock { case paragraph(InlineText), heading(InlineText), list([ListItem]), code([String]) }` and `struct ListItem { marker: String; text: InlineText }`.
  The rules are the ones `line` uses today (spec 2611.0017 D2): the same heading, list item and fence tests, extracted, not copied. Consecutive list items of one kind form one `.list`; a blank line, another block, or an item of the other kind (ordered after unordered, or the reverse) ends it, as the prototype's `parse` does. A paragraph's lines join with one space. The text of each paragraph, heading and list item is settled on its own (D4 of 2611.0017): whitespace collapses to one space and is trimmed at both ends, so the gap after `##` or after a list marker is not in the text. A code block keeps its lines as written (no trim, no collapse); an unclosed fence runs to the end. An ordered item keeps the number as written (`3.` stays `3.`). A paragraph or heading with empty text is dropped, and so is a code block whose lines are all empty or whitespace (as `line` gives no run for them today). A list item with empty text is kept with its marker only, because `line("- ")` gives one `•` run today. `MarkdownBlock`, `ListItem`, `InboxPreview` and `InboxPreview.Body` are `Equatable` and `Sendable`.
- **D2 (`line` keeps its behaviour).** `InlineMarkdown.line` is rebuilt on `blocks`: each block flattened as today (heading → its runs; list item → `bullet` run + space + runs; code → one `code` run of `ChromeText.oneLine(lines joined by " ")`), joined by one space, then `settle`. Every existing `InlineMarkdownTests` case passes unchanged.
- **D3 (pane copy).** `InboxCopy.preview(_ item:, place:, nowMs:) -> InboxPreview`: `id`, `kind`, `tag`, `title`, `age`, `place`, and `body: InboxPreview.Body`, which is `.blocks([MarkdownBlock])` for an item with text, `.noText` otherwise. A text whose `blocks` are empty (only markup, e.g. a lone fence) shows `.blocks([.paragraph(.literal(ChromeText.oneLine(text)))])`, as `line` falls back. A text that is empty or only whitespace (the CLI drops only an empty one, `report.rs:23`) is `.noText`. The row's quote is not changed: it keeps `“”` for such a text (2611.0017 S30). `InboxCopy.noText = "no text"`, `InboxCopy.nothingSelected = "preview · nothing selected"`.
- **D4 (no tool tip).** `InboxRow.toolTip` and `InboxCopy.toolTip` are removed; a row view sets no tool tip.
- **D5 (pointer effects).** `InboxKeys.click(_ id:, count:, state:) -> (State, Effect)`: count 1 selects `id`, sets focus `.list` and returns `.none`; count ≥ 2 returns `.jump(id)` only when `id` is the selected id, else it acts as count 1. Reason: the first click selects, and the list then scrolls the selected row into view, so the second click of a double-click can land on a neighbour; that click must not fly to a card the user did not pick. A `go ↵` button (row or pane header) is `.jump(id)` of its item. The pane header's `go ↵` acts on the selected id.
- **D6 (grip focus).** `InboxKeys.State` gains `focus: Focus` (`.list` default, `.grip`). Focus is state, not first responder: the panel keeps first responder, so `keysOwner` and `returnKeys` are unchanged. A mouse-down on the grip sets `.grip`; a row click, a filter change (button or Tab) and opening the panel set `.list`. With `.grip`, ↑ returns `.resizePane(steps: 1)` and ↓ `.resizePane(steps: -1)` and the selection does not move; every other key does what it does with `.list`. There is no key that moves focus to the grip: a click is the way in (limit, see *Trade-offs*).
- **D7 (split sizes).** `InboxPreviewSplit` (TarmacKit), all in design points: `standard = 236`, `minimum = 72`, `listMinimum = 126` (two rows of the prototype), `step = 24`. `shown(wanted: CGFloat?, room: CGFloat, scale: CGFloat) -> CGFloat`: `room` is the height between the header and the footer less the grip, in screen points; the result is `wanted ?? standard` times `scale`, clamped to `[minimum·scale, max(minimum·scale, room − listMinimum·scale)]`, then rounded to a whole point with `.rounded()` (a half goes up). The list gets `max(0, room − shown)`: when the room is less than the minimum, the pane keeps its minimum and the list has no height. The design bounds are `[minimum, min(2000, max(minimum, room / scale − listMinimum))]` (the shown bounds in design points, never above D8's read limit). `stepped(wanted:, steps:, room:, scale:) -> CGFloat?` and `dragged(wanted:, by delta: screen points, room:, scale:) -> CGFloat?` start from the **shown** height in design points (`wanted ?? standard` clamped to the design bounds), add `steps · step` or `delta / scale` (a positive `delta` is the grip moved up, so the pane grows), and clamp to the design bounds. When the result equals the start, they return `wanted` unchanged (nil stays nil): an action that does not change the shown height does not change the wanted height, so a plain click on the grip (a drag of 0) or a step at a bound never overwrites a saved height that a small window cannot show. `scale` is `Theme.chrome(1)`.
- **D8 (the saved height).** `AppPrefs.Values.inboxPreviewHeight: Double?`, key `inbox_preview_height`, design points. Read when it is a number in `[72, 2000]`; anything else is no entry. Written after every other key, only when present and accepted. The wanted height is saved at a drag's end, at each grip arrow key, and at a reset; a reset saves no entry (the standard). The shown height is clamped at layout only: a small window never overwrites the saved height.
- **D9 (hover colour).** `Palette.rowHover` is derived, not stored: `mix(bg2, bg3, 1/3)` with the one `mix` that `ThemeFile` uses today, moved to `Palette` so both share it. No theme-file key; a file theme gets its hover from its own `bg2` and `bg3`. `Theme.rowHover` exposes it.
- **D10 (row look).** `OverlayRowView.paint`: selected → `bg3` and a 1 px inset border `Theme.focusBorder`; else hovered → `Theme.rowHover`; else clear. `BoardSwitcherRow` does not paint itself (it only sets `selected`). An inbox row's inline code box keeps its 2611.0017 fill: `bg2` when selected, else `bg1`, hovered too (`bg1` stands apart from `rowHover`). This also changes the board switcher's rows (same class, same `bg2` list) — intended: one row language in both overlays.
- **D11 (row `go ↵`).** A small chip `go ↵` (the inbox chip, `InboxFilterButton`, with its own metrics, in a go look: mono 10, `text` colour, `bg1` fill, 1 px `line` border, radius 4) at the row's bottom-right (10 pt from the right, 7 pt from the bottom), shown while the row is hovered or selected. The place line leaves the chip's width and a gap, and never less than 48 pt (the chip grows with the Interface size). A click on it is `.jump(id)` and does not first select.
- **D12 (pane layout).** Top to bottom inside the panel: header, list (scrolls), grip, pane, footer. Grip: 9 pt tall, `bg1`, 1 px `line` top rule, a 28 × 2 pt centred handle in `line`, `agent` while hovered, dragged or focused; cursor `resizeUpDown`. Pane: `bg1`, padding 8 / 14 / 10, gap 8. Pane header (one line): kind chip, title (mono 10.5, `text`, one line, cut at the tail), age (mono 10, `faint`), `go ↵` chip (same as D11). Nothing selected: the header is `preview · nothing selected` (mono 10, `faint`) and the body is empty. Body: a scroll view that fills the rest. Place: one line, mono 10, `faint`, cut at the tail, under the body (shown only with text). `.noText`: the body is two lines, `no text` and the place, mono 10, `faint`; no place line below.
- **D13 (pane text).** An `NSTextView` (not editable, not selectable, no links) on TextKit 1 that draws the boxes itself, in `drawBackground(in:)`, with a text inset as wide as the box padding (QA: a layout manager's background drawing is clipped to the lines it draws, which cut off the top of a first code block and the left edge of a span that starts a paragraph). Body mono 11, `muted`, line height 1.55; padding 0 × 12 for the corner quotes. Heading: semibold mono 11, `text`. Paragraph and heading spacing 7. List: hanging indent 18, or the widest marker of that list plus 6 when that is more (so `10.` does not tab past the indent; found in QA), the marker in `faint`. Code span: boxed line by line around its glyphs (an enclosing rect runs to the end of a line the span wraps on; found in QA), the 2611.0017 box (1 px `line` border, radius 3), with fill `bg2`, because the pane itself is `bg1`. Code block: fill `bg0`, 1 px `line` border, radius 4, padding 6 × 8, `text` colour, lines joined by `U+2028`, wrapped. Bold → semibold, italic → the family's italic else `.obliqueness 0.2` (as `InlineTextLabel`), link → its text, underlined, not clickable. The quote marks `“` and `”` are two `faint` labels inside the scroll view's document view, with the text: `“` at its top-left corner, `”` at the bottom-right corner after the last line, so they scroll with the text.
- **D14 (refresh).** The pane's body is rebuilt, and scrolled to its top, only when the selected id or its text changes. The header (age) follows every render. Fonts and colours are baked into the attributed string, so a theme change (`themeChanged`) or a font change (`fontsChanged`) rebuilds the body too, keeping its scroll position. All fonts follow the Interface size and font choice; colours follow the theme. No pane view takes first responder: the panel keeps the keys (D6).
- **D15 (click wiring).** A row click → `InboxKeys.click(count: event.clickCount)`. The board does not move and the inbox stays open on a single click. Double-click and `go ↵` go through `jump(to:)`, which closes the inbox (unchanged).

### What stays in the shell, and why

Drawing (layout manager, attributed strings, views) and event plumbing. Every decision about what is shown, what a click or key does and what height is stored is a kit function. Per `docs/coding-style.md`, the `TarmacApp` shell has no unit tests.

## Alternatives Considered

- **A stored hover colour per theme + a `tarmac-row-hover` file key.** Eight more literals and a file key for a colour that a rule gives exactly; rejected (D9).
- **The grip as a real first responder.** Breaks `keysOwner`/`returnKeys` (the panel must stay first responder) and needs focus-ring code; rejected for state focus (D6).
- **Per-run views (`InlineTextLabel`) for the pane.** It does not wrap; a wrapped layout by hand repeats TextKit. Rejected for TextKit 1 (D13).
- **A WKWebView pane.** A web view per panel for 280 scalars, and its memory and focus cost; rejected.

## Migration & Rollback

One optional prefs key. An older build ignores it, and when it saves prefs it drops the key (`encode` writes only the keys it knows); the pane then opens at the standard height. Accepted. Rollback: revert the change; no data to migrate.

## Security Considerations

The text is a claim from a process. It is drawn as text: no links, no images, no HTML, no click targets (G2).

## Acceptance Scenarios

Notation: `b"…"` bold run, `i"…"` italic, `c"…"` code, `l"…"` link, `•` bullet run; `P[…]` paragraph, `H[…]` heading, `L[(marker, …), …]` list, `C[lines]` code block.

### Edge Cases

- **S20 (unclosed fence)** [auto]: `"run:\n```\nmake qa"` → `P["run:"]`, `C["make qa"]`.
- **S21 (only markup)** [auto]: text `"```\n```"` → `blocks` is `[]`; the preview body is `.blocks([.paragraph(.literal("``` ```"))])`.
- **S22 (list ends at a paragraph)** [auto]: `"- a\n- b\nnext"` → `L[("•","a"),("•","b")]`, `P["next"]`.
- **S23 (prefs refused values)** [auto]: `"inbox_preview_height": 50`, `3000`, `"236"`, `true` each decode to nil, and the other keys still decode.
- **S24 (reset)** [auto, via `AppPrefs`]: values with a height, then the reset (nil) → the encoded bytes have no `inbox_preview_height` key.
- **S25 (filter clears grip focus)** [auto]: focus `.grip`, ⇧Tab → focus `.list`.
- **S31 (whitespace-only text)** [auto, `InboxCopyTests`]: a report with text `"  \n "` → preview body `.noText`.
- **S32 (list kind change)** [auto]: `"- a\n1. b"` → `L[("•","a")]`, `L[("1.","b")]`.
- **S27 (empty blocks, `line` parity)** [auto, `InlineMarkdownTests`]: `"- "` → `L[("•", [])]`, and `line("- ")` is still one `•` run; `"```\n  \n```"` → `blocks` is `[]`; `"# \nx"` → `P["x"]` (the empty heading is dropped).

### Error Scenarios

- **S26 (stale id)** [auto]: selected `x`, and `x` is no longer in the rows; `click(x, count: 2)` → `.jump(x)`, state unchanged. The shell needs no new guard: `jump(to:)` already returns at once for an item that is gone (`inbox.item(id)` is nil, `AppController+Inbox.swift:172`).

### QA (dev channel, not automated)

- **Q1.** Open the inbox with three items. Click the second row: it is selected (bg3 + a 1 px `focus-border` outline, agent at 50 %), the pane shows its whole text with markdown, the board does not move, the inbox stays open.
- **Q2.** Hover a non-selected row: a quieter fill than the selected one, and `go ↵` appears on it. Check Breeze Light, Breeze Dark, Catppuccin Latte/Mocha, GitHub Light/Dark, Solarized Light/Dark (screenshot each).
- **Q3.** Double-click a row; click the row `go ↵`; click the pane `go ↵`; press ↵: each flies to the card and closes the inbox.
- **Q4.** Drag the grip up and down: the split changes, stops at the pane minimum and at two rows of list. Double-click the grip: back to the standard height. Click the grip, press ↑ and ↓: it moves by one step; press ↓ in the list afterwards (after a row click): the selection moves.
- **Q5.** Drag to a new height, quit with `make qa-quit`'s path or ⌘Q, `make run` again, open the inbox: the same height; `.dev/config/app-prefs.json` has `inbox_preview_height`.
- **Q6.** A bell item: the pane shows `no text` and its place. Nothing selected (empty filter): `preview · nothing selected`.
- **Q7.** A long report (12 list lines): the pane scrolls inside itself; the quote marks sit at the top-left and the bottom-right of the text; a code block sits between them.
- **Q8.** Open the board switcher: hovered and selected rows use the new look (D10).
- **Q9.** With the inbox open, wait over a refresh: the pane does not jump back to its top while scrolled. Change the theme while scrolled: the pane takes the new colours and keeps its place.
- **Q10 (keys stay with the panel).** Click the pane body, then the pane header, then the grip; after each, press ↓ and then Esc: ↓ acts (selection or resize) and Esc closes the inbox and gives the keys back to the card that had them.

## Trade-offs and Limitations

- The grip's keyboard focus comes only from a click on it (D6); there is no key to move focus to it.
- An older build that saves prefs drops `inbox_preview_height`.
- For a blank text (empty or only whitespace) the row shows `“”` (2611.0017 S30) and the pane says `no text`.
- A one-line fence such as ```` ```make qa``` failed ```` loses text in the pane, as on the row (#426, the shared fence rule). The pane's "whole text" holds for every other text until #426 is fixed. (Fixed in #426: such a line is now a paragraph, and its backticks a code span; 2611.0017 S36, S38.)
- The pane does not render blockquotes, tables, nesting, or escapes (2611.0017's limits).
- A file theme that gives `tarmac-bg2` and `tarmac-bg3` the same colour gets a hover equal to both (D9 derives it). G8 binds the eight catalog themes only.
