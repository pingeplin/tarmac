# 2607.0005 Cmd+W closes a dead terminal card without depending on the daemon's no-op

**Date:** 2026-07-03
**Status:** implemented
**Author:** EP Lin

> Fixes GitHub issue #57 — `fix(cards): ensure Cmd+W closes a dead (crashed) card`.

## Context

A dead (crashed/exited) terminal card renders at `opacity: 0.55` (`.card.dead`, theme/card.css) but is otherwise a normal card: `onCardGrab` (`App.tsx` ~1507) sets `selectedId` for any card id with no dead exclusion, and `CardShell.tsx`'s `onHeaderPointerDown`/`onBodyPointerDown` call `onGrab` unconditionally. So a dead card can already be clicked into selection.

Cmd+W on a selected term card (`App.tsx` ~1145-1189) always does the same thing regardless of `card.dead`: it computes `otherLive` (other live, non-dead terms on the board), routes through `focusedClose.decide("term", otherLive)` to get `{ kind: "closeTerminal", replace }`, unconditionally calls `void termClose(termId)` (`desktop/src/ipc/daemon.ts:66` → Tauri `term_close`), then filters/replaces the card by `termId` — a filter that matches regardless of `dead`, so the card *is* already removed from the board today.

The daemon's `Msg::TermClose` handler (`core/crates/tarmacd/src/conn.rs` ~272-283) looks up `term_id` in `daemon.terms`; if it's already gone (exited/reaped) it just debug-logs and no-ops. This is confirmed safe. But the frontend's correctness currently *depends* on that daemon no-op — it fires the IPC call even when it already knows, locally, that the pty is dead and there's nothing to signal.

## Motivation

Issue #57 asks for behavior that doesn't quietly lean on an implicit daemon guarantee. Sending `termClose` for a card the frontend already knows is dead is a wasted round-trip at best and a latent coupling at worst — if the daemon's no-op behavior ever changed (e.g. started asserting the term exists), Cmd+W on a dead card would break with no test to catch it. The fix decouples the frontend's card-removal correctness from that daemon-side assumption: skip the IPC call when the card is already dead, since there is genuinely nothing to signal.

## Proposed Solution

### Overview

Extend `focusedClose.decide`'s `"term"` case with a `dead: boolean` third parameter. The existing `replace` computation (via `termExitDecide(0, otherLiveTerminals)`) is unchanged by this — only a new `signalClose` field is added to the `closeTerminal` action, computed as `!dead`. `App.tsx` passes `card.dead` through and gates the existing `void termClose(termId)` call on `action.signalClose`.

### Key Components

- **`focusedClose.decide` (`desktop/src/kit/focusedClose.ts`)** — signature becomes `decide(kind: Kind, otherLiveTerminals: number, dead?: boolean): Action`. Only the `"term"` branch reads `dead`; `"doc"` and `"none"` are unaffected. `dead` defaults to `false` so the default-arg contract itself stays backward-compatible — confirmed by grep, `App.tsx:1165` is the module's *only* production call site today, and this spec updates that one site regardless, so the default exists as an API-safety guarantee for future callers, not to avoid touching an existing unmigrated one.
- **`Action`'s `closeTerminal` variant** — gains `signalClose: boolean`: `{ kind: "closeTerminal"; replace: boolean; signalClose: boolean }`. `replace` keeps its exact current derivation; `signalClose = !dead`.
- **`App.tsx` Cmd+W wiring (~1162-1170)** — pass `card.dead` as the third arg to `focusedCloseDecide`; gate the `termClose` IPC call on `action.signalClose`. No other line in the Cmd+W block changes: the proactive card removal/replacement, `termBoardIndexRef` bookkeeping, `setSelectedId(null)`, and `schedulePersist` all run exactly as today regardless of `dead`.

### Data Flow

1. User selects a dead term card (already works, per Context) and presses Cmd+W.
2. `App.tsx` computes `otherLive` (unchanged — dead cards were already excluded from this count via `!c.dead`) and now also reads `card.dead`.
3. `focusedCloseDecide("term", otherLive, card.dead)` returns `{ kind: "closeTerminal", replace, signalClose: !card.dead }`.
4. If `action.signalClose` is `true` (card was live), `void termClose(termId)` fires exactly as before. If `false` (card was dead), the daemon call is skipped entirely — no IPC round-trip, no reliance on the daemon's `TermClose`-on-unknown-id no-op.
5. Everything downstream — `replace`-driven fresh-shell spawn or plain removal, `termBoardIndexRef.remove`, `setSelectedId(null)`, `schedulePersist(bid)` — proceeds unconditionally, unchanged from today's behavior. The card leaves the board either way.

### Interface Contract

```ts
// desktop/src/kit/focusedClose.ts
export type Action =
  | "noop"
  | "shelfDoc"
  | { kind: "closeTerminal"; replace: boolean; signalClose: boolean };

/**
 * `dead` (term case only): true when the focused terminal's pty has already
 * exited. When dead, `signalClose` is false — there is nothing live to tell
 * the daemon to close, so the frontend must not depend on `TermClose` being
 * a safe no-op for an already-gone term_id. `replace` is unaffected by `dead`.
 */
export function decide(kind: Kind, otherLiveTerminals: number, dead?: boolean): Action;
```

- `decide("term", otherLive, false)` and `decide("term", otherLive)` (omitted, defaults `false`) behave identically to today's two-arg call, plus `signalClose: true` on the returned object.
- `decide("term", otherLive, true)` returns the same `replace` value as the corresponding non-dead call (replace math is keyed only on `otherLiveTerminals`), with `signalClose: false`.
- `"doc"` and `"none"` cases ignore the third argument.

## Alternatives Considered

### Make the daemon's `TermClose` no-op the documented contract and leave the frontend as-is

Rejected — the daemon behavior is already safe (verified), but the issue specifically asks for the *frontend* to not rely on it. Relying on an internal daemon implementation detail for frontend correctness is a hidden coupling across the wire boundary; a small `kit/` change removes it for near-zero cost.

### Skip the whole Cmd+W block early when `card.dead` is true (return before computing `otherLive`/`action`)

Rejected — this would special-case dead cards outside the routing function, duplicating the `replace` logic's dependency on `otherLive` and making `focusedClose.ts` no longer the single source of truth for "what does Cmd+W do to a term card." Threading `dead` through `decide` keeps the rule pure, unit-tested, and in one place — consistent with how `replace` itself is already computed there rather than inline in `App.tsx`.

### Add a `hasClose`-style ✕ button to `TerminalCard` for dead cards

Out of scope — the issue title scopes this to Cmd+W. `DocCard`'s ✕ affordance is a separate, already-shipped mechanism; adding an equivalent to `TerminalCard` is a different feature, not this fix.

## Acceptance Scenarios

### Happy Path
- **S1:** Given a selected term card with `dead: false` and `otherLive: 0`, when `decide("term", 0, false)` is called, then it returns `{ kind: "closeTerminal", replace: true, signalClose: true }` — identical `replace` to today's behavior, `signalClose` newly `true`.
- **S2:** Given a selected term card with `dead: false` and `otherLive: 2`, when `decide("term", 2, false)` is called, then it returns `{ kind: "closeTerminal", replace: false, signalClose: true }`.

### Edge Cases
- **S3:** Given a selected term card with `dead: true` and `otherLive: 0` (it was the board's last live terminal, and is itself dead), when `decide("term", 0, true)` is called, then it returns `{ kind: "closeTerminal", replace: true, signalClose: false }` — `replace` unaffected by `dead`, `signalClose` is `false`.
- **S4:** Given a selected term card with `dead: true` and `otherLive: 3`, when `decide("term", 3, true)` is called, then it returns `{ kind: "closeTerminal", replace: false, signalClose: false }`.
- **S5:** Given no third argument, when `decide("term", N)` is called for any `N`, then the result matches the `dead: false` case (`signalClose: true`) — pins the default-arg contract itself (there is exactly one production call site, `App.tsx:1165`, and it is updated to pass `card.dead` per this spec; S5 guards the *signature's* backward compatibility for any future two-arg caller, not a currently-unmigrated one).
- **S6:** Given `decide("doc", N, true)` or `decide("none", N, true)` (a `dead` argument nonsensically passed to non-term kinds), when called, then the result is `"shelfDoc"` / `"noop"` respectively, unaffected by the third argument — no regression to the non-term branches.
- **S7 (App.tsx wiring, verified by code review + manual repro, not a unit test):** Given a selected dead term card and Cmd+W is pressed, then `void termClose(termId)` is *not* called (no IPC round-trip for an already-dead pty), while the card is still removed (or replaced with a fresh shell, if it was the last live terminal) exactly as it is for a live card today.
- **S8 (regression guard):** Given a selected *live* term card and Cmd+W is pressed, then `void termClose(termId)` *is* still called (unchanged from current behavior) and the replace/remove logic is byte-for-byte the same as before this change.

## Trade-offs and Limitations

- The `App.tsx` wiring change is verified by code review + manual repro, not an automated test — consistent with this repo's existing App/UI-shell testing gap (see spec `2607.0004`'s identical treatment), not a new gap introduced here.
- The daemon's `TermClose`-on-unknown-id no-op (`core/crates/tarmacd/src/conn.rs` ~272-283) is left completely unchanged — it remains safe and is not being removed as a safety net, it's simply no longer something the frontend's correctness *depends on* for the dead-card path. Live-card Cmd+W still calls `termClose` and still benefits from that no-op for any race where the pty exits between selection and keypress.
- `dead` defaults to `false` in `decide`'s signature specifically so this is a pure additive change to the function's contract — no existing non-term call site needs updating to keep compiling, though `App.tsx`'s one `"term"` call site is updated per this spec regardless.
