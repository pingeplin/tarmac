## Gate

The owner's decisions O4 and O5 of design 2611.0020 bind this spec:

- Front matter is parsed out of the body and shown in a sidebar as key/value rows; a list shows as chips.
- Sidebar option A: front matter on top, the outline below; the current section is marked with the agent accent; a click on an entry scrolls to its heading.
- Drag the inner edge: 160–420, standard 240. Below 160 it collapses to a 30px strip with `{}` and `≡` icons and heading ticks. A double-click on the edge sets 240.
- A wide card: open by default, and it pushes the text, which re-wraps. A 392 card: closed by default; a strip icon slides the panel over the text with no re-wrap.

Review decisions of the design (advisor, 2026-11-21) also bind it: the outline comes from marked's `heading` tokens (A1); overlay width `[min(160, upper), upper]` with `upper = min(420, cardWidth − 30 − 8 − 12)` (A3 as amended); the sidebar scrolls on its own with no bar; the outline keeps element references; field values go in as text; a drag re-wraps live; a collapse keeps the width from before the drag (A3).

## Context

- **Page.** `DocTemplate.html`: `.doc-scroll` (absolute, `inset: 0`, `overflow-y: auto`, scroll bar hidden) > `.doc-prose-sizer` > `.doc-prose-scaler` (`transform: scale(zoom / K)`) > `.doc-prose#prose`. `.doc-prose` is `calc(var(--card-w) * K)` wide; `--card-w` is the card's world width, set by `tarmacDoc.layout(zoom, cardWidth, height)`.
- **Script.** `doc-render.js` defines `tarmacDoc` (`render`, `layout`, `fonts`, `theme`, `scrollTo`) and posts `docScroll`, `docLink`, `docOverLink`, `docEditing`, `docImages`. `doc-layout.js` (slice 1) defines `tarmacDocLayout.render(markdown)` and `textColumns(table)` on its own `marked.Marked` instance, DOM-free, tested in `DocLayoutScriptTests`.
- **Swift.** `DocWebView` reads the file, calls `tarmacDoc.render(markdown)` through `runInCardWorld(_:arguments:)` (`callAsyncJavaScript`, no completion handler today), and `tarmacDoc.layout(...)` from `layoutPage(viewport:)` with `CardBox.cardSize(ofBody:)`.
- **Presses.** The local mouse-down monitor (`AppController+Keys.swift`) calls `handlePress` and returns the event: a press on a doc body selects the card, then reaches the page. A press on a link does not select (`CardPress.link`, from the page's `docOverLink`).
- **Wheel.** With no card selected the board takes every wheel; over the selected card's body the wheel goes to the page.
- **Edges.** A card's resize handle zone is 6 **screen** px inside its outer edge at every zoom (`CardHandles.edgeThickness`); `CardView.hitTest` gives the scroll thumb, then a handle, before the body (`CardHit.at`). The card's scroll thumb is 10 world px wide, 2 world px from the body's right edge (`ScrollIndicator`). `scrollCover` (the thumb track's bottom cover) is 0 for a doc card; a left sidebar does not change it.
- **Scroll units.** `.doc-scroll`'s `scrollTop`, `clientHeight` and `scrollHeight` are screen px (the sizer is not scaled). A world px is `zoom` screen px.
- **marked tokens.** A `heading` token has `depth` (1–6), `text` and inline `tokens`; a setext heading is a `heading` token too. A heading inside a list item or a blockquote is a nested token. `walkTokens` visits tokens in document order. Raw HTML (`<h2>x</h2>`) is an `html` token.
- **Front matter today.** `---\ntitle: x\ntags: [a, b]\n---\n` renders as `<hr>` then one setext `<h2>` that holds both lines (`title: x` and `tags: [a, b]`).
- **Theme tokens on the page** (after slice 1): `--bg1`, `--bg2`, `--line`, `--muted`, `--term-bg`, `--text`, `--prose-text`, `--agent`, `--agent-dim`, `color-scheme`. `Palette` also has `bg3` and `faint`.

## Decisions

### Front matter (`TarmacKit`, `DocFrontMatter`)

- **D1. When a block is front matter.** All of these hold: line 1 is `---` with only spaces after it; a later line is `---` or `...` with only spaces after it (the first such line closes the block); at least one line between them is a key line; and every non-blank line between them is a key line, a `- item` line, a line that starts with a space or a tab, or a line that starts with `#`. A key line starts at column 0 with a key, then `:`, then the end of the line or a space. A key is one or more characters other than `:`; its first character is a Unicode letter, a digit or `_` (so `my key`, `a.b` and `標題` are keys; `- x`, `# x` and `"x"` are not). Line ends are `\n` or `\r\n`; a `\r` before `\n` is not part of a line (Swift: split on Unicode scalars or UTF-8, since `"\r\n"` is one `Character`). Otherwise the markdown is unchanged and there are no fields. Cost: a doc that opens with `---`, a `Note: text` line and `---` is a thematic break and a setext heading today; it becomes the field `Note` (design D8). Prose between two `---` lines is never taken, because a prose line fails the last rule.
- **D2. Fields.** `DocFrontMatter.split(_ markdown: String) -> (fields: [Field], body: String)`, `Field { key: String; value: Value }`, `Value = .text(String) | .list([String])`, all `Equatable` and `Sendable`. In order of the key lines:
  - A value that is empty after the trim (`key:` or `key: ` with trailing spaces) is the same as nothing after `key:`.
  - `key: value` → `.text(value)`, trimmed; one pair of matching surrounding quotes (`"…"` or `'…'`) is removed.
  - `key: [a, b]` (the trimmed value starts with `[` and ends with `]`) → `.list`, split on `,`, each item trimmed and unquoted as above, empty items dropped.
  - `key:` with nothing after it, followed by one or more lines `- item` (any indent) → `.list` of the items, trimmed and unquoted. With no such lines → `.text("")`.
  - Any other non-blank line after a key line (an indented continuation, a nested key, a comment) is trimmed and appended to that field: to a `.text` after a line break `\n` (to an empty `.text` with none), so a nested map shows one line per entry; to a `.list` as one more item, as written (a `- x` line after an inline list is the item `x`; any other line keeps its text). A blank line (only spaces or tabs) is dropped. Any line before the first key line is dropped. A key is trimmed (`key : v` has the key `key`). An item line is optional indent, `-`, then a space or the end of the line; an empty item is dropped. After `key:`, the first non-blank line decides: an item line makes a `.list` (`.list([])` when its items are all empty: no chips), any other non-key line a `.text`; a key line starts the next field.
  - A key that appears twice gives two fields.
- **D3. Body.** The body is the text after the closing line's line end (empty when there is none). `DocWebView` renders the body and passes the fields to the page.

### Sidebar rules (`TarmacKit`, `DocSidebar`)

- **D4. Numbers.** `standard = 240`, `minimum = 160`, `maximum = 420`, `strip = 30`, `grip = 8`, `textMinimum = 392` (`Placement.docSize.width`). All world px.
- **D5. Mode.** `DocSidebar.mode(cardWidth:, hasContent:, stored:, overlayOpen:) -> Mode`, `Mode = .none | .strip | .docked(width) | .overlay(width)`. `Stored { width: Double?; open: Bool? }` (nil = no choice yet).
  - `hasContent` false → `.none`.
  - The card is **wide** when `cardWidth − standard ≥ textMinimum` (632 or more).
  - `DocSidebar.range(cardWidth:) -> ClosedRange<Double>`: wide → `minimum ... min(maximum, cardWidth − textMinimum)`; not wide → `min(minimum, upper) ... upper` with `upper = min(maximum, cardWidth − strip − grip − thumbClear)` and `thumbClear = 12` (`ScrollIndicator.width + inset`), so an overlay's grip stays clear of the card's scroll thumb. `DocSidebar.resizable(cardWidth:)` is true when the range has more than one value (wide, or a card wider than 210); with false there is no grip.
  - Wide: `stored.open ?? true` → `.docked(clamp(stored.width ?? standard, range))`; else `.strip`.
  - Not wide: `overlayOpen` → `.overlay(clamp(stored.width ?? standard, range))`; else `.strip`.
  - `DocSidebar.overlayOpen(_ open: Bool, cardWidth:) -> Bool` is false for a wide card, else `open`: an open overlay is dropped when its card becomes wide, so a card that goes back to narrow shows the strip.
- **D6. The space a mode takes.** `DocSidebar.occupied(_ mode:)`: `.none` 0, `.strip` 30, `.docked(w)` `w + grip`, `.overlay` 30. The text is laid out at `cardWidth − occupied` (the overlay lies over the text and does not change it).
- **D7. Actions.** `DocSidebar.Action = .open | .close | .resize(Double) | .reset`. `DocSidebar.apply(_:, stored:, overlayOpen:, cardWidth:) -> (stored: Stored, overlayOpen: Bool)`:
  - `.open`: wide → `stored.open = true`; not wide → `overlayOpen = true`.
  - `.close`: wide → `stored.open = false`; not wide → `overlayOpen = false`.
  - `.resize(w)` (only reachable when `resizable`, so the range's low end is `minimum`): `w < minimum` → a collapse: the stored width is kept; wide → `stored.open = false`, not wide → `overlayOpen = false`. Else `stored.width = min(w, maximum)`.
  - `.reset`: `stored.width = standard`; wide → `stored.open = true`; not wide → `overlayOpen = true`.
  - A card resized across 632 changes the mode, never `stored`. A clamp in D5 changes the width in use, never `stored.width`.
- **D8. The page's report.** The page posts `docSidebar` with `{action: "open"}`, `{action: "close"}`, `{action: "reset"}` or `{action: "resize", width: <number>}`. `DocSidebar.Action(report: Any)` accepts a dictionary with one of those `action` strings; for `resize`, `width` must be a finite number > 0 (read through `JSONValue`, as `ScrollMetrics(report:)` does, so a Boolean is not a number). Other keys are ignored. Anything else is nil, and nil changes nothing.
- **D8a. The render result.** `DocSidebar.outlineCount(result: Any?) -> Int?`: a dictionary whose `outline` is a whole number ≥ 0 (through `JSONValue`) gives it; anything else, `nil` included, is nil. `DocSidebar.hasContent(fieldCount:, outlineCount:)` is `fieldCount > 0 || outlineCount > 0`.

### Page rules (`doc-layout.js`, DOM-free, JavaScriptCore-tested)

- **D9. Outline.** `tarmacDocLayout.parse(markdown, mark) -> {html, outline}`; `render(markdown)` stays and returns `parse(markdown, "").html`. `outline` is every `heading` token of depth 1–3, in document order (nested ones too), as `{depth, text}`. `text` is the heading's plain text, whitespace collapsed and trimmed: a `text` token gives its `text` with the entities `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&#39;` and numeric `&#N;`/`&#xH;` decoded (other named entities, such as `&copy;`, show as written: accepted); an `escape` or `codespan` token gives its `text` as written (marked keeps them raw); a token with child `tokens` (emphasis, strong, link, del) gives its children's text; `br` gives a space; any other inline token (inline `html`, `image`) gives nothing. When `mark` is not empty, each such heading is rendered with the attribute `data-outline="<mark>-<index>"` (its index in `outline`); no other markup changes. The page passes a new random `mark` each render, so a doc's raw HTML cannot write an attribute the page takes for its own. A raw HTML heading is not in the outline.
- **D10. Current section.** `tarmacDocLayout.currentSection(tops, scrollTop, viewHeight, scrollHeight, zoom) -> index`. `tops` are the headings' tops in the scroller's content, in order; `tops`, `scrollTop`, `viewHeight` and `scrollHeight` are the scroller's (screen) px. `[]` → −1. When the doc scrolls (`scrollHeight > viewHeight + 1`) and the scroller is at its end (`scrollTop + viewHeight ≥ scrollHeight − 1`), the answer is the last index. Otherwise it is the last `i` with `tops[i] ≤ scrollTop + 24 · zoom` (the reading line is 24 world px below the view's top), or 0 when there is none: the first heading is current until one passes the reading line (a doc's first heading sits about 36 world px down, spike of 2026-11-21).
- **D11. Drag.** `tarmacDocLayout.dragWidth(startWidth, deltaScreen, zoom, direction, minWidth, maxWidth) -> {width, collapsed}`. `width = startWidth + direction · deltaScreen / zoom` (`direction` +1 for a sidebar on the left, −1 on the right), then `collapsed = width < minWidth`; when not collapsed, `width = min(width, maxWidth)`. The page passes `minWidth` and `maxWidth` from the last state it was given (D12).

- **D11a. Shown mode.** `tarmacDocLayout.shownMode(state, fieldCount, outlineCount)` is `"none"` when both counts are 0, else `state.mode`.
- **D11b. Geometry.** `tarmacDocLayout.geometry(state, cardWidth, drag)` → `{textWidth, offset, panel}` in world px: `offset` is where `.doc-scroll` starts from the sidebar's side, `panel` the panel's width (0 when none). With `drag` null: `none` → `{cardWidth, 0, 0}`; `strip` → `{cardWidth − strip, strip, 0}`; `docked` → `{cardWidth − width − grip, width + grip, width}`; `overlay` → `{cardWidth − strip, strip, width}`. With `drag = {width, collapsed}` (D11) in `docked`: not collapsed → as `docked` at `drag.width`; collapsed → as `strip`. In `overlay`: the panel is `drag.width`, or 0 when collapsed; the text does not change.
- **D11c. Release.** `tarmacDocLayout.release(moved, drag)` → `null` when not `moved`; `{action: "close"}` when `drag.collapsed`; else `{action: "resize", width: drag.width}`.
- **D11d. Strip.** `tarmacDocLayout.strip(fieldCount, outline, current)` → `{icons, ticks, lit}`: `icons` is `["fields", "outline"]` less `"fields"` when there are no fields and less `"outline"` when the outline is empty; `ticks` the outline indices of depth 1 or 2; `lit` the last tick index ≤ `current`, or −1 (an h3 that is current lights the tick of the heading above it).
- **D11e. Icon click.** `tarmacDocLayout.iconClick(mode, section, icon)` → `{post, section}`: `section` is the panel section the open panel shows (`"fields"` or `"outline"`). In `strip` → `{post: "open", section: icon}`. In `overlay`: `icon == section` → `{post: "close", section}`; else `{post: null, section: icon}` (the panel stays open and scrolls to the other section). In `docked` and `none` (no strip shown) → `{post: null, section}`.
- **D11f. Scroll target.** `tarmacDocLayout.scrollTarget(headingTop, viewHeight, scrollHeight, zoom)` → `clamp(headingTop − 8 · zoom, 0, max(0, scrollHeight − viewHeight))`, all in the scroller's screen px.

### Page wiring (`doc-render.js`, `DocTemplate.html`)

`doc-render.js` builds the elements, forwards events, and takes every decision from D11a–D11f (thin wiring, exception 2, discharged by QA).


- **D12. State to the page.** `state = {mode: "none"|"strip"|"docked"|"overlay", width, occupied, minWidth, maxWidth, resizable, strip, grip, side: "left"}` (world px): `minWidth` is `DocSidebar.minimum`, `maxWidth` the upper end of `DocSidebar.range(cardWidth:)`, `resizable` D5's, and `strip` and `grip` D4's, so the page writes none of these numbers itself. Swift sends it in three calls: `tarmacDoc.layout(zoom, cardWidth, height, state)` (one call per card resize or zoom), `tarmacDoc.render(markdown, fields, state)` and `tarmacDoc.sidebar(state)` (after an action or a render result). In `render`, `state` is computed with `hasContent` true; the page applies it in the same task as the new content. For every state it gets (`layout`, `render`, `sidebar`), the page applies `mode: "none"` instead while its current content has no fields and no outline, so a new card never shows its text at one width and then another, and a layout that lands while a render is pending cannot show a sidebar the content does not have. `DocWebView.hasContent` starts true. Both `layout` and the state set `--text-w` to `cardWidth − occupied`; `.doc-prose` and the wide-block cap use `--text-w` in place of `--card-w`. `:root` declares `--text-w` with the same default as `--card-w`.
- **D13. Structure.** The sidebar is a sibling of `.doc-scroll`, with its own sizer and a scaler (`.doc-side-scaler`) at `scale(zoom / K)`, laid out at K, so a zoom does not re-wrap it. It scrolls on its own (`overflow-y: auto`, no visible bar). `.doc-scroll` starts `occupied · zoom` screen px from the sidebar's side. In `.overlay` the panel lies over `.doc-scroll` after the 30px strip, with a `1px·K` `var(--line)` border on its inner edge (no shadow: the template has no colour literal). After each render the page finds its headings by `data-outline` with that render's `mark` and keeps the element references for D10 and D18.
- **D14. Content.** The sidebar is laid out at K with the Document font: entries and values in `--prose-font` at `0.86 ×` `--prose-size` (12px at 14), keys and the two headers in `--chrome-font` at `0.75 ×` `--prose-size`; so a Document size change re-wraps it with the text, and `tarmacDoc.fonts` re-measures it. A `FRONT MATTER` header and one row per field (key in `faint` mono, value as text; a `.list` as chips on `bg3`), only when there are fields. An `OUTLINE` header and one entry per outline item, indented by depth, only when there is an outline. The entry of the current section has a 2px left border in `--agent` and `--text` colour. Every key, value and entry is written with `textContent`.
- **D15. Strip.** The `{}` icon (only with fields) and the `≡` icon (only with an outline), then one tick per outline item of depth 1 or 2, the current one in `--agent`. The icons and ticks keep at least 6 world px from the card's outer edge, and the ticks end 20 world px above the body's bottom (the card's edge zone is 6 and its corner zone 20 screen px, `CardHandles`). Below zoom 1 these zones can cover part of the strip, and a press there resizes the card. A click on an icon posts `open` (and scrolls the panel to its section); a click on a tick scrolls the doc to that heading.
- **D16. Grip.** In `.docked` and `.overlay`, a `grip`-wide (8 world px) grip on the sidebar's inner edge, `cursor: col-resize`. A press on it starts a drag (the page stops the press from starting a selection); each move calls `dragWidth` and lays the sidebar and, in `.docked`, the text out at that width (text at `cardWidth − width − grip`, `.doc-scroll` from `(width + grip) · zoom` screen px, live re-wrap); a collapsed width shows the strip (in `.docked`, text at `cardWidth − strip`). Spike (2026-11-21, 3000-line doc): a live re-wrap takes a median of 12 ms on a 1280 card and 18–20 ms on an 800 card, so live stays; re-wrap on release is not needed. The release posts `close` when the last move collapsed, else `resize` with the width. A press and release with no move posts nothing. A double-click posts `reset`. Below zoom 0.5 the card's right edge zone (6 screen px) can cover an overlay's grip, which ends 12 world px from the edge.
- **D17. Close.** In `.docked`, a `⇤` button in the `FRONT MATTER` or `OUTLINE` header posts `close`. In `.overlay`, a click on the active strip icon or a press on the text posts `close`.
- **D18. Outline click.** A click on an entry or tick scrolls `.doc-scroll` so the heading's top is 8 world px (`8 · zoom` screen px) below the top of the view (clamped to the scroll range). When the scroll is not clamped and ends more than 1 px above the end, and no later heading starts within 16 world px below it, that heading is then the current section (8 < 24, D10).
- **D19. Render result.** `tarmacDoc.render(markdown, fields, state)` takes `fields` as an array of `[key, value]`, `value` a string (`.text`, shown with its line breaks) or an array of strings (`.list`), and resolves to `{outline: n}`. Swift reads it (`callAsyncJavaScript` completion) with `DocSidebar.outlineCount(result:)` and sets `hasContent` with `DocSidebar.hasContent`; a nil count changes nothing. A render that a later render replaced resolves to no object. That result, and a result for a read that is not the latest, change nothing.
- **D20. Tokens.** `ThemeCSS.properties` adds `--bg3` and `--faint` after `--muted`.

### Swift wiring (`DocWebView`)

- **D21. Owner.** `CardView` holds the card's `DocSidebar.Stored` (the one copy): `DocWebView` reads it through `stored: () -> DocSidebar.Stored` and writes it through `onStoredChanged: (DocSidebar.Stored) -> Void`, both set by `CardView` when it makes the body (it is never rebuilt by a cull, a board switch or a reconnect, and slice 3's `sendLayout` and `landDocCard` read and seed the card there). `DocWebView` holds `overlayOpen` and `hasContent`, splits the front matter in its read, computes the state with `DocSidebar` and the card width of `layoutPage`, and sends it (D12); it re-sends it in `didFinish` after a page load (a web process that ended loses the page, not these properties). A `docSidebar` message from the main frame goes through `DocSidebar.Action(report:)` and `apply`; the new `Stored` goes to `CardView` through a callback, and the state is sent again. `DocWebView` sets `overlayOpen` through `DocSidebar.overlayOpen(_:cardWidth:)` on every layout.

## Out of scope

- Persisting `stored` (slice 3, #445). The right side and the Settings pane (slice 4, #446); `side` is always `"left"` here and `direction` +1.
- A front matter `title` shown as a heading. A full YAML parser.
- Keyboard control of the sidebar.

## Acceptance scenarios

### Front matter (`DocFrontMatterTests`)

- **S1 (basic)** [auto]: `"---\ntitle: Hello\nstatus: proposed\n---\n# Body\n"` → fields `[title: .text("Hello"), status: .text("proposed")]`, body `"# Body\n"`.
- **S2 (quotes)** [auto]: `title: "A: b"` → `.text("A: b")`; `x: 'y'` → `.text("y")`; `x: "y'` → `.text("\"y'")`.
- **S3 (inline list)** [auto]: `tags: [mcp, "api", , release-2]` → `.list(["mcp", "api", "release-2"])`.
- **S4 (block list)** [auto]: `tags:\n  - a\n  - "b"\nnext: 1` → `tags: .list(["a", "b"])`, `next: .text("1")`; `empty:` then `other: 2` → `empty: .text("")`; `tags: [a]\n  - b\n  c` → `.list(["a", "b", "c"])`; `key:\n  -\nx: 1` → `key: .list([])`, `x: .text("1")`; `tags: \n- a` (a space after the colon) → `tags: .list(["a"])`.
- **S5 (other lines)** [auto]: `desc: one\n  two\n# note\nx: 1` → `desc: .text("one\ntwo\n# note")`, `x: .text("1")`; `metadata:\n  type: project\n  originSessionId: abc` → `metadata: .text("type: project\noriginSessionId: abc")`; a `#` line before the first key is dropped; a blank line is dropped; `key:\n  text` → `key: .text("text")`; `a: 1\na: 2` → two fields `a`, in order.
- **S6 (not front matter → unchanged)** [auto]: `"---\n\nSome text\n\n---\nmore"` (no key line) and `"---\nSome prose here.\nNote: x\n---\nmore"` (a prose line) → no fields, body equals the input.
- **S7 (no closing line → unchanged)** [auto]: `"---\ntitle: x\n# Heading"` → no fields, body equals the input.
- **S8 (CRLF and `...`)** [auto]: `"---\r\ntitle: x\r\n...\r\nbody"` → `title: .text("x")`, body `"body"`.
- **S9 (fence spaces)** [auto]: `"---  \ntitle: x\n---  \nbody"` → `title`, body `"body"`; `" ---\ntitle: x\n---\n"` (space before) → unchanged.
- **S10 (setext cost)** [auto]: `"---\nNote: text\n---\nbody"` → `Note: .text("text")`, body `"body"` (design D8's stated cost).
- **S11 (key shape)** [auto]: `"---\nkey:value\n---\n"` → unchanged (no space after `:`); `my_key-2: v`, `my key: v`, `a.b: v` and `標題: v` → one field each; `"x": v` → unchanged.
- **S12 (empty doc / first line only / closing at the end)** [auto]: `""` and `"---"` → unchanged; `"---\ntitle: x\n---"` (no line end after the closing line) → `title: .text("x")`, body `""`.

### Sidebar rules (`DocSidebarTests`)

Unless a scenario says otherwise: "wide" is card 1280, "narrow" is card 392, stored is `{nil, nil}` and `overlayOpen` is false.

- **S13 (none)** [auto]: `hasContent` false → `.none` at cards 160, 392, 632 and 1280, with stored `{300, true}` and `overlayOpen` true too.
- **S14 (wide threshold)** [auto]: card 632 → `.docked(240)`; card 631 → `.strip`.
- **S15 (docked clamp and range)** [auto]: card 700, stored width 400 → `.docked(308)`; card 1280, stored 400 → `.docked(400)`; card 1280, stored 100 → `.docked(160)`. `range(632)` = `160...240`, `range(1280)` = `160...420`.
- **S16 (closed wide)** [auto]: card 1280, stored `{nil, false}` → `.strip`.
- **S17 (overlay and range)** [auto]: `overlayOpen` true: card 392 → `.overlay(240)`; card 392, stored width 420 → `.overlay(342)`; card 160 → `.overlay(110)`. ### Live (QA, `make run`)

The QA doc has YAML front matter (`title`, `status`, `date`, `tags: [a, b, c]`, a block list, `note: <b>bold</b>`), h1, five h2 with h3 under two of them, a code block holding `# not a heading`, a raw `<h2>`, and enough text to scroll. A second doc has no front matter and no heading.

`tarmac dev` sets the zoom (`zoom`) and the card size (`resize`), selects (`focus <doc>`) or clears the selection (`focus board`), and reads `scroll` and `focused_card` (`snapshot`). A press, drag, click or wheel at a point is a HID event from `swift scripts/qa/wheel-gesture.swift <card id> --at <x>,<y> …`, with `x,y` in screen points from the card body's top-left: `--events 0` for no wheel, `--press`, `--drag <dx>,<dy>` with `--steps`, `--release`, and `--clicks 2` (only with `--press --release` and no `--drag`). A press can be held across calls, for a capture mid-drag. The dev window must be key for a press to select (run `tarmac dev focus board` first in S36 and S44). No `tarmac dev` verb reads the sidebar, so its mode, width and marked entry, and positions in the text, come from screen captures, in world px (screen px / zoom), ±2.

## Risks

- **Press routing** (S36): the spike showed that it works. If it regresses, `CardPress` gets a `.docControl` place reported by the page (as `.link` is), and a grip press then does not select the card.
- **Slow page**: a page that takes long frames applies the drag's moves late, not never (spike). A first render of a 3000-line doc takes about 2 s today, with or without the sidebar.
