## Gate

The owner's decision O6 binds this spec:

- A new Settings pane "Documents", after Fonts and Theme. Its icon is an SF Symbol, as on the other panes.
- Group "Markdown cards". Row "Sidebar side". Two clickable picture tiles, "Left" and "Right". The selected tile has a blue border.
- Help text: "The sidebar holds the front matter and the outline."
- Standard: Left. Stored in `app-prefs.json`.
- A change moves the sidebar of every open markdown card at once. Each card keeps its width and its open state.
- UI copy is English only.

The approved mockup is board `SettingsSide`, option 2. This spec describes the tiles from O6 only.

Design D14 also binds: on the Right, sidebar content keeps 12 px clear of the card's outer edge, where the card's scroll thumb is.

## Decisions

### Preference (`TarmacKit`)

- **D1. Type.** `DocSidebar.Side: String, CaseIterable, Sendable { case left, right }`, in this order, with `title` `"Left"` and `"Right"`. It sits in `DocSidebar` because the sidebar's rules own it; `AppPrefs` and the page both use it.
- **D2. Value.** `AppPrefs.Values.docSidebarSide: DocSidebar.Side`, last in the initializer, `= .left`. No existing call site changes.
- **D3. Key.** `doc_sidebar_side` (design D17), snake case as the other keys. `encode` writes `,"doc_sidebar_side":"right"` **after** `inbox_preview_height`, only for `.right`. So a file with no choice keeps its bytes, and no existing bytes test changes. `testS15TheHeightIsWrittenLastAndReadsBack` still passes (it has no side) but its name is then wrong: rename it `testS15TheHeightIsWrittenAfterTheThemesAndReadsBack` (a rename, no assertion change).
- **D4. Read.** `decode` reads the key as a string: `DocSidebar.Side(rawValue:) ?? .left`. So `"left"` is Left (and is not written back), and anything else is Left: another string, another type, `null`, no key, a damaged file. A bad value changes no other key, as for `theme`.

### Page state (`TarmacKit`, `DocSidebar`)

- **D5. Side in the state.** `PageState` gets `side: Side` (initializer default `.left`). `pageState(cardWidth:stored:overlayOpen:side:)` gets `side` last, default `.left`, and copies it. `arguments` sends `"side": side.rawValue` and a new key `"thumbClear": thumbClear` (12). The page then writes no clearance number of its own (2611.0022 D12's rule).
- **D6. Width and open state do not depend on the side.** `mode`, `range`, `apply` and `Stored` take no side. `pageState` for `.right` equals the one for `.left` in every field but `side` (S6). This is what keeps each card's width and open state on a change (O6). The overlay's upper end `cardWidth − 30 − 8 − 12` stays: on the Right the overlay's grip then ends 12 px from the card's **left** edge, clear of the 6 px left edge zone at zoom 0.5 and up.
- **D7. Changed assertion.** `test2611_0022D12ThePageState`'s arguments dictionary gains `"thumbClear": 12`. Its other lines stay, by the defaults of D5.

### Page rules (`doc-layout.js`, JavaScriptCore-tested)

- **D8. Side name.** `tarmacDocLayout.side(state)` is `"right"` when `state` is an object whose `side` is exactly `"right"`, else `"left"`. `direction(side)` stays as it is (+1 left, −1 right): a drag on the Right grows the sidebar to the left. The page uses `side(state)` for the attribute (D10) and for the drag.
- **D9. Panel start.** `parts` returns `panelStart` in place of `panelLeft`: the panel's start, measured from the sidebar's outer edge (`state.strip` in `overlay`, else 0). A rename only: the value does not change. `geometry`'s `offset` is measured the same way, so `geometry` needs no side. Changed assertion: the key name in `test2611_0022TheSidebarsParts`'s `box` helper.

### Page wiring (`doc-render.js`, `DocTemplate.html`)

Thin wiring and presentation (exceptions 2 and 1, discharged by QA S12–S21). The template rules have `DocTemplateTests` (S9).

- **D10. Attribute and lengths.** `applySide` sets `data-sidebar-side` to `side(state)` on `document.documentElement`, and `--side-thumb-clear` to `state.thumbClear` px, and `--side-panel-start` (renamed from `--side-panel-left`) to `parts.panelStart` px. `data-side` keeps the mode. Before the first state the attribute is absent and the left rules apply.
- **D11. Mirrored places.** Under `:root[data-sidebar-side="right"]` the template mirrors each left place of *Context*. Each mirrored rule sets only the properties named here, never a `background` shorthand: a shorthand under this selector would outrank `[data-side="overlay"] .doc-side-grip { background: none; }` and draw a hairline on a right overlay.
  - `.doc-scroll`: `left: 0; right: calc(var(--side-offset) * var(--zoom))`.
  - `.doc-side-strip`: `left: auto; right: 0`.
  - `.doc-side-panel`: `left: auto; right: calc(var(--side-panel-start) * var(--zoom))`.
  - overlay panel border: `border-right: 0; border-left: calc(1px * var(--zoom)) solid var(--line)`.
  - `.doc-side-grip`: `left: auto; right: calc((var(--side-panel-start) + var(--side-panel)) * var(--zoom)); background-position: 100% 0`, so the hairline is beside the panel.
  - The panel's content stays left to right; the entries keep their left indent and left mark.
- **D12. Clear of the thumb (design D14).** Under the same selector:
  - `.doc-strip`: `padding-right: calc(var(--side-thumb-clear) * var(--oversample-k))`. The strip stays 30 wide (a wider strip would change the text width, against D6). Its icons and ticks are centred in the inner 18 px: icons 12–30 px from the outer edge, ticks 14–28 (h1) and 16.5–25.5 (h2).
  - `.doc-side-content`: `padding-right: calc(var(--side-thumb-clear) * var(--oversample-k))`. It equals today's 12, so nothing moves; the rule ties the clearance to the thumb.
  - The thumb is not moved: it is the card's, on every card kind (2610.0003). On the Right it shows over the sidebar's outer 12 px while it shows.
- **D13. Close mark.** `.doc-side-close` on the Right has `transform: scaleX(-1)`, so `⇤` shows as `⇥`, pointing at the edge it closes to. The button keeps its place at the end of the header, 12 px from the outer edge (D12).
- **D14. A change of side.** A new state with another side changes only the attribute: no text width changes (D6), so no line re-wraps; the scroll position and the current section stay. The page needs no new entry point: `tarmacDoc.sidebar(state)` takes it.

### App: setting and broadcast (`TarmacApp`)

Thin wiring (exception 2), discharged by QA.

- **D15. Owner.** A new `DocumentSettings` (`TarmacApp/DocumentSettings.swift`), in the shape of `FontSettings`: `init(prefs:)` resolves `Theme.docSidebarSide` from `prefs.values.docSidebarSide`; `var side`; `choose(_ side:)` returns for the side already chosen, else `prefs.update { $0.docSidebarSide = side }`, resolves, and calls `onChange`. `Theme` gets `static var docSidebarSide: DocSidebar.Side = .left`, "as `DocumentSettings` last resolved it", beside `fontFamilies`. The side is read at the time a state is built, so a card made after a change (a new open, a board built later, a page reload) gets it with no broadcast.
- **D16. Broadcast.** `protocol DocSidebarSideFollowing: NSView { func docSidebarSideChanged() }` and `NSView.broadcastDocSidebarSideChanged()`, in `TarmacApp/DocSidebarSideFollowing.swift`, in the shape of `ThemeFollowing` (design D19). `AppController.init` gets `documents: DocumentSettings` and sets `documents.onChange` to `tellEveryView { $0.broadcastDocSidebarSideChanged() }`, as `themeChanged` does. So every open markdown card is told, on mounted and unmounted boards, culled or not.
- **D17. Card.** `DocWebView` conforms. `sidebarState()` passes `side: Theme.docSidebarSide`. `docSidebarSideChanged()` sends `tarmacDoc.sidebar(state)` when `pageLoaded`; a page not loaded yet gets the side in `didFinish`. The one send is shared with `sidebarReported`. `stored` and `overlayOpen` are not touched: an open overlay stays open on the other side.
- **D18. Launch order.** `AppDelegate` makes `DocumentSettings(prefs:)` after `ThemeSettings` and before `RootView`, so no card exists before the side is resolved. It passes it to `AppController` and `SettingsWindowController`.

### App: the pane (`TarmacKit` + `TarmacApp`)

- **D19. Pane case.** `SettingsPane.documents` after `theme`, title `"Documents"`. Changed assertion: `testS19ThePanesAreFontsThenThemeAndTitled` now pins `[.fonts, .theme, .documents]` and `["Fonts", "Theme", "Documents"]` (its name keeps "FontsThenTheme"; renamed to `testS19ThePanesInOrderAndTitled`).
- **D20. Icon.** `SettingsSidebar.symbol(of: .documents)` is `doc.text` (design D18). Presentation.
- **D21. Pane.** `DocumentsPane` (`TarmacApp/DocumentsPane.swift`), in the shape of `ThemePane`: a group title `"Markdown cards"`, then a `SettingsGroup.box` with one row, `"Sidebar side"`, whose control is the row of the two tiles (spacing 8) over the help text `"The sidebar holds the front matter and the outline."` (`smallSystemFontSize`, `secondaryLabelColor`). A press of a tile calls `documents.choose(side)` and sets each tile's `state`. `reload()` sets the tiles' states when the window opens. `SettingsWindowController` gets `init(fonts:theme:documents:)` and the new case in `view(of:)` and `show`.
- **D22. Group title.** `SettingsGroup.titled(_ title: String, _ box: NSView) -> NSView`: a label in `.boldSystemFont(ofSize: NSFont.systemFontSize)` over the box, spacing 6, both full width. Only the Documents pane uses it. Presentation.
- **D23. Tiles.** The shared parts of `ThemeTile` move into `PictureTile` (`TarmacApp/PictureTile.swift`): `button(title:)` (the radio button, image above, title under it, bold when on, AX role radio button with no subrole) and `image(selected:draw:)` (the 66 × 44 picture with its ring room, and the 2.5 px ring in `controlAccentColor` when selected). `ThemeTile` keeps its card drawing and calls `PictureTile`; its images must not change (S22). `DocSideTile` draws a card schematic: a header band, a sidebar band 18 px wide on its side with three short lines, and four text lines in the rest. It uses system colours only (`separatorColor`, `tertiaryLabelColor`, `quaternaryLabelColor`) and nothing from the theme. **Assumption, not verified:** an `NSImage` drawn by a handler in dynamic system colours follows the window's appearance (which follows the theme's variant) with no redraw. S22 checks it. If it does not, `DocumentsPane.reload()` draws the pictures again when the window opens, and `DocumentSettings` gets no theme hook. Presentation.
- **D24. The ring is the accent colour.** O6 says "blue border"; the Theme tiles' ring is `controlAccentColor`, which is blue unless the user chose another accent in macOS. This spec uses the accent, as the Theme pane does, so the window has one look.

### QA script (exception 3)

- **D25. Verb.** `settings-window.swift` gets `side <Left|Right>`: it presses that tile of the Documents pane and prints `tile <title> value=<0|1>`, as `theme` does; with no such tile it fails with "run `pane Documents`". The header's `pane` line lists `Fonts, Theme, Documents`, and a line for `side` is added. `rows` needs no change: it prints the two tiles and the labels.

## Out of scope

- Moving the card's scroll thumb to the text's edge when the sidebar is on the Right (D12).
- A per-card side. A side for HTML cards. Right-to-left text in the panel.
- Keyboard control of the tiles beyond what a radio `NSButton` gives.
- A `tarmac dev` verb that reads the sidebar or the side.
