- **R1.** The record lives in a per-board `term_records` table, not in the tiles. It moves to a new term id through `SpawnTerm.succeeds`.
- **Q1.** A cold spawn still mints a new term id. The "never reuse a persisted id" rule stays.
- **Efficiency (from `/simplify`).** The cwd is read only when the foreground pid changes, and once at shutdown. A cwd change never marks the state dirty. Nothing records the process name.
- **2026-11-14, at this spec's gate:**
  - **OQ2 = (a).** ⌘W on a dead card still sends no `TermClose` in this slice. A dead card's entry stays until slice 4.
  - **The rollback growth is accepted.** An older app leaves entries under old ids during a rollback.
  - **The reviewer's rules are accepted:**
    - `succeeds` looks only in the new term's board (S20).
    - A late cwd read after a close, an exit or a board delete stores nothing (S23).
    - `TermClose` deletes the entry whether or not the term is live, in whichever board holds it (S26).

## Context

What the code does today (64708b6):

- **Persistence.** A board persists `docs`, `tiles` and `board`. Each is a `PersistedBoard` in `core/crates/tarmacd/src/persist.rs`. A terminal tile has `x, y, w, h, z, term_id` and no cwd.
- **`Layout` replaces tiles.** `Layout` (app→daemon) replaces a board's tiles wholesale: `conn.rs` `Msg::Layout` → `Registry::apply_layout` → `set_tiles` in `boards.rs`. The app builds the tiles from its own cards (`LayoutTiles.build`) and leaves dead cards out.
- **Restore mints new ids.** `BoardRestore.plan` (`app/Sources/TarmacKit/BoardRestore.swift`) gives each tile that is not in `live_terms` a freshly minted id. It also keeps `restoredID[persisted] = new`, which doc owners use.
- **The spawn sends no cwd.** `AppController.spawn` (`AppController+Terminals.swift`) sends `SpawnTerm { cwd: nil, cmd: nil, inherit_cwd_from }`.
- **`spawn_cwd` checks the cwd.** `spawn_cwd` (`conn.rs`) checks a given `cwd` through the gate. A path that is not a directory, or a check that does not answer in time, falls back to `$HOME` with no error.
- **The process poll.** `proc_name_loop` (`term.rs`) ticks every 750 ms. It reads `handle.foreground_pid()` and `proc::process_name`, and pushes `TermProc` when the *name* changes. It never marks the state dirty. The loop starts in `term::spawn` (`term.rs:193`), before `spawn_term` puts the term in `term_boards` (`conn.rs:422-425`), and its first tick fires at once.
- **The foreground pid.** `foreground_pid()` is the leader of the pty's foreground process group (`term.rs:89-94`). A shell with job control (the default `$SHELL -il`) gives each command its own group, so the pid changes when a command starts and again when the prompt comes back. The plain shells in the scenarios below run builtins only (`read`, `cd`, `echo`, `exit`), so their foreground pid does not change.
- **The cwd read.** `PathGate::pid_cwd(pid)` (`reader.rs`) is a gated `proc_pidinfo` read on a blocking thread, with a 1 s limit.
- **Shutdown.** The SIGHUP/SIGTERM/SIGINT task in `tarmacd/src/main.rs` removes the socket and calls `process::exit(0)`. It does not save first.
- **The app's restart wait.** On a version mismatch the app SIGTERMs the daemon and waits up to `restartWaitBudget` (2 s, `DaemonClient.swift`) for the socket to go.
- **Term exit.** At exit the pump (`term.rs`) removes the term from `terms` and `term_boards`, then pushes `Exit { code }`. `code: None` means a signal death. `TermClose` SIGHUPs the process group. A `TermClose` for a term that is not live does nothing today (`conn.rs:270-273`).
- **Closing a dead card.** A failed exit holds the card open dead, and a dead card is never in a `Layout` (`AppController+Terminals.swift:273-285`, `LayoutTiles.build`). ⌘W on a dead card sends no `TermClose` (`FocusedClose.swift:30-42`, `AppController+Terminals.swift:310`).
- **The save loop.** `mark_dirty` wakes `save_loop` (`persist.rs:182-194`), which waits 150 ms and then writes through `write_atomic`, always to the same `state.json.tmp` (`persist.rs:172`). An app connect to a board with no docs does not mark the state dirty. A `BoardSwitch` does (`conn.rs:299-304`).
- **The test harness.** `TestDaemon::restart` sends SIGKILL (`tests/common/mod.rs:89-95`). `signal_and_wait` sends a given signal. The harness `Restore` struct destructures `Msg::Restore` field by field, and `Spawn` has no `succeeds` (`tests/common/mod.rs:303-359`), so both need the new key. `make kill-daemon` also sends SIGKILL (`Makefile:117`).
- **Conformance vectors.** They are V1–V17 (`docs/protocol.md` § Conformance vectors, `tarmac-protocol/src/tests.rs`, `app/Tests/TarmacKitTests/ConformanceTests.swift`, `RustEncoderParityTests.swift`).

## Motivation

A version-mismatch restart (each `brew upgrade`) kills every terminal. Each card comes back at its frame, but its shell opens in `$HOME`. The user must `cd` back in each card. This slice restores the folder. It also builds the `term_records` table that slice 4 (resume) builds on.

## Proposed Solution

### Overview

The daemon keeps, for each board, a table `term_records: { term_id → { last_cwd } }`.

- **Recording.** The daemon fills the table from cwd reads. It reads when a terminal's foreground pid changes, and once more at shutdown.
- **Saving.** It saves the table in `state.json` beside `tiles`. `Layout` never touches it.
- **Restore.** `Restore` carries the table.
- **Spawn.** On a first-visit cold spawn, the app sends the persisted `last_cwd` as `SpawnTerm.cwd`, and the persisted id as `SpawnTerm.succeeds`. The daemon moves the entry to the new id.

### Key Components

- **`TermRecord`** (`tarmac-protocol`) — `{ last_cwd: Option<String> }`, with `last_cwd` omitted when nil. It is a struct, so slice 4 can add `resume` with no new type.
- **`Registry.term_records`** (`tarmacd/src/boards.rs`) — `HashMap<String, TermRecord>` on each board. `apply_layout` and `set_tiles` leave it unchanged.
- **`PersistedBoard.term_records`** (`persist.rs`) — `#[serde(default, skip_serializing_if = "HashMap::is_empty")]`. A file with no key loads as empty.
- **Cwd recording** (`term.rs`, beside `proc_name_loop`). When the foreground pid differs from the last tick's pid, including the first pid seen:
  - The daemon reads `pid_cwd` through the gate.
  - If the read gives a path, the daemon stores it as the term's `last_cwd` in the record of the term's board (`term_boards`).
  - A read that is out, or that gives `None`, keeps the old value.
  - **It does not call `mark_dirty`.**
  - The `TermProc` push stays keyed on the name, as today.
  - **A late read stores nothing.** A read that returns after the term's entry was deleted (`TermClose`, or an exit with `code: Some(0)`), or after the term left `terms`, or after its board was deleted, does not create the entry again. It never stores in another board's table (`registry_mut` falls back to the active board for an unknown id, `boards.rs:433-440`).
  - The read of the first pid seen must land in the term's own board, though the first tick can come before `spawn_term` sets `term_boards` (see *Context*). A term that has run no command yet still gets its spawn folder recorded (S2 checks this).
- **Shutdown save** (`main.rs` signal task). Before it unlinks the socket, the task does two things:
  - It reads `pid_cwd` for every live terminal, concurrently. All the reads share one deadline: `SHUTDOWN_CWD_BUDGET` = 500 ms. A read that misses the deadline keeps the old value.
  - It writes `state.json` once, through the existing atomic write. Then it unlinks the socket and exits.

  The whole sequence fits inside the app's 2 s wait. The shutdown write is the last write: no `save_loop` write runs at the same time as it (both use `state.json.tmp`) or after it. The same sequence runs for SIGTERM, SIGHUP and SIGINT.
- **Entry lifetime** (daemon).
  - `TermClose { term_id }` deletes the entry, as soon as the message arrives, and marks the state dirty. This holds whether or not the term is live (design §4, *Deleting*: a `TermClose` deletes an entry that no tile names). A term that is not live has no `term_boards` entry, so the daemon deletes the key from whichever board's table holds it (term ids are unique, so at most one does). A `TermClose` for an id with no entry changes nothing and saves nothing. The app sends no `TermClose` for a dead card in this slice (OQ2 = a).
  - An exit with `code: Some(0)` deletes the entry and marks the state dirty.
  - An exit that is non-zero or a signal death keeps the entry, because the card is held dead.
  - A `SpawnTerm` with `succeeds: Some(old)` moves `old`'s entry to the new `term_id` when the spawn succeeds, and marks the state dirty. The daemon looks for `old` only in the table of the new term's board. An entry for `old` on another board is not moved.
  - A deleted board takes its table with it.
- **`Restore.term_records`** — the daemon fills it from the board's table. The key is omitted when the table is empty.
- **`BoardRestore.plan`** (`TarmacKit`) — it takes the restore's `term_records`. Each cold-spawned `Term` gets two values:
  - `spawnCwd = term_records[persisted]?.lastCwd`;
  - `succeeds = persisted`.

  A rebound term gets neither. A legacy tile with no `term_id` gets neither, and so does the one terminal that `plan` adds to a board with no term tile.
- **`AppController.spawn`** — it sends `cwd: s.spawnCwd` and `succeeds: s.succeeds`. This is wiring only: the decision is in `BoardRestore`.

### Data Flow

1. **Recording.** A command starts in terminal T, so the foreground pid changes. The daemon reads that pid's cwd and stores `term_records[T].last_cwd`. Nothing is saved yet.
2. **Saving.** A later change (a `Layout`, a doc open) saves `state.json` with the table. A SIGTERM also saves it, after one more cwd read of each live terminal.
3. **Restore.** A new daemon loads the table. The app's first-visit restore of that board receives `Restore { tiles, term_records, live_terms: [] }`.
4. **Spawn.** `BoardRestore.plan` mints T′ for the tile of T. The app sends `SpawnTerm { term_id: T′, cwd: last_cwd(T), succeeds: T }`.
5. **Move.** The daemon spawns in that cwd (or `$HOME`, as today) and moves T's entry to T′. The next `Layout` names T′.

### Interface Contract

Additive only. A missing key decodes as empty or nil on both sides, and both codecs ignore unknown keys.

```
TermRecord      { last_cwd?: str }                       // map, string keys
restore         { …existing…, term_records?: { <term_id>: TermRecord } }   // omitted when empty
spawn_term      { …existing…, succeeds?: str }            // omitted when nil
state.json      boards[i].term_records?: { <term_id>: { last_cwd?: str } }
```

- **`succeeds` is ignored** when it names a term that is live, or that has no entry, or when the spawn fails. It is never an error.
- **Encoding.** An empty `term_records` and a nil `succeeds` are omitted (no key), and so is a nil `last_cwd`. `SpawnTerm.cwd` and `cmd` keep today's encoding: they have no skip attribute, so a nil is written as msgpack nil (`lib.rs:93-94`).
- **New conformance vectors.** No existing vector covers `restore` or `spawn_term`, so each vector gives the whole frame. The hex is the bytes of `rmp_serde::to_vec_named`, in the key order it writes.
  - **V18:** `{t:"restore", docs:[], tiles:[], term_records:{"t1":{last_cwd:"/w"}}}`. `docs` is required and `tiles` is always written (`lib.rs:75-77`). `board`, `board_id` and `live_terms` are omitted.
  - **V19:** `{t:"spawn_term", term_id:"t1", cols:80, rows:24, cwd:nil, cmd:nil, succeeds:"t0"}`. `board_id` and `inherit_cwd_from` are omitted.
  - Both codecs decode them, and both round-trip them. The Swift encoder matches Rust's bytes (`RustEncoderParityTests`). V1–V17 do not change.
- **Docs.**
  - `docs/protocol.md` gets a section for the two keys, and V18–V19.
  - `docs/architecture.md` gets updates in *Persistence*, *Layout persistence*, *Restore and reconnect* and *What survives what*. The row "Daemon restart → a freshly launched app cold-spawns new shells" becomes "…in their last folder".

## Alternatives Considered

- **Reuse the persisted term id.** This was rejected in Q1. It needs guards against a late `Exit` from the old pty, and against survivors that still hold the old `TARMAC_TERM_ID`. It also merges "slot" with "shell instance".
- **Put `last_cwd` on `Tile`.** This was rejected in R1. `Layout` replaces tiles wholesale, so the next `Layout` would drop the value.
- **Read the cwd on every 750 ms tick.** This was rejected (`/simplify`). It runs a gated `proc_pidinfo` on a blocking thread every tick for each terminal, even while the user is idle.

## Migration & Rollback

- **Migration.** None. An old `state.json` has no `term_records` and loads as empty. Terminals restore in `$HOME` once, and record from then on.
- **Rollback.**
  - An older daemon reading a new `state.json` ignores `term_records`, because `PersistedBoard` does not deny unknown keys. Its next save drops the key. That loses the record, but no other data.
  - An older app ignores `Restore.term_records`. It sends no `succeeds`, so the entries stay under the old ids until a `TermClose` or a clean exit names them. Nothing breaks. The owner accepted this growth on 2026-11-14.

## Security Considerations

The table holds directory paths that the user's shells already had. It goes only to `state.json` and to the app over the daemon socket. The daemon sets no file mode on either (`write_atomic` uses `File::create`, `persist.rs:172-173`), and this slice changes neither. It adds no new reader. No new input reaches a shell: `SpawnTerm.cwd` already exists and is gate-checked.

## Acceptance Scenarios

The daemon scenarios are integration tests in `core/crates/tarmacd/tests/` (new suite `folder_restore_integration.rs`), on the `common` harness: a pinned `TARMAC_SOCKET`/`TARMAC_STATE` temp dir, `spawn_daemon`, `signal_and_wait`. The exceptions are marked "unit": they need a fixture `PathFs`, so they run in-process on `Daemon::with_fs`, in `core/crates/tarmacd/src/state/tests/` (`with_fs` is private to `state`, `state.rs:97`). The app scenarios are `TarmacKitTests`. A scenario that needs a cwd uses a temp dir made by the test.

Terms used below:

- **A probe** is a new app connection (`connect_app`) to a board with no docs. Its `Restore` shows the table in memory, and it causes no save (see *Context*, *The save loop*). A test that waits for a value polls with new probes up to a deadline. A new app connection replaces the old one and cancels it (`install_app`, `state.rs:374-390`), so after a probe the test sends and reads on the newest connection.
- **Paths** A, B, D and H are canonical (`std::fs::canonicalize`, as `term_cwd_inherit_integration.rs:14` does): `pid_cwd` and `pwd` give resolved paths, and a temp dir under `/var` resolves to `/private/var`.
- **A seeded state** is a `state.json` that the test writes before the daemon starts. The harness needs a way to do this (today `TestDaemon::start` makes its temp dir itself).
- **A saved check** is `wait_for_state` on `state.json` with no `Layout` or other save trigger sent after the action. It shows that the action itself marked the state dirty.
- **A job-control shell** is a shell with job control and no rc files, so each command gets its own foreground process group. Which shell does this reliably in the harness pty is not verified yet (OQ1). Each test that needs one first asserts the precondition: a `TermProc` for T with a `pid` that differs from T's first `TermProc` pid.
- **A plain shell** is `/bin/sh -c "read _; …"`, as in `term_cwd_inherit_integration.rs:17-29`. Its foreground pid does not change.

### Happy Path

- **S1 (recorded on a command, with no shutdown):**
  - Given a job-control shell T spawned in temp dir A on board-0, and a probe shows `term_records[T].last_cwd == A`,
  - when it runs `cd B && sleep 3`, and a `TermProc { name: "sleep" }` for T arrives with a new pid,
  - then, with no signal sent to the daemon, a probe's `Restore` for board-0 has `term_records[T].last_cwd == B`.
  - (A SIGTERM-based check would pass on the shutdown read alone, so it does not test this rule.)
- **S2 (idle `cd` caught at shutdown):**
  - Given a plain shell T spawned in A that runs `read _; cd B && echo MOVED; read _`, and a probe shows `term_records[T].last_cwd == A` (the first pid seen),
  - when the test sends a line, waits for `MOVED`, and then sends SIGTERM (`signal_and_wait`),
  - then the daemon exits with status 0, and the next daemon's `Restore` has `term_records[T].last_cwd == B`.
  - The entry in `state.json` has the key `last_cwd` and no other key (no process name).
- **S3 (`succeeds` moves the entry):**
  - Given a seeded state with `term_records[T] = {last_cwd: B}` on board-0, and no live T,
  - when the test sends `SpawnTerm { term_id: T′, cwd: B, succeeds: T }` with a plain shell that prints `pwd`,
  - then the shell of T′ prints B, a probe's `Restore` has key T′ and no key T, and a saved check shows the same.
  - "Key T′" alone does not prove the move, because the first read of T′ records B too. "No key T" is the check that fails without the move. S25 checks the moved value.
- **S4 (the plan carries cwd and `succeeds`; TarmacKit):**
  - Given a `Restore` with a term tile T, `term_records[T].lastCwd = "/w"` and empty `live_terms`,
  - when `BoardRestore.plan` runs with a mint that returns T′,
  - then the planned term T′ has `needsSpawn`, `spawnCwd == "/w"` and `succeeds == T`.
- **S5 (wire):**
  - V18 and V19 decode to the stated structures in both codecs and round-trip.
  - The Swift encoder's bytes equal Rust's `to_vec_named` bytes for both.
  - In both codecs, a `restore` with an empty table and a `spawn_term` with a nil `succeeds` encode with no `term_records` and no `succeeds` key, and a `TermRecord` with a nil `last_cwd` encodes as an empty map.
  - V1–V17 still pass unchanged.

### Edge Cases

- **S6 (`Layout` keeps the table):**
  - Given a seeded state with `term_records[T]` on board-0 and no live T,
  - when the app sends a `Layout` for board-0 that lists no tile for T,
  - then a probe's `Restore` still has `term_records[T]`, and so does `state.json` after the `Layout` save.
- **S7 (a cwd change does not save):**
  - Given a job-control shell T in A on board-0 (no docs), a `Layout` whose save `wait_for_state` has seen, and then 500 ms more (past the 150 ms save delay), the test keeps the bytes of `state.json`,
  - when T runs `cd B && sleep 3`, and a probe shows `term_records[T].last_cwd == B`,
  - then `state.json` is byte-for-byte the kept bytes 1 s later.
  - A later `Layout` save writes `last_cwd == B`.
- **S8 (TermClose deletes):**
  - Given a live plain shell T whose entry a `Layout` save has written to `state.json`,
  - when the app sends `TermClose { term_id: T }`,
  - then after T's `Exit`, a probe's `Restore` has no key T, and a saved check shows no key T.
- **S9 (a clean exit deletes, a failure keeps):**
  - Given plain shells T1, T2 and T3 whose entries a `Layout` save has written,
  - when T1's shell runs `exit 0`, T2's runs `exit 3`, and T3's runs `kill -9 $$`,
  - then after their `Exit` frames (codes `Some(0)`, `Some(3)`, `None`), a probe's `Restore` has no key T1 and still has T2 and T3, and a saved check shows no key T1.
- **S26 (TermClose deletes the entry of a term that is not live):**
  - Given a seeded state with `term_records[T]` on board-1, no live T, and board-0 active,
  - when the app sends `TermClose { term_id: T }`,
  - then a saved check shows no key T on any board, and board-1's `Restore` (after a `BoardSwitch`) has no key T.
  - A `TermClose` for an id with no entry sends no `err` frame.
- **S10 (a rebound term gets no cwd; TarmacKit):**
  - Given a tile T that is in `live_terms`,
  - when `BoardRestore.plan` runs,
  - then the planned term keeps id T, with `needsSpawn == false`, `spawnCwd == nil` and `succeeds == nil`.
- **S11 (no record; TarmacKit):**
  - Given a cold-spawn tile T with no `term_records[T]`,
  - when `BoardRestore.plan` runs,
  - then `spawnCwd == nil` and `succeeds == T`.
- **S12 (the board's only fresh terminal; TarmacKit):**
  - Given a `Restore` with no term tiles,
  - when `BoardRestore.plan` adds the board's one terminal,
  - then that term has `spawnCwd == nil` and `succeeds == nil`.
- **S13 (an old state file):**
  - Given a seeded state in today's shape (no `term_records`) with two boards,
  - when the new daemon loads it and, with no terminal spawned, saves it after a `Layout`,
  - then the first `Restore` has an empty table, and the saved file has no `term_records` key for any board. (S5 checks that an empty table is sent with no key.)
- **S14 (a gone folder):**
  - Given a seeded state with `term_records[T].last_cwd == D`, where D does not exist, and a daemon started with `HOME` set to a temp dir H,
  - when the test sends `SpawnTerm { term_id: T′, cwd: D, succeeds: T }` with a plain shell that prints `pwd`,
  - then the shell prints H, no `err` frame comes within 1 s (`none_within`), and a probe's `Restore` has no key T.
- **S20 (`succeeds` does not reach another board):**
  - Given a seeded state with `term_records[T]` on board-1, and board-0 active,
  - when the test sends `SpawnTerm { term_id: T′, board_id: board-0, succeeds: T }`,
  - then board-1's `Restore` (after a `BoardSwitch`) still has key T.
- **S21 (a legacy tile; TarmacKit):**
  - Given a `Restore` with one term tile that has no `term_id`, a `term_records` with any entry, and empty `live_terms`,
  - when `BoardRestore.plan` runs,
  - then the planned term has `needsSpawn`, `spawnCwd == nil` and `succeeds == nil`.
- **S22 (a background board records in its own table):**
  - Given board-0 active and board-1 in the background,
  - when the test spawns a plain shell T in A with `board_id: board-1`,
  - then board-1's `Restore` (polled with `BoardSwitch` to board-1 and back) comes to show `term_records[T].last_cwd == A`, and after that, board-0's `Restore` has no key T.
  - The order matters: a board-0 check made before the record exists passes for the wrong reason.
- **S24 (the cwd is read only on a pid change; unit):**
  - Given a `with_fs` daemon whose fixture `PathFs` counts `pid_cwd` calls (`StuckFs::calls`, `fixtures.rs:81-83`), and a plain shell T idle at `read _`,
  - when T's first read has been stored, and then 3 s pass (4 ticks) with no pid change,
  - then the fixture's `pid_cwd` count is the same at the end of the 3 s as at the start.
- **S25 (the move carries the value, and a `None` read keeps it; unit):**
  - Given a `with_fs` daemon with `term_records[T] = {last_cwd: B}` on its board, no live T, and a fixture `PathFs` whose `pid_cwd` answers `None`,
  - when `SpawnTerm { term_id: T′, succeeds: T }` succeeds, and the first `pid_cwd` call for T′ has returned and its result has been applied,
  - then `term_records[T′].last_cwd == B` and there is no key T.
  - `StuckFs` counts a call when it starts (`fixtures.rs:69-75`), so a count alone does not show that the result was applied. The test waits for a signal from the fixture on return, and then for one more tick, before it asserts.

### Error Scenarios

- **S15 (an unusable `succeeds`):**
  - Given (a) `succeeds` names a live plain shell L that has an entry, or (b) it names an id with no entry,
  - when a `SpawnTerm { term_id: X, succeeds: … }` carries it,
  - then X's shell starts (its output arrives), no `err` frame comes within 1 s, and in (a) a probe's `Restore` still has key L.
- **S16 (a failed spawn moves nothing):**
  - Given a seeded state with `term_records[T]`, no live T, and a live term X,
  - when the test sends `SpawnTerm { term_id: X, succeeds: T }`,
  - then an `err` frame names X as in use, and a probe's `Restore` still has key T with its seeded value.
- **S17 (a slow cwd read at shutdown; unit):**
  - The seam:
    - The fixture `PathFs` holds `pid_cwd` for one named pid and answers the others. Today `StuckFs` holds `pid_cwd` for every pid (`fixtures.rs:58-59`, `121-124`), so the fixture needs a per-pid hold.
    - The gate limit is well above the budget (30 s, as `state/tests/opens.rs:426` uses), so only `SHUTDOWN_CWD_BUDGET` can end the wait. (The fixture `LIMIT` is 200 ms, below the budget, and a test on it would pass on the gate limit.)
    - The save part of shutdown can run without `process::exit` (`main.rs:105-116` exits in the same task today).
  - Given 3 live terminals with records, where the cwd read of one is held,
  - when the shutdown save runs,
  - then it writes the state and returns within `SHUTDOWN_CWD_BUDGET` + 300 ms.
  - In the written state, the held term keeps its previous `last_cwd`, and the other two have the fixture's fresh values.
- **S18 (the save comes before the socket goes):**
  - Given S2's setup up to `MOVED` (a probe showed A, and the shell is now in B with no pid change),
  - when the daemon gets SIGTERM, and the test polls the socket path every 5 ms or less,
  - then at the first poll that finds the socket gone, `state.json` already has `last_cwd == B`, and it parses.
  - The daemon exits with status 0.
  - The same holds for SIGHUP and SIGINT.
- **S23 (a late read stores nothing; unit):**
  - Given a `with_fs` daemon whose fixture `PathFs` holds every `pid_cwd` from the start (so the first-pid read of the next term is the held one), and two boards,
  - when a plain shell T is spawned on board-1, the fixture shows its first `pid_cwd` call has started, then (a) a `TermClose { term_id: T }` arrives and T's `Exit` follows, or (b) board-1 is deleted, and then the fixture lets the read return,
  - then, one tick later, no board's table has key T. In (b) the active board's table has no key T either (`registry_mut` falls back to the active board, `boards.rs:433-440`).

### QA (dev channel, not automated)

- **S19 (end to end):**
  - On `make run`, `cd` one terminal into a repo folder and run one command there. `cd` a second terminal into another folder at an idle prompt only.
  - Quit the dev app (⌘Q). Then, if the dev daemon still runs, send it SIGTERM by the pid that `lsof -t` gives for the dev socket's absolute path. Do not use `make kill-daemon`: it sends SIGKILL (`Makefile:117`), which skips the shutdown save. Never kill by name.

  - Why not keep the app running: a running app marks the cards of a dead daemon dead, and does not cold-spawn (`docs/architecture.md` §6, *What survives what*).

## Trade-offs and Limitations

- **A crash or SIGKILL loses the last idle `cd`.** The state keeps whatever the last save wrote.
- **A cwd change is saved only with the next other save, or at shutdown.** So a crash after a burst of commands, with no layout change, restores an older folder.
- **The cwd is the foreground process's cwd.** A command that ran in a subfolder, such as `make -C sub`, is recorded as `sub` until the next pid change at the prompt.
- **Shutdown gets up to 500 ms slower.** It stays inside the app's 2 s restart wait.
- **The entry of a dead card stays.** A dead card is never in a `Layout`, and today ⌘W on a dead card sends no `TermClose` (*Context*). The daemon deletes the entry on a `TermClose` for it, and in this slice the app sends none (OQ2 = a), so nothing deletes that entry, and it has no tile after an app relaunch. Slice 4 adds "reopen here".
