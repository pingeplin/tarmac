Written 2026-11-14 from the code at `main` d5ff6bd. The approach is the design's (§2) and is not open here. These decisions of the owner bind this spec:

- **§2 form.** Mockup "A + offscreen pills": a transient right-side panel, a title-bar button with the unread count, and report and exit kinds on the existing offscreen pills. The mockup canvas was not readable for this spec. The design text and the rules below are the source.
- **Backlog §3.** "No rail is built, by design." The owner accepted a *transient* panel on 2026-11-14. The panel is never docked and never resizes the board.
- **R3 and the English-only rule (2026-11-14).** Report copy places the report in time only: `report · during <proc>`. All UI copy is English.
- **Principle 2.** Nothing an agent does moves the view or takes keys. A jump happens only on the user's ↵ or click.
- **Principle 6.** The daemon owns reports and their read flags. Bell and exit items are the app's own list, and an app relaunch loses them (design §2, accepted).
- **Additive protocol only,** in two codecs, gated by the conformance vectors.

Decisions this spec had to make, which the design does not settle, are marked **[D1]…[D19]** in the body. **All were decided on 2026-11-14** (owner, reviewed with Fable). The list with one line each is in *Open Questions*, OQ1.

- **D1–D3, D5–D19: accepted as proposed.** D18 is a closed list of named keys only; `tarmac dev press` takes no printable key.
- **D4: changed. The scope is not cut.** Bells and exits are listed from every board, as reports are. `Bell` and `Exit` get an optional `board_id` (additive, one vector each). The traps the owner named are written into the body:
  1. The daemon reads the exit's board **before** `term_ended` removes the `term_boards` entry (`state.rs:508`; the push is at `term.rs:379-380`).
  2. The app feeds the inbox **before** the board, session and live-card guards of `handleBell` (`AppController+Terminals.swift:372-374`), `handleExit` (`:248-250`) and `handleTermReport` (`:365-367`).
  3. An exit item on a never-shown board: at the first visit its tile is cold-spawned under a new id (`BoardRestore.plan`, `succeeds: tile.termID`, `BoardRestore.swift:78`). The jump flies to the **successor** card through that map. With no successor, the row drops.
  4. When a board is first built, its bell and exit items whose term has no card and no successor are removed.
  5. A bell row of a board not built yet reads `bell` and `<board> › shell` (no proc, no cwd). Accepted.
  6. Frames the daemon pushes while no app is connected are dropped. Accepted (design §2).
- **OQ2: `⌘I` is kept.** The local key monitor (`AppController+Keys.swift:7`) runs before the terminal view, so the key ladder takes `⌘I` before any program sees it. The cost is the same as `⌘K`, `⌘T` and `⌘W`. No probe blocks the build; the limit is a note in *Trade-offs*.
- **OQ6: the title-bar button stays in the title bar.** If the accessory fails on macOS 26, the implementer **stops and reports**. It is not moved to the status bar without the owner (the mockup has it in the title bar).

## Motivation

With four or more agent terminals on two boards, the user has to look at every card to find the one that waits. Slice 2 put a chip on each card. A chip is on the card, so it is seen only when the card is. This slice gives one place that lists what needs the user, on every board, and a key that takes the user to it.

## Proposed Solution

### Overview

1. The daemon adds `board_id` and `cwd` to every `term_report` that has a kind. At an app's connect, it also sends the current report of every terminal on the **other** boards [D1, D2, D3].
2. The daemon adds `board_id` to every `bell` and `exit` it pushes [D4].
3. The app keeps an inbox store (pure, in TarmacKit), apart from the cards. It holds report items (from `term_report`) and bell and exit items (from `bell` and `exit`), from every board, built or not [D4, D5].
4. `⌘I` or the title-bar button opens a panel on the right side. It lists the items, newest first, with filters. ↵ or a click jumps to the card (since spec 2611.0018 a click selects and previews; ↵, a double-click or `go ↵` jumps): a board switch if needed, then a flight, then prime [D13, D14]. A row whose terminal was replaced at the board's first build jumps to the replacement [D4].
5. The offscreen pills get three new signals: a blocked report, an exit and a done report, in a fixed rank [D11].
6. While the panel is open, the pills, the minimap and the toasts keep to the board area left of the panel [D12].

### Key Components

**Protocol** (`tarmac-protocol/src/lib.rs` and the Swift codec, same change) [D1–D4].

- `Msg::Bell` and `Msg::Exit` each get `board_id: Option<String>`, after their existing keys, with `#[serde(default, skip_serializing_if = "Option::is_none")]`. With `None` they encode as today, byte for byte. In Swift: `.bell(termID:boardID:)` and `.exit(termID:code:boardID:)`, with `boardID: String? = nil` as the default, so existing call sites stay.
- Rust patterns that list every field (`Msg::Bell { term_id }`, `Msg::Exit { term_id, code }`) stop compiling and gain `..` or the new field: `honest_signals_integration.rs:22`, `term_cwd_inherit_integration.rs:91`, `tests/common/mod.rs:313`, `term.rs:338,380,506`, `tarmac-protocol/src/tests.rs:964-965,980,1031,1037`.

- `Msg::TermReport` gets two keys, after `read`, in this order:
  - `board_id: Option<String>`: the board the terminal is filed under.
  - `cwd: Option<String>`: the terminal's `last_cwd` record when the report was made.
  - Both have `#[serde(default, skip_serializing_if = "Option::is_none")]`.
- A frame with no `kind` (a removal) carries neither key. So V23 does not change.
- A frame with a `kind` from this daemon always carries `board_id`. `cwd` is sent when the record has one.
- No new message type.

**Daemon — the place of a report** (`reports.rs`, `state.rs`).

- `CurrentReport` gets `board_id: Option<String>` and `cwd: Option<String>`. `frame` writes them.
- `Reports::report` takes them as one more argument (a small `Place { board_id, cwd }` value is fine).
- `Daemon::report` reads them **before** it takes the `reports` lock:
  - `board_id`: `term_boards[term_id]` (lock, read, release).
  - `cwd`: that board's `term_records[term_id].last_cwd` (the `boards` lock, read, release).
  - Then `change_report` as today. The lock rule of slice 2 stays: `reports` is never held while `boards` or `terms` is taken.
- The place is read at each report, so a repeat gets the place of its own time.

**Daemon — the board of a bell and an exit** [D4] (`term.rs`, `state.rs`).

- **Bell** (`term.rs:338`): the pump reads `term_boards[term_id]` (lock, read, release) and pushes `Bell { term_id, board_id }`. Bells are debounced, so this lock is rare.
- **Exit** (`term.rs:379-380`): the board must be read **before** `term_ended` removes the `term_boards` entry (`state.rs:508`); after it, the entry is gone. So `Daemon::term_ended` returns the `Option<BoardId>` that its `term_boards.remove` gives, and the pump pushes `Exit { term_id, code, board_id }` with it.
- A frame pushed while no app is connected is dropped, as every push is (`state.rs:602-608`). So a bell or an exit while the app is away is not listed. Accepted (design §2).

**Daemon — the all-board replay at connect** [D1] (`conn.rs`, `reports.rs`).

- `Reports::elsewhere(&self, shown: &[String]) -> Vec<Msg>`: one frame for each term that has a current report and is not in `shown`, sorted by term id. A term with no report gets no frame.
- `AppConn` gets `told_elsewhere: bool`, false at first.
- In `change_and_send_active_board`, inside the existing `reports` lock block (`conn.rs:202-207`), after the active board's `snapshot`: when `told_elsewhere` is false, send `reports.elsewhere(&live_terms)` on `conn.tx`, then set it true.
- So the replay runs once per app connection, on its first restore, before the scrollback replay. A later `BoardSwitch`, `BoardCreate` or board delete sends only the shown board's frames, as today. Live pushes keep the app current after that.
- The active board's frames are not sent twice: `elsewhere` leaves out `live_terms`.
- No frame with no `kind` is sent for other boards. A new app connection starts with no report items: a fresh app has none, and a reconnecting app drops them at the disconnect [D10].

**App — codec** (`TarmacKit/Messages.swift`).

- `.termReport` gets `boardID: String?` and `cwd: String?`. Both are decoded when present and written only when set.
- `TermReport.frame` gives the board and the folder too, for example as a small `TermReportFrame { termID, boardID?, cwd?, report? }`. `TermReport` itself does not change, so `ReportChip` does not change.

**App — the inbox store** (`TarmacKit/Inbox.swift`, new; pure, the clock passed in) [D4–D10].

- `Inbox.Item`:
  - `id`: `(termID, family)`, with `family` ∈ `report`, `bell`, `exit` [D5].
  - `kind`: `.report(TermReport.Kind)`, `.bell`, `.exit(code: Int?)`.
  - `termID`, `boardID`, `atMs`, `proc: String?`, `cwd: String?`, `text: String?` (reports only), `read: Bool`.
- `Inbox` (a value type) with these operations. Each returns nothing; the app reads the result through the queries below.
  - `apply(report frame, fallbackBoard:)`:
    - With a `kind`: put the report item for the term. Its board is the frame's `board_id`, else `fallbackBoard` (the app's `ownerBoard(ofTerm:)`, for an older daemon). With neither, the frame is dropped.
    - The item's `read` is the frame's `read`. A frame with a new `at_ms` replaces the item and moves it to the top.
    - With no `kind`: remove the report item.
  - `bell(termID, boardID, proc, cwd, nowMs)`: put the bell item. A second bell on the same term sets a new `atMs` and `read: false` [D5].
  - `reportEnded(termID)`: remove the term's report item. The app calls it in `holdOpen` [D10]; `exit` below does the same for every `exit` frame, before any card check. The daemon sends no `term_report` at an exit (slice 2, D4), so without this a report item of a terminal with no card (a never-built board) or of a lost terminal (reconcile → `markLost` → `holdOpen`) would stay for ever.
  - `exit(termID, boardID, code, proc, cwd, nowMs)`: for a code that `TermExitToast.title` names (non-zero or nil), put an exit item; for 0, put none. It also removes the report item. The caller reads `proc` and `cwd` from the session before `holdOpen` clears `procName`.
  - `touch(termID)`: mark the term's bell and exit items read [D6].
  - `removeTerm(termID)`, `removeBoard(boardID)`.
  - `keepBoards(ids)`: remove every item whose board is not in `ids`. The app calls it on each `board_list`, so a deleted board that was never built leaves no item (`removeBoard` in the app returns early for a board it has not built, `AppController+Boards.swift:13`).
  - `lostConnection()`: remove every report item. Dismissals stay [D9, D10].
  - `boardBuilt(boardID, cards: Set<termID>, successors: [old termID: new termID])` [D4]. The app calls it once, when a board is first built (`build`, `AppController+Layout.swift:62`), with the board's terminal cards and the plan's cold spawns (`SpawnRequest.succeeds`, `BoardRestore.swift:78`). It records each successor, then removes every bell and exit item on that board whose term has no card and no successor.
  - `target(termID) -> termID?`: the term itself, else its recorded successor, else nil. The jump uses it.
  - `dismiss(id)`, `clearRead(filter)` [D9].
- Queries:
  - `items(filter) -> [Item]`: not dismissed, newest first by `atMs`; on a tie, the item put later first [D7].
  - `unreadCount`: items not dismissed and not read, all boards, all kinds [D8].
  - `unreadReports(board:)`: the number of unread report items on a board [D16].
  - `exitUnread(termID) -> Bool`: for the pill [D11].
- **Dismissals** are kept as a set of `(termID, family, atMs)`. A frame or event with the same key stays hidden. A new `atMs` shows again [D9].
- **The cap.** At most `Inbox.maxItems` = 200 items. Over the cap, the oldest read item goes first, then the oldest item [D5].

**App — copy** (`TarmacKit/InboxCopy.swift`, new; pure) [D19].

- Kind tag: `blocked`, `done`, `bell`, `exit`.
- Title:
  - report: `report · during <proc>`, or `report` with no `proc` (R3; the same words as the chip's tool tip, `ReportChip.swift:60`).
  - bell: `bell · during <proc>`, or `bell` with no `proc`.
  - exit: `TermExitToast.title(code:)` (`shell exited · 3`, `killed by signal`).
- Quote: reports only, set in `“…”`, made one line (`oneLine`, below). None for a report with no text.
- Place: `<board> › <terminal> · <cwd>`. With no cwd: `<board> › <terminal>`. A cwd under the home folder starts with `~`. The home folder is an argument.
  - `<board>`: the board's name, else its id.
  - `<terminal>`: the card's label when the card exists, else the item's `proc`, else `shell` (`TermLabel.initial`).
  - A bell or exit item of a board not built yet has no `proc` and no `cwd` (the app has no session there). It reads `bell` (or the exit wording) and `<board> › shell`. Accepted [D4].
- Age: `ChromeText.reportAge(elapsedMs:)` (`<1m`, `Nm`, `Nh`, `Nd`), from `atMs`.
- `oneLine(text)`: every run of whitespace, newlines included, becomes one space; then it is trimmed.
- Empty list: `no items`.
- `InboxBadge.text(unread:)`: `inbox` for 0, `inbox · N` up to 99, `inbox · 99+` above.

**App — keys** [D13].

- `KeyLadder.Facts` gets `inboxOpen: Bool`. `KeyLadder.Action` gets `toggleInbox` and `inboxKey`.
- New order of `KeyLadder.decide`:
  1. Composing, or a borrowed document holds the keys → pass through (unchanged).
  2. `⌘K` → `toggleSwitcher` (unchanged).
  3. **`⌘I` → `toggleInbox`** (new).
  4. `⌘W` → `closeSelectedCard` (unchanged).
  5. Switcher open → `switcherKey` (unchanged).
  6. **Inbox open → `inboxKey`** (new).
  7. `⌘T`, the Return fly, `ESC`, the console rung (unchanged).
- So while the panel is open, it gets every key but `⌘K`, `⌘I` and `⌘W`. The Return fly and `EscLadder` never see a key then.
- `⌘W` with the panel open closes the panel first, then closes the selected card, as it does with the switcher (`AppController+Keys.swift:68-70`).
- `InboxKeys.handle(press, state, rows) -> (state, effect)` (`TarmacKit/InboxKeys.swift`, new; pure). `rows` is the list of item ids the panel shows, in order. `State { filter, selected: Inbox.ItemID? }`. Effects: `none`, `close`, `jump(ItemID)`, `remove(ItemID)`, `leaveForMenu`.
  - **The selection is an item id, not an index** [D13]. The list is newest first and changes while the panel is open (D17). With an index, a report that arrives just before ↵ would shift the rows, and ↵ would act on another item: an agent would steer the user's key (principle 2).
  - `InboxKeys.reselect(selected, oldRows, newRows) -> ItemID?`, run on every change of the list: the selected id stays while it is in `newRows`, wherever it moved. When it left, the selection goes to the item now at its old index, clamped; with no rows, nil. A new item never moves the selection. With nil and rows present, the top row is selected.
  - ↑ / ↓ move to the row above / below the selected one, clamped, no wrap.
  - ↵ → `jump(selected)`; with no selection, `none`.
  - ⌫ → `remove(selected)`; with no selection, `none`.
  - Tab / ⇧Tab → the next / previous filter, in the order all → reports → bell → exit, wrapping; the selection goes to the top row of the new filter.
  - `ESC` → `close`.
  - Any other key with ⌘ → `leaveForMenu`. Any other key → `none` (taken, so it never reaches the terminal).
- **Focus.** The panel copies the switcher's pattern:
  - Open: the panel's view takes first responder (`takeKeys`) and remembers the view that had it. So the menu's Paste cannot reach the terminal behind.
  - Close (`⌘I`, `ESC`, the button, or a press outside): first responder goes back to the remembered view (`returnKeys(fallback: rootView.board)`).
  - A jump closes the panel without giving the keys back; the jump gives them to its target [D14].
- **The switcher and the panel never show together.** Opening one closes the other.
- **A board switch closes the panel** (in `beginArrivingSwitch`, beside `closeSwitcher()`).
- **A press on the board while the panel is open** closes the panel, and then the press does what it does today (select, raise, prime). A press on the panel is the panel's.

**App — the jump** [D14] (`TarmacKit/InboxJump.swift`, new; pure, and wiring).

- `InboxJump.plan(item, activeBoardID) -> Plan`: `.fly(termID)` when the item's board is the active board, else `.switchThenFly(boardID, termID)`.
- `InboxJump.land(cardExists:, cardDead:) -> Landing`: `.prime` (a live card), `.select` (a dead card), `.drop` (no card).
- **The card to land on** is `inbox.target(termID)`: the item's own term when it has a card, else its successor [D4]. An exit on a board not built yet is the common case: at the first visit the dead terminal's tile is cold-spawned under a new id that `succeeds` the old one, so the row lands on that fresh shell (`.prime`). `boardBuilt` runs inside `build`, before `finishArrive`, so the successor is known when the pending jump lands. With no target, the landing is `.drop`.
- Wiring:
  - `.fly`: close the panel; then the landing on the active board.
  - `.switchThenFly`: close the panel, keep `pendingJump = (boardID, termID)`, call `performSwitch(to:)`. When `performSwitch` returns at its guard (an unknown board, `AppController+Boards.swift:184`), clear `pendingJump` and remove the item. In `finishArrive`, before it picks the keyboard's home, take `pendingJump`: when its board is the arrived board, do the landing; else (another switch overtook it) drop it.

    - `.select`: select the card, fly to it, the card takes the keyboard, as a click on it does (2611.0011 D10), so Return reaches its reopen offer. Before #403: the keyboard stayed with the board.
    - `.drop`: remove the item. No flight. The switch (if any) stands.

  - A jump sets `preFlightViewport = nil`. It does not set one.
  - A jump does not mark a report read. Only typed input does (R2).

### Data Flow

1. The app starts. It connects. The daemon sends `board_list`, board-0's `restore`, board-0's report frames, and then one frame for terminal T on board-1, which reports `blocked "May I run rm?"`. That frame has `board_id: "board-1"` and `cwd: "/Users/u/w/api"`.
2. The app has never built board-1. The store keeps the item. The button reads `inbox · 1`. The ⌘K switcher row of board-1 reads `1 running · 1 report · 0 cards`.
3. The user presses `⌘I`. The panel opens on the right. Its top row: `blocked  report · during claude  2m`, then `“May I run rm?”`, then `board-1 › claude · ~/w/api`. The panel holds the keys.
4. The user presses ↵. The panel closes. The app sends `board_switch`. The `restore` of board-1 builds T's card; `finishArrive` takes the pending jump: T becomes prime, the board flies to it, T takes the keyboard. The report frames that follow put the chip on T's header.
5. The user types `y`. The app sends `input {typed: true}`. The daemon marks the report read and pushes it again. The row dims; the button reads `inbox`.
6. `claude` exits. The poll removes the report and pushes a frame with no `kind`. The item goes.

### Interface Contract

Additive only. Both codecs ignore unknown keys and unknown types.

```
term_report  { t:"term_report", term_id, kind?, text?, at_ms?, proc?, read?,
               board_id?: str, cwd?: str }                                         daemon → app
bell         { t:"bell", term_id, board_id?: str }                                 daemon → app
exit         { t:"exit", term_id, code, board_id?: str }                           daemon → app
```

- **`board_id`.** The board the terminal is filed under when the report was made. Sent with every frame that has a `kind`, from a daemon of this version. Not sent on a frame with no `kind`.
- **`bell.board_id`, `exit.board_id`.** The board the terminal was filed under when it rang or ended. The daemon reads the exit's board before it forgets the terminal. Missing means unknown (an older daemon); the app then uses its own index.
- **`cwd`.** The terminal's `last_cwd` record when the report was made. Sent when the record has one. Not sent on a frame with no `kind`.
- **The connect replay.** On an app connection's first restore, after the shown board's report frames and before its scrollback replay, the daemon sends one `term_report` for each live terminal on another board that has a current report. A later restore on the same connection does not send them again.
- **Not persisted.** No key in `state.json`.
- **New conformance vectors** (hex = `rmp_serde::to_vec_named` bytes, in its key order; each vector gives the whole frame). They are named **Vn, Vn+1, Vn+2**: n is the next free number when this lands. Slice 4 (2611.0011) owns V25–V27 and slice 6's draft claims V28–V32, so n is 33 if both land first. Renumber at merge (OQ3).
  - **Vn:** `{t:"term_report", term_id:"t1", kind:"blocked", at_ms:1700000000000, board_id:"board-1", cwd:"/w"}` (no `text`, `proc` or `read` key; `at_ms` is a msgpack uint64, `cf`).
  - **Vn+1:** `{t:"bell", term_id:"t1", board_id:"board-1"}`.
  - **Vn+2:** `{t:"exit", term_id:"t1", code:3, board_id:"board-1"}`.
  - Both codecs decode each one and round-trip it. The Swift encoder's bytes equal Rust's (`RustEncoderParityTests`). Every vector that has landed keeps its bytes; V22 and V23 (`term_report`) and every `bell` and `exit` vector in particular, because a `None` `board_id` is not written.
- **Docs.**
  - `docs/protocol.md`: the section *A terminal's report* gets the two keys, their table rows and the connect replay; § M2 honest signals gets `board_id` on `bell` and `exit` (`protocol.md:148, 395`); Vn–Vn+2.
  - `docs/architecture.md`: §4 *Focus and keys* (the new rungs 3 and 6, the panel's key ownership), §4 *Wayfinding and overlays* (the inbox panel, the five signals and their rank, the uncovered area), §4 *Boards and the ⌘K switcher* (the report count), §3 *Terminal sessions* (the place of a report, the connect replay), §6 *What survives what* (bell and exit items and dismissals are lost on an app relaunch; reports and their read flags are not).
  - `docs/backlog.md` §3: one line under "right rail": a transient inbox panel exists by owner decision 2026-11-14 (design 2611.0006 §2); it is not a docked rail.

## Alternatives Considered

- **A request for all reports (`reports_list` → `reports`).** It works at any time, not only at connect. It costs one new message pair, two vectors and one round trip, and the app would have to ask after every reconnect anyway. The connect replay reuses the existing frame and the existing lock block. Rejected [D1].
- **All boards' frames on every restore.** Simple, but it resends every report at every board switch, and it adds nothing: live pushes already reach the app between restores. Rejected [D1].
- **A full `restore` for every board at connect.** It would also give bells, labels and folders of never-built boards. It is far more traffic and would build cards nobody opened. Rejected.
- **No `board_id` on `bell` and `exit`; list bells and exits of built boards only.** No protocol cost for them, but it cuts the owner's "items from ALL boards". Rejected by the owner (D4, 2026-11-14).
- **A daemon-side clear from the app** (a new app → daemon `report_dismiss`). It would remove the card chip too, and it would let the user end an agent's claim, which only the agent's own `clear` or its process's end may do today. Rejected [D9].
- **Unread first, then newest.** It makes rows jump when they are read. Rejected for plain newest-first [D7].
- **A docked rail that resizes the board.** Against backlog §3. Rejected by the owner (design §2).

## Migration & Rollback

- **Migration.** None. Nothing is persisted.
- **A new daemon with an older app.** The app ignores `board_id` (on all three frames) and `cwd`. The connect replay's frames are for terminals on boards it has not built, so its `handleTermReport` drops them (no session). Nothing changes on screen.
- **A new app with an older daemon.** No `board_id`: the store uses `ownerBoard(ofTerm:)`, so reports, bells and exits of built boards are listed and others are not. No `cwd`: the place has no folder. No connect replay: a never-built board's reports appear when it is shown.
- **Rollback.** Revert the change. No state to clean.

## Security Considerations

- **The text is a claim.** The panel shows it only in `“…”`, as plain text, in one line, with the full text as a tool tip (spec 2611.0018 replaced the tool tip with the preview pane, and spec 2611.0017 draws inline markdown). It is never markup and has no links (slice 2).
- **`board_id` and `cwd` are observed by the daemon.** The caller cannot set them. `cwd` is the record the daemon read with `proc_pidinfo` through the gate.
- **The folder is shown in the user's own window only.** It already shows in the terminal itself; the panel adds no new reader.
- **Keys.** The panel takes keys only while open, and only after the user opened it. An agent's report never opens it and never moves the view (principle 2).

### Edge Cases

- **One bell item per terminal (one bell item per terminal; TarmacKit):** a bell at 10 then a bell at 20 on T give one bell item at 20, unread, even after a `touch` in between.
- **Touch marks bell and exit items read (what marks bell and exit items read; TarmacKit):** `touch(T)` marks T's bell and exit items read and leaves T's report item as it was. No other operation marks a bell or exit item read.
- **Exit adds an item and removes the report (an exit; TarmacKit):**
  - T with a report item and a bell item; `exit(T, "board-0", code: 3, proc: "zsh", cwd: "/w", now)` removes the report item, keeps the bell item and adds an exit item, unread.
  - On a store with no item for U, `exit(U, "board-1", code: 3, proc: "make", cwd: "/w/x", now)` adds an exit item with board `board-1`, `proc` `make` and `cwd` `/w/x` (a plain shell's `exit 3`, "QA jump to a dead or gone card").
  - `exit(T, …, code: nil, …)` adds an exit item. `exit(T, …, code: 0, …)` adds none and still removes the report item.
- **Every end of a report removes its item (every end of a report removes its item; TarmacKit):**
  - A report item for T on board-1 (a board the app has not built); `exit(T, "board-1", code: 0, …)` removes it and adds no item. (The wiring calls `exit` for every `exit` frame before the card check; "QA inbox lists all boards" checks that path.)
  - A report item for T; `reportEnded(T)` as `holdOpen` calls it for a lost terminal removes it and keeps T's bell item.
  - Items on board-0, board-1 and board-2; `keepBoards(["board-0", "board-2"])` removes every board-1 item and no other.
- **Dismissed report stays hidden on replay (dismiss and clear read; TarmacKit):**
  - `dismiss(item)` hides an unread report: `items` leaves it out, `unreadCount` drops by one.
  - A frame for the same term with the same `at_ms` (a replay) stays hidden. A frame with a new `at_ms` shows again, unread.
  - With filter `bell`, `clearRead(.bell)` hides the read bell items and leaves read report items. With `all`, it hides every read item.
- **Lost connection removes report items only (a lost connection; TarmacKit):** `lostConnection()` removes every report item, keeps bell and exit items, and keeps the dismissal of "Dismissed report stays hidden on replay": the replayed frame with the same `at_ms` stays hidden.
- **Removed card or board removes its items (a card or a board goes; TarmacKit):** `removeTerm(T)` removes T's three items. `removeBoard("board-1")` removes every item on board-1 and none elsewhere.
- **Cap drops the oldest read item first (the cap; TarmacKit):** with 200 items of which the oldest two are unread and the third oldest is read, a 201st item removes the third oldest (the oldest read one). With 200 unread items, a 201st removes the oldest.
- **Frame with no board uses the fallback board (a frame with no board; TarmacKit):** a frame with no `board_id` uses `fallbackBoard`. With no fallback either, no item is made.
- **Pill signal and fly target rank (the pill signal and rank; TarmacKit, `OffscreenHintsTests`):**
  - `signal`: an unread blocked report with a lit bell → `blocked`; a **read** blocked report with a lit bell → `bell`; an unread exit, no bell → `exit`; an unread done report and an unread exit → `exit`; an unread done report on a live card → `done`; a read done report on a live card → `live`; a dead card with nothing unread → nil.
  - `flyTarget`: `[live z 5000, bell z 0]` → the bell (this fails under `1000 + z`); `[done z 9, exit z 1]` → the exit; `[blocked z 1, bell z 9]` → the blocked; two `bell`s with equal `z` → the first.
- **Pill labels cut long text (pill labels; TarmacKit):**
  - blocked, name `claude`, text `abcdefghij\n  klmnopqrstuvwxyz0123` (31 scalars after `oneLine`) → `claude · “abcdefghij klmnopqrstuv…”` (23 scalars + `…`). This fails if the newline is kept or the cut is at 24.
  - A text of exactly 24 scalars is not cut.
  - done with no text → `claude · report`. exit → `claude · exited`. bell → `claude · 14:32` (unchanged). live → `claude` (unchanged).
- **Panel geometry and pill projection (panel geometry; TarmacKit):**
  - area 1100 × 673 at (0, 0): width 360; `panelRect` = (740, 0, 360, 673); `uncovered(open: true)` = (0, 0, 740, 673); `uncovered(open: false)` = the area.
  - area 900 wide: width 300.
  - Placing hints in `uncovered`: a hint whose centre is at x = 800 (under the panel, inside the board) is projected to the right edge of `uncovered`: the pill's right side is at 740 − `edgeMargin`.

- **Unbuilt board bell and exit make items (a bell and an exit of a board not built yet; TarmacKit):**
  - `bell(T, "board-1", proc: nil, cwd: nil, now)` on an empty store makes one bell item on board-1. Its copy is title `bell` and place `board-1 › shell`.
  - `exit(U, "board-1", code: 3, proc: nil, cwd: nil, now)` makes one exit item, title `shell exited · 3`, place `board-1 › shell`.
- **First board build keeps live and successor items (the first build of a board; TarmacKit):**
  - Items: a bell on board-1 for T (live, so its card is built with the same id), an exit on board-1 for U (dead; its tile is cold-spawned as U2 with `succeeds: U`), an exit on board-1 for W (no tile), and a bell on board-2 for X.
  - `boardBuilt("board-1", cards: [T, U2], successors: [U: U2])` keeps T's and U's items, removes W's, and keeps X's.
  - `target(T) == T`; `target(U) == U2`; `target(W) == nil`.
  - This fails if the build removes U's row (it has no card of its own) or keeps W's.
- **Bell and exit frames carry the board (the board on `bell` and `exit`; integration, `honest_signals_integration.rs` or `report_integration.rs`):**
  - Given board-0 active and a terminal T spawned on board-1 that runs `printf '\a'; read _`,
  - then the `bell` frame for T has `board_id: "board-1"`.
  - When the test types `exit 3` into T, the `exit` frame has `code: 3` and `board_id: "board-1"`. This fails if the board is read after `term_ended` (the entry is gone then, so `board_id` would be missing).
- **Inbox is fed before the card guards (the inbox is fed before the card guards; TarmacKit + QA):** the store calls take no card argument, so "Unbuilt board bell and exit make items" covers the store. The wiring order (store first, then the guard) is checked by "QA inbox lists all boards": a bell and an exit on a board that was never shown are listed.

## Trade-offs and Limitations

- **A bell or exit row of a board not built yet is thin** [D4]. It reads `bell` (or the exit wording) and `<board> › shell`, with no process and no folder: the app has no session there. Accepted.
- **Bells and exits while no app is connected are lost** [D4]. The daemon drops a push with no app. Accepted (design §2).
- **An exit row of a board not built yet jumps to the fresh shell** that replaced the dead terminal at the first visit, not to a dead card: no dead card is restored (*Layout persistence*).
- **The inbox list and the card can differ** [D9]. ⌫ and "clear all read" hide items in the panel only. The card's chip, the bell dot and the report pill stay, because they show the daemon's and the terminal's facts. Only the exit pill follows the exit item, because the exit item is its only state.
- **Dismissals and bell and exit items are lost on an app relaunch.** Reports and their read flags come back from the daemon.
- **A jump does not mark a report read** (R2: only typed input does). After a jump the row stays bright until the user types.
- **The cwd is the record at report time.** It lags by at most one command (slice 1). Bell and exit items use the last record the app saw, which can be older; with none, the place has no folder.
- **`⌘I` is taken from every terminal program** (OQ2). A program that bound super+i through the kitty keyboard protocol loses it, as it already loses `⌘K`, `⌘T` and `⌘W`.
- **The title-bar button follows the system appearance,** not Tarmac's theme. The rest of the panel follows the theme.
- **Cards under the open panel are covered.** They get pills, and the board does not reflow (backlog §3).

## Implementation notes (2026-11-15)

Recorded after QA and review; they settle cases the body does not.

- **A closed card makes no row afterwards.** `⌘W` removes the card and its rows at once, and the daemon's `exit` for the SIGHUP comes after. The inbox is fed before every card guard (D4), so the store remembers removed terminals (`Inbox.removeTerm`) and puts no item for them. Term ids are never reused. A board's removal forgets its terminals the same way.
- **A dropped jump removes its row** (`Inbox.remove`), as *The jump* says; it does not dismiss it, so a later frame with the same `at_ms` shows it again.
- **`active_element` names an overlay.** While the switcher, the restore card or the inbox holds first responder, the dev snapshot's `active_element.card` is null and `overlay` and `returns_to` name it and the card it hands the keys back to ("QA smoke run inbox jump" checks both).
- **`--until` polls through a board switch.** While no board is on screen, a wait keeps polling until its deadline instead of answering `app_not_ready` at once.
- **A board never shown has no card count** in its ⌘K row: the app has counted none, and `0 cards` beside a report count misled.
- **Removed `Inbox.removeBoard`.** `keepBoards` on each `board_list` covers every caller.

**Changed by #403** (2026-11-17): a jump that lands on a dead terminal card
gives the keyboard to that card, as a click on it does (2611.0011 D10), so
Return reaches its reopen offer. Before, the card was selected and the
keyboard stayed with the board, so Return did nothing. This holds for an
inbox ↵ or click, and for a click on an edge pill (D14, *The jump*). A jump
to a live card is unchanged: it becomes prime and takes the keys.
