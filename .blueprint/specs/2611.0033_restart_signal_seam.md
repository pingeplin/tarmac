# 2611.0033 The restart signal is a dependency of the client

**Date:** 2026-11-23
**Status:** accepted (spec-evaluator review, 2026-11-23)
**Author:** EP Lin
**Issue:** #491

## Context

`DaemonClient.replaceDaemon` (`app/Sources/TarmacKit/DaemonClient.swift`) calls `kill(pid, SIGTERM)` itself. The pid is the result of `DaemonLaunch.restartTarget`: first `hello_ok.daemon_pid` from the socket, then the child the client spawned. It is the only call of `kill(2)` under `app/Sources/`.

`DaemonClientTests` run that call for real. A test that expects no restart still gives the client a pid: `testMessagesReachTheAppInOrder` pushes the literal `daemonPid: 4242`, and two more tests push the pid of a `/bin/sleep` they started.

## Motivation

One wrong expression in `TarmacKit` sends a real signal from a unit test to a process the test does not own:

- `shouldRestart` with `==` for `!=` sends SIGTERM to pid 4242, whatever that is on the machine.
- `restartTarget` returning -1 reaches `kill(2)`, where -1 is every process of the user: the installed Tarmac and its daemon too.

No such fault is in the tree. A broken work-in-progress change makes one, and a mutation-testing run makes them on purpose (#501).

## Proposed Solution

### Overview

The client gets the function that sends a signal from its caller. `TarmacKit` holds no call of `kill(2)`. The tests give the client a sender that records each request and delivers it only to a child of the test process, so the restart behaviour is still tested with a real process and a real signal.

### Key Components

- **`DaemonClient.init(…, signal:)`** — a new parameter with **no default**, of type `DaemonClient.Signal` = `@Sendable (pid_t, Int32) -> Void`. `replaceDaemon` calls it with the restart target and `SIGTERM`. No default: each caller must choose, and a test cannot get the real sender by leaving an argument out.
- **`AppController.daemonClient()`** (`TarmacApp`) — passes the real `kill`. It is the one place under `app/Sources/` that calls `kill(2)`.
- **`tarmac-smoke`, `tarmac-term-demo`** — pass a sender that does nothing. Both name no app version, so they restart nothing today.
- **`scripts/check/arch.mjs`** — a new entry of `RULES`: a call of `kill(` or `killpg(` in a Swift file under `app/` is a finding, except in `app/Sources/TarmacApp/AppController+Connection.swift` and `app/Tests/TarmacKitTests/OwnChild.swift`.
- **`app/Tests/TarmacKitTests/OwnChild.swift`** — the fence, and the one file under `app/Tests/` that calls `kill(2)`. `OwnChild.signal(pid, signal)` sends only to a child of the test process and returns false otherwise; test clean-up uses it. `FencedSignal` is the sender a test gives the client: it records every request, and passes it to its delivery function only when the pid is greater than 1 and its parent, as the kernel reports it (`proc_pidinfo`), is the test process. The delivery function is an init parameter: `makeClient` gives `kill`, and the "Fenced sender refuses unsafe pids" tests give a recorder, so a broken fence in "Fenced sender refuses unsafe pids" signals nothing. `tearDown` fails the test when the fence of a client from `makeClient` refused a request.

### Interface Contract

```swift
extension DaemonClient {
    public typealias Signal = @Sendable (_ pid: pid_t, _ signal: Int32) -> Void
}
public init(socketPath: String? = nil, channel: …, appVersion: …, environment: …, executableDir: …,
            timing: …, deliveryQueue: …, signal: @escaping Signal)
```

Product behaviour does not change: the app sends the same signal to the same pid at the same point.

### What may reach `kill(2)` (closed list)

| Path | Held by |
| --- | --- |
| `TarmacApp`'s wiring, with the pid from `restartTarget` | the arch rule ("Arch check refuses kill calls outside two files"); the shell has no unit tests by design |
| A test's clean-up of a process it spawned (`tearDown`, `DaemonSpawnerTests`); those pids come from `DaemonSpawner.spawn` and `spawnedDaemonPid`, which are `TarmacKit` code | the same fence: `OwnChild.signal`, the one call of `kill(2)` under `app/Tests/` ("Fenced sender refuses unsafe pids", "Fenced sender signals a live child", "Arch check refuses kill calls outside two files") |
| `FencedSignal`, for a child of the test process | "Fenced sender refuses unsafe pids", "Fenced sender signals a live child" |

`DaemonLaunch.swift` holds decisions only and calls nothing. `DaemonSpawner.swift` starts a program whose path the test gives; it sends no signal.

## Alternatives Considered

### A default of the real `kill`

The issue's first wording. Every test that leaves the argument out then stays on the real `kill(2)`, and the 4242 test is such a test.

### A recorder that delivers nothing

`testAStaleDaemonWithoutAPidIsTheSpawnedChild` needs the spawned child to die before the client may spawn again, and two tests assert the signal that killed the process. A recorder alone loses that coverage or needs a second, fake notion of "dead".

## Acceptance Scenarios

### Happy Path
- **Handshake with other daemon version sends SIGTERM:** Given a daemon that reports another version and the pid of a child of the test, when the client handshakes, then the sender's requests are exactly `[(that pid, SIGTERM)]` and the child dies of SIGTERM.
- **Handshake with same version sends no signal:** Given a daemon of the app's own version that reports a pid, when the client handshakes, then the sender gets no request. The same for an app that names no version, and for `testMessagesReachTheAppInOrder` (pid 4242).
- **Stale daemon without pid gets SIGTERM via spawn:** Given a stale daemon that reports no pid and is the child the client spawned, when the client handshakes, then the sender gets exactly one request: SIGTERM to the pid of the first launched fake daemon (its script records `$$`, and `exec` keeps that pid). The fence delivers it, and the fake daemon is launched a second time.

### Edge Cases
- **Fenced sender refuses unsafe pids:** Given a fenced sender with a recording delivery function, when it is asked to signal pid 0, 1, -1, the test process itself, the parent of the test process, or the pid of a child the test spawned and reaped, then it records the request, its delivery function gets no call, and it reports the request as refused.
- **Fenced sender signals a live child:** Given the fenced sender with `kill`, when it is asked to signal a live child of the test process with SIGTERM, then the child dies of SIGTERM and the request is not refused.

### Error Scenarios
- **Arch check refuses kill calls outside two files:** Given a Swift file under `app/` (sources or tests) other than `Sources/TarmacApp/AppController+Connection.swift` and `Tests/TarmacKitTests/OwnChild.swift`, with a call of `kill(` or `killpg(` (also as `Darwin.kill(`), when `make arch-check` runs, then it fails and names the line. A `//` comment, `skill(`, `kill_all(`, and a Swift file outside `app/` are not findings. A module prefix (`Foundation.kill(`) and backticks are findings.
- **Tree of this change passes arch check:** Given the tree of this change, when `make arch-check` runs, then it passes.

## For the Implementing Agent

> **Your job:** make every acceptance scenario above pass with tests that would *fail if the behavior were wrong*.

Safety order: the fence ("Fenced sender refuses unsafe pids") goes in and passes before any knockout of `shouldRestart` or `restartTarget` is run. On the tree before this change such a knockout signals a foreign pid.

- **Behavioral over structural** — assert the requests and the signal that killed the process, not internals.
- **Every test can fail.**
- **Deterministic, isolated, readable.**

## Definition of Done

- [ ] `make test` is green; `make lint` and `make fmt-check` are clean.
- [ ] Every acceptance scenario maps to at least one test.
- [ ] Knockouts, run only after "Fenced sender refuses unsafe pids" passes: `shouldRestart` with `==` makes "Handshake with same version sends no signal" fail with a recorded request and no foreign signal; `restartTarget` returning -1 makes a test fail with a refused request.
- [ ] No call of `kill(` under `app/Sources/TarmacKit/`.

## Trade-offs and Limitations

- The fence trusts `proc_pidinfo`. A child that has exited and was reaped can have its pid reused by a foreign process; that process is not a child of the test, so the fence refuses it.
- The arch rule reads text, one line at a time. It does not see `kill` called through another name (`let k = kill`), a call with `kill` and `(` on two lines, code after a `//` inside a string, or `posix_spawn` of `/bin/kill`. It reports a call inside a `/* */` comment, and a method of that name on any type.
- This lifts one of the conditions of #501. It does not make a third-party mutation tool safe to install on a developer Mac.
