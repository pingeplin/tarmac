**Date:** 2026-11-21

**Author:** EP Lin

**Branch:** `feat/443-doc-reading-column`, from `main` at `92c41b4`.
**Design:** [2611.0020](../../docs/designs/2611.0020_markdown_card_reading_layout.md), slice 1 (O1–O3, design D1–D7). Decision ids in this spec are its own: spec D8 (theme tokens) has no design counterpart and is not the design's D8. No wire change.

## Gate

The owner's decisions O1–O3 of design 2611.0020 bind this spec: a 46em centered text column; tables and code blocks up to 1040px, centered, with sideways scroll in their own box; text columns of a table at least about 220px; the table look of board `Tables` treatment 4.

## Context

- **Page.** `app/Sources/TarmacApp/Resources/DocTemplate.html`. `.doc-prose` is `width: calc(var(--card-w) * K)`, `max-width: calc(720px * K)`, padding `18px·K 22px·K`, left-aligned. `pre` is `pre-wrap`. There is no table CSS.
- **Scale.** The prose is laid out at K = 3 times its size and scaled by `zoom / K`. So a length written as `N px·K` (`calc(Npx * var(--oversample-k))`) is N px on the board, and a bare `1px` is 1/3 px on screen at zoom 1. The link underline today is a bare `1px`.
- **Script.** `Resources/Web/doc-render.js`: `render(markdown)` parses with the global `marked` into a `<template>`, re-addresses images, then moves the content into `#prose`. `DocWebView.scripts` loads `marked.umd.js` then `doc-render.js` into the card's content world. `Package.swift` copies all of `Resources/Web`, so a new file there ships with no packaging change.
- **marked tables.** The bundled marked is v18.0.5. `marked.lexer` gives a `table` token with `header` and `rows`; each cell has `align` and inline `tokens` (`codespan`, `text`, `strong`, …). `new marked.Marked()` makes an instance whose `use({renderer: {table}})` override sees that token and can call `marked.Renderer.prototype.table` for the default markup (checked with node on the bundled file, 2026-11-21). A raw HTML `<table>` is an `html` token and is never a `table` token. The default renderer writes a bare `<table>` with `<thead>` and, when there are body rows, `<tbody>`. A column's alignment (`:---`, `:---:`, `---:`) is an `align="left"` / `align="center"` / `align="right"` attribute on each `th` and `td`, never a `style`. A presentational `align` loses to any author `text-align` rule.
- **Theme tokens on the page.** `ThemeCSS.properties` gives `--bg1`, `--bg2`, `--term-bg`, `--text`, `--prose-text`, `--agent`, `--agent-dim` and `color-scheme`. There is no `--line` and no `--muted`. `Palette` has `line` and `muted` for every theme.
- **Document size.** `FontSizeRule.document` is 10…24px, standard 14. At 23px and up, 46em is wider than 1040px.
- **Tests.** `DocTemplateTests` reads the template text: no colour literal (S17: no hex, no `rgb(`/`rgba(`), `--oversample-k: 3`, no `14px` in the `.doc-prose` rule. `ThemeCSSTests` pins the names and values of the properties in four tests. No suite runs `doc-render.js`. `CardShimTests` runs the shipped `card_shim.js` in a `JSContext` read from the source tree, with an `exceptionHandler` that fails the test.

## Decisions

- **D1. The column.** The text column is `min(46em, the prose width less 2 × 22px·K)` wide and centered in the prose box. `em` is the font size of `.doc-prose` (`--prose-size · K`). The value `46em` appears once in the template, in the `.doc-prose` rule, and is resolved there, so a child's font size cannot change it. (An `em` inside an unregistered custom property resolves at each element that uses it, not where it is declared. So `46em` is used only in the `.doc-prose` rule, or the property is registered with `@property` as a `<length>`.) Every block of the doc (heading, paragraph, list, blockquote, `hr`, image) has its left edge on the column's left edge, as today on the prose's padding edge. The `720px` limit goes. Block spacing stays what it is today: the vertical margins of the blocks still collapse (the implementation uses padding on `.doc-prose`, or a grid with spacing that gives the same result; the choice and the spike that chose it go in the PR).
- **D2. Wide blocks.** `.doc-table` and `pre` are wide blocks. A wide block is at least the column width, at most `min(1040px·K, the prose width less 2 × 22px·K)`, and between those it is as wide as its content needs. It is centered on the column's center. Content wider than its maximum scrolls sideways inside the block. When the column is wider than that maximum (Document size 23px and up on a wide card), the column width wins: a wide block is never narrower than the column. The page itself never scrolls sideways.
- **D3. Table wrapper.** `doc-layout.js` (D5) renders each markdown table (a `table` token) as `<div class="doc-table">` + marked's default table markup + `</div>`. This includes a table with no body rows and a table inside a list item or a blockquote. The wrapper is the scroll box and draws the outer border, so the border does not scroll away. A raw HTML `<table>` is not a `table` token: it gets no wrapper and no table rule of this spec (every rule selects inside `.doc-table`), so it looks as it does on `main`.
- **D3a. Nested wide blocks.** Only a wrapper or a `pre` that is a direct child of `.doc-prose` breaks out to the D2 width. One inside a list item or a blockquote stays in its container: its left edge on the container's content edge, at most the container's width, with its own sideways scroll.
- **D4. Table look.** Every line is `calc(1px * var(--oversample-k))` thick (1px on screen at zoom 1); below, "1px" means that. `.doc-table`: `1px solid var(--line)`, radius `8px·K`. `table`: `border-collapse: collapse`, `width: 100%`. `th`: font size `0.82em`, weight 500, colour `var(--muted)`, background `var(--bg2)`, `white-space: nowrap`, bottom border `1px solid var(--line)`. `td`: top border `1px solid var(--line)` from the second body row on (a line between rows, none at the outer edge). `th` and `td`: padding `8px·K 12px·K`, `text-align: left`, `vertical-align: top`. A cell with `align="center"` or `align="right"` keeps that alignment: the template has a `text-align: center` rule for `[align="center"]` and a `text-align: right` rule for `[align="right"]`, each at least as specific as the left rule and after it. No vertical line between cells. `code` inside a cell: `white-space: nowrap`.
- **D5. Text columns.** New file `Resources/Web/doc-layout.js` defines `tarmacDocLayout` on the global object. It uses no DOM, so it loads in a bare `JSContext` after `marked.umd.js` with no exception.
  - **API.** `tarmacDocLayout.render(markdown)` returns the HTML string of the doc: the global `marked`'s output, except that every `table` token is rendered by D3 and D5. It uses its own `new marked.Marked()` instance, so the global `marked`'s options are not changed. `doc-render.js` calls it in place of `marked.parse`. `tarmacDocLayout.textColumns(table)` takes a `table` token and returns the rule's answer.
  - **A cell's prose.** Walk the cell's inline tokens in order: a `codespan` adds nothing; a token with `tokens` (`strong`, `em`, `del`, `link`) adds its children's prose; a `text` or `escape` token adds its `text`; a `br` adds one space; any other token adds nothing. The result is trimmed with `String.prototype.trim`.
  - **Width.** A prose's width is the sum over its code points of 2 for an East Asian wide or fullwidth character and 1 for any other. Wide means a code point in one of these ranges: U+1100–115F, U+2E80–303E, U+3041–33FF, U+3400–4DBF, U+4E00–9FFF, U+A000–A4CF, U+AC00–D7A3, U+F900–FAFF, U+FE30–FE4F, U+FF00–FF60, U+FFE0–FFE6, U+1F300–1F64F, U+1F900–1F9FF, U+20000–3FFFD.
  - **Rule.** Entry `i` of the answer is true when some body row's cell `i` has a prose width of 40 or more. The answer has one entry per header cell. Header cells do not count.
  - **Markup.** Every `th` and `td` of a true column gets `class="doc-text-col"` (header row included). Other cells are marked's default markup unchanged (an `align` attribute stays).
  - **Look.** A `.doc-text-col` cell is at least `220px·K` wide when the table is laid out. The template gives it `min-width: calc(220px * var(--oversample-k))`. If a spike shows that WebKit ignores `min-width` on a table cell, the rule uses `width` with the same value (the auto table layout treats a cell's `width` as its minimum), and the PR records the spike.
  - `DocWebView.scripts` loads `marked.umd.js`, `doc-layout.js`, then `doc-render.js`.
- **D6. Code blocks.** `pre`: `white-space: pre`, `overflow-x: auto`, `word-break: normal`. A long code line does not wrap (a behaviour change from `pre-wrap`).
- **D7. Scroll bar.** A wide block that scrolls shows a thin horizontal scroll bar that is always visible: `::-webkit-scrollbar` height `8px·K`, thumb `var(--muted)` with a radius, track transparent. The `::-webkit-scrollbar` rules select only `.doc-table` and `.doc-prose pre`, so the page's vertical scroll bar stays hidden as today. A wide block whose content fits shows no scroll bar.
- **D8. Tokens.** `ThemeCSS.properties` adds `--line` (`palette.line`) and `--muted` (`palette.muted`), directly after `--bg2`. They follow a theme change as every token does (`DocWebView.themeChanged` sends all of `properties`). This changes the existing `ThemeCSSTests` assertions; the PR lists each one:
  - `testS15TheLightDeclarationsAreTheEightOfTheContractInOrder` is renamed for ten declarations.
  - `names` (used by S15 light, S15 dark and 2610.0008 S28) gains `--line`, `--muted` after `--bg2`.
  - S15 light values gain `#b4b9be`, `#535d66`; S15 dark gains `#474e55`, `#b9bfc4`; 2610.0008 S28 latte gains `#acb0be`, `#55586e`, each after the `--bg2` value.
  - S16 (`page` with the light palette) also checks `--line: #b4b9be;` and `--muted: #535d66;`.

### Template (`DocTemplateTests`)

A "rule" is the text between `{` and `}` after a selector list in the template's `<style>`. A rule "for `X`" is one whose selector list has the selector `X`.

- **S1 (column once)** [auto]: Given the template, then `46em` occurs exactly once, inside the `\n  .doc-prose {` rule, and `720px` does not occur.
- **S2 (wide cap)** [auto]: Given the template, then the rule for `.doc-prose > .doc-table` and the rule for `.doc-prose > pre` (the direct children, D3a) each have a `max-width:` whose value contains `calc(1040px * var(--oversample-k))`, or is `var(--name)` where the `.doc-prose` rule declares `--name` with a value that contains it.
- **S3 (table look)** [auto]: Given the template, then:
  - the rule for `.doc-prose .doc-table` (or `.doc-table`) has a `border:` with `solid var(--line)`, a `border-radius: calc(8px * var(--oversample-k))` and `overflow-x: auto`;
  - the rule for `.doc-table th` has `var(--bg2)`, `var(--muted)` and `white-space: nowrap`;
  - a rule for `.doc-table td code` (or `.doc-table th code, .doc-table td code`) has `white-space: nowrap`;
  - every rule whose selector names `th` or `td` has `.doc-table` in that selector (a raw HTML table is untouched, D3);
  - every `border` width in a rule for `.doc-table`, `th` or `td` is `calc(1px * var(--oversample-k))` (D4);
  - no rule in the template has `border-left`, `border-right` or `border-inline`.
- **S4 (code blocks)** [auto]: Given the template, then the rule for `.doc-prose pre` has `white-space: pre;` and `overflow-x: auto;`, and `pre-wrap` does not occur in the template.
- **S5 (text column minimum)** [auto]: Given the template, then the rule for `.doc-table .doc-text-col` (or `.doc-text-col`) has `min-width: calc(220px * var(--oversample-k))` (or `width:` with that value, per D5).
- **S6 (no colour literal, still)** [auto, regression guard]: the existing S17 test passes unchanged. It passes on `main` too; it guards that the new rules use only tokens (`transparent` is allowed).
- **S25 (column alignment)** [auto]: Given the template, then a rule for `.doc-table [align="center"]` (or `.doc-table th[align="center"], .doc-table td[align="center"]`) sets `text-align: center`, a rule for the `right` form sets `text-align: right`, and both come after the rule that sets `text-align: left`.

## Spike results (2026-11-21, a throwaway dev app at zoom 0.5)

- **D1:** padding on `.doc-prose` (`max(22px·K, (card-w·K − 46em) / 2)`) centers the column; normal block flow, so margins collapse as before.
- **D2:** a direct-child wide block with `position: relative; left: 50%; transform: translateX(-50%); width: max-content; min-width: 100%; max-width: <cap>` breaks out and centers; a table that fits stays the column width.
- **D5:** `min-width` on a `td` works in WebKit's auto table layout (the `Does` column held 220).
- **D7:** `::-webkit-scrollbar` on `.doc-table` and `pre` draws an always-visible bar in the scaled layout, and a sideways wheel over the focused card scrolls the box.
- Not seen at zoom 0.5: the left and right outer border of the too-wide table. QA S19 checks it at zoom 1.
