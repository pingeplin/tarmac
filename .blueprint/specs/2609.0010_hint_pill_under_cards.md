# 2609.0010 Occluded offscreen-hint pills paint under cards

**Date:** 2026-09-08
**Status:** final
**Author:** EP Lin
**Issue:** [#126](https://github.com/pingeplin/tarmac/issues/126) `fix(board): offscreen-hint pill paints over a card when no free edge gap exists`

## Context

An offscreen signalling card gets a wayfinding pill pinned to the viewport edge toward it
(`desktop/src/ui/OffscreenHints.tsx`, laid out by `stackPills()` in
`desktop/src/kit/offscreenHints.ts`). Since #64 / PR #65 the layout treats every visible card rect
as an obstacle and searches the edge band for a free gap.

That search is **best-effort by contract**. When the cards saturate the band,
`resolveAlongPos()` returns the clamped desired position anyway (`return best ?? clampedDesired`)
and the pill is emitted at a spot it already knows is occupied. Paint order then decides the
outcome, and today it decides against the card: `.offscreen-hints` is `z-index: 40`
(`desktop/src/theme/chrome.css:96` on `main` — every line reference in this section is
main-relative) inside `.board-stack`, while its sibling `.board` is an isolated stacking context at
`z-index: auto` (`desktop/src/theme/app-only.css:42`). The pill's opaque `var(--bg2)` body lands on
top of the card and hides its content.

The two earlier rounds moved the pill; this one changes who wins when it cannot move.

## Motivation

A wayfinding hint that hides the thing you are working in is a net loss: the board's whole claim
is that every mark on screen is backed by an observable fact, and a hint occluding a live terminal
trades a real fact (what the terminal is printing) for a redundant one (a card exists offscreen —
already carried by the minimap and by the Return-fly). Cards are the content; hints are furniture.
Furniture yields.

## Proposed Solution

### Overview

`stackPills()` already knows, per pill, whether it managed to find a spot clear of every card. Make
that fact explicit as `PlacedPill.occluded`, and let the view paint the two classes in two layers:

- **not occluded** -> the existing `.board-stack` overlay, above every card. Byte-for-byte the
  behaviour on `main`.
- **occluded** -> a second mount of the same component *inside* `.board`, between `<EdgeLayer>` and
  `.card-layer`, so the pill hides behind the card it could not avoid.

The placement algorithm itself — the gap search, the sibling stacking, the clamping, the priority
rule and the Return-fly target — is unchanged. Only the reporting of the result and where each pill
is painted change.

### Key Components

- **`desktop/src/kit/offscreenHints.ts`** — `PlacedPill` gains `occluded: boolean`, set in
  `stackPills()` by testing the pill's **rounded, painted** rect against the raw obstacle rects
  (`rectsIntersect`), not against the `stackGap`-padded intervals: `occluded` means *this pill
  covers card content*, not *this pill is near a card*.
- **`desktop/src/App.tsx`** — the `offscreen` useMemo returns `pillsOver` / `pillsUnder` instead of
  one `pills`; keeps `<OffscreenHints pills={offscreen.pillsOver} />` in `.board-stack` exactly
  where it is today, and passes `hintPillsUnder={hidden ? [] : offscreen.pillsUnder}` to each
  `<Board>`.
- **`desktop/src/board/Board.tsx`** — gains `hintPillsUnder: PlacedPill[]` and renders
  `<OffscreenHints pills={props.hintPillsUnder} />` after `<EdgeLayer>` and before
  `<div className="card-layer">`.
- **`desktop/src/theme/app-only.css`** — one new rule, `.board > .offscreen-hints { z-index: 0 }`.
  The descendant selector (specificity 0,2,0) beats the base `.offscreen-hints` rule without
  touching it.
- **`desktop/src/theme/chrome.css`** — **unchanged**, which keeps the design-sync kit
  (`theme/kit.css` imports tokens + card + chrome + preview-defaults, never `app-only.css`) free of
  a rule that only means anything inside `.board`.
- **`desktop/src/ui/OffscreenHints.tsx`** — unchanged; it is mounted twice.

### Why this yields the required order

Inside `.board` (the stacking context, via `isolation: isolate`) the paint order becomes:

```
.board background (--bg0)  <  EdgeLayer (z auto)  <  .offscreen-hints (z 0)  <  .card-layer cards (z = c.z)
```

- **Cards with `z >= 1` win on z-index.** Every card created in-session gets `topZ(cards) + 1` —
  in `App.tsx`, at the `spawnNewTerminal` term-card branch and the doc-card creation branch of the
  open handler — so `z >= 1`. `topZ` itself reduces from `0` (`board/model.ts:102`).
- **Cards with `z === 0` win on tree order.** A restored tile with no `z` on the wire defaults to
  `0` (`kit/layoutTiles.ts:141,148`), which ties with the overlay's `z-index: 0`; the tie breaks in
  DOM order, and `.card-layer` is rendered *after* the overlay. Both cases are covered without
  relying on either alone.
- **Hints stay above provenance edges**: `EdgeLayer` is `z-index: auto` and precedes the overlay.
- `.offscreen-hints` is `position: absolute; inset: 0` and `.board` fills `.board-stack`, so the
  overlay's coordinate space and clip rect are unchanged — pill positions computed against
  `engine.viewportSize` (which reads the `.board` element's rect) still land where they did. The
  move makes `BoardEngine`'s existing "inset:0 over the board, so this is exactly its coordinate
  space" comment literally rather than accidentally true.

### Why lowering the z-index alone cannot work

`.board` paints an opaque `background-color: var(--bg0)`. Anything behind it — any negative
z-index on the overlay while it remains a sibling — disappears completely rather than showing
through around the cards. The under-card layer has to be *inside* the board.

### Why per-pill, and not simply demoting the whole overlay

The first cut of this change moved the single overlay under the cards and argued that pills which
*did* find a gap are unaffected, because `stackPills` builds each pill's `bandRect` across its full
cross-axis extent and filters obstacles by `rectsIntersect(bandRect, o)` — so a pill that found a
gap intersects no card's **border box**. That argument is true of the border box and false of what
is painted:

`.card` carries `box-shadow: 0 calc(16px * var(--zoom)) calc(38px * var(--zoom)) rgba(0,0,0,0.5)`
(`theme/card.css:12`; `--shadow-prime` and `--shadow-lift` are larger). At zoom 1 that reaches
**~35px below** the border box and ~19px to each side, while the obstacle padding is
`HINT_STACK_GAP = 8` and `resolveAlongPos` parks a nudged pill **flush at `card.bottom + 8`** —
the common outcome, since a pill's desired position is the projection of its card's centre and ties
in the gap search favour the forward (downward) gap. Measured consequences of demoting such a pill:

| | zoom 1 | zoom 3 |
|---|---|---|
| card above the pill | top rows washed ~0.33-0.38 alpha, fading over ~27px | whole pill washed ~0.31-0.43, uniform |
| card below the pill | 0 (the shadow reaches only 3px upward) | negligible |
| card beside the pill | ~0.15 at the near edge, gone within 11px | ~0.21, gone within 49px |

At zoom 1 that is a visible top-shading and an inconsistency against a crisp neighbour pill; above
zoom ~2.1 the whole pill sits in the shadow and the `--muted` live-pill label falls below AA
contrast. Cosmetic, but a regression for pills the fix was never meant to touch — and #126 asks for
demotion precisely "when they cannot be relocated to other available spaces". Splitting by
`occluded` costs one boolean, one CSS rule and a second mount, and leaves every non-occluded pill
identical to `main`.

### Interface Contract

```ts
// desktop/src/kit/offscreenHints.ts
export interface PlacedPill {
  // ...existing fields
  /** The placed pill still overlaps a card: the edge band was saturated and the
   *  gap search had to fall back. The view paints these UNDER the cards. */
  occluded: boolean;
}

// desktop/src/board/Board.tsx
interface BoardProps {
  // ...existing props
  /** The pills stackPills could not place clear of a card, for THIS board.
   *  App passes [] for a hidden board. */
  hintPillsUnder: PlacedPill[];
}
```

Additive only: `occluded` is a new field on an app-internal type. No wire-protocol change, no
persisted-state change, no change to `OffscreenHints`'s own props (so the design-sync kit export and
its fixtures are untouched).

## Alternatives Considered

### Demote the whole overlay (the first implementation)

Move the single overlay into `.board` under `.card-layer`; no kit change, ~15-line diff. Rejected
after review — see *Why per-pill*: card drop shadows reach 4x further than the obstacle padding, so
it silently dims pills that had found room, worst at high zoom.

### Transparent `.board` + background on `.board-stack` + `z-index: -1`

Pure CSS: move the opaque `--bg0` up to `.board-stack`, make it a stacking context, and give the
overlay a negative z-index. Rejected — action at a distance. The board's background would live on a
container two levels from anything that reads as "the canvas", and the next person to re-add
`background` to `.board` would silently delete every pill, with no test to catch it.

### React portal from `App` into the active board element

Keeps ownership in `App` and appends the under-layer into `.board`. Rejected — it needs a DOM handle
out of `BoardEngine` plus a first-render null guard, where a prop is idiomatic and typed. `Board`
already owns the other under-card furniture (`EdgeLayer`).

## Acceptance Scenarios

**On automation.** The *decision* (which pills are occluded) is pure and lives in `kit/`, so it is
unit-tested — S1. The *paint order* is app-layer CSS: `desktop/vitest.config.ts` runs
`src/**/*.test.ts` in the node environment with no jsdom and no component-testing dependency, and
the repo's position is that UI components get DOM tests "later if/when they need" them. Adding that
infrastructure for one CSS rule is not proposed, and a test that greps `Board.tsx` for element order
would be the brittle source-pinning #117 removed. So S3/S4/S5 are **human QA**, declared here so
`/verify` scores them as specified rather than as gaps.

- **S1 [G] — `occluded` reports what is actually painted.** Given `stackPills` with a set of
  obstacles, when the pills are laid out, then each pill's `occluded` equals
  `rectsIntersect(paintedRect, someObstacle)` — false with no obstacles, false for a pill nudged
  into a free gap, true when the band is saturated, and, on a saturated multi-pill edge where some
  pills clear the card and some cannot, true/false **per pill**. Automated,
  `desktop/src/kit/offscreenHints.test.ts` (`describe("occluded")`). The decisive case is a fallback
  placement that still lands clear: two stacked cards leaving a 36px raw gap — wider than the 24px
  pill, narrower than the `24 + 2*stackGap` the padded intervals demand — so the gap search fails
  and the pill falls back onto a position that covers nothing. Mutation-checked, executed: deriving
  `occluded` from `obstacles.length > 0`, from the `stackGap`-padded intervals, from "the search fell
  back", or with `every` instead of `some` each fails at least one case.

- **S2 [G] — placement itself is unchanged.** Given the change, when the pre-existing
  `offscreenHints.test.ts` cases run, then all of them pass **unedited** — the gap search, sibling
  stacking, clamping, edge projection, priority and fly-target contracts are provably untouched, and
  `git diff origin/main -- desktop/src/ui/OffscreenHints.tsx desktop/src/theme/chrome.css` is empty.
  Automated.

- **S3 [QA] — an occluded pill paints under the card.** Given a board with two terminal cards, when
  card A's centre is panned offscreen past the right edge and card B is then resized (without
  panning again) to span the full viewport height flush against that same edge, then A's pill is
  hidden behind B — B's content fully legible, no pill drawn over it. Before this change the pill
  covers B. **Then quit and relaunch Tarmac** so the board restores from `state.json`, and repeat:
  that is the only path that produces a `z === 0` card, and therefore the only check of the
  DOM-order tie-break the code comment calls load-bearing. Human QA — the Tarmac window is not
  visible to screenshot automation, so this reading is the reviewer's.

- **S4 [QA] — a pill that found room is untouched, including next to a card.** Given the same board,
  when B is moved so it sits *inside* the right-edge band without saturating it — leaving a gap
  large enough that A's pill is nudged to rest just below B — then A's pill renders exactly as it
  does on `main`: full contrast, no shadow wash from B, above the provenance edges. Repeat once at
  high zoom (toward 3x), where a demoted pill would be visibly greyed. This is the case that killed
  the whole-overlay approach; it is the reason the split exists. Human QA.

- **S5 [QA] — a hidden board renders no pills.** Given the warm-board model (every board stays
  mounted; inactive ones are `display: none`), when the app renders, then only the active board is
  passed a non-empty `hintPillsUnder` — `hidden ? [] : offscreen.pillsUnder` at the call site.
  Verified by reading `App.tsx`; typecheck guarantees the prop exists and is typed, nothing more.

- **S8 [QA] — a partly-visible card's own pill.** Given a live terminal card panned until its centre
  is offscreen past an edge while its body still covers that edge band, when the pill is placed, then
  it is now `occluded` by its own card and hides behind it — where on `main` it painted over its own
  visible sliver (the state #58 closed as acceptable). The card itself is still on screen, so nothing
  is lost that the eye cannot already see; confirm that reading is acceptable. Human QA — this is the
  most common real-world trigger of the new path, so it wants a deliberate yes.

- **S6 [G] — the diff stays minimal.** Given the change, when the diff is reviewed, then
  `git diff --name-only origin/main` returns exactly: `desktop/src/App.tsx`,
  `desktop/src/board/Board.tsx`, `desktop/src/kit/offscreenHints.ts`,
  `desktop/src/kit/offscreenHints.test.ts`, `desktop/src/theme/app-only.css`, and this spec. In
  particular `core/`, `desktop/src-tauri/`, `desktop/src/ui/` and `desktop/src/theme/chrome.css` are
  absent.

- **S7 [G] — the suite and typecheck are green.** Given the change, when `make test` runs, then it
  passes end to end, including `tsc --noEmit` over the new field and prop. Automated.

## Trade-offs and Limitations

- **An occluded pill can be hidden entirely.** That is the intended outcome — cards win — and it is
  what #126 asks for. The signal is not lost: the Return-fly target comes from the hint set
  (`selectFlyTarget(hints)`), not from where a pill was placed, and the minimap keeps painting the
  card's bell/live colour.
- **Two mounts of one component.** The cost of keeping non-occluded pills identical to `main`: the
  same overlay is rendered in two stacking contexts, split by one boolean. A single mount inside the
  board would be simpler and is what the first cut did; the shadow measurements above are why it is
  not what ships.
- **No automated regression for the paint order.** If someone later re-parents the under-layer,
  raises its z-index, wraps it in a container (the CSS rule wants a *direct* child of `.board`), or
  swaps the two pill lists at the call sites, only QA catches it. `occluded` itself *is* covered, so the half of the fix that
  can be tested is tested; the CSS half is accepted as QA rather than importing jsdom for a
  structural assertion.
