# 2609.0016 Hold ⌘Q to quit

**Date:** 2026-09-17
**Status:** accepted
**Author:** EP Lin
**Issue:** [#171](https://github.com/pingeplin/tarmac/issues/171)
**Design doc:** [2609.0016](../../docs/designs/2609.0016_hold_to_quit.md) (approved)

## Context

One ⌘Q slip (Q sits next to W, and ⌘W closes a card) quits the cockpit
mid agent-run. The red button quits too, through the last-window exit path.
The approved design adopts Chromium's confirm-to-quit. A keyboard ⌘Q shows a
"Hold ⌘Q to Quit" notice. Holding it for 500 ms, or a second tap within 1 s,
quits on release. An app-menu toggle turns the guard off, and the red button
hides the window instead of quitting. Read the design first. This spec keeps
its decision, turns it into testable behaviour, and records what investigation
changed.

**Verified before writing this spec.** Five read-only investigators and one
empirical harness checked these claims on `feat/171-confirm-quit-live-terminal`
@ 08715c9 (= `main` cf09edc plus the design). The crates are tauri 2.11.3,
tauri-runtime-wry 2.11.3, tao 0.35.3, muda 0.19.3, wry 0.55.1, objc2 0.6.4 and
objc2-app-kit/-foundation/-core-graphics 0.3.2. Line numbers are current.

1. **A kitty keyboard program swallows ⌘Q before the menu can see it.**
   Measured in the main checkout's `.dev/key-harness/quit171/quit.cjs`, not
   this worktree's `.dev/` (Playwright WebKit, the worktree's xterm
   6.1.0-beta.288 and `kit/termKeyRoute.ts`). With a terminal
   focused and kitty flags 1 or 5 (Claude Code pushes 5; by source, any flag
   set including bit 1, 2 or 8, `KittyKeyboard.ts:486-503`), xterm encodes
   ⌘Q as `ESC[113;9u`. The same happens to ⌘H, ⌘M, ⌘A, ⌘T, ⌘C without a
   selection, ⇧⌘Q and ⌥⌘Q. In each case xterm calls `preventDefault` on the
   textarea (`CoreBrowserTerminal.ts:887-890, 927-929`;
   `KittyKeyboard.ts:212-213, 499-507`). WebKit then treats the keydown as
   handled and never re-sends it to the native menu (`WebViewImpl.mm:5880-5900`).
   - The cause is `xtermHandlesKey` (`kit/termKeyRoute.ts:42-51`). It returns
     `true` for every ⌘ chord except ⌘V and ⌘C with a selection.
   - With flags 0 (a plain shell), xterm emits nothing for these chords and
     cancels nothing. That matches spike v3.
   - **So the guard, and today's plain Quit, never fire while Claude Code has
     focus.** Design constraint 7 holds only for a plain shell.
   - A capture-phase listener that only calls `stopPropagation` keeps xterm
     out, and the keydown stays uncancelled.
2. **How a keyboard ⌘Q reaches the Quit item.** WebKit claims the keydown and
   round-trips it to the page. If the page leaves it unhandled, WebKit re-sends
   the same `NSEvent` object through `[NSApp _setCurrentEvent:]` +
   `[NSApp sendEvent:]` (`WebViewImpl.mm:5880-5900`), and the main menu matches
   it. No traced path calls the Quit action twice for one keyDown, but that
   rests on AppKit's closed dispatch order. S20 hardens against it.
3. **Nothing re-installs the app menu after `build()`.** Only
   `AppHandle::set_menu`/`remove_menu`, `Menu::set_as_app_menu`, or the JS
   `set_as_app_menu` command (allowed by `core:default`) replace it. muda never
   resets an item's target or action (muda `macos/mod.rs:473-554`).
4. **The default app submenu** is `items()[0]`. Its id is an auto-generated
   counter (muda `macos/mod.rs:333`), so reach it by position, never by id:
   - About, separator, Services, separator, Hide ⌘H, Hide Others ⌥⌘H,
     separator, **Quit ⌘Q (last)**;
   - Quit's action is `terminate:`, with no target.

   Under `make run` the titles read "tarmac-app", so match the item by action,
   never by title. All muda menus set `autoenablesItems = NO`.
5. **muda flips a `CheckMenuItem` itself** before it sends `MenuEvent`
   (muda `macos/mod.rs:1125-1130`). `on_menu_event` reads the new state and
   must not toggle it again.
6. **`AppHandle::exit(0)`** emits `ExitRequested { code: Some(0) }`, then
   `RunEvent::Exit`. It sends **no `CloseRequested`** to any window (tauri
   `app.rs:574-580`; tauri-runtime-wry `lib.rs:2748-2755, 4354-4366`). The
   design's `quitting` flag is therefore dead weight, and this spec drops it.
   - `terminate:` arrives only as `RunEvent::Exit` through tao's
     `applicationWillTerminate:`.
   - **Calling `NSApplication::terminate` inside a tao/tauri callback** (a
     `run_on_main_thread` closure, `on_menu_event`, a `RunEvent` handler) can
     deadlock. `applicationWillTerminate` → `AppState::exit` re-locks tao's
     callback mutex (tao `app_state.rs:203-217, 272-282`). Calling it from the
     retargeted AppKit action is safe (spike v3's click-to-terminate).
7. **Red button.** tao's `windowShouldClose:` returns NO and queues
   `CloseRequested`. With `api.prevent_close()` the window is never destroyed,
   so `ExitRequested { code: None }` never fires. tao implements no
   `applicationShouldTerminateAfterLastWindowClosed:`. `hide()` is `orderOut`.
   `set_focus()` does nothing unless the window is visible and not minimized,
   so call `show()` first.
8. **Reopen.** The event is `RunEvent::Reopen { has_visible_windows, .. }`
   (`#[non_exhaustive]`). `Builder::run(ctx)` is literally
   `self.build(ctx)?.run(|_, _| {})` (tauri `app.rs:2449-2452`).
9. **Activation.** `NSApplicationDidBecomeActiveNotification` is exposed under
   objc2-app-kit feature `NSApplication`. tao registers nothing for it. An
   inactive-app Dock click posts it **and** `Reopen`, so the restore must be
   idempotent. It also posts at launch. Showing a notice never posts it,
   because Tarmac is already active.
10. **Clock.** `NSEvent.timestamp`, `NSProcessInfo.systemUptime` and
    `clock_gettime(CLOCK_UPTIME_RAW)` share one base: seconds since boot,
    excluding sleep. A probe on this Mac agreed within 2 µs. `libc` is already a
    dependency.
11. **Key state.** `objc2_core_graphics::CGEventSource::key_state(CGEventSourceStateID::CombinedSessionState, u16) -> bool`
    (features `CGEventSource`, `CGEventTypes`, `CGRemoteOperation`). No
    permission requirement is documented, and check Q8 gates it.
12. **Notice panel.**
    - Borderless + `NonactivatingPanel` is a valid NSPanel mask.
    - `hidesOnDeactivate` has no documented default (`NSWindow.h:416`). A
      Swift probe on this Mac read YES for a plain NSPanel and NO for one
      created with `NonactivatingPanel`. Set it to NO explicitly anyway: if it
      is YES, ⌘Tab mid-hold removes the notice.
    - Post the VoiceOver announcement on `NSApp`, because `mainWindow` is nil
      while the window is hidden.
    - `NSMenuItem.target` is **weak**, so the target object must live for the
      app's lifetime.
13. **Threads.** `AppHandle::run_on_main_thread` runs inline on the main
    thread and goes through the event-loop proxy otherwise
    (tauri-runtime-wry `lib.rs:235-248`). It returns `Err` once the loop has
    exited. A non-async `#[tauri::command] fn` runs inline on WebKit's scheme
    handler thread, the main thread.
14. **Toggle storage.** `app.path().app_config_dir()` resolves from the
    `tauri.conf.json` identifier, so the dev and installed apps would share it.
    The daemon socket's parent directory keeps them apart:
    - `<worktree>/.dev/` under `make run`;
    - `~/Library/Application Support/tarmac/dev/` for an unpinned debug build;
    - `~/Library/Application Support/tarmac/` in release.

    `bridge.rs`'s `daemon_log_path()` already uses it (`bridge.rs:637-640`).
15. **The switcher gate** (`App.tsx`):
    - Line 1271 skips `stopPropagation` only for
      `metaKey && key.toLowerCase() === "q"`.
    - Line 1406 skips `preventDefault` only for
      `metaKey && (key === "q" || key === "Q")`.
    - The design's `App.tsx:1395-1399` citation is stale.

    Letting ⌘V through while the switcher is open would paste into the focused
    terminal: xterm listens for `paste` on its textarea without capture
    (`CoreBrowserTerminal.ts:378-380`).
16. **The snapshot's top-level keys are pinned** by
    `desktop/src/kit/devSnapshot.test.ts:49-58`, and `devUntil` already parses
    `true`/`false`.

## Motivation

A slip costs the user their place in every open board, and after a
`brew upgrade` it also restarts every shell (#172). Finding 1 shows that today
⌘Q is dead while Claude Code has focus, and so are ⌘H and ⌘M. Without the
kitty change below, the guard would be missing in the issue's headline case.

## Proposed Solution

### Overview

The design's mechanism is unchanged:
- retarget the native Quit item;
- decide in a pure `QuitGuard`;
- poll the triggering key's state off the main thread;
- show a non-activating notice;
- add an app-menu toggle;
- hide on close, and restore on activation or `Reopen`.

This spec adds three things and drops one:

- **Adds a kitty route.** While a kitty program is active, every ⌘ chord on a
  character key, except plain (no ⌃/⌥) ⌘C without a selection, stands aside
  from xterm, so the native menu's key
  equivalents (Quit, Hide, Minimize, Full Screen, Edit) decide. Approved on
  2026-09-18 (see *Open Questions*): it reverses #152/#154's "other ⌘ chords
  stay with kitty programs".
- **Adds a switcher gate.** While the switcher is open, every non-composing
  keydown that reaches the switcher block stops propagating. Only non-⌘ keys the switcher doesn't handle are cancelled.
  While it is open, a capture-phase `paste` listener stops every paste.
- **Adds a snapshot report.** `tarmac dev snapshot` reports
  `quit_guard: { retargeted, enabled }`, and `make qa` asserts `retargeted`.
- **Drops the `quitting` flag** (finding 6).

### Key Components

- **`desktop/src-tauri/src/quit_guard.rs`** (new, pure, unit-tested). Holds the
  `QuitGuard` state machine, `route`, `shortcut_label`, `notice_text` and the
  timing constants. It uses no AppKit types.
- **`desktop/src-tauri/src/app_prefs.rs`** (new). Pure functions resolve the
  prefs path and decode/encode the toggle. A thin std::fs read and an atomic
  write (tmp + rename) sit beside them.
- **`desktop/src-tauri/src/window_lifecycle.rs`** (new, pure). `HiddenByClose`
  records whether the red button hid the window, and hands out the restore
  exactly once.
- **`desktop/src-tauri/src/quit_notice.rs`** (new). The pure part is the
  notice frame and screen choice, with tests at the bottom. The AppKit part is
  the lazily created `NSPanel`: fade, generation counter and announcement.
- **`desktop/src-tauri/src/quit_intercept.rs`** (new, AppKit wiring). It
  contains:
  - the `QuitTarget` `define_class!` object, alive for the app's lifetime;
  - `tarmacQuit:`, which reads `[NSApp currentEvent]` and the **sender** item's
    live `keyEquivalent`/mask, calls `route`, then applies effects;
  - `appDidBecomeActive:`, a selector observer on the default
    `NSNotificationCenter`;
  - the retarget walk;
  - the key-state poller;
  - the debug log;
  - the `#[cfg(debug_assertions)]` command `dev_quit_guard`.
- **`desktop/src-tauri/src/lib.rs`**:
  - `Builder::menu` (default menu plus the check item);
  - `on_menu_event`;
  - `on_window_event(CloseRequested)`;
  - `.build(ctx).expect(..).run(|app, ev| …)` for `Reopen`;
  - `.setup()`, which installs the intercept.
- **`desktop/src-tauri/src/bridge.rs`** gains `pub(crate) fn app_prefs_path()`
  beside `daemon_log_path()`.
- **`desktop/src/kit/termKeyRoute.ts`** gets the kitty ⌘ rule.
  **`desktop/src/kit/boardSwitcher.ts`** gets
  `switcherCancelsUnhandledKey`.
- **`desktop/src/App.tsx`** changes in three places:
  - the switcher's `stopPropagation` becomes unconditional (line 1271);
  - the fallthrough `preventDefault` goes through the kit predicate
    (line 1406);
  - a capture-phase `paste` listener is added next to the keydown listener
    (lines 1526-1532). While the switcher is open it calls `stopPropagation`
    and `preventDefault` on every paste; closed, it does nothing. Cancelling

- **Dev snapshot.** `desktop/src/kit/devSnapshot.ts` gains

### Data Flow

1. **Startup.**
   - Read `app_prefs_path()` and compute the initial `enabled` with
     `warn_before_quit`. It lives in one shared `AtomicBool`.
   - `Builder::menu` builds `Menu::default`. It inserts
     `CheckMenuItem::with_id(handle, "warn_before_quit", "Warn Before Quitting (⌘Q)", true, enabled, None::<&str>)`
     into `items()[0]` at `len − 1`, i.e. immediately before Quit.
   - `.setup()` walks `NSApp.mainMenu` recursively for items whose action is
     `terminate:`. It sets each such item's target to `QuitTarget` and its
     action to `tarmacQuit:` (the default menu has exactly one), then adds the
     activation observer. If no such item is found, it logs
     `tarmac: quit guard disabled: no Quit menu item`, and the app still runs
     with a native Quit.
2. **A keypress or click on Quit** calls `tarmacQuit:(sender)`:
   - `currentEvent`, `now_ms` and the sender's live key equivalent and mask
     build a `QuitEvent`. A nil `currentEvent` builds `is_key_down: false`, so
     it routes `TerminateNow`.
   - `route(&ev, enabled)` decides. The debug line (step 8) is written after
     `route` and **before** its result is applied, because `terminate:` never
     returns:
     - `TerminateNow` → `NSApp.terminate(None)`, **inside this action only**;
     - `Guard` → `on_quit_key(press_ms, keyCode, isARepeat)` → apply effects.
3. **The poller**, started by `StartPolling(k)`, samples
   `key_state(Combined, k)` and `now_ms` every 50 ms. It hops to main with
   `run_on_main_thread`, calls `on_poll(sampled_ms, held)` and applies effects.
   It ends on `StopPolling` or when `run_on_main_thread` returns `Err`.
4. **Effects:**

   | Effect | What the wiring does |
   | --- | --- |
   | `ShowHud` | Shows the notice with `notice_text(item key equivalent, mask)` at full opacity, cancels any pending linger or fade (generation counter), and posts the announcement on `NSApp` |
   | `LingerThenFadeHud` | After `LINGER_MS`, fades over `FADE_MS`, then `orderOut`. A completion whose generation is stale does nothing |
   | `HideWindows` | Hides the main window, and cancels a pending linger or fade so the notice stays up until the app exits (the design's "`LingerThenFadeHud` is the only effect that removes the notice"). It does **not** touch `HiddenByClose` |
   | `StartPolling(k)` / `StopPolling` | Starts or stops the poller for key `k` |
   | `Exit` | `app.exit(0)` (never `terminate`: finding 6) |

5. **Toggle click.** muda flips the item. `on_menu_event` (id
   `warn_before_quit`) reads `is_checked()`, stores it in the `AtomicBool`, and
   writes `encode_prefs(value)` to `app_prefs_path()`. The write is
   best-effort; a failure logs `tarmac: could not save app prefs: <error>`.
6. **Red button.** `CloseRequested` → `api.prevent_close()`,
   `window.hide()`, `HiddenByClose::close_requested()`.
7. **Restore.** On `appDidBecomeActive:` or `RunEvent::Reopen`, if
   `take_restore()` returns true, call `show()` then `set_focus()`.
8. **Debug log** (`#[cfg(debug_assertions)]`): one stderr line per
   `tarmacQuit:` call:
   `tarmac: quit-key route=<guard|terminate> type=<NSEventType raw|-> repeat=<bool|-> age_ms=<n|-> press_ms=<n|->`.
   `-` means the field does not apply: `type`, `age_ms` and `press_ms` with no
   current event, and `repeat` for anything but a keyDown. `isARepeat` is read
   whenever the event is a keyDown, whatever the route.
9. **Where state lives.** Everything below is touched on the main thread only:
   - `QuitTarget`'s ivars (or a `thread_local!` / `MainThreadBound`) hold the
     `QuitGuard`, the notice panel, the poller generation, and an `AppHandle`
     clone for `exit`, `hide` and `run_on_main_thread`;
   - `Mutex<HiddenByClose>` and the `enabled` `AtomicBool` are app-managed state
     (`app.manage`), because `on_window_event`, `RunEvent::Reopen` and
     `on_menu_event` reach them through the `AppHandle`;
   - the retarget keeps the one `QuitTarget` alive in main-thread storage, and
     `dev_quit_guard` compares item targets against that same object by
     pointer.

   The guard is borrowed only for one `route` / `on_quit_key` / `on_poll` call
   and released before effects are applied. `StartPolling` bumps the poller
   generation and spawns a thread that carries it. `StopPolling` bumps it
   again. A poller exits once its generation is stale, and a hop whose
   generation is stale does nothing.

### Interface Contract

`desktop/src-tauri/src/quit_guard.rs`:

```rust
pub const HOLD_MS: u64 = 500;
pub const SECOND_TAP_MS: u64 = 1_000;
pub const FRESHNESS_BOUND_MS: i64 = 2_000;
pub const POLL_MS: u64 = 50;
pub const LINGER_MS: u64 = 1_000;
pub const FADE_MS: u64 = 200;

// NSEventModifierFlags raw bits, restated so this module needs no AppKit.
pub const SHIFT: u64 = 1 << 17;
pub const CONTROL: u64 = 1 << 18;
pub const OPTION: u64 = 1 << 19;
pub const COMMAND: u64 = 1 << 20;

#[derive(Debug, Clone, PartialEq)]
pub enum Phase {
    Idle { last_start_ms: Option<u64> },
    Showing { started_ms: u64, key_code: u16 },
    Confirming { since_ms: u64, key_code: u16 },
}
#[derive(Debug, PartialEq)] pub enum Route { TerminateNow, Guard }
#[derive(Debug, PartialEq)]
pub enum Effect { ShowHud, LingerThenFadeHud, HideWindows, StartPolling(u16), StopPolling, Exit }
pub struct QuitEvent {
    pub is_key_down: bool,
    pub modifiers: u64,            // the event's raw modifierFlags
    pub item_mask: u64,            // the Quit item's live keyEquivalentModifierMask
    pub item_key_equivalent: String,
    pub age_ms: i64,               // now_ms − press_ms; negative for a future timestamp
}
pub struct QuitGuard { /* phase, last_press_ms */ }
impl Default for QuitGuard { /* hand-written: Idle { last_start_ms: None }, last_press_ms: None */ }
impl QuitGuard {
    pub fn phase(&self) -> &Phase;
    pub fn route(&self, ev: &QuitEvent, enabled: bool) -> Route;
    pub fn on_quit_key(&mut self, press_ms: u64, key_code: u16, is_repeat: bool) -> Vec<Effect>;
    pub fn on_poll(&mut self, sampled_ms: u64, key_down: bool) -> Vec<Effect>;
}
pub fn shortcut_label(key_equivalent: &str, mask: u64) -> String;
pub fn notice_text(key_equivalent: &str, mask: u64) -> String; // "Hold {label} to Quit"
pub fn press_ms(timestamp_s: f64) -> u64;          // NSEvent.timestamp seconds → whole ms, floored; ≤ 0 or NaN → 0
pub fn age_ms(now_ms: u64, press_ms: u64) -> i64;  // now − press as signed; never panics
```

The wiring builds `QuitEvent.age_ms` only through `age_ms(now_ms, press_ms(ts))`
and never subtracts `u64`s itself. `press_ms` and `age_ms` are pure decisions,
so they are tested (S38), not treated as thin wiring.

**Rules.**

- **Keyboard Quit.** An event is a keyboard Quit iff all of these hold:
  - `is_key_down`;
  - `modifiers & (SHIFT|CONTROL|OPTION|COMMAND)` equals
    `(item_mask & (SHIFT|CONTROL|OPTION|COMMAND))`, bitwise-OR'd with `SHIFT` when
    `item_key_equivalent` is exactly one character that lowercasing changes;
  - `item_key_equivalent` is non-empty, because an item with no shortcut
    cannot be triggered by a key;
  - `0 <= age_ms <= FRESHNESS_BOUND_MS`.

  Every other modifier bit (Caps Lock, NumericPad, Help, Function) is ignored.
- **`route`.** `Guard` iff the event is a keyboard Quit and
  (`phase != Idle` or `enabled`). Otherwise `TerminateNow`.
- **`shortcut_label`.**
  - Glyphs appear in Apple's order ⌃⌥⇧⌘, taken from the mask plus the implied
    ⇧ above. Each glyph appears at most once.
  - A key equivalent carries ⇧ by the same test as the keyboard-Quit rule:
    exactly one character that lowercasing changes.
  - The key is `item_key_equivalent` uppercased.
- **Effect order.** Effects come back in the order the table lists them.
  Tests compare whole `Vec<Effect>`s.

The state table. The design's table is authoritative, with two amendments:
- **(a)** the duplicate row, which runs before every other chord row;
- **(b)** the stale rule runs before every other poll row.

"Recent" means `press_ms.checked_sub(last_start_ms)` is `Some(d)` with
`d < SECOND_TAP_MS`, a strict inequality. `None` (an older press) is not
recent. Poll arithmetic never underflows, because the stale row runs first.

| From | Input | To | Effects |
|---|---|---|---|
| any | chord, not repeat, `press_ms == last_press_ms` (same NSEvent delivered again) | unchanged | none |
| Idle, no recent start | chord, not repeat | Showing { started_ms: press } | ShowHud, StartPolling(key) |
| Idle, recent start | chord, not repeat | Confirming { since_ms: press } | HideWindows, StartPolling(key) |
| any | chord, repeat | unchanged | none |
| Idle | poll | Idle | none |
| Showing / Confirming | poll with `sampled_ms` < `started_ms` / `since_ms` | unchanged | none |
| Showing | poll, held, `sampled − started < HOLD_MS` | Showing | none |
| Showing | poll, held, `sampled − started ≥ HOLD_MS` | Confirming { since_ms: sampled } | HideWindows |
| Showing | poll, released | Idle { last_start_ms: Some(started_ms) } | LingerThenFadeHud, StopPolling |
| Showing | chord, not repeat | Confirming { since_ms: press, key_code: kept } | HideWindows |
| Confirming | chord, not repeat | unchanged | none |
| Confirming | poll, held | Confirming | none |
| Confirming | poll, released | Idle { last_start_ms: None } | StopPolling, Exit |

`last_press_ms` is set by every non-repeat chord that is not a duplicate.

**Notice panel.**
- **Window.** A borderless `NonactivatingPanel`, `Buffered` backing, created
  once and kept in main-thread storage. It sets:
  - `hidesOnDeactivate` NO, `ignoresMouseEvents` YES;
  - level `NSFloatingWindowLevel`;
  - collection behaviour `CanJoinAllSpaces | FullScreenAuxiliary`;
  - opaque NO, a clear background, and no shadow.
- **Content.** An `NSBox` of type Custom with fill
  `colorWithWhite:0.2 alpha:0.75`, corner radius 20 and no border. It holds a
  centred bold 24 pt white `NSTextField` label.
- **Placement.** The panel is framed with `notice_frame` on the `visibleFrame`
  of the screen `pick_screen` chooses.
- **Announcement.** `NSAccessibilityPostNotificationWithUserInfo(NSApp,
  AnnouncementRequested, {Announcement: text, Priority: High})`.

## Alternatives Considered

The design's alternatives A–G stand. The ones below were added after
investigation.

### Leave kitty routing alone

This costs no code, and kitty programs keep every ⌘ binding. But ⌘Q, ⌘H, ⌘M
and ⌘A stay dead while Claude Code has focus, so the guard and its toggle do
nothing in the case the issue exists for. Not chosen, but it is the named
alternative in the open decision.

### Guard only ⌘Q under kitty, by key

This would need `e.key === "q"` or `e.code === "KeyQ"`, the literal matching
the design rejected: it breaks under input sources and remaps.

### Match Quit in a local keyDown monitor with a throwaway single-item `NSMenu`

A local keyDown monitor (before WebKit) would build a detached probe menu
holding a copy of the live Quit key equivalent and mask. `performKeyEquivalent:`
would let AppKit decide whether this event is the Quit shortcut. That removes:
- the WebKit round trip;
- the freshness heuristic;
- the kitty and switcher changes;
- menu-replacement fragility.

**Not chosen here.** It changes the approved mechanism, and nobody has shown
that a detached menu matches like the menu bar under Zhuyin, Kana or a remap.
It would need spike v4 and a design amendment. Recorded as the follow-up if the
retarget's costs bite.

### NSUserDefaults or `app_config_dir()` for the toggle

`app_config_dir()` is shared between dev and installed builds (finding 14).
NSUserDefaults for the unbundled dev binary uses one `tarmac-app` domain for
every worktree. It also needs another objc2-foundation feature and unsafe code.

### Keep the `quitting` flag

`app.exit(0)` sends no `CloseRequested` (finding 6), so the flag would guard
nothing.

## Security Considerations

`app-prefs.json` holds one boolean in the per-channel support directory,
beside the daemon socket, which is created with the user's umask. It is not
secret. A crafted file can at most turn the guard off. The dev command is
compiled out of release builds.

### Edge Cases

- **S2:** A non-key event (`is_key_down: false`, modifiers `COMMAND`, age 0) →
  `TerminateNow`, with `enabled` in `Idle`. This is a menu click. A gesture
  guards only keyboard Quits: in `Showing` (after S10), the same non-key event
  and a keyDown with modifiers `OPTION|COMMAND` each → `TerminateNow`.
- **S3:** A keyDown whose ⇧⌃⌥⌘ bits differ from the item's → `TerminateNow`:
  - modifiers `0` (keyboard menu navigation's Return);
  - modifiers `OPTION|COMMAND` against a `COMMAND` item.
- **S4:** Extra bits never break a match. `COMMAND | 1<<16` (Caps Lock),
  `COMMAND | 1<<23` (Function), `COMMAND | 1<<21` (NumericPad) and
  `COMMAND | 1<<22` (Help) each → `Guard`.
- **S5:** Item `"Q"`/`COMMAND`: a keyDown with `SHIFT|COMMAND` → `Guard`, and
  one with `COMMAND` → `TerminateNow`. Item `"Q"`/`SHIFT|COMMAND` (⇧ both in
  the character and the mask): a keyDown with `SHIFT|COMMAND` → `Guard`.
- **S6 (remap):** Item `"q"`/`OPTION|COMMAND`: a keyDown with
  `OPTION|COMMAND` → `Guard`, and one with `COMMAND` → `TerminateNow`.
- **S7 (freshness):** Given an otherwise-matching keyDown:
  - `age_ms` 2_000 → `Guard`;
  - 2_001 → `TerminateNow`;
  - −1 → `TerminateNow`;
  - 28_000_000 (timestamp 0) → `TerminateNow`.
- **S8 (toggle off):** Given `enabled == false`, a keyboard Quit gives:
  - `TerminateNow` in `Idle`;
  - `Guard` in `Showing` (after S10);
  - `Guard` in `Confirming` (after S12's hold).
- **S13 (stalled poller):** Given `Showing` from a press at 10_000, when the
  first poll is `on_poll(10_700, false)`, then
  `[LingerThenFadeHud, StopPolling]` and `Idle { last_start_ms: Some(10_000) }`.
  It is a tap, never `Exit`. If that first poll is `on_poll(10_700, true)`
  instead, then `[HideWindows]` and
  `Confirming { since_ms: 10_700, key_code: 12 }`: `since_ms` is the sample,
  not `started_ms + HOLD_MS`.
- **S15 (second-tap boundary):** Given a press at 0 released by
  `on_poll(400, false)`, `on_quit_key(1_000, 12, false)` gives
  `[ShowHud, StartPolling(12)]` and
  `Showing { started_ms: 1_000, key_code: 12 }`. From the same start,
  `on_quit_key(1_050, 12, false)` gives the same effects and
  `Showing { started_ms: 1_050, key_code: 12 }`.
- **S16 (re-press while showing):** Given `Showing` from a press at 10_000 with
  key 12, when `on_quit_key(10_300, 13, false)`, then `[HideWindows]` and
  `Confirming { since_ms: 10_300, key_code: 12 }`. There is no second
  `StartPolling`, and the original key is kept.
- **S17:** Given `Confirming { since_ms: 10_500, key_code: 12 }` from S12's
  hold, `on_quit_key(10_700, 12, false)` (a non-repeat chord at a new
  timestamp) → `[]`, and the phase stays
  `Confirming { since_ms: 10_500, key_code: 12 }`.
- **S18 (repeats):** a repeat gives `[]` and leaves the phase unchanged in each
  of:
  - `Idle { last_start_ms: Some(10_000) }` after a press at 10_000 released by
    `on_poll(10_120, false)`: `on_quit_key(10_200, 12, true)`;
  - `Showing` from a press at 10_000: `on_quit_key(10_100, 12, true)`;
  - `Confirming { since_ms: 10_500, key_code: 12 }` from S12's hold:
    `on_quit_key(10_560, 12, true)`.

  A hold whose first poll already reads released cannot quit, and a second tap
  still can. Given a press at 0 released by `on_poll(50, false)`:
  - `on_quit_key(500, 12, true)`, then `on_quit_key(1_500, 12, true)`, each
    give `[]`, and the phase stays `Idle { last_start_ms: Some(0) }`;
  - `on_quit_key(500, 12, true)` gives `[]`, then
    `on_quit_key(900, 12, false)` gives `[HideWindows, StartPolling(12)]` and
    `Confirming { since_ms: 900, key_code: 12 }`.
- **S19 (stale polls):**
  - On a fresh guard, and in `Idle { last_start_ms: Some(10_000) }` after a
    press at 10_000 released by `on_poll(10_120, false)`,
    `on_poll(10_200, false)` and `on_poll(10_200, true)` each give `[]` and
    leave the phase unchanged.
  - Given `Showing { started_ms: 950, key_code: 12 }` from a fresh guard's
    `on_quit_key(950, 12, false)`, `on_poll(450, false)` gives `[]` and the
    phase stays `Showing { started_ms: 950, key_code: 12 }`.
  - Given the second-tap `Confirming { since_ms: 950, key_code: 12 }` from
    S14, `on_poll(900, false)` gives `[]` and the phase stays
    `Confirming { since_ms: 950, key_code: 12 }`.
  - Boundary: given `Showing` from a press at 10_000, `on_poll(10_000, false)`
    gives `[LingerThenFadeHud, StopPolling]`. A sample taken at the entry time
    is not stale (strict `<`).
- **S20 (duplicate delivery):**
  - Given `Showing` from `on_quit_key(10_000, 12, false)`, calling
    `on_quit_key(10_000, 12, false)` again gives `[]`, and the phase stays
    `Showing { started_ms: 10_000, key_code: 12 }`, not `Confirming`.
  - Given `Idle { last_start_ms: Some(10_000) }` after a press at 10_000
    released by `on_poll(10_120, false)`, `on_quit_key(10_000, 12, false)`
    gives `[]`, and the phase stays `Idle { last_start_ms: Some(10_000) }`, not
    `Confirming`.
  - A repeat never updates `last_press_ms`. Given `Showing` from
    `on_quit_key(10_000, 12, false)`, `on_quit_key(10_100, 12, true)` gives
    `[]`, then `on_quit_key(10_000, 12, false)` gives `[]` and the phase stays
    `Showing { started_ms: 10_000, key_code: 12 }`.
- **S21:** Given a press at 0 released by `on_poll(400, false)`, a second tap
  exactly `SECOND_TAP_MS − 1` after the start, `on_quit_key(999, 12, false)`,
  gives `[HideWindows, StartPolling(12)]` and
  `Confirming { since_ms: 999, key_code: 12 }`. This pins the strict `<`,
  together with S15's 1_000. Given `Idle { last_start_ms: Some(1_000) }` (a
  press at 1_000 released by `on_poll(1_100, false)`), an older
  `on_quit_key(900, 12, false)` does not panic: it gives
  `[ShowHud, StartPolling(12)]` and `Showing { started_ms: 900, key_code: 12 }`.
- **S25:** `warn_before_quit` returns:
  - `None` → `true`;
  - `Some(b"not json")` → `true`;
  - `Some(b"{}")` → `true`;
  - `Some(br#"{"warn_before_quit":"no"}"#)` → `true`;
  - `Some(br#"[false]"#)` → `true`;
  - `Some(br#"{"warn_before_quit":false}"#)` → `false`;

  - `{key "c", meta, alt, hasSelection: false}` → `false`;

  Record the time from the second release to the notice's disappearance
  (expected about 1.2 s); a region screen recording settles it.

## Trade-offs and Limitations

- **Kitty programs lose ⌘ chords other than ⌘C.** Under a kitty program (if
  the open decision is approved), every other ⌘ chord on a character key now
  reaches the app's menu instead of the program. ⌘ with a named key (⌘Enter,
  ⌘↑) and a bare ⌘ press still go to the program.
  An unbound ⌘-letter chord beeps, as it already does in a plain shell.
  Programs keep ⌘C without a selection. #152/#154 argued the opposite for
  "other ⌘ chords"; this spec trades that for native menu shortcuts (⌘Q, ⌘H,
  ⌘M, ⌘A, ⇧⌘Z) working under Claude Code.
- **Unguarded paths.** A mouse click on Quit, Dock → Quit, the ⌘Tab-switcher Q
  and logout still quit at once (design).
- **Edit shortcuts reach the menu while the switcher is open.** The switcher
  no longer cancels ⌘ chords it does not own, so that AppKit decides what the
  Quit chord is. ⌘A, ⌘Z, ⌘X and ⌘C now reach the Edit menu instead of being
  swallowed, and an unbound ⌘ chord beeps. Only ⌘V is stopped, by the paste
  listener. Q13 records the effect.
- **A Quit remap without ⌘** (e.g. ⌃⌥Q) is not guaranteed to reach the menu:
  the open switcher cancels non-⌘ keys it does not own, and a focused
  terminal's xterm handles ⌃/⌥ chords. Remaps that include ⌘ are covered.
- **Freshness bound of 2000 ms.** A page busy for more than 2 s turns a real ⌘Q
  into an immediate quit. A stale ⌘ keyDown within 2 s turns a VoiceOver Quit
  press into a notice, and a second press quits. Q12 measures the busy case.
- **Menu replacement.** Replacing the menu drops the retarget. Only `make qa`
  D11 catches it, and D11 is not on CI.
- **The toggle's label is static.** "Warn Before Quitting (⌘Q)" does not
  follow a remap; the notice does.
- **Prefs follow the daemon socket.** A `TARMAC_SOCKET` override moves
  `app-prefs.json` with it. Each `make run` worktree has its own toggle state.
- **Lifecycle.**
  - While hidden, the webview keeps rendering and terminals keep running.
  - ⌘W from inside an HTML card's iframe now hides the window instead of
    quitting (Q14).
  - Right after the red button, the window returns only on the next activation
    or Dock click.
- **Accessibility.** A hold is hard for some users. The alternatives are the
  menu click, the toggle and a second tap, and the notice is announced.
- **⌘T side effect.** `App.tsx`'s ⌘T handler calls `preventDefault`
  without `stopPropagation`. Under this spec's kitty rule, xterm stands aside
  for ⌘T, so the `ESC[116;9u` leak the harness saw also goes away. It is not
  separately tested.
