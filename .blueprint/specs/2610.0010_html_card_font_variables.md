## Context

An HTML card is a web view that holds a host page. The author's file runs in `<iframe sandbox="allow-scripts">` at `tarmac-card://doc/<path>` (`app/Sources/TarmacApp/HTMLCardView.swift:5-11`, `Resources/Web/card-host.html`). A CSS variable on the host page does not cross into the frame. So the variables must be set inside the frame, by the shim.

What the code does today (`ff49575`):

- `CardProtocol.respond` answers with `<script>{shim}</script>\n` and then the file bytes, with the CSP `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; …` (`app/Sources/TarmacKit/CardProtocol.swift:94-105`). The shim is `Resources/Web/card_shim.js`. `CardSchemeHandler` reads it once (`CardSchemeHandler.swift:18`) and hands it to `CardSchemeRouter.respond` (`:40-43`) from a background queue. `webView(_:start:)` itself runs on the main actor (`:9`, `:29`).
- The shim is the first thing in the document. A `<script>` before the author's `<!DOCTYPE>` already puts the document in quirks mode. The shim already adds a `<meta name="color-scheme">` to the head as its first act (`card_shim.js:13-34`).
- The host talks to the shim with `CardHostMessage` (`zoom`, `cull`, `scrollTo`; `app/Sources/TarmacKit/CardHostMessage.swift:3-22`). `HTMLCardView.post` runs `tarmacCard.post(<json>)` (`HTMLCardView.swift:234-237`). `card-host.js` forwards it to `card.contentWindow` (`card-host.js:115-117`). The shim accepts a message only when `e.source === window.parent` (`card_shim.js:317`).
- A message posted before the new document has started goes to the document it replaces. `HTMLCardSession` solves this for `cull` and `zoom` by answering every `ready` with the state (`HTMLCardSession.swift:34-48`; test `testAFirstReadyAssertsTheCullStateThenMagnifiesAndAdoptsTheMode`).
- The document is reloaded only when its address changes, and the address changes only with the file's change time (`HTMLCardView.swift:120-125`, `CardURL.src`). A font change does not reload it.
- A font change reaches a view when the view conforms to `FontFollowing`. `AppController.fontsChanged` broadcasts to the window and to every board that is not mounted (`AppController.swift:188-207`), and `tellTree` reaches a culled card (`FontFollowing.swift:12-24`). `DocWebView` conforms and passes `FontCSS` values as script arguments (`DocWebView.swift:141-150`). `HTMLCardView` conforms to `ThemeFollowing` and not to `FontFollowing` (`HTMLCardView.swift:16`).
- `FontCSS.interface`, `FontCSS.document` and `FontCSS.proseSize` give the CSS values (`app/Sources/TarmacKit/FontCSS.swift:10-14`). `Theme.fontFamilies` holds the family in effect for each role, after the saved name is checked against the Mac's families (`FontSettings.swift:45-48`). `Theme.proseFontSize` holds the Document size (`Theme.swift:54`).
- The zoom of an HTML card is set in `layoutDocument()`. It runs from `host.onResize`, from `loadDocument()` and on `.modeChanged` (`HTMLCardView.swift:66`, `:218`, `:250`). In magnify mode the frame is laid out once at `CardZoom.magnifyK` (3) and scaled down. In reveal mode it is laid out at real screen pixels (`HTMLCardView.swift:222-232`, `CardZoom.swift:9-23`).

Why it is a gap: the user picks a Document size and families in Settings. A markdown card follows them. An HTML card made for the board cannot (2610.0005 and 2610.0006 say so on purpose). The issue asks for an opt-in: the author reads the settings through CSS custom properties and a page that does not read them is unchanged.

### Measured

**First probe** (a `WKWebView` in a throwaway Swift program, `loadHTMLString`; macOS 26.7; 2026-10-09; not the app). The page was: a `<script>` first, then `<!DOCTYPE html><html style="background: rgb(1, 2, 3)">` with a `<style>` that sets `--tarmac-prose-size: 99px` on `:root`.

| Way to set `--tarmac-prose-size: 14px` | `html` `style` attribute after load | Value an author script reads | Quirks mode |
| --- | --- | --- | --- |
| `document.documentElement.style.setProperty` in the first script | `--tarmac-prose-size: 14px;` — the author's `background` is **lost** | 14px | yes |
| A constructed stylesheet in `document.adoptedStyleSheets`, rule `:root {}`, value set with `rule.style.setProperty` | `background: rgb(1, 2, 3)` — kept | 14px | yes |

The first row is why the inline style on `<html>` is not used. The HTML parser adds an attribute of the author's `<html>` tag only when the element does not have it. The shim runs first, so the `style` attribute exists and the author's is dropped. A page that sets `<html style="…">` would render differently. That breaks "a page that does not use the variables renders exactly as before".

**Second probe** (the verifier's; macOS 26.7; 2026-10-09). It uses the real frame shape: a sandboxed `<iframe sandbox="allow-scripts">`, an opaque origin, a `tarmac-card://` scheme handler, the exact `CardProtocol.csp` as the response header, and a shim-like script before the author's bytes. The dev window was visible. The probe and its logs are kept outside the repository.

- The constructed stylesheet works in that frame under that header. No `securitypolicyviolation` event fired.
- An author script in the head reads the values while the page is parsed.
- The head has no new element. It holds the shim's script, the colour-scheme meta, the author's elements and nothing else.
- `document.styleSheets` has one more entry, last, with `ownerNode` `null`. `document.styleSheets[0]` and `document.querySelector("style")` are still the author's.
- The author's `<html style>`, `class` and `lang` survive. With the inline variant the author's `style` is lost (first probe, confirmed).
- A live update of `--tarmac-prose-size` from 14px to 20px reflows the page with no reload: a block of `calc(var(--tarmac-prose-size) * 100)` goes from 1400 to 2000 px.
- `document.compatMode` is `BackCompat`, with or without the new block. The shim's `<script>` before the `<!DOCTYPE>` already makes it so.
- A raw `<` in the filled literal let an injected script run (control run). With `<` escaped it did not.
- Hidden: with the web view's ancestor hidden or detached in a visible window, the update is applied and the shim's `ResizeObserver` posts the new total a few seconds later at most. In a fully occluded window the observer waits for a layout.

Cascade, for the chosen `:root {}` rule (one name set in six places by the page; "Tarmac's" is the value of the shim; the same winners after a live update from 14px to 20px):

| The page sets the name with | Who wins on the root |
| --- | --- |
| `:root { … }` (same specificity) | Tarmac |
| `html { … }` (lower specificity) | Tarmac |
| `html[data-x] { … }` (higher specificity) | the page |
| `:root { … !important }` | the page |
| a `style` attribute on `<html>` | the page |
| a rule on a descendant | the descendant keeps its own value |

The measured `:where(:root) {}` variant (Alternatives) makes every page declaration win.

## Motivation

An HTML card that wants to look like the rest of the board has no way to take the user's reading size or font. The user changes the size in Settings and the markdown cards follow; the report an agent wrote in HTML does not. Page zoom was rejected in the issue: it changes every page and conflicts with the frozen-zoom model. A variable is a choice of the author and costs the other pages nothing.

## Proposed Solution

### Overview

Tarmac gives each HTML card document three CSS custom properties on its root element:

| Property | What it holds | Source |
| --- | --- | --- |
| `--tarmac-prose-size` | The Document size, a length in px | `FontCSS.proseSize(Theme.proseFontSize)` |
| `--tarmac-prose-font` | The Document family before the system prose stack | `FontCSS.document(Theme.fontFamilies[.document])` |
| `--tarmac-mono-font` | The Interface family before the system monospace stack | `FontCSS.interface(Theme.fontFamilies[.interface])` |

The values are in the page before its first byte is parsed. They change in place, with no reload, when the user changes the Document size, the Document family or the Interface family. A page that does not use the properties is not changed.

Two ways carry the values:

1. **At load.** The scheme handler fills a marker inside the shim with the values in effect at the time of the request. The shim declares them at once.
2. **After load.** A new host message, `fonts`, carries the values. The shim applies it. The session re-sends the current values on every `ready`, as it does for `cull`.

The shim declares the values in a constructed stylesheet with one `:root` rule. It does not use the inline style of `<html>` (see Measured). Its rule is `:root {}`.

### Key Components

- **`CardFontVariables`** (`app/Sources/TarmacKit/CardFontVariables.swift`, new). The pure owner of the three names, their values, the JSON form and the marker fill. Built from the raw settings; uses `FontCSS`.
- **`CardHostMessage.fonts`** (`app/Sources/TarmacKit/CardHostMessage.swift`). A fourth case that carries a `CardFontVariables`.
- **`HTMLCardSession`** (`app/Sources/TarmacKit/HTMLCardSession.swift`). Holds the values last given, says whether a new set is a change, and answers `ready` with them.
- **`card_shim.js`** (`app/Sources/TarmacApp/Resources/Web/card_shim.js`). One marker, a constructed stylesheet, and a `fonts` branch in the message listener.
- **The shell** (`app/Sources/TarmacApp/`): `Theme.cardFonts` (builds one `CardFontVariables` from the three settings), `HTMLCardView` (conforms to `FontFollowing`), `CardSchemeHandler` (fills the shim per request). No decision lives here.
- **`GUIDE.md`** (`core/crates/tarmac-cli/src/GUIDE.md`) and **`docs/architecture.md`**.
- **The QA record** `qa/html-card-font-variables-qa.md` and its fixtures.

### Data Flow

A document is opened, or reloaded because its change time changed:

1. `loadDocument()` sets the frame source. WebKit asks the card scheme handler for the file.
2. `CardSchemeHandler.webView(_:start:)`, on the main actor, reads `Theme.cardFonts` and fills the shim marker with `CardFontVariables.filling(_:)`. It hands that shim to `CardSchemeRouter.respond`. The signature of `respond` and of `CardProtocol.respond` does not change.
3. The body is `<script>{filled shim}</script>\n` and the file bytes. The shim runs before any byte of the file. It makes the stylesheet and declares the three properties.
4. The document posts `ready`. `HTMLCardSession` answers `cull`, then `fonts` with the current values, then `zoom`.

The user changes a setting:

1. `AppController.fontsChanged` broadcasts. `HTMLCardView.fontsChanged()` reads `Theme.cardFonts`.
2. `HTMLCardSession.fontsChanged` returns a `fonts` message when the values differ from those last given, and `nil` when they are the same. A Terminal size step gives the same values, so an HTML card is sent nothing.
3. The view posts the message. The shim sets each property on its rule. The author's CSS that uses `var(--tarmac-…)` is laid out again by the engine.

A setting changes while the document loads: the message goes to the old document or to the new one. If it goes to the old one, the new one has the values of its request. The new document's `ready` brings the current values (step 4 above). Either way the document ends on the current values.

A culled card: the view is hidden and still in the tree. It is sent the message. The shim does not gate it: the cull gate holds timers and frames and nothing else.

### Interface Contract

**Names and values.** The names are in `CardFontVariables` and nowhere else in Swift. The shim does not know them (it accepts any name that starts with `--tarmac-`).

```swift
public struct CardFontVariables: Equatable, Sendable {
    public static let proseSize = "--tarmac-prose-size"
    public static let proseFont = "--tarmac-prose-font"
    public static let monoFont  = "--tarmac-mono-font"
    public static let marker    = "/*tarmac-fonts*/"

    public init(interfaceFamily: String?, documentFamily: String?, documentSize: Double)
    public var json: String                      // {"--tarmac-mono-font":"…","--tarmac-prose-font":"…","--tarmac-prose-size":"14px"}
    public func filling(_ shim: String) -> String
}
```

| Property | With nothing chosen | With `Fira Code` / `Georgia` / 13.5 |
| --- | --- | --- |
| `--tarmac-prose-size` | `14px` | `13.5px` |
| `--tarmac-prose-font` | `-apple-system, "SF Pro Text", system-ui, sans-serif` | `"Georgia", -apple-system, "SF Pro Text", system-ui, sans-serif` |
| `--tarmac-mono-font` | `ui-monospace, monospace` | `"Fira Code", ui-monospace, monospace` |

The values are `FontCSS` output, byte for byte. `FontCSS` does not change.

**`json`.** A compact object with sorted keys, built with `JSONValue`. After that one more rule applies: `<` is written as its JSON escape, a backslash and `u003c`. U+2028 and U+2029 are written the same way (`u2028`, `u2029`), never raw. The result is still valid JSON, and it is a valid JavaScript expression. The same text is safe in an HTML `<script>` element and in a script that the app evaluates. This is the one escaping rule and `CardFontVariables.json` is its one owner.

**`filling(_:)`.** The same rule as `ThemeCSS.put` (`app/Sources/TarmacKit/ThemeCSS.swift:36-43`). The marker is replaced by `json` when `shim` holds it exactly once. Otherwise `shim` is returned as it is. The shim file holds the marker as `var bootFonts = [/*tarmac-fonts*/][0];`. So the raw file and the filled file are both valid JavaScript. The tests that load it raw (`CardShimTests.source()`) see `undefined`.

**Host message.**

```
{"tarmac":"fonts","vars":{"--tarmac-mono-font":"…","--tarmac-prose-font":"…","--tarmac-prose-size":"14px"}}
```

`CardHostMessage.fonts(CardFontVariables).json` is that text. The view posts it as it posts every other message: `HTMLCardView.post` splices `message.json` into `tarmacCard.post(…)` and does not change. This is safe because `json` is a valid JavaScript literal by the escaping rule (S6), as the doc comment of `CardHostMessage.json` already says. `post` is not rewritten to pass an argument: the messages to the document would then not all go through one WebKit call (`evaluateJavaScript` today, `callAsyncJavaScript` for a script with arguments), and the order between the two calls is not measured.

**Session.**

```swift
extension HTMLCardSession {
    public mutating func fontsChanged(_ fonts: CardFontVariables) -> CardHostMessage?   // nil when `fonts` is no change
}
```

The session keeps the values last given. A `ready` posts them after `cull` and before `zoom`. A session that was given none posts no `fonts`. `reloaded()` keeps them.

**Shim behaviour.**

- At load, after the `started` post and before the first listener on the window: if `bootFonts` is an object, apply it. (`started` stays the shim's second act, as `docs/architecture.md` says.)
- `apply(vars)`: if there is no constructed stylesheet yet, make one with `replaceSync(":root{}")` and append it to `document.adoptedStyleSheets`. Then for each own key of `vars` that starts with `--tarmac-` and has a string value, call `rule.style.setProperty(key, value)` on its one rule. Any other entry is skipped. Any exception is caught: a page without the properties is the page it was.
- The `fonts` message is accepted from `window.parent` only, as the other messages are. It is applied at once, also before `DOMContentLoaded` (unlike `zoom`, nothing waits for `ready`). It uses no timer and no frame.
- The fonts block and the `fonts` message add nothing to the head and write nothing to `documentElement.style` or to an attribute. (The shim writes `style.zoom` and `style.scrollbarWidth` on its other paths, `card_shim.js:296` and `:390`. They are not changed.)

**Cascade rule (the precedence).** Tarmac declares the three names in one `:root {}` rule of a constructed stylesheet. The engine orders that sheet after every sheet of the page. So the ordinary cascade decides, with Tarmac's rule last (the table in Measured):

- A page rule of a specificity up to that of `:root` (`:root {}`, `html {}`) does **not** win. Tarmac's value is read.
- A page rule of a higher specificity on the root (for example `html[data-x]`), a page rule with `!important`, and the page's own `style` attribute on `<html>` **do** win, for the root.
- A page rule on a descendant gives that subtree its own value.
- The same winners hold before and after a live change, because both go to the same rule.

The guide tells the author: do not set these names. To get another value, use another name.

**No wire change.** Nothing crosses the daemon socket. The fonts are in `app-prefs.json` (`FontSettings`). `CardHostMessage` is a message between the app and the page, not a `Msg`. `docs/protocol.md`, the vectors V1–V13 and docs-check rule 4 (`scripts/docs-check.mjs:111`) are not touched.

**Not changed.** `CardProtocol.respond` and `CardSchemeRouter.respond` (signatures and CSP), `card-host.js`, `card-host.html`, `FontCSS`, the daemon, `DevSnapshot`.

### The shell, which is wiring

What stays in `TarmacApp`, under exceptions 1 and 2 of `docs/coding-style.md` §1.3:

- `Theme.cardFonts`: builds one `CardFontVariables` from `fontFamilies[.interface]`, `fontFamilies[.document]` and `proseFontSize`.
- `HTMLCardView`: conforms to `FontFollowing`. `fontsChanged()` asks the session, then posts. `init` calls it once before the page loads. `post` is as it is today.
- `CardSchemeHandler.start`: for the `doc` host, reads `Theme.cardFonts` before `reads.async` and passes `cardFonts.filling(shim)`.

The decisions (what the values are, how a hostile name is escaped, when a message is sent, what a `ready` brings) are in `TarmacKit` and in the shim, and they have tests.

## Alternatives Considered

### The inline style of `<html>`

`documentElement.style.setProperty` is one line. It wins over every page rule. Rejected: it drops the author's `<html style>` (Measured), and an author's `style.cssText = …` or `removeAttribute("style")` removes the properties.

### A `<style>` element in front of the file

It also reaches the first paint. Rejected for two reasons. It is a new element before the author's first, so `document.querySelector("style")` and `document.styleSheets[0]` would find Tarmac's. And its rule comes before the author's, so the precedence flips: the page's own `:root` rule would win.

### A `:where(:root) {}` rule: the page always wins

The same sheet with the rule `:where(:root) {}`, which has no specificity. Measured: every page declaration wins (a page `:root` 99px, a page `html {}` 33px), and a name that the page does not set still gets Tarmac's value, also after a live update. It works. Rejected by the user's decision: Tarmac's value wins over a page rule up to the specificity of `:root`.

### A message only (no values in the response)

The shim asks, or the host sends on `started`. Rejected: the reply comes after at least one task. An inline script that reads `getComputedStyle` while the page loads (a canvas chart that sets `ctx.font`) would see nothing. The card is out of sight until the document is shown (`card-host.js:73-87`), so the user would not see a flash, but the script would.

### The values in the frame's address

`CardURL.src` would carry them. Rejected: the address changes the document, so a font change would reload it.

### A second `<script>` with the values, before the shim

Rejected: a second element before the file, and the values would sit in a global the page can read. A marker inside the shim leaves one `<script>` and no global.

### Scale the whole card by the Document size

Rejected in the issue. It changes every page and fights the frozen zoom.

### Also give the Terminal font

Not asked. A terminal family is a cell grid choice and means nothing to a page.

### Migration Steps

1. None. No data, no file format, no wire. A page that does not use the properties is unchanged (S37).

## Security Considerations

The family name is the user's text and reaches two sinks.

- **The HTML `<script>` in the response.** `json` writes `<` as a backslash and `u003c`, so `</script>` and `<!--` cannot occur. U+2028 and U+2029 are escaped, so the literal is one line for every parser. `filling` replaces a marker that is outside any string, and the replacement is not searched again. S6 and S7 test a hostile name.
- **The script that posts the message.** `post` splices `message.json`. This is safe because `json` is a valid JavaScript literal (S6), and `<` is the necessary escape: a raw `<` let an injected script run (Measured).
- **Inside the page.** The value is a CSS string made by `FontCSS` (`"` and `\` escaped, control characters refused). The shim sets it with `style.setProperty`, which parses a value and does not build CSS text. The shim takes only `--tarmac-` names with string values, and only from the parent window. The author cannot post as the parent (`card_shim.js:317`).
- **What the page learns.** The page can read the user's chosen family name and size. This is the purpose of the change. The page already runs with no network, so it cannot send them out.
- A saved name must be a family the Mac has (`FontRole.familyInEffect`), so a hostile name cannot come from `app-prefs.json` in a real run. The tests give the pure functions a hostile name on purpose: they do not rely on that check.
- The CSP, the sandbox and the scheme handler's host rules do not change.

## For the Implementing Agent

> **Your job:** make every acceptance scenario above pass with tests that would *fail if the behavior were wrong*. A green suite that passes for the wrong reason does not satisfy this contract — `/verify` will hunt for vacuous tests by asking, of each behavior, "what is the smallest change that breaks this, and would any test catch it?"

Implement however you work best. Only the result is checked. The repository's own rules still bind (`docs/coding-style.md`): red first and observed red; the smallest correct diff; no line-noise comments; do not run `cargo fmt`; verify with `make`, not the editor.

A guard is not the red of any change. Start from the **[red]** scenarios and watch each fail on the unmodified tree for the reason you predicted.

Points that are easy to get wrong:

- **Do not use the inline style of `<html>`.** It looks simpler and passes most tests. It drops the author's `<html style>` (Measured). S11 and S37 are the checks, and S37 passes before the change.
- **`jsonString` alone is not safe in a `<script>`.** `JSONValue` escapes `"`, `\` and control characters only (`JSONValue.swift:89-107`), and `FontRole.isFamilyName` refuses control characters only (`FontRole.swift:31-33`). A name with `</script>` passes both. `<` must be escaped in `CardFontVariables.json`: it is the necessary escape (a raw `<` let a script run in the control run). S6 uses that name.
- **The stand-in window has no `setProperty`, no `CSSStyleSheet` and no `adoptedStyleSheets`.** `style` in `CardShimTests.page` is `{}` (`CardShimTests.swift:42`). The shim's `try/catch` would hide a missing stub and make S10, S11 and S17 pass for the wrong reason. Add recording stubs to the stand-in, also a recording `setProperty` on the root's `style`. Do not make that `style` throw on a write: the zoom and the `ready` path write to it. S13 removes the stubs again.
- **The marker must be a JavaScript comment on a valid line.** `CardShimTests.source()` loads the raw file (`CardShimTests.swift:321-327`). A bare `@@FONTS@@` would not parse. The filled line must parse too: `/*tarmac-fonts*/ null` becomes `{…} null`, a syntax error. So the marker is alone in `[…][0]`. S8 holds the count at one, because `filling` does nothing for any other count. S10 loads the filled file.
- **Fill the shim in the handler. Do not change `CardProtocol.respond`.** The values must be read on the main actor before `reads.async`, as `shim` and `headers` are. The fonts are read per request, not once at start, because they change.
- **`post` stays as it is.** Do not rewrite it to pass an argument. `json` is a valid JavaScript literal (S6).
- **`ready` must re-send the values.** The load fill is the values of the request. A change between the request and the new document's listener goes to the old document. S24 is the check. Do not add a second path (a timer, a retry).
- **A session that was given no fonts posts none.** The existing session tests have no fonts and must pass unchanged (S22). The view tells the session in `init`, before the page loads, so a real card always has values.
- **Dedupe in the session, not in the view.** The Terminal size change broadcasts to every view. The session says "no change" for the same values (S23), as `DocWebView.fontsGiven` does for a markdown card.
- **The font change must not call `layoutDocument()` and must not post `zoom`.** The frame size, the root zoom and the scale stay as they are (S38, S39, S20). Do not add the call "to be safe".
- **No scheduling.** Apply the message in the listener. A `requestAnimationFrame` or a timer would be held while the card is culled (S20). The shim's `ResizeObserver` on the root already reposts the scroll metrics when the layout changes (`card_shim.js:369-375`).
- **Names live once.** The shim takes any `--tarmac-` name. If a name is wrong in `GUIDE.md`, S25 fails (it reads the guide across packages). Do not copy the three names into the shim or into `HTMLCardView`.
- **Reword two places in `GUIDE.md`**: the hard rule "Use an inline `<style>` and a system font stack." (`GUIDE.md:82-84`) and the checklist line "All CSS in a `<style>` block; system font stack." (`GUIDE.md:169`). Neither may say the system stack is the only choice. S25 checks both. Add the fonts item and the example with fallbacks. Write for an agent that has no checkout: no repo path, no link that is not `http` (S26). Tell the author to give every use a fallback, and not to set the three names.
- **An ACTIVE doc may not name a file in backticks before the file exists** (`scripts/docs-check.mjs:90-109`). Name `CardFontVariables.swift` and `qa/html-card-font-variables-qa.md` in `docs/architecture.md` only when they exist, or do not name them. A link to the QA record fails the link rule before it exists.
- **The existing exhaustive-switch test breaks by design** (S16). That compile error is the first red.
- **Never launch `dist/Tarmac.app`** and never kill a daemon by name. All live QA is against `make run`; stop its daemon with `make kill-daemon`. Pin the channel as `make run` does.

Test principles, the ones `/verify` scores against:

- **Behavioral over structural** — assert observable output, not internals.
- **Every test can fail** — no copied expected value, no tautology.
- **Deterministic, isolated, readable** — no shared state, no dependence on a font beyond the system faces and one installed family named in the QA record.

## Trade-offs and Limitations

- **The page learns the user's font choice.** This is the purpose. It is by choice of the author and the page has no network.
- **The author can lose the variables.** A page script that replaces `document.adoptedStyleSheets` removes Tarmac's sheet. The live update then goes nowhere. The page did this to itself.
- **A trace remains.** `document.styleSheets` has one more entry, last, with `ownerNode` `null` (Measured). A page that loops over `document.styleSheets` and reads `sheet.ownerNode` without a check would throw. The guide does not promise that the list is unchanged.
- **Tarmac's value wins over a page rule up to the specificity of `:root`** (`:root {}`, `html {}`). To keep another value the page uses another name. This is the user's decision; the `:where(:root)` variant (Alternatives) was measured and not chosen.
- **The Document size is in px, in the page's own units.** In magnify mode, 14px looks like 14 px at board zoom 1 and is scaled with the card. In reveal mode it is 14 real screen pixels at every zoom, as all `px` are there. A page that sets `:root { font-size: var(--tarmac-prose-size) }` and uses `rem` follows the size. A page with widths in `px` does not reflow its boxes.
- **A change between the request and the first `ready` can paint once with the older value.** The card is out of sight until the document is shown (`card-host.js:73-87`), and `ready` corrects the value. No scenario can time this by hand. S21, S23 and S24 pin the correction.
- **Interface is a monospace stack.** The role is fixed-pitch only (`FontRole.fixedPitchOnly`), so the name says `mono`.
- **Outside Tarmac the properties are unset.** A page must give a fallback. The guide says so.
- **The Terminal font and size are not given.**
- **The dev snapshot is not changed (out of scope).** `DevSnapshot.Fonts.documentCSS` and `documentSize` already show what the app hands to a doc card (`DevSnapshotReader.swift:65-73`). What a page holds is inside a sandboxed frame. To read it, the driver would need an asynchronous round trip into the card, a new snapshot field and new dev-socket shapes in the CLI and in Swift. `scroll.total` of a fixture is the witness, as in 2610.0006 S19. The Interface stack is not in the snapshot (only its PostScript name). This is not needed to test the change.
- **Colours are not given.** A card follows the theme with `color-scheme` and `prefers-color-scheme` (2610.0007). Theme variables for HTML cards are another issue.
