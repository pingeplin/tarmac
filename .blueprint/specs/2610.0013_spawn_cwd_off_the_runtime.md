# 2610.0013 Check a new terminal's cwd off the runtime, with a time limit

**Date:** 2026-10-30
**Status:** accepted
**Author:** EP Lin
**Issue:** [#279](https://github.com/pingeplin/tarmac/issues/279) `fix(terminal): a terminal whose cwd is on a hung volume freezes the daemon at spawn`
**Builds on:** [2610.0012](2610.0012_doc_path_reads_off_the_runtime.md) (`reader::PathGate`, #274–#277)

## Context

`SpawnTerm` (`conn.rs:239`) runs two blocking calls on a tokio worker:

- `spawn_cwd` (`conn.rs:358`): for `inherit_cwd_from`, it calls `TermHandle::live_cwd` (`term.rs:99`) → `proc::pid_cwd` → `proc_pidinfo(PROC_PIDVNODEPATHINFO)`.
- `term::spawn` (`term.rs:128`): it calls portable-pty 0.9.0 `spawn_command` (`term.rs:170`). That calls `Path::is_dir` on the cwd (`cmdbuilder.rs:506`), and falls back to `$HOME` when the answer is false.

Measured on the #267 WebDAV mount with requests held (`scratchpad/hang267/q279/`):

- A `SpawnTerm` whose cwd is on the mount froze the whole daemon. Six hellos over 12 s got no answer. The blocked stack was `spawn_command → … → Path::is_dir → stat`. No child had been forked yet.
- A `SpawnTerm` with `inherit_cwd_from` a terminal whose cwd is on the mount froze it too. The blocked stack was `spawn_cwd → live_cwd → pid_cwd → proc_pidinfo`, and `proc_pidinfo` did not return within 5 s in 3 of 3 tries (one run, `run1.log`).
- With `is_dir` bounded at 1 s and falling back to `$HOME`, the shell started in `$HOME` about 1.02 s after the send, and every hello answered in under 1.3 ms. portable-pty never ran `chdir` into the dead dir.

## Decision

Both calls go through the daemon's `PathGate`, with `READ_LIMIT` (1 s). An `Out` is treated as "no usable cwd", and the terminal starts in `$HOME`. That is what portable-pty already does for a cwd that is not a directory. The spawn does not fail.

- `pid_cwd(pid)`: `Out` means no cwd to inherit. The spawn then uses `$HOME`, as it does today when `live_cwd` gives `None`.
- `is_dir(cwd)`: this check runs on the gate before `spawn_command`, on the cwd from the request or from `pid_cwd`. `Out` or `false` gives `$HOME`. `true` passes the cwd to portable-pty, whose own `is_dir` then runs on a path that just answered.
- The `$HOME` default is not checked on the gate. A spawn with no cwd, or one that fell back to `$HOME`, makes no `is_dir` call on the gate.
- Each of the two calls has its own limit. A spawn with `inherit_cwd_from` waits at most 2 × the limit before `spawn_command`.

## Interface

- `PathFs` gets `is_dir(&Path) -> bool` and `pid_cwd(pid) -> Option<String>`. `RealFs` implements them with `Path::is_dir` and `proc::pid_cwd`. The test double can hold them, as it holds the other calls. A `pid_cwd` hold may hold every pid, so a test does not need the source terminal's pid.
- The key of `is_dir(cwd)` is the cwd path itself, the same key a doc read of that path uses. So a cwd whose call is out shares the one call with any doc read on it, and `is_out_dir` reports its dir as out while it is. The watcher then skips that dir, which is right: its volume is not answering, and notify would hang on it too. Decided 2026-10-30.
- The key of `pid_cwd` must give one call per pid at a time. The implementer picks a key that cannot collide with a real path. Document it in the `PathGate` doc comment.
- No protocol change. No new error text.

## Trade-offs

- A cwd on a slow but live volume (more than 1 s) starts in `$HOME`. The user sees the shell in their home dir, with no error. The same trade-off as #267 (Decision 1).
- **Accepted race:** `is_dir` answers `true`, and then the volume dies before the child's `chdir`. `Command::spawn` then blocks a worker until the volume answers. The window is from the gate's `is_dir` to the child's `chdir`. portable-pty's own `is_dir` (`cmdbuilder.rs:506`) runs in it, and so does its `search_path` for a relative `cmd` (`cmdbuilder.rs:420-451`). The harness could not produce it. Closing it would need `spawn_command` on a blocking thread with a limit, plus cleanup of a late child. That is not done here.

## Acceptance Scenarios

Unit tests go in `state.rs` / `conn.rs` / `term.rs` tests as fits. They run in-process on a daemon whose gate uses the `PathFs` double (hold by method and path, or every `pid_cwd`). The double is now private to the `state.rs` test module, and the `SpawnTerm` step is private to `conn.rs`. The implementer makes the one reachable from the other. `LIMIT = 200 ms`. A multi-thread runtime with 2 workers, as in 2610.0012.

Terms:
- **The spawn returns:** the `SpawnTerm` step that `dispatch_app_msg` runs (`spawn_cwd`, then `spawn_term`) completes. The new term is in the daemon's terms. This is the timed event. The shell's output is not timed.
- **At once:** the spawn returns in `< LIMIT`. **Waits the limit:** the spawn returns in `< 3 × LIMIT`.
- **Runs in D:** the spawned command is `/bin/sh -c "pwd -P"`. The test collects its `output` frames from the app channel until its `exit` frame, and compares the trimmed text with D canonicalized. `$HOME` is the test process's `HOME`, canonicalized. Each test's temp dir is not under `$HOME`. No sleep: the frames drive the test.
- **No error:** no `err` frame reaches the app channel between the send and the `exit` frame.

An in-process test cannot show that another connection is answered: on 2 workers, one blocked worker leaves the other free. The unit test's check is the bound on the spawn's own return: a held call made on a worker never returns, so the spawn misses the bound. Q1 checks the other connection.

- **S1:** A `SpawnTerm` with an explicit `cwd` (a real dir) whose `is_dir` is held waits the limit, runs in `$HOME`, with no error.
- **S2:** The same as S1, but the `cwd` does not exist and `is_dir` is not held. The spawn returns at once and runs in `$HOME`, as today.
- **S3:** A `SpawnTerm` with a live, reachable `cwd` runs in that cwd. This is the regression guard. The existing `tests/term_cwd_inherit_integration.rs` tests guard the inherited case and stay green.
- **S4:** A `SpawnTerm` with `inherit_cwd_from` a running terminal (in a real temp dir) whose `pid_cwd` is held waits the limit, runs in `$HOME`, with no error.
- **S4b:** A `SpawnTerm` with `inherit_cwd_from` a running terminal whose `pid_cwd` answers its dir D, and `is_dir` of D is held. The spawn waits the limit, runs in `$HOME`, with no error.
- **S5:** After the spawn of S1 (or S4) returned, a second `SpawnTerm` with the same held `is_dir` path (or from the same source terminal) returns at once and runs in `$HOME`. The double's call count for that method stays 1.
- **S6:** After S1 (or S4), the test releases the hold. It waits for the held call to end by an event or a bounded poll, as 2610.0012's tests do, never by a fixed sleep. The next `SpawnTerm` with that `cwd` (or from that source terminal) then runs in that dir.
- **Q1 (hand QA, WebDAV harness):** With the mount held, run a `SpawnTerm` with `cwd` on the mount, and one with `inherit_cwd_from` a terminal in the mount. The second connection's hello must be answered in under 100 ms during each. Each shell starts in `$HOME` within 1.1 s. Run the same on `main` as the baseline.
