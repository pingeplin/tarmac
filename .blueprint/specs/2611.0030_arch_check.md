# 2611.0030 Architecture check

**Date:** 2026-11-22
**Status:** accepted (spec-evaluator review, 2026-11-22)
**Author:** EP Lin
**Issue:** #480

## Context

Some rules of this repo are facts about the tree. No formatter, linter or compiler setting holds them; they are written in `CLAUDE.md` and `docs/coding-style.md` and checked by review. `make docs-check` (`scripts/docs-check.mjs`) is the precedent for a rule of this kind that a script decides.

Measured on `main` at `1bcad80`:

| Rule | State today |
| --- | --- |
| `TarmacKit` imports no AppKit, no WebKit, neither sibling | holds: it imports Foundation, CoreGraphics, Darwin, Synchronization |
| `TarmacTerm` imports neither sibling | holds |
| `Bundle.module` only in `BundledResource.swift` | holds |
| the daemon sends a signal in one place | holds: `libc::kill` is in `tarmacd/src/term.rs` and nowhere else under a crate's `src/` |
| no profile changes `debug-assertions` | holds: `core/Cargo.toml` has no `[profile.*]` table |
| the serde stack is pinned with `=` | holds: `serde`, `rmp-serde`, `serde_bytes` |
| every `TarmacKit` module has its paired test file | 6 of 186 modules have none (188 files, two of them `+` slices): `CardCull`, `DaemonSocket`, `JavaScriptNumber`, `StrictJSON` (named in `docs/coding-style.md` §4 as predating the rule), `InlineMarks`, `SpawnRequest` (#481) |

Since #475 the compiler holds each Swift file to its own imports. It does not forbid an import.

## Motivation

A rule that a script can decide must not depend on a reviewer or on a sentence in a prompt. Each rule here guards something that fails quietly: a `TarmacKit` file that imports AppKit still builds, and takes a decision out of the only layer that has unit tests; a profile that turns `debug-assertions` off moves a debug build onto the installed app's socket.

## Proposed Solution

### Overview

`make arch-check` runs `scripts/check/arch.mjs`: plain node, no build, under a second. It is part of `make test` and of CI. A failure goes through `scripts/check/report.mjs`.

### Key Components

- **`scripts/check/arch.mjs`** — a table of rules. Each rule has a name, the reason it exists, the command or action that fixes a violation, and a function from the tracked files to the places that break it. The script reads tracked files only.
- **`scripts/check/arch-exceptions.json`** — the `TarmacKit` modules that have no paired test file, each with an issue and a reason. An entry that is no longer needed is a violation, so the list shrinks.
- **`make arch-check`**, a prerequisite of `make test`.
- **`arch-check` job in `.github/workflows/lint.yml`**, on `ubuntu-latest`.

### The rules

| Name | A violation is |
| --- | --- |
| `kit-imports` | a tracked `*.swift` file under `app/Sources/TarmacKit/` with an `import` of `AppKit`, `Cocoa`, `WebKit`, `SwiftUI`, `TarmacTerm` or `TarmacApp` |
| `term-imports` | a tracked `*.swift` file under `app/Sources/TarmacTerm/` with an `import` of `TarmacKit` or `TarmacApp` |
| `bundle-module` | `Bundle.module` in code of a tracked `*.swift` file anywhere in the repository other than `app/Sources/TarmacApp/BundledResource.swift` |
| `one-signal-site` | `libc::kill` or `libc::killpg` in code of a tracked `*.rs` file under `core/crates/*/src/` (at any depth) other than `core/crates/tarmacd/src/term.rs` |
| `no-profile-override` | a `debug-assertions` key, with any value, in a profile table of `core/Cargo.toml` or of a `core/crates/*/Cargo.toml` |
| `serde-pinned` | `serde`, `rmp-serde` or `serde_bytes` in `[workspace.dependencies]` of `core/Cargo.toml` with a version that does not start with `=`, or one of the three missing there |
| `kit-tests` | a tracked file directly in `app/Sources/TarmacKit/`, named `<Module>.swift`, with no tracked `app/Tests/TarmacKitTests/<Module>Tests.swift` and no entry in the exceptions list; or an entry whose module has that test file, or has no tracked source file |

Details that make the rules exact:

- **Tracked files.** The script reads the paths that `git ls-files` lists, with their contents in the working tree. A listed path that is not in the working tree is skipped, and counts as absent for every rule (`kit-tests` too). An untracked file is not read. An exceptions list or a `core/Cargo.toml` that is absent in this sense is missing: exit 2. So every test fixture holds a valid `core/Cargo.toml` and exceptions list.
- **Code and comments.** In a Swift or Rust line, the text from the first `//` to the end of the line is not code. In a TOML line, the text from the first `#` to the end of the line is not read. A `/* */` comment and a string are code (see *Trade-offs*).
- **An `import`** is a line that has, in this order: optional spaces; zero or more attributes (`@` and a name, with an optional `(…)`, for example `@testable`, `@preconcurrency`, `@_spi(X)`); an optional access level (`public`, `package`, `internal`, `fileprivate`, `private`); the word `import`; an optional kind (`struct`, `class`, `enum`, `protocol`, `func`, `var`, `let`, `typealias`); then the module name, followed by the end of the code, a space, or a `.`. The name match is exact and case-sensitive: `AppKitLike` is not `AppKit`.
- **`canImport`.** A `#if` or `#elseif` line with `canImport(<M>)`, where `<M>` is a module that the rule forbids, is a violation of that rule (`kit-imports` and `term-imports` both).
- `Cocoa` and `SwiftUI` are in `kit-imports` because each one brings AppKit in.
- **Word ends.** `Bundle.module`, `libc::kill` and `libc::killpg` match only when the next character is not a letter, a digit or `_`. So `Bundle.moduleURL` and `libc::kill_all` are not violations.
- **TOML, read as text.** A table header is a line `[<name>]`. A profile table is one whose `<name>` is `profile` or starts with `profile.` (for example `[profile.dev]`, `[profile.release.package.foo]`); it runs to the next header. A key line starts, after spaces, with the exact key name, then spaces, then `=`. A version is the quoted text after `=`, or after `version =` in an inline table `{ … }`. An entry with no version (`{ path = … }`, `{ git = … }`) does not start with `=`, so it is a violation. `serde_json` and `serde-derive` are other keys, not `serde`.
- For `kit-tests`, a file named `<Module>+<Part>.swift` is a slice and needs no test file of its own, whether or not `<Module>.swift` exists.
- An exceptions entry has `module`, `issue` and `reason`, each a text that is not empty. Two entries with the same `module` make the list malformed.

### Interface Contract

```
make arch-check
node scripts/check/arch.mjs
        # exit 0: no rule is broken
        # exit 1: at least one rule is broken
        # exit 2: the check could not run (not in a git repository; core/Cargo.toml is missing; the exceptions list is missing or malformed)
```

All output goes to stderr; stdout stays empty. On exit 2 no rule runs, and one block from `report.mjs` names what is wrong. Otherwise, one block for each broken rule, in the order of the table. Each rule has its own summary text; no two rules share one.

```
✗ arch: TarmacKit must not import AppKit, WebKit or a sibling target
  at   app/Sources/TarmacKit/Placement.swift:3
  why  TarmacKit holds the pure decisions and is the only layer with unit tests
  fix  move the code that needs the module into TarmacApp, and pass the value in
  then make arch-check
```

`at` lines are `<repo-relative path>:<line>` (line numbers start at 1), one for each place, sorted in byte order as `report.mjs` sorts them. For `kit-tests` the place is `<source file>:1`, or `scripts/check/arch-exceptions.json:<line>` for an entry that is no longer needed, where `<line>` is the line of that entry's `"module"` key. For a `serde-pinned` dependency that is missing, the place is the line of the `[workspace.dependencies]` header, or `core/Cargo.toml:1` when there is no such table.

## Alternatives Considered

### More rules in `docs-check.mjs`

One script. Not chosen: `docs-check` is about documents and has its own report format; these rules are about code and use the shared reporter.

### An allow-list of imports for `TarmacKit`

Stricter: any new module would need an edit of the list. Not chosen now: the documented rule names what is forbidden, and a new system framework in `TarmacKit` is not always wrong. It can be added later without changing the script's shape.

## Acceptance Scenarios

S1–S10 are `node --test` tests in a temporary git repository that the test creates, with only the files a rule reads. S11–S13 are recorded commands on the real tree.

### Happy Path

- **S1:** Given a repository that breaks no rule, when `node scripts/check/arch.mjs` runs, then it exits 0 and writes nothing.
- **S11:** Given the real tree at the head of this change, when `make arch-check` runs, then it exits 0, and `make test` runs it.

### Each rule fires, and does not fire on its near miss

- **S2 (`kit-imports`):** `import AppKit`, `@testable import WebKit`, `import struct AppKit.NSColor`, `import Cocoa`, `import SwiftUI`, `import TarmacTerm` and `#if canImport(AppKit)` in a `TarmacKit` file are each reported at their line. `import Foundation`, `import AppKitLike`, `// import AppKit` and `import AppKit` in a `TarmacApp` file are not.
- **S3 (`term-imports`):** `import TarmacKit` in a `TarmacTerm` file is reported; `import AppKit` there is not.
- **S4 (`bundle-module`):** `Bundle.module` in code of any Swift file but `app/Sources/TarmacApp/BundledResource.swift` is reported; in a comment, and in `app/Sources/TarmacApp/BundledResource.swift`, it is not.
- **S5 (`one-signal-site`):** `libc::kill(` in `core/crates/tarmacd/src/conn.rs` is reported; in `core/crates/tarmacd/src/term.rs` and in `core/crates/tarmacd/tests/common/daemon.rs` it is not.
- **S6 (`no-profile-override`):** `[profile.dev]` with `debug-assertions = false` in `core/Cargo.toml` is reported at the line of the key; `[profile.release]` with only `lto = true` is not.
- **S7 (`serde-pinned`):** `serde = "1.0"`, `rmp-serde = { version = "1.3.1" }` and a missing `serde_bytes` are each reported; `serde = { version = "=1.0.228", features = ["derive"] }` is not.
- **S8 (`kit-tests`):** a `TarmacKit` module with no test file and no entry is reported at its source file; with a test file it is not; a `Module+Part.swift` is not; with an entry it is not; an entry whose module now has a test file, or whose module is gone, is reported at its position in the list.

### Report and errors

- **S9:** Given two broken rules, when the script runs, then it exits 1 and writes two blocks in the order of the rules table, each with its `why`, its `fix` and `then make arch-check`.
- **S10:** Outside a git repository, with an exceptions list that is missing, is not a JSON list, or has an entry with no `reason`, the script exits 2 and names what is wrong. An untracked file that would break a rule is not read.

### On the real tree

- **S12:** Each of the seven rules is knocked out once on the real tree (the violation is written into a tracked file, or into a new file that is then `git add`ed; `make arch-check` is run; the tree is restored): each one exits non-zero and names the rule's summary and the place.
- **S13:** `docs/coding-style.md` and `CLAUDE.md` name `make arch-check` beside each rule it now holds, and say what it does not hold. `make docs-check` passes.

### Exact matching (appended)

S14–S20 are `node --test` tests, as S1–S10.

- **S14 (import forms):** in a `TarmacKit` file, an indented `    import AppKit` inside `#if`, `public import AppKit`, `@_spi(X) import AppKit`, `import AppKit.NSColor` and `#elseif canImport(WebKit)` are each reported at their line. `import AppKit` after `//` on the same line is not. In a `TarmacTerm` file, `#if canImport(TarmacKit)` is reported under `term-imports`.
- **S15 (word ends):** `Bundle.moduleURL` in a Swift file and `libc::kill_all` in a crate's `src/` are not reported. `libc::killpg(` in `core/crates/tarmacd/src/conn.rs` is reported; `// libc::kill(` there is not.
- **S16 (`no-profile-override` forms):** `[profile.release]` with `debug-assertions = true` and `[profile.dev.package.foo]` with `debug-assertions = false` are each reported at the key's line; the same key in a crate's `[package]` table, and a `# debug-assertions = false` line inside `[profile.dev]`, are not.
- **S17 (`serde-pinned` near misses):** `serde_json = "1"` in `[workspace.dependencies]` is not reported; `rmp-serde = "=1.3.1"` is not; a missing `serde` is reported at the `[workspace.dependencies]` header line.
- **S18 (several places, one block):** given two `TarmacKit` files that break `kit-imports`, `Zeta.swift:9` and `Alpha.swift:10`, the script writes one `kit-imports` block whose `at` rows are `app/Sources/TarmacKit/Alpha.swift:10` then `app/Sources/TarmacKit/Zeta.swift:9`.
- **S19 (exceptions):** an entry whose module has a test file is reported at the line of its `"module"` key; two entries with the same `module` make the script exit 2; `OffscreenHintLayout+PillStack.swift` with no base file and no test file is not reported.
- **S20 (tracked content):** a tracked `TarmacKit` file changed in the working tree to `import AppKit`, and not staged, is reported; a tracked file deleted from the working tree is skipped with no error. On exit 1 and exit 2, stdout is empty.

## For the Implementing Agent

> **Your job:** make every acceptance scenario above pass with tests that would *fail if the behavior were wrong*. A green suite that passes for the wrong reason does not satisfy this contract — `/verify` will hunt for vacuous tests by asking, of each behavior, "what is the smallest change that breaks this, and would any test catch it?"

- Write each rule's tests first: the violation and the near miss.
- The script reads tracked files only and writes nothing.
- No rule text is deleted from the docs in this change.

## Definition of Done

- [ ] `make test` (which now runs `make arch-check`) and `make lint` are green.
- [ ] Every scenario maps to a test or to a recorded command with its observed values.
- [ ] No covered-but-vacuous scenarios; tests meet the Desiderata bar; no implementation-quality blockers.
- [ ] The PR's own CI run is green, the `arch-check` job included.

## Trade-offs and Limitations

- These forms are not seen, each one measured: a second `import` after a `;` on one line; `canImport(AppKit, _version: 1)` and `canImport( AppKit )`; `use libc::{kill, killpg}` followed by a bare `kill(…)`, and `libc :: kill`; a quoted `"debug-assertions"` key; and code after a `//` that is inside a string, which the rule reads as a comment.
- A rule that throws (a file it cannot read) is exit 2, never exit 1: it has not judged the tree.
- The rules read text, not syntax. An `import` built by a macro, or `Bundle.module` inside a string or a `/* */` comment, is judged by its text.
- `one-signal-site` names two functions of `libc`. A signal sent another way (a crate, a `Command` that runs `kill`) is not seen. `use libc::kill;` is reported on the `use` line, but a later bare `kill(` is not.
- `no-profile-override` reads only `Cargo.toml` files, as text. A profile set in `.cargo/config.toml`, in a `CARGO_PROFILE_*` variable, or with a dotted key (`profile.dev.debug-assertions = …`) or an inline table (`dev = { debug-assertions = … }`) is not seen.
- `serde-pinned` reads only `[workspace.dependencies]`, one key line for each dependency. A dotted key (`serde.version = …`) or a sub-table (`[workspace.dependencies.serde]`) is not read, so that dependency is reported as missing. Today each crate that uses one of the three takes it with `.workspace = true`.
- `kit-tests` checks that a test file exists, not what it tests.
- The three copies of `socket_path()` are not checked here: that needs a shared test vector read by both languages, as `resume_cmd_cases.json` is.

## Decisions

1. **The issue of the four older exceptions.** #481, which now holds all six modules.
2. **A slice, `<Module>+<Part>.swift`.** It needs no test file and no entry, whether or not a `<Module>.swift` exists: `OffscreenHintLayout+PillStack.swift` extends a type that `OffscreenHints.swift` defines. A file can skip the rule by its name; a reviewer still sees the name.
3. **`docs/coding-style.md` §4 names `Messages` as a module with no test file; it has one now.** S13 corrects that list of names. That is a fact, not a rule.
4. **`.cargo/config.toml`.** In scope for `no-profile-override` when it is tracked, at the repo root or under `core/`.
