# 2609.0006 A hidden board culls every card

**Date:** 2026-09-07
**Status:** draft
**Author:** EP Lin
**Issue:** [#104](https://github.com/pingeplin/tarmac/issues/104)
**Upstream design:** [`docs/designs/2609.0002_offscreen_html_card_throttle.md`](../../docs/designs/2609.0002_offscreen_html_card_throttle.md) §"Non-active boards, partly covered by accident" (names this fix as a deliberate follow-up; PR #106 lists it too)

## Context

`App` renders one `Board` per board at once; an inactive board's root gets
`display:none` (`desktop/src/board/Board.tsx:143`) so its xterm terminals stay
warm. `BoardEngine.apply()` (`BoardEngine.ts:288-305`) measures that root with
`getBoundingClientRect()` and passes the result to `applyCull(rect)`
(`:333-338`), which calls the pure predicate
`isCardVisible(frame, vp, r.width, r.height)` (`desktop/src/kit/cull.ts:53-61`).

On a hidden board `r.width === r.height === 0`. `visibleWorldRect`
(`cull.ts:31-46`) then computes `visW = 0 / zoom = 0`, `halfW = 0`, and returns a
zero-size rect anchored at the saved viewport centre `(cx, cy)`.
`rectsIntersect` (`kit/placement.ts:32-34`) uses strict `<`, so a card frame that
**strictly contains** `(cx, cy)` still intersects that degenerate rect and stays
visible. Every other card on the board is culled.

## Motivation

Since #72 (PR #106) a culled HTML card has its `requestAnimationFrame` /
`setInterval` / `setTimeout` gated by `card_shim.js`, driven by
`BoardEngine.onCullChange` → `Board.tsx:88-89` → `kit/cardCull.ts`. The
un-culled centre card therefore keeps burning CPU at its full visible rate on a
board nobody is looking at — measured in `2609.0002` at ~19% WebContent for one
heavy card. The card that lands under the prime terminal contains the saved
centre by construction, so this is the common case, not a corner.

## Proposed Solution

### Overview

Treat a zero-area viewport as "nothing is on screen": if
`viewWidthPx === 0 || viewHeightPx === 0`, `isCardVisible` returns `false` for
every card, regardless of frame or margin. This is one early return in pure
`kit/` code, which is where the repo's testability lives (only `kit/` and Rust
are unit-tested; the React/Tauri shell is not).

### Key Components

- **`desktop/src/kit/cull.ts` → `isCardVisible`** — the single change. Add the
  zero-area guard *before* delegating to `visibleWorldRect` + `rectsIntersect`.
- **`desktop/src/kit/cull.ts` → `visibleWorldRect`** — **unchanged**. It is
  exported and separately tested as a geometry helper; a degenerate rect at
  `(cx, cy)` is the arithmetically correct answer for a zero-size viewport, and
  changing it would alter a contract that is not the bug.
- **`desktop/src/board/BoardEngine.ts`** — **no change expected**. `applyCull`
  already forwards `r.width` / `r.height` verbatim; the flip to `visibility:hidden`
  and the `onCullChange` fan-out are the existing paths.
- **`desktop/src/kit/cardCull.ts`** — **no change**. `isCulled(visible)` is a
  pure `!visible`; once the predicate returns `false`, the pause payload follows
  from logic already covered by `kit/cardCull.test.ts`. No new test there — one
  that re-asserted the same boolean would be vacuous.

### Data Flow (after the fix)

1. Board becomes inactive → root gets `display:none`.
2. `ResizeObserver` fires → `BoardEngine.apply()` → `getBoundingClientRect()`
   returns `0×0`.
3. `applyCull(rect)` calls `isCardVisible(frame, vp, 0, 0)` per cullable → `false`
   for all.
4. Each card flips to `visibility:hidden`; `onCullChange(id, false)` fires once
   per card that was visible.
5. `Board.tsx:88-89` maps it through `isCulled` → the HTML card's shim pauses its
   schedulers. Terminal and doc nodes stay mounted.
6. On reveal, `display:none` is removed → `ResizeObserver` fires → `apply()`
   re-measures real dims → cards re-cull normally.

### Interface Contract

```ts
// desktop/src/kit/cull.ts — signature UNCHANGED, behavior extended
export function isCardVisible(
  frame: Rect,
  vp: Viewport,
  viewWidthPx: number,
  viewHeightPx: number,
  marginViewports: number = CULL_MARGIN_VIEWPORTS,
): boolean;
// New rule: viewWidthPx === 0 || viewHeightPx === 0  ⇒  false, for any frame,
// any vp, any marginViewports.
```

Input domain: `viewWidthPx`/`viewHeightPx` are `getBoundingClientRect()` dims, so
never negative. The rule is stated on `=== 0` and nothing else is specified for
out-of-domain input; no extra guard is required.

No wire-protocol, persisted-state, or public-API change. Nothing to migrate.

## Alternatives Considered

### Guard inside `visibleWorldRect`

Return an empty/sentinel rect at zero size. Rejected: `visibleWorldRect` is an
independently exported, independently tested geometry function whose current
output is arithmetically correct; the *visibility policy* is `isCardVisible`'s
job. Placing the rule there also does not fix the strict-`<` interaction without
inventing a sentinel that every future caller must know about.

### Guard inside `BoardEngine.applyCull`

An early `if (r.width === 0 || r.height === 0)` in the engine. Rejected: the
engine is DOM-bound and has no unit tests, so the rule would be unverifiable by
the suite — exactly the anti-pattern `kit/` exists to avoid.

### Skip `apply()` entirely while hidden

Would leave every card's cull state stale at whatever it was before the switch,
so a previously visible HTML card would never receive its pause. Solves nothing.

## Acceptance Scenarios

### Happy Path

- **S1 [auto]:** Given a zero-**width** viewport (`viewWidthPx === 0`,
  `viewHeightPx` normal) and a card whose frame **strictly contains** the
  viewport centre `(cx, cy)` — e.g. `vp = {zoom: 1, cx: 100, cy: 100}`, frame
  `{x: 50, y: 50, w: 100, h: 100}` — when `isCardVisible` is evaluated, then it
  returns `false`. *(This exact geometry is the discriminating case: it returns
  `true` on `main`. A card placed away from the centre already returns `false`
  and would be a vacuous test.)*
- **S2 [auto]:** Given a zero-**height** viewport (`viewHeightPx === 0`,
  `viewWidthPx` normal) and the same centre-containing frame, when
  `isCardVisible` is evaluated, then it returns `false`.
- **S3 [auto]:** Given both dimensions zero (`0, 0`) and the same
  centre-containing frame, at any `marginViewports` (including a large one, e.g.
  `3`), when `isCardVisible` is evaluated, then it returns `false` — the margin
  cannot resurrect a card on a zero-area viewport.

### Regression / Unchanged Behavior

- **S4 [auto]:** Given a normal non-zero viewport, when the existing
  `kit/cull.test.ts` and `kit/cardCull.test.ts` suites run unmodified, then they
  all pass — centre card visible, in-margin card visible, >1-viewport-off card
  hidden, wider margin resurrects a distant card.
- **S5 [auto]:** Given `visibleWorldRect` called with a zero-size viewport, when
  its result is inspected, then it is still the degenerate rect at `(cx, cy)`
  (`w === 0`, `h === 0`, `x === cx`, `y === cy`) — the geometry helper's contract
  is deliberately untouched, and this test pins that the fix did not migrate into
  it.

### Reveal & Warm-Board (QA)

The React/Tauri shell and `BoardEngine`'s DOM/ResizeObserver path have no unit
tests by design, so the following are manual. Record all three as a checklist in
the PR body; S8's reading additionally goes into `desktop/qa/cull-qa.md` as an
S39 re-run note (see Definition of Done), since that sheet currently records the
opposite result.

Reuse `cull-qa.md`'s established setup rather than re-deriving it: probe switches
live in `cull-probe.html`'s `<meta name="cull-probe">` tag (not URL params), a
layout with a card strictly containing a board's saved centre is composed by
writing `.dev/state.json`, and the daemon is isolated by `TARMAC_SOCKET`
(`make kill-daemon`, never `pkill`). S39 of that sheet is this bug's recorded
repro and its "before" reading.

- **S6 [QA]:** Given a board hidden with all cards culled, when it is made active
  again, then every card that belongs on screen renders, with no blank board, no
  card stuck at `visibility:hidden`, and no blank flash perceptible at normal
  switching speed. *Steps:* two boards, ≥3 cards on board-1 spread across the
  viewport; switch to board-0, switch back; observe all on-screen cards render.
  *Mechanism relied on (unchanged): `display:none` removal → `ResizeObserver` →
  `apply()` with real dims.*
- **S7 [QA]:** Given a terminal card on a board that is switched away from, when
  the user switches back, then the terminal is still warm: full scrollback intact
  and the output Channel still attached. *Steps:* on board-1 run `seq 1 500` then
  start a long-running emitter (e.g. `while :; do date; sleep 1; done`); switch
  to board-0; wait ~15 s; switch back; scroll up and confirm the `seq` output is
  present, and confirm new timestamped lines kept arriving during the away window
  (no gap). *This is the `Board.tsx:9-12` "terminals stay WARM" contract — the
  fix must not break it, since `visibility:hidden` never unmounts.*
- **S8 [QA]:** Given the issue's repro — an animating HTML card on board-1 whose
  frame **strictly contains** that board's saved viewport centre — when the user
  switches to board-0 and back after ~15 s, then that card was paused for the
  whole hidden period. *Steps:* re-run `cull-qa.md` S39 unchanged (two probe
  cards on board-1: one straddling the saved centre, one off-centre; switch to
  board-0, wait ~15 s, switch back). *Pass criterion — the sheet's own
  discriminator, gaps not counts:* on the **straddling** card's first line after
  the switch back, `gapRaf`, `gapInt` **and** `gapTo` are each within ~2 report
  periods of `dt`, matching the off-centre card. **Fail:** any gap pinned near
  ~1000 ms while `dt` runs to seconds, or a `dt ≈ 1000` line stream across the
  hidden window — which is exactly what S39 recorded on `main`. CPU sampling is
  optional corroboration only; one card's worth of WebContent CPU is inside that
  sheet's measured noise unless taken as marginal medians of 3 reps.
  *This is the end-to-end confirmation that #72's pause now reaches the centre
  card, and it turns S39's recorded "NOT paused" row into a paused one.*

## Trade-offs and Limitations

- The rule keys on the *viewport measurement*, not on a board-active flag, so it
  fires for any zero-area cause (a collapsed pane, a window minimised to zero) —
  which is the desired semantics, but it means the engine has no way to
  distinguish "hidden board" from "not laid out yet". Verified as safe today:
  `BoardEngine`'s constructor runs `apply()` from a post-commit `useEffect`, so
  an active board measures real dims at first mount and never sees a transient
  `0×0`.
- Terminal and doc cards on a hidden board flip to `visibility:hidden` where they
  previously might not have. This is a no-op for the PTY (the node stays mounted,
  the Channel stays attached) but it is precisely why S7 is a required QA cell.
- CPU improvement is a single card's worth; the fix closes the last hole in #72
  rather than adding new savings.
