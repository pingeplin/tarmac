# 2609.0002 Pausing a culled HTML card's schedulers

**Date:** 2026-09-05
**Status:** draft
**Author:** EP Lin
**Issue:** [#72](https://github.com/pingeplin/tarmac/issues/72) `feat(cards): throttle or hide offscreen HTML card JS to prevent runaway CPU/GPU use`
**Design doc:** [2609.0002](../../docs/designs/2609.0002_offscreen_html_card_throttle.md) — approved at the design gate 2026-09-05
**Related:** [#99](https://github.com/pingeplin/tarmac/issues/99) (magnify card renders at 1/K after a self-reload), spec [2607.0006](2607.0006_magnify_zoom_mode_for_html_cards.md) (S6, S9, S16, S17)

## Context

`BoardEngine.applyCull` (`desktop/src/board/BoardEngine.ts:322`) already toggles
`visibility:hidden` on every card more than one viewport off-screen
(`desktop/src/kit/cull.ts`, `CULL_MARGIN_VIEWPORTS = 1`). The culled element is the
per-card wrapper `<div>` in `desktop/src/board/Board.tsx` (`ref={setEl(id)}` →
`engine.setCullables`). Nothing in the card tree reads that state.

The design measured what that costs, in Playwright WebKit 2336, Safari 26.6, and —
decisively — inside Tarmac's own Tauri/WKWebView release bundle. Three findings bind
this spec:

1. **CSS visibility does nothing.** `visibility:hidden` and `display:none` leave rAF
   and both timer families at full rate in both engines. The issue's candidate (a) is
   a measured no-op.
2. **The engine already throttles offscreen geometry** — a culled frame runs rAF at
   0 Hz and both timer families at ~1 Hz — **but a pending, unserviced rAF request
   still costs ~5.5 points of WebContent CPU**, plus ~3.5 points of Tauri main
   process, whether or not any callback is ever delivered. Six culled animating cards
   cost **+6.04** points of WebContent over a 0.15% empty-board floor; ≈11 points
   summed across WebContent, GPU and main.
3. **A gate that merely holds callbacks is not enough.** WKWebView services a culled
   document's rAF exactly once every 10 s (an undocumented, phase-shifting engine
   tick). A hold-gate therefore keeps paying the full standing charge until that next
   tick — measured **4.09%** in the 10 s window opening *at* the pause, against
   **0.3%** for a cancel-gate — and **fails success criterion 3 (+3.79) for 0–10 s
   after every cull event**.

Two constraints shape where the tested logic can live:

- **The React/Tauri shell has no unit tests** (only pure `kit/` logic and Rust are
  tested — 38 of the repo's 40 test files are in `desktop/src/kit/`).
- **`card_shim.js` is `include_str!`'d** by the app's Tauri backend
  (`desktop/src-tauri/src/card_protocol.rs`) and prepended to every `tarmac-card://`
  response. It is not built from `kit/` and cannot import from it.

## Motivation

Issue #72 is the follow-up `2607.0004` §Trade-offs accepted deferred: "a runaway card
can still burn CPU/GPU in the shared process… throttling/`display:none`-on-offscreen
is future work". The in-app run reproduces it — an idle board with six culled
animating cards burns ≈11 points across three processes for nothing on screen, and the
design's success criterion 3 fails today at **+5.99**.

Doing nothing is the alternative the design explicitly reconsidered and rejected: the
condition it had been held open for (an "already rendering" host that would have made
the saving ~0) is not met — the idle board's floor is 0.15%, and even against a live
scrolling terminal six culled cards still cost **+3.10** points.

## Proposed Solution

### Overview

`BoardEngine` publishes each card's cull flip through a new callback. `Board.tsx`
routes the flip to a ref-held listener map. `HtmlCard` registers a listener and posts
`{ tarmac: "cull", culled }` into its iframe. `card_shim.js` — which captures the six
scheduler natives at load, before any card script runs — gates
`requestAnimationFrame` / `setInterval` / `setTimeout` behind that flag, and **the rAF
wrapper cancels outstanding native requests at pause** rather than merely holding
their callbacks.

The signal is a **state, not an edge**: every post carries the current boolean, both
sides are idempotent, and nobody has to track what was last sent.

### Key Components

- **`BoardEngine.onCullChange`** (`desktop/src/board/BoardEngine.ts`) — an optional
  callback shaped like the existing `onViewportChange` / `onRasterScaleSettle`, fired
  from **the single flip site inside `applyCull`**: the line that today writes
  `c.el.style.visibility`, which already runs only when the cached visibility actually
  flips. No new predicate, no new cache, no second call site.
- **`Board.tsx` cull listener map** — a `useRef<Map<string, (culled: boolean) => void>>`.
  `engine.onCullChange` looks the id up and calls the entry. The precedent is
  `termHandlesRef` in `desktop/src/App.tsx:265–273` (the ref at :265, `registerTerm`/`unregisterTerm` through :273); here **Board** owns the map,
  because the engine that fires it is Board's, not App's.
  **The signal must not go through React state.** `applyCull` runs synchronously
  inside the wheel handler and inside `flyTo`'s rAF loop, and no card component is
  `React.memo`'d, so a `useState` of culled ids would re-render every card on the board
  on every frame in which any card flips — which a fast pan across a dense board does
  on consecutive frames.
- **`desktop/src/kit/cardCull.ts`** (new) — the pure logic: the polarity mapping
  (`onCullChange`'s `visible` → the payload's `culled`), the message builder, and the
  register/unregister rules for the listener map. One line of logic that would
  otherwise sit in untestable glue and silently invert.
- **`HtmlCard`** (`desktop/src/cards/HtmlCard.tsx`) — registers on mount and
  unregisters on unmount, and posts the payload from **two** places covering disjoint
  cases: the registered listener (every flip after the document is live) and the
  `ready` handler **before the `readyHandledRef` guard** (the state a document is
  *born* into). The listener writes each value into a ref; the `ready` post reads that
  ref.
- **`card_shim.js`** (`desktop/src-tauri/src/card_shim.js`) — captures the six natives
  at load, adds a `cull` branch to the existing host-message listener, and wraps the
  three scheduler families.

### Data Flow

1. A pan/zoom/`setCullables` call reaches `BoardEngine.applyCull`. A card's computed
   `isCardVisible` differs from the cached value, so the flip site runs.
2. The flip site writes `el.style.visibility` (unchanged) **and** calls
   `this.onCullChange?.(c.id, visible)`.
3. `Board.tsx` maps `visible` → `culled` via `kit/cardCull` and calls that id's
   registered listener, if any. Only HTML cards register; nothing re-renders.
4. `HtmlCard`'s listener stores `culled` in a ref and posts
   `{ tarmac: "cull", culled }` to `iframeRef.current.contentWindow`.
5. `card_shim.js`'s message listener — after its existing `e.source !== window.parent`
   check — sets or clears the paused flag. On a `false → true` transition it cancels
   every outstanding native rAF request and moves those callbacks to the held queue. On
   `true → false` it flushes: held timeouts through one native `setTimeout(…, 0)` hop,
   held frames through one native `requestAnimationFrame`.
6. On a document load (first open, `?v=` reload, or a #99-shaped self-reload), the
   shim's `ready` reaches `HtmlCard`, which posts the ref's current value **before**
   consulting `readyHandledRef`, so a document born culled is paused on its first
   frame.

### Interface Contract

```ts
// desktop/src/board/BoardEngine.ts — additive optional callback, alongside
// onViewportChange and onRasterScaleSettle. Fired ONLY from applyCull's existing
// flip site, i.e. only when a card's culled state actually changes.
onCullChange?: (id: string, visible: boolean) => void;
```

```ts
// desktop/src/kit/cardCull.ts — new pure module.

/** The host→card payload. `culled` is a STATE, never a toggle or an edge. */
export interface CardCullMessage {
  tarmac: "cull";
  culled: boolean;
}

/** onCullChange's `visible` → the payload's `culled`. The polarity inversion,
 *  in one named place instead of a `!` buried in glue. */
export function cullMessage(visible: boolean): CardCullMessage;

/** Register `fn` under `id` in the listener map and return its unregister.
 *  Registering an id that is already present replaces the entry. The returned
 *  unregister removes the entry only if it is still the one this call installed
 *  (so a remount's unregister cannot delete the new listener), and is safe to
 *  call more than once. */
export function registerCullListener(
  map: Map<string, (culled: boolean) => void>,
  id: string,
  fn: (culled: boolean) => void,
): () => void;
```

```ts
// desktop/src/cards/HtmlCard.tsx — additive optional prop; absent ⇒ no gate.
// Board binds cardId(c) and returns the unregister, so no id plumbing leaks into
// the card.
onCullRegister?: (fn: (culled: boolean) => void) => () => void;
```

**Why one prop rather than `onTermRegister`/`onTermUnregister`'s two.** The terminal pair
passes the id back up on both calls because `App` — not the component's own parent —
owns that map. Here `Board` owns the map *and* already has `cardId(c)` in scope at the
call site, so binding it into the closure and returning the unregister removes the id
from the card's surface entirely; a card that cannot name an id cannot register under
the wrong one.

**`onCullRegister` goes on the `<HtmlCard>` element, never into Board's `shared`
object** (`desktop/src/board/Board.tsx:207`). `shared` is spread into both `<HtmlCard
{...shared}>` and `<DocCard {...shared}>`, and **TypeScript does not apply
excess-property checking to a spread of a variable** — so a cull prop parked in `shared`
would compile silently while being handed to `DocCard`, which has no use for it. The
existing `borrowed` / `onBorrow` / `onEscapeHome` props are already placed this way for
the same reason; follow them.

**Host↔card wire (host → shim only):**

| key | type | semantics |
|---|---|---|
| `tarmac` | `"cull"` | discriminant |
| `culled` | boolean (required) | the card's **current** cull state |

- **`parseCardMessage()` is not extended.** It covers shim→host messages only, exactly
  as `zoom` is deliberately absent from its union (`2607.0006` S16). A `cull` payload
  arriving *from* an iframe must still parse to `null`.
- The shim honours `cull` only when `e.source === window.parent` — the existing check
  in the message listener, which a nested frame or the card's own window cannot pass.

**Shim gate contract.** `card_shim.js` captures the natives it uses —
`requestAnimationFrame`, `cancelAnimationFrame`, `setTimeout`, `clearTimeout` and
`setInterval` — **at load, before any card script runs**, so the gate's own resume path
can never be gated by its own wrapper and a card that overwrites a global cannot break
resume. **`clearInterval` is deliberately neither captured nor wrapped**: an interval
keeps no shim-side state (the wrapper gates delivery, never creation, and hands back
the native id), so the native `clearInterval` is already correct and a wrapper would be
dead code. The `[S]` harness still installs all six, because the *harness* precondition
is about what exists before the IIFE runs, not about what the shim keeps.

- **`requestAnimationFrame`** — the wrapper owns its **own id space**: it returns its
  own monotonically increasing ids and keeps a `shimId → nativeId | null` mapping. (A
  call made while paused never reaches the native rAF, so there is no native id to
  return, yet `cancelAnimationFrame` must still accept what was returned.)
  - **On pause:** call the captured native `cancelAnimationFrame` on **every**
    outstanding native id and move those callbacks to the held queue. *This is the
    load-bearing half.*
  - **While paused:** new calls are held without scheduling anything native.
  - **On resume:** re-issue the held callbacks through **one** native
    `requestAnimationFrame` — the card sees one catch-up frame, not one frame per frame
    missed. That catch-up request is itself tracked as outstanding, so a re-pause
    before it fires cancels it like any other.
  - `cancelAnimationFrame` works on a **held** id: the entry is removed and the
    callback is never delivered.
  - **While running** (never paused, or since resumed): `cancelAnimationFrame(shimId)`
    resolves the mapping and calls the **captured native** `cancelAnimationFrame` with
    the native id. The wrappers are transparent on the un-culled path — a cancel that
    only searches the held queue would break every card that cancels a frame while
    visible, and would ship green (S40).
- **`setInterval`** — the wrapper **no-ops while paused**; the native timer keeps
  ticking, so ids stay valid for `clearInterval` and cadence is unchanged. **Ticks
  missed during a pause are dropped, not queued** — an interval is a cadence, not a
  work queue, and flushing N missed ticks on resume is the frame-storm this design
  exists to avoid. **It returns the native id directly — no shim id space.** The
  asymmetry with rAF is deliberate and is not a style choice: a `setInterval` call
  *always* reaches the native (the wrapper gates delivery, never creation), so a native
  id always exists to return, and `clearInterval` forwards it to the captured native
  unchanged. That is the id S14 asserts.
- **`setTimeout`** — gated at **fire** time, not at call time. The wrapper installed at
  creation checks the paused flag when the native timer fires and, if paused, moves the
  callback (with its extra arguments) to the held queue instead of running it. **A gate
  that only intercepts calls made *during* the pause lets a timeout issued before the
  cull run card code while paused** — a culled frame's timers are clamped to ~1 Hz, not
  stopped — failing criterion 1 by construction. Flush on resume through a native
  `setTimeout(…, 0)` hop so card code never runs re-entrantly inside the shim's message
  listener. **`clearTimeout` must work on a diverted callback**: held entries are keyed
  by their original id, so `clearTimeout(id)` removes the entry. **Like `setInterval`
  and unlike rAF, it returns the native id directly — no shim id space**, for the same
  reason: the native is *always* armed at call time (pinned semantic 1), so a native id
  always exists. "Their original id" above is therefore that native id, and it is the
  single key under which a timeout is findable whether it is still armed or already
  diverted into the held queue (S18).

**Four pinned semantics** (the Vitest suite asserts each):

1. **Clock.** A `setTimeout(fn, 5000)` issued while paused starts its clock **at call
   time**, not at resume — the wrapper arms the native timer immediately and gates only
   the delivery.
2. **Order.** Flushed callbacks are delivered in **issue order within a family**, and
   timeouts land before re-issued frames. The cross-family half is an *engine* property
   (a 0 ms timeout runs before the next animation frame), not shim logic — the unit
   suite asserts only **which native primitive carries each flush**; the observable
   ordering is QA-observed.
3. **Multiplicity.** A timeout that would have fired during the pause is delivered
   **exactly once** — neither dropped nor repeated.
4. **Timestamp.** A re-issued rAF callback receives a **fresh** native timestamp. A
   card computing `dt = ts - lastTs` therefore sees a delta spanning the whole cull and
   `x += v * dt` teleports on un-cull. The gate does not rewrite timestamps — that
   would lie to the card about the clock — so this is asserted behaviour and a
   documented consequence, not a defect to fix later.

**Idempotence, both sides.** A repeat `{culled:true}` while already paused returns early
and must not re-cancel, re-queue or double-hold anything; a repeat `{culled:false}` while
already running must not deliver anything twice or schedule anything spuriously. This is
what makes the host free to re-assert without tracking what it last sent — including the
benign case of a card culled and un-culled before its document commits, which arrives as
`culled:false` and is a no-op.

**Applied independent of `ready`.** The gate state is set whenever a well-formed `cull`
message arrives, whether or not `DOMContentLoaded` has fired. It shares nothing with the
`ready` / `pendingZoom` machinery.

**Never gated.** The shim's `console`, `error`, `unhandledrejection`, `escape` and
`ready` relays — a paused card must still be able to report. Also untouched by design:
Workers, `MessageChannel`/microtask loops, `scheduler.postTask`,
`requestIdleCallback`, CSS animations and transitions, `<video>`, nested frames' own
realms, and `while(true)`.

**Unchanged.** `CULL_MARGIN_VIEWPORTS` stays 1 and stays shared with terminal and
markdown cards. `cardSrcUrl`, `readyHandledRef`'s reset condition, `parseCardMessage`,
`applyCull`'s predicate, and every existing conformance vector.

## Alternatives Considered

The design doc argues these at length; they are recorded here so `/verify` can flag an
implementation that has silently drifted into one.

### Hold-gate instead of cancel-gate

Hold the callbacks without cancelling the outstanding native requests — the natural
thing to write, and it passes any test that only checks callbacks were not delivered.
**Rejected on measurement:** it pays the full standing charge until WebKit's next 10 s
service tick (**4.09%** against cancel's **0.3%**, 0–10 s per cull event, mean ~5 s) and
**fails success criterion 3 at +3.79** for that whole interval, on every cull. It also
inherits its correctness from an undocumented, phase-shifting engine cadence. This is
why **S7 asserts the native `cancelAnimationFrame` call**, not merely the absence of
delivery.

### Gate `requestAnimationFrame` only

About a third of the code, no held-timeout queue, none of the four semantics to pin,
and it captures most of the idle-board recovery (5.04 of the 6.04 points at N=6).
**Rejected** because the timer half is the component that **scales with N** (in-app
`timersonly` +0.75 at N=6; browser probe 1.4% at N=1 → 2.9% at N=6), so on the dense
boards this feature exists for it is the growing term — and because against a live
terminal the total marginal is +3.10 points whose rAF/timer split is unmeasured.

### `display:none` on the iframe while culled

The issue's candidate (a). **Measured: no effect** on rAF or on either timer family, in
either engine (30.1 Hz against a 29.9 Hz baseline in Playwright; 21.7 against 22.0 in
Safari).

### Read the cull state through `CardShell`'s `rootRef` + a MutationObserver

`rootRef` exists on every card kind with no caller, so it looks free. **Rejected:** the
culled element is the wrapper `<div>` in `Board.tsx`, an *ancestor* of the `CardShell`
root — the card would observe a node it does not own, hard-code Board's DOM shape, and
re-derive a signal the engine already computes.

### Expose `BoardEngine.cullVisible`

Widens a private cache into API and still needs a poll or observer to notice a change.

### A second, tighter cull threshold

Pause before a card is a full viewport out. **Rejected on the margin's purpose:**
`CULL_MARGIN_VIEWPORTS = 1` exists so a pan-back finds cards already live, and a card
one viewport out is one flick from being looked at. The saving is also unmeasured. It
would be a separate change, with its own threshold, touching a predicate shared with
terminal and markdown cards.

## Security Considerations

The card is untrusted, opaque-origin, `sandbox="allow-scripts"`, `allow=""`. This change
adds one **host→card** message and no card→host surface.

- **The `cull` payload must not become parseable card→host.** `parseCardMessage` stays
  as it is (S4), so a card that posts `{tarmac:"cull"}` at the host is ignored exactly
  as it is today.
- **A card cannot pause or unpause itself or a sibling.** The shim honours `cull` only
  from `window.parent` (S27), so a nested frame or a `window.postMessage` at the card's
  own window is inert.
- **A malformed or hostile payload must not throw.** The shim's every path is defensive
  by construction (`2607.0004`); a `cull` message with a missing or non-boolean `culled`
  leaves the gate state unchanged and does not break the relays (S28).
- **The gate cannot be used to silence a card.** The console, error, escape and `ready`
  relays are never gated (S26), so a paused card can still report — including reporting
  that it is paused.
- **No new privilege, no new origin, no daemon/protocol/CLI surface.** The wire protocol
  (`tarmac-protocol`) is untouched; no conformance vector changes.

## Acceptance Scenarios

Legend: **[K]** desktop kit unit test (Vitest, `desktop/src/kit/`), **[S]** shim-vm unit
test (Vitest, `desktop/src/card-shim.test.ts` — evaluates the *shipped*
`desktop/src-tauri/src/card_shim.js` bytes in a Node `vm`), **[Q]** manual QA checklist
item in a new `desktop/qa/cull-qa.md`.

> **Why [S] reads the shipped file.** `card_shim.js` is `include_str!`'d into the Tauri
> backend and is not built from `kit/`, so a copied-into-the-test version could pass
> while the shipped bytes are broken. The precedent is `desktop/src/kit-build.test.ts`,
> the repo's one test that reads a shipped artefact off disk rather than duplicating it.
> The design already demonstrated the harness: the shim runs verbatim in a Node `vm`
> with a ~40-line fake `window`/`document`, firing `DOMContentLoaded` produces
> `{tarmac:"ready", meta:"magnify"}`, and a host `zoom` sets
> `documentElement.style.zoom`. No jsdom, no new devDependency.

### Kit — polarity, payload shape, listener registry

- **S1 [K]:** Given `cullMessage`, when it is called with `visible = false` and again
  with `visible = true`, then it returns `{tarmac:"cull", culled:true}` and
  `{tarmac:"cull", culled:false}` respectively. **This is the polarity assertion** — the
  one line that would silently invert (pausing visible cards and running culled ones) if
  the `!` went missing or doubled, and the only place in the app where that inversion is
  automatically catchable.
- **S2 [K]:** Given `cullMessage`, when it is called **twice in a row with the same
  argument**, then both calls return the same `culled` value — the payload is a *state*
  derived from its input, not a toggle or an edge that alternates or depends on call
  history. A toggle implementation passes S1 and fails this.
- **S3 [K]:** Given a listener map, when `registerCullListener(map, "a", fn)` is called
  and the returned unregister is invoked, then `map` has an entry for `"a"` calling `fn`
  before and no entry for `"a"` after; invoking the same unregister a second time is a
  no-op; and registering `"a"` again with `fn2` and then invoking the **first**
  unregister leaves `fn2` installed (a remount's teardown must not delete the new
  listener).
- **S4 [K]:** Given `parseCardMessage` (`desktop/src/kit/cardConsole.ts`), when it is
  passed `{tarmac:"cull", culled:true}`, then it returns `null`. **Standing regression
  guard, green before any change is written** — `cull` is host→shim only, and the
  obvious mistake when adding a new `tarmac` discriminant is to widen the shim→host
  union with it (`2607.0006` S16 made the same call for `zoom`). Score it as a guard,
  not as evidence the feature works. It extends the existing `parseCardMessage` describe
  block in `desktop/src/kit/cardConsole.test.ts`.

### Shim vm — harness preconditions

- **S5 [S]:** Given a fake `window`/`document` exposing **all six** scheduler natives —
  `requestAnimationFrame`, `cancelAnimationFrame`, `setTimeout`, `clearTimeout`,
  `setInterval`, `clearInterval` — installed **before** the shim's IIFE is evaluated,
  and a fake `document.querySelector` that answers `meta[name="tarmac-zoom"]` with a
  stub whose `content` is a **known, test-chosen string** (`"magnify"`), when the
  shipped `card_shim.js` is evaluated in a Node `vm` and `DOMContentLoaded` is fired,
  then the fake `window.parent` receives `{tarmac:"ready", meta:"magnify"}` — asserted
  against that same chosen string, so a shim that posted a constant or `null` fails —
  and a subsequent host `{tarmac:"zoom", z:3}` sets
  `document.documentElement.style.zoom` to the **posted value** `3` (the fake `style` is
  a plain object, so it holds the number the shim assigned, not a CSS-serialized
  string — assert against what was posted, not against `"3"`). **This is a precondition,
  not a feature:** the shim captures its natives at load, so a harness that installs
  them late observes different functions than the shim captured and every other [S]
  scenario becomes meaningless. It doubles as the regression guard that the gate did not
  break the existing handshake.
- **S6 [S]:** Given the shim loaded against the fake natives **and card callbacks
  already issued through the wrappers** (an outstanding rAF request and a `setTimeout`
  whose deadline falls inside the coming pause), when `window.requestAnimationFrame`,
  `window.setTimeout` and `window.cancelAnimationFrame` are **replaced with spies that
  record and then throw**, and only then is a pause → resume round trip driven, then the
  outstanding request is still cancelled at pause and both callbacks are still delivered
  at resume, and **none of the replaced globals records a call**. The issue-before-
  replace ordering is load-bearing: once a global is replaced, card code can no longer
  reach the wrapper at all, so the callbacks under test have to predate it. This is what
  "captures the natives at load" means observably — a card that overwrites a scheduler
  global cannot break the gate's own resume path.

### Shim vm — requestAnimationFrame

- **S7 [S]:** Given a card that has called the wrapped `requestAnimationFrame` and whose
  request is outstanding (the native rAF returned id `N`, the callback has not run),
  when `{tarmac:"cull", culled:true}` arrives from `window.parent`, then **the captured
  native `cancelAnimationFrame` was called with `N`**, and the callback has not been
  delivered. **This is the single scenario that separates this design from the defective
  one** — a hold-gate passes every other rAF scenario here and still leaves the standing
  charge until WebKit's next 10 s service tick.
- **S8 [S]:** Given the shim is paused, when card code calls the wrapped
  `requestAnimationFrame`, then the captured native `requestAnimationFrame` records **no
  new call**, and the wrapper returns a **defined id, distinct per call** — the value
  S10's cancel path acts on. (A wrapper that returns `undefined` while paused satisfies
  the no-native-call half and leaves the card unable to cancel; that is why the return
  value is asserted here and not left to S10.) No new pending native request may be
  created while paused — that is the charge the gate exists to remove.
- **S9 [S]:** Given three rAF callbacks held across a pause — at least one **issued
  before the pause and still outstanding when it arrives**, and at least one **issued
  while paused** (a mixed fixture; whether the pause cancelled the first one's native
  request is S7's assertion, not this one's) — when `{culled:false}` arrives, then
  **exactly one** native `requestAnimationFrame` call is made by the resume, and when it
  fires all three callbacks run **once each, in issue order**. Not one native frame per
  held callback, and not one delivery per frame missed.
- **S10 [S]:** Given a callback held during the pause, when the card calls
  `cancelAnimationFrame` on the id the wrapper returned for it and the card is then
  resumed, then that callback is never delivered while the other held callbacks are.
- **S11 [S]:** Given a callback issued before the pause whose pre-pause native frame the
  harness would have driven with timestamp `T0`, when the catch-up native frame is driven
  on resume with a **distinct** timestamp `T1 ≠ T0`, then each re-issued callback
  receives `T1` — the fresh native timestamp, not a pre-pause value and not a rewritten
  one. The two timestamps must differ, or a shim that hands out a constant passes
  vacuously. (Pinned semantic 4; the card-visible `dt` jump across a cull is intended.)

### Shim vm — setInterval

- **S12 [S]:** Given an interval created before the pause, when the shim is paused and
  the fake native interval is ticked **three** times, then **zero** card callbacks are
  delivered, **and the captured native `clearInterval` was not called** with that
  interval's id — the native timer keeps ticking so its id stays valid for
  `clearInterval` and its cadence is unchanged.
- **S13 [S]:** Given the interval of S12 with its three missed ticks, when
  `{culled:false}` arrives, then **no callback is delivered by the resume itself**, and
  the card's callback next runs **exactly once**, on the next native tick — one, not
  three. Missed ticks are **dropped, not queued**: a queue-and-flush interval passes S12
  and produces the frame-storm this design exists to avoid.
- **S14 [S]:** Given an interval created before the pause, when the card calls
  `clearInterval` on it **while paused** and the shim is then resumed, then the callback
  is never delivered again and the captured native `clearInterval` was called with that
  interval's id — which *is* the native id, since `setInterval` has no shim id space
  (Interface Contract).

### Shim vm — setTimeout

- **S15 [S]:** Given a timeout **issued while running** whose native timer fires **during
  the pause** (i.e. its deadline falls inside the cull), when the fake native fires it,
  then the card's callback is **not** run. **Fire-time gating is what this asserts**, and
  this is the only scenario whose *fixture* is built for it — a timeout outstanding
  **across** the pause boundary, the case no measurement to date has exercised. A
  call-time wrapper is the shape that lets card code run while paused, failing success
  criterion 1 by construction. (It also fails S16–S18 and S20, whose fixtures all
  presuppose a diverted timeout, and S19 in its hold-at-call-time form; see the
  mutation table. S15 is named because it is the one that *tests for it* rather than
  tripping over it.)
- **S16 [S]:** Given the diverted timeout of S15, when `{culled:false}` arrives, then
  the callback has **not** run at the instant the shim's message listener returns, it
  runs **exactly once** afterwards, and it is carried by a call to the captured native
  `setTimeout` with delay `0`. Card code must never run re-entrantly inside the shim's
  message handler.
- **S17 [S]:** Given `setTimeout(fn, d, "a", 7)` diverted across a pause — S15's fixture:
  issued while running, its native timer firing during the pause — when it is flushed on
  resume, then `fn` is called with `("a", 7)` and with nothing else appended, so extra
  arguments survive both the divert and the flush hop.
- **S18 [S]:** Given a timeout already diverted into the held queue (its native timer has
  fired), when the card calls `clearTimeout` on its id and the shim is then resumed,
  then the callback **never runs at any point** — not during the pause, not at the
  resume, and not when the flush hop is drained. (Asserted over the whole run, not only
  after the resume: a wrapper that gated at call time would have let it run *during* the
  pause, and a post-resume-only assertion would score that as a pass.) Under fire-time
  gating the native timer is already spent, so held entries must be keyed by their
  original id — without this a card that cancels a timeout during a cull still sees it
  run on un-cull, the exact analogue of S10.
- **S19 [S]:** Given the shim is paused, when card code calls `setTimeout(fn, 5000)`,
  then the captured native `setTimeout` is called **immediately, with delay 5000** — the
  clock starts at call time, not at resume. (Pinned semantic 1.)
- **S20 [S]:** Given two timeouts diverted in order A then B and three rAF callbacks held
  in order X, Y, Z — **both families held at once**, which no other scenario sets up —
  when the shim resumes, then the timeouts are delivered A then B and the frames X then
  Y then Z: **issue order within each family**, and — because the fake natives are
  manually drained one family at a time — the two families do not interleave *in this
  harness*. **The no-interleaving half is a property of the fixture, not a promise about
  the engine**: the spec disclaims cross-family ordering everywhere else (S21, pinned
  semantic 2, S38), and this scenario does not quietly reinstate it. What it catches is a
  shim that puts both families in **one shared queue** — which would interleave here,
  under a drain order that gives it no excuse to. (Pinned semantic 2, the half that is
  shim logic.) The frame half overlaps S9
  deliberately and is not a restatement of it: S9's fixture holds frames only, so it
  cannot catch a single shared queue that interleaves the two families while still
  looking ordered inside each one.
- **S21 [S]:** Given held callbacks of both families — the timeouts **diverted**, i.e.
  issued while running with their native timers firing during the pause (S15's fixture,
  the same one S17 and S18 use) — when the shim resumes, then held **timeouts** are
  carried by the captured native `setTimeout` (delay 0) and held **frames** by the
  captured native `requestAnimationFrame` — asserted as *which native primitive carries
  which family*. Pinning the fixture to the diverted shape is deliberate: a fixture that
  issued its timeouts *while already paused* would survive a call-time-gating wrapper,
  and this suite must leave that shape no hole. The observable "timeouts land before re-issued
  frames" is an engine property (a 0 ms timeout runs before the next animation frame in
  every engine), not shim logic, and is QA-observed in S38 rather than asserted here.

### Shim vm — idempotence, re-pause, and load ordering

- **S22 [S]:** Given the shim is already paused with callbacks held, when a **second**
  `{culled:true}` arrives, then the captured native `cancelAnimationFrame` records no
  additional call, and a single subsequent `{culled:false}` delivers each held callback
  **exactly once**. Re-asserting a state the host cannot know is redundant must be free.
  (The exactly-once delivery is the observable that a double-hold would break, so the
  held queue's contents are not inspected — reaching into the queue would be a
  structural assertion on internal state, which this spec never permits; the one
  sanctioned exception is asserting *which captured native was called*, listed under
  "Behavioral over structural".)
- **S23 [S]:** Given the shim is running (not paused), when a `{culled:false}` arrives,
  then nothing is delivered and nothing is scheduled natively by the message itself;
  and afterwards a card `requestAnimationFrame` reaches the captured native **exactly
  once** and its callback runs when that native request is drained, and a card
  `setTimeout` arms the captured native and runs its callback when that native timer is
  fired. "Behaves exactly as before" is spelled out as those two deliveries so the
  scenario has a real observable rather than an absence.
- **S24 [S]:** Given a resume has scheduled its flush hop and its catch-up frame but
  neither has fired yet, when `{culled:true}` arrives again, then the catch-up native
  rAF id is passed to the captured native `cancelAnimationFrame`; and when the flush hop
  does fire, the held timeout callbacks are **re-diverted rather than run** — and a
  second `{culled:false}` then delivers **each of them exactly once**, and **re-issues
  the held rAF callbacks and delivers each of those exactly once too**. Both families'
  final clauses are what separate re-holding from discarding: without the timeout half a
  re-pause that drops the timeout queue passes, and **without the frame half a shim that
  cancels the catch-up frame and then throws the held rAF callbacks away also passes** —
  each silently violating pinned semantic 3 for its own family. A fast
  cull → un-cull → cull must not run card code while paused, must not lose it, and must
  not leave a fresh pending native request behind.
- **S25 [S]:** Given the shim has loaded but `DOMContentLoaded` has **not** fired (no
  `ready` posted yet), when `{culled:true}` arrives from `window.parent`, then a
  subsequent card `requestAnimationFrame` is held rather than scheduled natively. The
  gate is independent of the `ready` handshake and of `pendingZoom`.

### Shim vm — repeated round trips

- **S41 [S]:** *(numbered out of sequence — added at the `/verify` gate, alongside S40;
  S1–S39 are stable references and were not renumbered.)* **A delivered callback is
  never delivered again.** Given a callback that has already run — whether delivered
  **naturally while the card was running**, or **by a catch-up flush**, or **by a
  timeout flush** — when the card is culled and un-culled again (and again), then it
  runs **exactly once in total**, and once the queues have drained a further round trip
  costs **no new native `requestAnimationFrame` and no new flush hop**, and cancels
  nothing a second time.

  > **Why this is separate from S9/S16/S22/S24.** Every other exactly-once assertion in
  > this spec settles inside **one** pause → resume round trip, and a real board culls
  > and un-culls a card constantly as the user pans. Three independent one-line
  > omissions — failing to drop a held entry after a natural frame, after a catch-up
  > flush, or after a timeout flush — leave spent callbacks in the queues, where every
  > later un-cull re-delivers them. That is pinned semantic 3 violated, and it is the
  > frame storm the design cites when it rejects interval queueing. **Verified by
  > execution:** each of the three was run as a mutant against the shipped bytes and
  > survived the whole suite until this scenario existed. The trailing "costs nothing"
  > clauses close the same class on the other side: a resume that schedules a catch-up
  > frame or a flush hop with nothing to flush leaves a pending native request behind on
  > every un-cull — the exact standing charge this feature exists to remove — and a pause
  > that retains a spent catch-up id cancels it twice.

### Shim vm — a throwing flushed callback

- **S42 [S]:** *(numbered out of sequence — added at the `/verify` gate, with S40 and
  S41; S1–S39 are stable references and were not renumbered.)* **A card callback that
  throws during a flush is isolated and reported.** Given held callbacks in both
  families with a throwing one in the **middle** of each queue, when the card is
  resumed, then every other held callback in both families is still delivered, in issue
  order; and the exception is **relayed** as an `error` console entry rather than
  swallowed.

  > **Both halves are needed, and neither is decorative.** The native schedulers
  > isolate callbacks by giving each its own task; the flush runs a whole queue inside
  > one loop, so it has to isolate them itself — otherwise one bad card callback
  > silently drops every callback queued behind it, which looks exactly like the gate
  > losing work. And the *live* rAF path lets a throw reach `window.onerror` and the
  > shim's existing error relay, so a flush that swallowed exceptions would make a
  > card's error vanish **precisely when the callback happened to be flushed after a
  > cull** — a reporting asymmetry the card author cannot see. **Verified by
  > execution:** removing the flush's `try/catch` entirely passed the whole suite until
  > this scenario existed.

### Shim vm — the never-paused path

- **S40 [S]:** *(numbered out of sequence — added at the spec-review gate; S1–S39 are
  stable references and were not renumbered, per `2609.0001`'s S21/S22 precedent.)*
  **The cancel/clear wrappers must be transparent when no `cull` message has ever
  arrived.** Given a shim that has never been paused, when the card schedules one
  callback in each family through the wrapped `requestAnimationFrame`, `setTimeout` and
  `setInterval`, then cancels each through the wrapped `cancelAnimationFrame`,
  `clearTimeout` and `clearInterval`, and the fake natives are then fully drained, then
  the captured native `cancelAnimationFrame`, `clearTimeout` and `clearInterval` were
  each called with that family's **native** id, and **none of the three callbacks ever
  runs**. This is the unit-level half of success criterion 5 (S32 is the CPU half): a
  wrapper whose cancel path only searches the held queue — the natural shape once the
  held queues exist — silently breaks every card that cancels a frame or a timer while
  visible, and passes every other [S] scenario except S14 (which covers the
  `clearInterval` third from the paused state), because every other one pauses first.
  The *scheduling* half of the never-paused path is S23's and is not restated here.

### Shim vm — what is never gated

- **S26 [S]:** Given the shim is paused, when card code calls `console.log("x")`, when a
  `window` `error` event fires, when an `unhandledrejection` event fires, and when an
  `Escape` `keydown` fires, then `window.parent` receives
  `{tarmac:"console", level:"log", args:["x"]}`, a `{tarmac:"console", level:"error", …}`
  for each of the two error paths, and `{tarmac:"escape"}` respectively. **All five
  never-gated relays are covered, `ready` included:** given a shim that is paused
  *before* `DOMContentLoaded` (S25's ordering), when `DOMContentLoaded` then fires,
  `window.parent` still receives `{tarmac:"ready", …}`. The `ready`-while-paused half is
  load-bearing rather than decorative — it is the message the host answers with the
  born-culled state, so a gated `ready` would break S34's P1 path outright. A paused card
  must still be able to report, including that it is paused.
- **S27 [S]:** Given the shim is running, when a `{tarmac:"cull", culled:true}` message
  arrives whose `source` is **not** `window.parent`, then the gate state is unchanged
  (a subsequent card rAF still reaches the native). A nested frame or the card's own
  window cannot pause or unpause the card.
- **S28 [S]:** Given a `{tarmac:"cull"}` message from `window.parent` with `culled`
  **missing**, and again with `culled` set to a non-boolean (e.g. the string `"true"`),
  when each is delivered **from both gate states — running and paused** — then the gate
  state is unchanged in all four cases, observed as in S27 by whether a subsequent card
  `requestAnimationFrame` reaches the captured native, and the console and escape relays
  still work afterwards.

  > **The paused half is the load-bearing one.** From the *running* state the
  > `culled`-missing case is vacuous: `!!undefined` is `false`, which is the state the
  > shim is already in, so a naive `paused = !!d.culled` passes. Delivered while
  > **paused**, that same naive line silently **un-pauses** the card — the real defect,
  > and the only way this scenario can fail. Likewise the non-boolean `"true"` from the
  > running state is what catches a naive coercion **pausing** on garbage.
  >
  > **"Neither call throws" is deliberately not asserted.** The shim's whole message
  > listener body sits inside a `try/catch` (`desktop/src-tauri/src/card_shim.js:277–306`),
  > so nothing a malformed payload does can propagate out — the claim is unfalsifiable
  > from the harness. The falsifiable requirement is the state-unchanged assertion above,
  > plus the relays still working (which is what a swallowed exception mid-listener would
  > *not* break, but a broken listener registration would).

### Manual QA — the app shell and the measured criteria

The React/Tauri shell has no unit tests by design (only pure `kit/` logic and Rust are
tested), and CPU is not measurable from Vitest. These are checklist items in a **new**
`desktop/qa/cull-qa.md`, each recorded VERIFIED / NOT VERIFIED with the observation,
following the `desktop/qa/html-card-qa.md`, `magnify-card-qa.md` and `doc-refresh-qa.md`
convention. **The file must open with the dev-daemon caution**, worded as
`magnify-card-qa.md`'s: kill any installed `tarmacd` first (`pkill tarmacd`), since a
persistent installed daemon hijacks the dev app.

- **S29 [Q] — success criterion 1, culled cards deliver nothing.** Given
  `desktop/qa/cull-probe.html` opened as N=1 and again as N=6 cards, when the board is
  panned until they cull, then each card's own rate history reads **0/s for rAF,
  setInterval and setTimeout** while culled — including a `setTimeout` **issued while
  running whose deadline falls inside the cull**, which the probe must arm explicitly
  (its ordinary chains re-arm inside their callbacks, so no timeout was ever outstanding
  across a pause in any measurement to date). Read the rates off the card's own
  counters, not from CPU.

  > **All three counters, every time — the rAF zero alone proves nothing.** An
  > **un-gated** culled card *already* reads **0 rAF/s** (the engine delivers one frame
  > per 10 s) while its timers keep running at **~1 Hz** — the design's measured
  > `0 / 1 / 1` row. So the **`setInterval` and `setTimeout` zeros are the gate's only
  > rate-level evidence**; a QA item that reads the rAF counter alone would be recorded
  > VERIFIED against a build in which the `cull` message never arrives at all. **S34, S35
  > and S36 inherit this rule** — "paused" means 0/s on all three counters, never on rAF
  > alone.
- **S30 [Q] — success criterion 3, marginal CPU at every phase.** Given six culled
  animating cards, when marginal WebContent CPU (loops running minus the same board with
  loops disabled) is sampled over **two consecutive 10 s windows, the first opening *at*
  the pause**, then both windows read **≤ 1 point**. **The probe must not rely on
  WebKit's 10 s service tick**, which is undocumented, unversioned and re-anchors its
  phase on any delivered frame. A cell that settles for ≥12 s before sampling scores a
  hold-gate as passing — that is exactly the error the out-of-repo harness made before
  it added two-window sampling. Record the ungated baseline in the same session
  (expected ≈ +6 points, which is #72 reproduced) so the delta is measured, not
  compared against a number from another machine.

  > **Which baseline: "loops disabled", not "N=0".** The design states criterion 3 two
  > ways — "over the N=0 baseline" in the criterion's own sentence, and "cards' loops
  > running minus the same board with their loops disabled" in the sentence after it.
  > They differ by ~0.05 points (N=0 floor 0.15%; N=6 culled with `none` 0.2%), i.e. far
  > inside the noise, but a checklist cannot be ambiguous about what it subtracts. **This
  > spec resolves it to loops-disabled**, because it holds the card count, the DOM, the
  > iframes and the board layout fixed and varies only the thing under test — the N=0
  > board differs in all of them. The ≤ 1 point bar is unchanged either way.
- **S31 [Q] — success criterion 4, resume is prompt.** Given a paused card, when the
  board pans back, then **the first full one-second bucket of the card's own rate
  history that begins after the un-cull** already reads within the card's pre-cull band
  on all three counters — the band recorded for that same card, same panel and same
  session immediately before the cull, not a number from another machine. Read a *full*
  bucket, never the partial one straddling the un-cull, whose count is an artefact of
  where in the second the pan landed. (Unmeasured to date — pan-back showed 28–30 Hz
  within ~2 s, but nothing timed the ≤1 s requirement.)
- **S32 [Q] — success criterion 5, nothing inside the margin changes.** Given a card that
  stays visible (or within the one-viewport margin), when the gate ships, then (a) its
  rate band on all three counters **overlaps** the band from the same measurement taken
  with the gate reverted, and (b) the two marginal WebContent CPU figures differ by
  **≤ 1 point** — criterion 3's bar, reused here because CPU sampling noise makes
  literal "unchanged" undecidable and an undecidable checklist item cannot be recorded
  VERIFIED. **This is unmeasured to date** — the design's visible hold/cancel cells are
  unusable because their gates fired while the page was still occluded, so the cards
  never ran visibly. Take both halves in one session, on one machine, so the comparison
  is within-session.
- **S33 [Q] — success criterion 6, the round trip is invisible to the document.** Given a
  magnify card **that carries an explicit `<meta name="tarmac-zoom" content="magnify">`**
  and a known scroll position, when it is culled and un-culled, then its
  **boot id, `scrollY`, root zoom, ICB probe `offsetWidth` and ~300-character wrap
  signature are identical** before and after, and the console strip still shows
  **exactly one** `zoom-mode declared=… effective=…` line.

  > **The meta tag is required for the console-line half to mean anything.**
  > `HtmlCard.tsx:150` pushes that line only when `msg.meta !== null`, and the shim's
  > `readMeta()` returns `null` for a document with no `<meta name="tarmac-zoom">`. Since
  > magnify is the *default* mode, the natural fixture — a plain magnify document — logs
  > **zero** lines before and after, and "exactly one" would be unfalsifiable: a shim
  > posting a second `ready` would still show zero. `desktop/qa/magnify-probe.html`
  > carries the meta and is the fixture of record for S17.

  Cross-check against
  `../../desktop/qa/magnify-card-qa.md` S6 (wrap points, `wrap-probe.html` decides by
  character offset) and S17 (no second zoom message, no second console line). **A cull
  round trip must never reload the document** — that is #72's third acceptance bullet and
  the #99 failure path.
- **S34 [Q] — success criterion 7, P1: born culled.** Given a card opened onto a region
  of the board that is already culled, when it loads, then **at most its first
  one-second history bucket is non-zero**, every bucket after that reads **0/s on all
  three counters** (S29's all-three rule), and it never reaches its visible rate.
  (Worded as a steady state with one grace bucket on purpose: the card's script runs
  from load until the `ready` → cull round trip completes, and the pause cancels what it
  issued — "zero callbacks ever" would fail a correct build. P1 measured why the
  listener alone cannot cover this case: a post issued before the new document commits
  lands on the frame's outgoing `about:blank` window and is dropped.)
- **S35 [Q] — success criterion 7, P2: `?v=` reload while culled.** Given a paused,
  culled card, when its file is rewritten so `lastChangedMs` changes and the iframe
  reloads via `?v=`, then the new document **comes back paused** — 0/s on all three
  counters (S29) — without any pan.
- **S36 [Q] — success criterion 7, P3: the #99-shaped self-reload.** Given a paused,
  culled card, when the document reloads **itself** (`location.reload()` from card JS,
  the shape #99 describes — `src` and `lastChangedMs` both unchanged, so
  `readyHandledRef` stays set), then it **comes back paused** — 0/s on all three
  counters (S29). **This has never been
  run**: the design infers it from the guard analysis, and it is the scenario that
  requires the cull post to sit **before** the `readyHandledRef` guard rather than after
  it. Verify it here for the first time. It must hold under **either** resolution of #99
  — this design does not depend on that decision.
- **S37 [Q] — success criterion 9, the probe is committed and instrumented.** Given
  `desktop/qa/cull-probe.html` is committed to the repo, then it (a) installs a
  `requestAnimationFrame` / `cancelAnimationFrame` **outstanding-count wrapper as the
  first statement of the probe's own script**, keeping a live count of outstanding ids
  and sampling it; (b) carries URL switches for **N**, **loops on/off** and the
  **across-the-pause one-shot**, so one file serves every cell (pattern precedent:
  `2607.0004`'s `desktop/qa/sandbox-probe.html`). **There is deliberately no card-side
  "gate off" switch**: the shim is prepended before the file's first byte, so every
  scheduler reference a card can capture is already the shim's wrapper and nothing the
  card does can bypass the gate. An un-gated baseline comes from a build with the gate
  reverted. For the same reason the probe's own reporter is gated too, so a paused card
  emits no lines at all — every line therefore carries `dt`, the real wall time it
  covers, and the evidence is zeros over a multi-second `dt` on the first line after
  un-cull; and (c) has its in-app numbers recorded in
  `../../docs/designs/2609.0002_offscreen_html_card_throttle.md` and summarised in
  `../../docs/architecture.md`.

  > **"First statement of the probe's script", not "before anything else loads" — the
  > stronger wording is unimplementable.** `card_protocol.rs`'s `compose_body`
  > (`desktop/src-tauri/src/card_protocol.rs:44–52`) writes `<script>` + the whole shim
  > + `</script>` and only *then* the file's first byte, so **no card script can precede
  > the shim**. Once this design ships, a card-side wrapper therefore wraps the *shim's*
  > wrappers rather than the natives — which is fine and is what the card-side count is
  > for (it measures what the card holds), but it is not the instrument the regime
  > question needs.
  >
  > **The host page's outstanding-rAF count is a different instrument and is explicitly
  > NOT part of this scenario.** "Is Tarmac in the isolated regime?" is a question about
  > what the **host** page holds — the harness record says so directly
  > (`RESULTS.md`, "The outstanding-rAF-count method was not run … in the host page")
  > and the design's *Riskiest assumption* agrees. Answering it needs a wrapper in the
  > host document before the app's own code runs, i.e. a `desktop/src/` change, not a QA
  > artefact. **Deferred to [#105](https://github.com/pingeplin/tarmac/issues/105)**; nothing in this spec is gated on it, and
  > no scenario here may claim to turn "consistent with isolated" into "established".

  The out-of-repo harness at `/Users/eplin/workspace/tarmac-worktrees/inapp72-harness/`
  (`RESULTS.md` + `results5_twowin.jsonl`) is the precedent this in-repo probe replaces —
  it covered N=0/1/6, visible and culled,
  `heavy`/`rafonly`/`timersonly`/`none`/`hold`/`cancel`, the live-terminal regime cell
  and the two-window cells. **That path is a transient scratch location outside the repo
  and will not survive** — treat it as provenance for numbers already quoted in the
  design, never as a live dependency.
- **S38 [Q] — pinned semantic 2, the cross-family half.** Given a card with both a
  timeout and rAF callbacks held across a pause, when it resumes, then the probe's
  delivery log shows the **timeout callbacks before the re-issued frame callbacks**.
  This is an engine property the unit suite deliberately does not promise (S21) — record
  it as observed.
- **S39 [Q] — non-active boards, and the documented gap.** Given HTML cards on a board
  that is not active (App keeps every board mounted and hides the inactive ones with
  `display:none`), when that board is hidden, then the cards the existing cull predicate
  reaches are paused — 0/s on all three counters (S29). **Record explicitly that the
  card straddling that board's saved
  viewport centre is NOT paused** — a `display:none` board delivers a `0×0`
  ResizeObserver entry, `visibleWorldRect` degenerates to a zero-area rect at
  `(cx, cy)`, and `rectsIntersect`'s strict `<` (`desktop/src/kit/placement.ts:33`)
  leaves "the frame strictly contains `(cx, cy)`" as the surviving predicate. That is
  **already true today**, is **not** fixed by this change, and closing it would touch a
  predicate shared with terminal and markdown cards — it is
  [#104](https://github.com/pingeplin/tarmac/issues/104), deliberately out of scope
  here. Record the observation under #104 in `cull-qa.md`.

Repo rules that bind this change:

- `make` must pass before the PR: `make docs-check` + `cd core && cargo test` +
  `cd desktop && npm test` + the app cargo test.
- Formatting is convention-by-imitation — match the surrounding code. `card_shim.js` is
  ES5-flavoured, defensive, `var`-based; keep it that way (it runs in an untrusted
  document and must never throw).
- Comments earn their place only by explaining a non-obvious *why*. Two things here are
  worth a line each: **why the rAF wrapper cancels** (the standing charge until WebKit's
  10 s service tick) and **why the `ready` post precedes the `readyHandledRef` guard**
  (a #99-shaped self-reload leaves the ref set). Nothing else is.
- **The wire protocol, daemon and CLI are untouched.** No `Msg` variant, no conformance
  vector, no `docs/protocol.md` change. If you find yourself editing `core/`, stop —
  you have left the spec.
- **`CULL_MARGIN_VIEWPORTS` stays 1** and `applyCull`'s predicate is unchanged.

Design constraints that are easy to violate silently:

- **Fire from the single existing flip site.** `applyCull`'s `if
  (this.cullVisible.get(c.id) === visible) continue;` already guarantees the callback
  fires only on a real flip. Do not add a second call site, a second cache, or a fire
  from `setCullables`.
- **No React state for the cull signal.** A `useState` of culled ids re-renders every
  card on the board on every frame in which any card flips.
- **The register-before-first-`applyCull` invariant** holds because React runs child
  effects before parent effects and `HtmlCard` is rendered **inline** by `Board`. Do not
  wrap it in `lazy`/`Suspense` or hoist it behind another component.
- **The `ready` post reads a ref, and precedes the guard.** The listener writes each
  value into a ref; the `ready` handler posts that ref's value **before** it reads
  `readyHandledRef`. If no flip has been observed yet, the ref's default is `false` and
  the post is a harmless `culled:false`.
- **The rAF wrapper owns its id space — and the two timer wrappers deliberately do
  not.** A paused rAF call never reaches the native, so there is no native id to return:
  return a wrapper id and keep a `shimId → nativeId | null` map. S7's assertion is about
  the **native** id the fake native rAF handed out. `setTimeout` and `setInterval` are
  the opposite case — both always reach the native at call time, so both return the
  native id straight through and their held entries are keyed by it. Do not unify the
  three behind one id allocator: doing so silently changes what `clearTimeout(id)` and
  `clearInterval(id)` mean for ids a card captured, and S14/S18/S40 assert the native
  id.

Write tests to the project's conventions and to these principles (the same ones
`/verify` scores against — see
`/Users/eplin/.claude/plugins/cache/runway/blueprint/4.0.0/references/test-desiderata.md`
and `.../references/anti-patterns.md`):

- **Behavioral over structural** — assert observable output/effects, not internals. The
  deliberate exception is a *class*, not a list: **any [S] scenario that asserts which
  captured native was called with what**. For the shim the native call **is** the
  observable effect — it is what the engine sees, and the whole hold-vs-cancel
  distinction is invisible to a delivery-only assertion. Say so in each such test's
  name. The line that must not be crossed is different and absolute: **no test reaches
  into the shim's own state** — not the held queues, not the paused flag, not the
  `shimId → nativeId` map. That is why S22 asserts exactly-once delivery rather than
  queue contents.
- **Every test can fail** — no copy-pasted expected values, no asserting a constant.
- **Deterministic, isolated, readable** — the fake natives are manually drained, so no
  test may depend on real time passing; no cross-test state; AAA structure.
- **Do not restate coverage.** S4 belongs in the existing `parseCardMessage` block and
  must not re-assert the console/escape/ready cases already there.
- **Do not write a "CPU" unit test.** CPU is a QA measurement (S30) and cannot be
  asserted from Vitest; a unit test that claims to measure it would be theatre.

## Trade-offs and Limitations

- **The `ready` path gains one more post.** It is the most fragile surface in this
  feature — `readyHandledRef` is once-per-load on purpose (`2607.0006` S17) and #99 is
  open against it. Idempotence rather than a guard is the mitigation: the payload is a
  state, so the new post cannot interact with `readyHandledRef` in either direction. It
  is still a change to the path that broke last time.
- **A wrapped scheduler is visible to card code**, as `console.*` already is since
  `2607.0004`. A card that inspects `requestAnimationFrame.toString()` sees the wrapper.
- **A re-issued rAF callback sees a `dt` spanning the whole cull** (pinned semantic 4),
  so `x += v * dt` teleports on un-cull. This is asserted behaviour, not a defect: the
  alternative is to lie to the card about the clock.
- **A card's in-flight frame is deferred rather than completed** at pause — observable
  to a card that measures its own frame timestamps across a cull.
- **The loud cases are untouched.** `while(true)` never yields, so it can neither receive
  a pause nor notice a cull, and a Worker keeps a core hot in a realm the shim cannot
  reach. Both are watchdog/isolation questions, explicitly out of scope for #72.
- **The card straddling a hidden board's saved viewport centre is not culled and so not
  paused** (S39). Already true today; not fixed here.
- **The saving is bounded.** Against a terminal producing output the page is already
  rendering, and six culled cards then cost +3.10 points rather than +5.99 — halved, not
  eliminated. Idle is the case #72 is about.
- **Some criteria are first measured at implementation time.** Criterion 1's
  `setTimeout`-across-the-pause case (S29), criterion 4 (S31), criterion 5 (S32) and the
  P1/P2/P3 reload paths (S34–S36) were never exercised by the design's measurements.

## Out of Scope

Exactly as the design lists:

- `while(true)` and Worker busy loops; any watchdog or process-isolation work.
- Changing `CULL_MARGIN_VIEWPORTS`, or adding a second threshold.
- Terminal and markdown cards; `visibility:hidden` culling is unchanged for them.
  Pausing cards on a **non-active board** is in scope only because the existing cull
  predicate already reaches them — no code here reads window, board or app visibility
  state.
- Pausing on window occlusion, app background, or display sleep.
- Any daemon, protocol or CLI change.
- **#99's `readyHandledRef` decision.** This design is correct under either resolution,
  and S36 must pass under either.

## Open Questions

*All three were closed at the spec gate on 2026-09-05. Kept, with their arguments, so
the reasoning survives — none is an open decision.*

- [x] **DECIDED — the zero-area-viewport one-liner for non-active boards is out of
      scope, and is filed as its own issue.** The design *offers* but does not decide it:
      in `applyCull`, treat a zero-area viewport rect as "no viewport" and cull
      everything, which would also pause the straddling-centre card of S39. It is a
      one-line change to a predicate **shared with terminal and markdown cards**, so it
      does not ride along with a change scoped to HTML cards. **Nothing in this spec
      depends on it**: S39 records the straddling-centre card as NOT paused, and the
      Trade-offs section carries it as a limitation that is already true today. Tracked as
      [#104](https://github.com/pingeplin/tarmac/issues/104) `fix(board): a hidden
      board's card straddling the saved viewport centre is never culled`.
- [x] **DECIDED — S32's tolerance is ≤ 1 point of marginal WebContent CPU plus
      overlapping rate bands.** Criterion 5 says a visible card's rate and marginal CPU
      are "unchanged", but CPU sampling noise makes literal equality undecidable and an
      undecidable checklist item cannot honestly be recorded VERIFIED. The bar is
      borrowed from criterion 3 for want of a measured one — the design's visible
      hold/cancel cells are unusable. The argument for tightening (the gate never fires
      for a card inside the margin, so in principle *nothing* should move) was weighed
      against the absence of any baseline for run-to-run drift, and **≤ 1 point was
      accepted as written**. S32 needs no further change.
- [x] **DECIDED — the host page's outstanding-rAF instrument is filed as its own issue.**
      S37 already scopes `cull-probe.html` to *card-side* counters and defers the
      host-page count; it is tracked as
      [#105](https://github.com/pingeplin/tarmac/issues/105) `chore(qa): count the host
      page's outstanding rAF requests to settle the idle-board regime`. Until it runs, "Tarmac is in the isolated regime" stays *consistent
      with* the data and is never written as established. Nothing in this spec is gated
      on it.
- [ ] **The `[S]` suite's fake-native fidelity** *(not a decision — a standing caveat)*.
      The harness models the natives as
      manually drained queues. It cannot model WebKit's 10 s service tick, so no unit
      test can show the *cost* difference between hold and cancel — only that the cancel
      call happens (S7). S30 is the only place the cost claim is checked, and it is
      manual. Accepted as designed; flagged so nobody mistakes a green `[S]` suite for
      evidence about CPU.
