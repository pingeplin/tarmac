# 2611.0020 A width cap for media in HTML cards

**Date:** 2026-11-21
**Status:** accepted (2026-11-21) by the spec-evaluator and the Fable advisor, under the owner's rule. The advisor found that rule B makes some media larger; D1 now uses rule E, and G5 and S25 guard it.
**Author:** EP Lin
**Issue:** [#447](https://github.com/pingeplin/tarmac/issues/447) `feat(card): keep media from growing past a readable width in HTML cards, and guide authors`
**Branch:** `feat/447-html-media-cap`, from `main` at `9b80fe0`.
**Builds on:** spec 2610.0010 (the font sheet), spec 2611.0019 (the list-marker sheet), the layout guidance of #448. No wire change.

## Gate

The owner chose option (a) of #447 on 2026-11-21: Tarmac caps the width of every medium in an HTML card, also a medium the author sized with `width: 100%`. The owner gave no test card; the cap is checked with generated media.

- **G1.** A wide image, SVG, canvas or video in an HTML card is at most 560 px wide (card px, the same in every zoom mode), and never wider than its container.
- **G2.** A capped medium is scaled, not cropped or distorted.
- **G3.** An author rule that sets `max-width` on a medium wins, except a rule of specificity 0 (`:where(…)`; see Trade-offs). The guide says how to lift the cap.
- **G5.** The rule never makes a medium larger, in either dimension, than it is without the rule.
- **G4.** Markdown cards are out of scope. Part G (layout guidance) landed in #448.

## Context

- The shim (`card_shim.js`) runs before any author script, placed after the doctype by `CardProtocol`. It has `adoptSheet(text)`, which appends a constructed sheet to `document.adoptedStyleSheets`. The font sheet is adopted at boot when fonts are given; the list-marker sheet only under a root zoom ≠ 1.
- `GUIDE.md` says "Tarmac adds up to two stylesheets … last in `document.styleSheets`, and they have no `ownerNode`".
- The card CSP allows `img-src data: blob:` and `media-src data: blob:`, so test media are `data:` URIs.
- An adopted sheet is an author-origin sheet placed after the document's sheets. A `:where()` rule has specificity 0, so any author rule for the same property with a type, class or id selector wins, and so does an inline `style`. An author rule with specificity 0 (`:where(img) {…}`) loses to it by order.

### Facts measured before this spec (2026-11-21, system WebKit, macOS 26.7.2, offscreen `WKWebView`, the shipped shim with the sheet adopted at boot, a 1000 px body)

Rule A = `:where(svg, img, video, canvas) { max-width: min(100%, 560px); height: auto }` (the board's sketch).

| medium | no rule | rule A | pixels under rule A |
| --- | --- | --- | --- |
| `img` 2000×500 | 2000×500 | 560×140 | scaled |
| `img width=1200 height=300` | 1200×300 | 560×140 | scaled |
| `img style="height:200px"` | 800×200 | 560×200 | distorted (stretched) |
| `svg viewBox style="width:100%"` | 1000×250 | 560×140 | scaled; a nested `svg` scales with it |
| `svg width=1000 height=250`, no `viewBox` | 1000×250 | 560×140 | **cropped** (the right 440 px are lost) |
| `canvas` inline `width:1200px;height:200px` | 1200×200 | 560×200 | distorted (a circle draws as an ellipse) |
| `video width=1200 height=300` | 1200×300 | 560×140 | — |
| `canvas width=1200 height=300`, no CSS size (rule B, measured after the first draft) | 1200×300 | 560×140 | — |
| `img` in a 200 px box | 2000×500 (overflows) | 200×50 | scaled |
| `img` in a table cell, a flex row, an inline-block | 2000×500 | 560×140 | no collapse |
| `svg` 1000 wide in an author `overflow:auto` 600 px box | 1000 (scrolls) | 560 (no scroll) | scaled |
| 24 px `img`, 16 px `svg` | same | same | — |

At root zoom 3 every box is the same in card px (×3 in zoomed px).

The expected values of S7, S8, S13 and S23 were measured under rule E: the S7 circle draws 84×84; the S8 image draws 140 px high with 30 px white bands above and below; S13 gives 2000×500, 1000×250, 2000×500; in S23 the `div`'s `scrollWidth` and `clientWidth` are both 600.

Rule B = `:where(svg[viewBox], img, video, canvas) { max-width: min(100%, 560px); height: auto; object-fit: contain }`:

- The SVG with no `viewBox` keeps 1000×250 and is not cropped.
- The inline-height `img` and the inline-size `canvas` keep their author box height (560×200) and draw letterboxed, not distorted: the circle stays round.
- All other rows as rule A.
- `height: auto` beats an author's `height` attribute (an attribute is a presentational hint, below any author rule). `<img width=400 height=400>` of a 4:1 image was 400×400 (stretched) and becomes 400×100. `<svg viewBox="0 0 1000 100" height=200>` becomes 560×56. `<svg viewBox="0 0 100 100" width=300 height=100>` stays 300×100.
- **It makes some media larger, or makes them vanish** (measured after the advisor asked): `<img height=40>` of the PNG (160×40 with no rule) becomes 560×140; `<svg viewBox="0 0 100 20" height=20>` inside an inline-block (100×20) becomes 0×0. Both come from `height: auto` on a medium with a `height` and no `width`. Rejected.

Rule C (rule B without `height: auto`) keeps those two, but gives `<img width=1200 height=300>` a 560×300 box (letterboxed) and `video width=1200 height=300` 560×300.

Rule E = rule C, plus `height: auto` only on media with a `width` attribute:

```css
:where(svg[viewBox], img, video, canvas) { max-width: min(100%, 560px); object-fit: contain; }
:where(img[width], svg[viewBox][width], video[width]) { height: auto; }
```

Measured on 17 fixtures (the rows above, the two of the previous point, `svg viewBox` with no size, with only `width`, in a table cell, in an inline-block, `canvas` sized by its attributes and by inline CSS, `video`): no box is larger than with no rule. `img height=40` stays 160×40, the inline-block sparkline 100×20, `<svg viewBox="0 0 1000 100" height=200>` becomes 560×200 (drawn letterboxed by the SVG's own `preserveAspectRatio`), every other row as rule B.

## Proposed Solution

### Decisions

- **D1. The rule.** The shim adopts one sheet with the two rules of rule E (*Facts*):
  `:where(svg[viewBox], img, video, canvas) { max-width: min(100%, 560px); object-fit: contain; }`
  `:where(img[width], svg[viewBox][width], video[width]) { height: auto; }`
- **D1a. `height: auto` only with a `width` attribute.** A medium the author sized with both attributes keeps its ratio when capped. A medium with a `height` and no `width` keeps its height; G5 rules out `height: auto` on it (*Facts*, rule B).
- **D2. `svg[viewBox]` only.** An SVG with no `viewBox` cannot scale, so a cap crops it. It keeps its size. A nested `svg` matches too but has no CSS box of its own to cap; it scales with its parent (measured).
- **D3. `object-fit: contain`.** Where an author rule or inline style fixes the height, the capped box no longer has the medium's ratio; `contain` draws the medium whole and undistorted in it.
- **D4. When.** At shim boot, before the body is parsed, in every HTML card: magnify, an author's `tarmac-zoom` opt-out, and a reveal card. The cap is about the width of the page, not about zoom.
- **D5. Its own sheet, adopted first.** The media sheet is adopted at boot, before the font sheet, so it is the first of Tarmac's sheets in `document.adoptedStyleSheets`. The font sheet and the list-marker sheet are appended after it, as today. The rule is the same in every card, so there is one media sheet per load and it is never changed (a fonts message or a zoom adds no second one). Every HTML card now has at least one adopted sheet: a raw shim (no fonts) now adopts one sheet, where before it adopted none (this changes the tested behaviour of spec 2610.0010 S12, see *For the Implementing Agent*).
- **D6. Guarded.** If `CSSStyleSheet` or `document.adoptedStyleSheets` is missing, or adopting the media sheet throws, the card has no cap and every other job of the shim still runs: the font sheet is still adopted with its values, `ready` is still posted, the zoom still applies. The failure posts nothing (no console relay) and no exception reaches the page.
- **D7. Guide.** `GUIDE.md` says what the cap is, that it also caps `width: 100%`, how to lift it (`max-width: none` or `100%` on the element, any selector but `:where()`), and "up to three stylesheets". The `.duo svg` example of #448 sits in a column under 560 px at 1080 px `main`, so it needs no change; the guide says a full-width chart in `main` needs the lift.

### Trade-offs

- **In a reveal card (`tarmac-zoom` opt-out) the cap is 560 CSS px of a page laid out at its on-screen size**, so at a board zoom of 50 % it covers 1120 card px (Q2, 2026-11-21). In magnify it is 560 card px at every board zoom. Like every CSS length in reveal mode.
- **A dense diagram capped at 560 px may not be readable.** Q1: a 1600×600 `viewBox` with 11 px labels draws its labels about 4 px high; the lifted copy reads well. The author lifts it.
- **An author's `width: 100%` chart is capped at 560 px.** The owner's choice (option a). The author lifts it with one rule.
- **A medium in an author's `overflow: auto` box is capped, so the box no longer scrolls.**
- **`height: auto` replaces an author's `height` attribute with the medium's own ratio where a `width` attribute is also given** (`<img width=400 height=400>` of a 4:1 image: 400×100, was stretched 400×400). It is what common CSS resets do (`img { max-width: 100%; height: auto }`).
- **`object-fit: contain` also applies to a medium that is not capped** where an author rule fixes both sizes to another ratio: it draws letterboxed, not stretched. An author `object-fit` wins.
- **An author `:where(img) { max-width: … }` loses** (same specificity, earlier). Rare.
- **`iframe`, `object`, `embed` and CSS background images are not capped.**
- **An author script that sets `document.adoptedStyleSheets = [...]`** (not a `concat`) removes the media sheet, and with it the cap. The font sheet has the same limit today.
- How many cards already set their own media `max-width` was not counted; such a rule wins (G3).

## Scenarios

Terms for the WebKit scenarios (suite `WebKit`):

- **Page.** The shipped shim after the doctype, as `CardProtocol` places it, in an offscreen `WKWebView` of 1400×900 (the harness of `CardListMarkerTests`). The page CSS is `html { background: #fff } body { margin: 0; width: 1000px }`, so the body is 1000 card px wide also at root zoom 3 (where the view is only about 466 card px wide). The zoom is posted as in `CardListMarkerTests`. "No zoom" = no zoom is posted.
- **Box.** `getBoundingClientRect()` width × height, in card px (zoomed px ÷ root zoom), ±1 px.
- **Media.** Generated `data:` URIs. "The PNG" = 2000×500, black with its right tenth red. An SVG is black with the right tenth of its drawing (its `viewBox`, or its `width` when it has no `viewBox`) red.
- **Pixel checks** read a snapshot of the view, at no zoom only (at zoom 3 a 560 card px medium is 1680 px wide, more than the view). "Red at its right edge" = the pixels 5 px inside the medium's drawn right edge, at mid-height, are red.
- **Control.** Every page also holds `<svg id="control" viewBox="0 0 1000 250" style="width:100%">` (a measured row). Each scenario also asserts that the control's box is 560×140, so a scenario that would pass without the cap still fails on the unmodified tree. The control is not an `img`, so the author `img` rules of S13–S15 do not lift it.
- **The media sheet** = the entry of `document.adoptedStyleSheets` whose first rule's `style.objectFit` is `contain`. (WebKit's text for the selector is not pinned.)

## Out of scope

Markdown cards. `iframe`/`object`/`embed`, CSS background images. A meta opt-out (option d): an author rule already lifts the cap.

## Alternatives Considered

- **Rule B** (`height: auto` on every medium): makes an `img` with only a `height` larger and collapses a sparkline in an inline-block (*Facts*). Rejected for rule E.
- **Rule C** (no `height: auto`): a capped `img width=1200 height=300` gets a 560×300 box with empty bands. Rejected for rule E.
- **Rule A** (the board's sketch, no `[viewBox]`, no `object-fit`): crops an SVG with no `viewBox`, and stretches an `img` or `canvas` whose height the author fixed (*Facts*). Rejected.
- **A meta opt-out** (option d of #447): not built; an author rule already lifts the cap (*Out of scope*).

## Interface Contract

- `card_shim.js`: a media sheet adopted at boot in every HTML card (D1, D4–D6), first of Tarmac's sheets in `document.adoptedStyleSheets`, with no `ownerNode`. No new message, no attribute, no global, no wire change.
- `GUIDE.md`: D7. `docs/architecture.md`: the shim's jobs list gains the media cap.
