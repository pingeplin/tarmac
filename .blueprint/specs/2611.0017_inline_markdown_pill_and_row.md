## Gate

The owner made these decisions on 2026-11-19. They bind this spec:

- **G1. Scope.** The edge pill's quote and the inbox row's quote only. The inbox preview (the full text of a report) is out of scope: it is still under discussion.
- **G2. Bold is semibold.** A second use of semibold in the chrome (after the inbox count and the delete confirm) is accepted.
- **G3. The report chip's tooltip** is out of scope. The owner wants it removed: follow-up issue [#422](https://github.com/pingeplin/tarmac/issues/422).

The rules the owner saw in the design canvas, which this spec makes exact:

- **R1.** Inline only, on ONE line, on both surfaces: **bold** (semibold), *italic*, `code`, and [link](url) shown as its text, underlined, with no click target.
- **R2.** Block marks are dropped: a `#` heading is plain text with no size change; a list item gets one `•` (an ordered item keeps its `1.`); a code fence is one code run; blocks are joined by one space.
- **R3.** The pill's 24-scalar limit counts the rendered text, not the markup.
- **R4.** The quote marks “ ” stay on both surfaces.
- **R5.** A code run is drawn in a box: fill `bg1`, a 1 px `line` border, radius 3, no accent colour. On a selected row the fill is `bg2`. Markdown never uses the agent, amber, ok or console-error colours.
- **R6.** A read row goes all faint, bold too. The code box stays. Nothing is dimmed by transparency.
- **R7.** A text with no markdown gives the same output as today.

## Context

- **Pill.** `OffscreenHintLayout.pillLabel` (`app/Sources/TarmacKit/OffscreenHints.swift:85`) returns a `String`: `name · “<first 24 scalars of ChromeText.oneLine(text)>”`, cut to 23 scalars + `…` when longer. The string goes through `Hint.label` and `PlacedPill.label` (`OffscreenHintLayout+PillStack.swift:9`) to `OffscreenHintPill` (`app/Sources/TarmacApp/OffscreenHints.swift:100`), which draws it in one `ChromeLabel` at 10.5 and sizes the pill from it. A pill is rebuilt on a font or theme change (`RootView` calls `offHints.forget()`).
- **Row.** `InboxCopy.quote` (`app/Sources/TarmacKit/InboxCopy.swift:41`) returns `“oneLine(text)”`. `InboxRowView` (`app/Sources/TarmacApp/InboxRowView.swift`) draws it in an `OverlayLabel`, mono 11, `muted` (or `faint` when read), truncated at the tail. `configure` is called again on a font or theme change (`InboxPanelView.redraw`).
- **Text.** A report's text is at most 280 scalars (`docs/protocol.md`, "A terminal's report"). The daemon cuts it, so a mark can arrive unclosed.
- **The dev snapshot** has no pill label and no row quote (`DevSnapshot.Hint` is card, signal, edge). The visual scenarios are QA by screenshot.

### Facts checked before this spec (2026-11-19)

- **Fonts.** Every Tarmac font is a fixed-pitch family (`InstalledFamily`). `Theme.mono(size, weight: .semibold)` gives the system mono's real semibold. For a chosen family it gives the family's bold face, or regular when the family has no bold (`Theme.swift:76-80`). For example, Monaco has no bold.
- **Italic.** Menlo and the system mono have an italic face. Monaco and Fira Code have none. In a CTLine, `NSAttributedString.Key.obliqueness` has no effect. A font made with a slant matrix (`c: 0.2`, as `TarmacTerm/TerminalFonts.swift:66-74`) does slant (offline spike).
- **Code box.** An attributed string alone cannot draw a rounded, bordered box. Space made with `.kern` puts CoreText's caret offsets in the wrong places (+3 on each character instead of +6 on two). Drawing each run as its own CTLine, with the box padding added by hand, gives even boxes (offline spike, PNGs checked by eye).
- **Colour.** An `NSColor` foreground is drawn correctly by `CTLineDraw`.
- **Line height.** For mono 11, `NSAttributedString.size().height` is 14.0, and CoreText ascent + descent + leading is 12.96. The new label must keep today's height (D9).

### Facts found during QA (2026-11-19), which changed D9's drawing

- A CTLine per run (the first build) did not keep a text field's metrics: `NSLayoutManager.defaultLineHeight` is 13 for system mono 11 and 17 for Monaco 13, where a text field fits to 14 and 16. In the flipped view, a slant in the font matrix leaned backwards (Monaco's italic looked upright).
- `NSAttributedString.draw(at:)` in a flipped view, 2 pt in, is pixel-identical to a one-line `NSTextField` of the same string, for system mono 11, Monaco 13 and Menlo 11 (offline compare). It also draws `.obliqueness`. So D9 draws each run that way.

## Proposed Solution

### Overview

A pure module in TarmacKit, `InlineMarkdown`, turns a report's text into an `InlineText`: a list of runs, each with one mark. `pillLabel` and `InboxCopy.quote` return `InlineText` instead of `String`. One new AppKit view, `InlineTextLabel`, draws an `InlineText` on one line. The pill and the row both use it.

### Decisions

- **D1. One parser in TarmacKit, hand-written.** Not `AttributedString(markdown:)`: its block handling and its version-to-version behaviour are not ours to test, and the rules below are small. The rules follow the prototype, with the changes D3–D6 name.
- **D2. Blocks** (one line at a time; `\r\n`, `\r` and `\n` all end a line):
  - **Fence:** a line that starts with ```` ``` ```` (an info string after it is ignored) opens a fence, unless it has another backtick after its opening run of backticks: CommonMark allows no backtick in an info string, so such a line (```` ```make qa``` failed ````) is not a fence but an "other line", inline-parsed (issue #426). A line that closes a fence needs only to start with ```` ``` ````. The fence ends at the next line that starts with ```` ``` ````, or at the end of the text (an unclosed fence). Its body is the lines between, joined by one space and trimmed at both ends, as one code run. The body is not inline-parsed. An empty or whitespace-only body gives no run.
  - **Heading:** at the start of the line, `#` to `######`, then whitespace, then the text. The text is inline-parsed. `#412` is not a heading. A heading is one line.
  - **List item:** optional leading whitespace, then `-`, `*` or `+` (unordered) or ASCII digits and `.` or `)` (ordered), then whitespace, then the text. The text is inline-parsed. An unordered item gets the mark `•`. An ordered item keeps the mark as typed (`1.`, `2)`). The mark is a `bullet` run followed by a plain run of one space. A list item is one line: the next line does not continue it.
  - **Blank line** (empty, or whitespace only): ends a paragraph.
  - **Other lines:** join the open paragraph, with one space between lines. The paragraph is inline-parsed as one text. A fence, heading or list-item line also ends the open paragraph.
  - Blocks are joined by a plain run of one space. Blockquotes (`>`), rules (`---`) and tables are not handled; they stay as typed.
  - The block rules come first. So a line `* a *b*` is a list item with the text `a *b*`, and a line `*a* b` (no whitespace after the first `*`) is a paragraph.
- **D3. Inline marks**, found left to right. At each position, the first of these that matches wins: code, link, bold, italic.
  - **Code:** a run of one or more backticks, then the content, then the next run of backticks of the same length (amended for issue #426; as CommonMark). A run of another length is part of the content, so ``` ``a`b`` ``` is the code `` a`b ``. The content is literal and is trimmed at both ends. A content that is empty or whitespace only is not a code span: its backticks stay as typed (this differs from a fence, D2, which drops a whitespace-only body). A run with no later run of its length is literal as a whole: no span starts inside it. When the content is empty or whitespace only, only the opening run is literal: the run that would have closed it can open a span of its own, so `` ` ` x` `` is `` "` " c"x" `` (CommonMark gives a span of one space here; this rule keeps the text `x` in a box and is what the single-backtick rule always did).
  - **Link:** `[`, the text, the next `]`, which must be directly followed by `(`, then the url, which ends at the next `)`. The text is trimmed at both ends and must not be empty then. The run is the text, with the mark `link`; the url is dropped. `![alt](src)` is not special: `!` stays and the rest is a link. `[a](b (c))` gives `l"a" ")"`.
  - **Bold:** `**x**` or `__x__`.
  - **Italic:** `*x*` or `_x_`.
  - **The closing mark** is the next same mark after the opening that can close (for `_`, see the word test below). When the content between them is not valid, the opening mark is literal and the scan goes on at the next character. So `*a *b*` gives `"*a " i"b"`, and `***a***` gives `b"*a" "*"`.
  - For bold and italic, `x` is not empty and does not start or end with whitespace.
  - **The word test for `_` and `__`.** The mark's outside neighbour is the character before an opening mark, or the character after a closing mark. The mark is not a mark when that neighbour is a letter, a digit or `_`, or when it is a `.` that has a letter or digit on its other side. A `_` that fails the test cannot open or close a run. So `snake_case_name`, `__init__.py` and `self.__dict__` stay as typed; `(_a_)` is italic `a`; `_a_.` is `i"a" "."`; `_snake_case is odd_` is italic `snake_case is odd`.
  - A `*` inside a word is a mark (as CommonMark): `a*b*c` gives italic `b`.
  - **No nesting.** The content of a bold, italic or link run is literal. So ``**see `x`**`` is bold ``see `x` ``, with its backticks.
  - Backslash escapes are not handled: `\*` stays as typed.
  - An unclosed mark is literal (`**half` stays `**half`).
  - When no rule matches at a position, that character is plain text and the scan goes on at the next character.
- **D4. Whitespace.** In this order:
  1. A plain run next to a plain run joins it. (So `a  \n- b` gives `"a " •"•" " b"`, with one space before the `•`.)
  2. Every run of whitespace, as `ChromeText.oneLine` finds it (`Character.isWhitespace`), is one space, in every run, code too.
  3. The whole line is trimmed at both ends.
  4. An empty run is dropped, and the result is in normal form (D7).
  No marked run starts or ends with whitespace (D2 trims a fence body; D3 trims code and link text; bold and italic content cannot; a bullet has none), so a space at a run boundary is always in a plain run, and `plain == ChromeText.oneLine(plain)`.
- **D5. No result.** When the rendered text is empty (for example, only an empty fence, a whitespace-only fence, or a heading with no text), the result is `InlineText.literal(ChromeText.oneLine(text))`. For a blank text (empty, or whitespace only) that is no runs, and `plain` is `""`.
- **D6. R7 as an invariant.** "No markdown" means that no fence, heading or list-item rule (D2) and no inline mark (D3) matches. (The paragraph and blank-line rules always match; they do not count.) Then the result is `InlineText.literal(ChromeText.oneLine(text))`. A line `- x` does match, so it becomes `• x`.
- **D7. The types** (TarmacKit, `Equatable`, `Sendable`):
  - `InlineMark`: `plain`, `bold`, `italic`, `code`, `link`, `bullet`.
  - `InlineRun`: `text`, `mark`.
  - `InlineText`: `runs`, and `plain: String` (the runs' texts joined). `InlineText.literal(_:)` makes one plain run, or no runs for `""`.
  - **Normal form.** Every `InlineText` has no empty run and no two plain runs side by side. `literal`, `prefix`, `quoted` and `+` keep this form: they join plain runs that come side by side. So `quoted` of `b"May" " I?"` is `"“" b"May" " I?”"`.
  - `InlineText + InlineText`: the runs of the left, then the runs of the right, in normal form. The pill label (D8) is made with it.
  - `InlineMarkdown.line(_ text: String) -> InlineText`: D2–D6.
  - `InlineText.prefix(scalars: Int) -> InlineText`, for a limit of 1 or more: when the rendered text has more scalars than the limit, it keeps the first `limit − 1` scalars, cut across runs, each kept run keeping its mark, and adds a plain `…`. Otherwise it returns the text unchanged. This is today's `start(of:)`, moved to runs, for the pill. `prefix(scalars: 1)` of a longer text is a plain `…`.
  - `InlineText.prefix(characters: Int) -> InlineText`: the same rule, counted in `Character`s, so a cut never splits a grapheme (an emoji with a skin tone, a flag). It is for the row (D10).
  - `InlineText.quoted`: a plain `“`, the runs, a plain `”`.
- **D8. What changes in the kit's API.**
  - `TermReport.quote: InlineText?` is the text parsed once, when the report comes (a pill is rebuilt on every viewport change, and one parse of 280 scalars took about 340 µs in a debug build). `pillLabel(..., quote: InlineText?)` takes it. Only the quote is parsed. The name, `hhmm`, `report` and `exited` are literal runs, so a terminal called `*scratch*` is not styled. A report with a quote gives `InlineText.literal("\(name) · ") + quote.prefix(scalars: quoteScalars).quoted`. Every other label is `InlineText.literal(<today's string>)`.
  - `Hint.label` and `PlacedPill.label` become `InlineText`. The pill layout uses only the measured size (`Options.pillSize`), so the placement does not change.
  - `InboxCopy.quote(_:) -> InlineText?`: `InlineMarkdown.line(text).quoted`. `InboxRow.quote` becomes `InlineText?`.
  - `InboxCopy.toolTip` keeps the raw text (the tooltip cannot style).
- **D9. `InlineTextLabel`** (TarmacApp, an `NSView`):
  - It draws each run as its own `NSAttributedString` (`draw(at:)`, the drawing a text field's cell uses), left to right, 2 pt inside its frame as a cell draws. The font is the surface's base font (Interface at 10.5 for the pill, mono 11 for the row), with these changes:
    - `bold`: `Theme.mono(size, weight: .semibold)`. This is the real semibold for the system mono, and the family's bold (or regular) for a chosen family, as the inbox count does today.
    - `italic`: the family's italic face when it has one, else the base font with `.obliqueness` 0.2 (as the board switcher slants its hint).
    - `link`: underlined, the same colour.
    - `code` and `bullet`: the base font.
  - Every run has the surface's text colour. Markdown never changes the colour.
  - A `code` run has 3 pt of padding on each side, inside its box, and the box is drawn under the run's text: fill and border as R5, radius 3, 1 pt border, with the height of the line.
  - Its width is the sum of the run widths plus the box paddings and the two cell insets. Its height is `NSAttributedString.size().height` of the base font, which is what a one-line text field fits to, so the row's `height()` and the pill's size do not change for a text with no code.
  - It takes the base font, the text colour, the box fill and the border colour from its caller, so a rebuild on a font or theme change re-applies them (the pill is rebuilt; the row's `configure` runs again).
- **D10. Row truncation.** The row is cut to its width by a kit rule, `InlineText.prefix(fitting: room, measure:)`: the longest `prefix(characters: n)` (n ≥ 1, so at least a `…`) that `measure` finds no wider than `room`. The shell passes its font measure (`InlineTextLabel`), so the cut decision is tested in the kit with a fake measure. A box cut by the width ends before `…`. A cut row ends in `…` and has no `”`, as today's tail truncation does (decided by Fable).
- **D11. Colours on the row.** Text: `muted`, or `faint` when read (as today, for every mark). Box fill: `bg1`, or `bg2` when the row is selected. Border: `line`. On the pill: the pill's own label colour (`OverlayPalette.hintLabel`), box fill `bg1`, border `line`.
- **D12. Fonts and the theme follow.** No cached `NSFont` or `NSColor` in `InlineTextLabel` outlives a `configure` or a pill rebuild.

### What stays in the shell, and why

The font resolution (D9), the colours (D11), the box geometry, and the measure D10 is given all need AppKit or font metrics. They are presentation (`docs/coding-style.md` §1.3, exception 1). Every rule about the text (what is a mark, what is cut, where `…` goes) is in the kit.

## Alternatives Considered

- **`AttributedString(markdown:, options: .inlineOnlyPreservingWhitespace)`.** It gives no block rules (R2) and its behaviour is Foundation's, not tested by us. Rejected (D1).
- **One `NSTextField` with attributes.** It cannot draw a bordered, rounded box (`.backgroundColor` is a square fill). Rejected.
- **One `CTLine` with `.kern` for the box padding, and `CTLineCreateTruncatedLine`.** The caret offsets came out wrong with kern, and the truncated line hides which characters it kept. Rejected (spike).
- **A `CTLine` per run.** Built first; its line height and baseline differ from a text field's, and a font-matrix slant leans backwards in a flipped view. Replaced (QA).

## Migration & Rollback

No wire, state or preference change. Revert the PR to roll back.

## Security Considerations

A link has no click target, so a report cannot make a pill or a row open a URL. The parser is linear over at most 280 scalars.

## Acceptance Scenarios

Where the tests live:

- **TarmacKit XCTest:** `app/Tests/TarmacKitTests/InlineMarkdownTests.swift` (new); `OffscreenHintsTests.swift` and `InboxCopyTests.swift` (extended; changed assertions are listed under *For the Implementing Agent*).
- **TarmacApp** is checked by QA on the dev channel (Q1–Q8).

Below, a result is written as runs: `b"x"` bold, `i"x"` italic, `c"x"` code, `l"x"` link, `•"x"` bullet, and a bare `"x"` plain. An input in backticks is the text as typed. Only `\n`, `\r` and `\t` are escapes (newline, carriage return, tab); every other `\` is one backslash. An input that holds a backtick is set in a longer backtick fence. "No runs" means an `InlineText` with an empty `runs` and `plain == ""`.

### Happy Path

- **S1 (inline marks):** ``Need OK to run `cargo test -p tarmacd` — it **touches** the dev socket.`` → `"Need OK to run " c"cargo test -p tarmacd" " — it " b"touches" " the dev socket."`.
- **S2 (each mark):** `*a*` → `i"a"`; `_a_` → `i"a"`; `**a**` → `b"a"`; `__a__` → `b"a"`; `[run 88](https://x.invalid/88)` → `l"run 88"`.
- **S3 (heading):** `## Blocked` → `"Blocked"`.
- **S4 (lists):** `- a\n- b` → `•"•" " a " •"•" " b"`, plain text `• a • b`. `1. a\n2) b` → plain text `1. a 2) b`, with `1.` and `2)` as bullet runs.
- **S5 (fence):** ```` ## Blocked\n```\nrm -rf target/\n``` ```` → `"Blocked " c"rm -rf target/"`.
- **S6 (paragraphs and blocks join by one space):** ``Done: **x**.\n- a\n\nLeft: run `make qa`.`` → `"Done: " b"x" ". " •"•" " a Left: run " c"make qa" "."`, plain text `Done: x. • a Left: run make qa.`.
- **S7 (the pill counts rendered scalars):** quote `Need OK to run [cargo test](u) now please` (name `claude`) → pill label `"claude · “Need OK to run " l"cargo te" "…”"`. The quoted part between `“` and `”` has 24 scalars.
- **S8 (the pill's name is literal):** `pillLabel(signal: .blocked, name: "*scratch*", ..., quote: "ok")` → `InlineText.literal("*scratch* · “ok”")`: one plain run.
- **S9 (the row quote):** `InboxCopy.quote` of a report with text `**May** I?` → `"“" b"May" " I?”"`.

### Edge Cases

- **S10 (R7, no markdown, unchanged):** for each of these texts the result is one plain run equal to `ChromeText.oneLine(text)`, and the pill label and row quote `.plain` equal today's strings: `May I?`, `  May\n\tI  run\r\n rm?  `, `snake_case_name`, `2 * 3 * 4`, `#412 done`, `price: $5 (approx)`, `a [b] c`, `C:\path\*`, `a\n\n\nb`, `__init__.py`, `self.__dict__`.
- **S11 (CRLF):** `- a\r\n- b` → plain text `• a • b` (CRLF is one `Character`).
- **S12 (unclosed marks):** `**half` → `"**half"`; `` run `cargo `` → `` "run `cargo" ``; ```` ```\nrm -rf `` (unclosed fence) → `c"rm -rf"`.
- **S13 (fence with an info string, and an empty fence):** ```` ```swift\nlet x = 1\n``` ```` → `c"let x = 1"`. ```` a\n```\n```\nb ```` → `"a b"` (no empty code run). ```` a\n```\n  \n```\nb ```` → `"a b"` (a whitespace-only body gives no run). ```` ```\n``` ```` alone → D5: `InlineText.literal("``` ```")`. A whitespace-only fence ```` ```\n  \n``` ```` alone → D5: the same.
- **S14 (no nesting):** ``**see `x`**`` → `` b"see `x`" ``.
- **S15 (`*` inside a word):** `a*b*c` → `"a" i"b" "c"`.
- **S16 (whitespace in code):** `` `a   b` `` → `c"a b"`; a fence body `x\n\n  y` → `c"x y"`. ```` a\n```\n\n  x\n```\nb ```` → `"a " c"x" " b"` (the fence body is trimmed, so there is one space before the box).
- **S17 (empty link text):** `[](u)` → `"[](u)"`.
- **S18 (backslash is not an escape):** `\*a\*` → `"\" i"a\"` (D3: the italic content is `a\`). Both backslashes stay in the plain text.
- **S19 (the pill cut lands in a code run):** quote `` `abcdefghijklmnopqrstuvwxyz` `` → the pill's quote runs are `"“" c"abcdefghijklmnopqrstuvw" "…”"`: 23 code scalars and a plain `…`, 24 in all.
- **S20 (the pill cut lands on a bullet):** `InlineMarkdown.line(t).prefix(scalars: 24)` for:
  - `abcdefghijklmnopqrstu\n- xyz` (`•` is scalar 23, kept) → `"abcdefghijklmnopqrstu " •"•" "…"`.
  - `abcdefghijklmnopqrstuv\n- xyz` (`•` is scalar 24, dropped) → `"abcdefghijklmnopqrstuv …"`.
  - `abcdefghijklmnopqrstu\n12. x` (the cut is inside `12.`) → `"abcdefghijklmnopqrstu " •"1" "…"`.
- **S21 (exactly 24 rendered scalars):** quote `**abcdefghijklmnopqrstuvwx**` (28 scalars as typed, 24 rendered), name `claude` → pill label `"claude · “" b"abcdefghijklmnopqrstuvwx" "”"`. It is not cut.
- **S22 (prefix keeps marks):** `prefix(scalars:)` on `"ab" b"cd" "ef"` with limit 4 → `"ab" b"c" "…"`; with limit 6 → unchanged; with limit 1 → `"…"`.
- **S23 (other pill kinds are unchanged):** each label equals `InlineText.literal` of today's string: bell `notes.md · 14:32`, live `agent` (its quote ignored), exit `claude · exited`, done with no text `claude · report`, bell with a quote `claude · 14:32`.
- **S25 (`*` as a list mark and as italic):** `* a *b*` → `•"•" " a " i"b"`. `*a* b` → `i"a" " b"`.
- **S26 (other list marks):** `+ a` → `•"•" " a"`. `  - a` (indented) → `•"•" " a"`. `- a\nb` → `•"•" " a b"` (the second line is a new paragraph). `a  \n- b` → `"a " •"•" " b"` (D4: one space before the `•`).
- **S27 (a mark in a heading):** `## **a** b` → `b"a" " b"`.
- **S28 (image syntax and marks in link text):** `![alt](src)` → `"!" l"alt"`. `[**a**](u)` → `l"**a**"`.
- **S29 (`_` next to punctuation):** `(_a_)` → `"(" i"a" ")"`.
- **S31 (closing marks):** `*a *b*` → `"*a " i"b"`. `***a***` → `b"*a" "*"`. `[a](b (c))` → `l"a" ")"`. `[a] (b)` → `"[a] (b)"` (no `(` directly after `]`).
- **S32 (`_` word test):** `_a_.` → `i"a" "."`. `_snake_case is odd_` → `i"snake_case is odd"`. `__pycache__/` → `b"pycache" "/"` (accepted, see *Trade-offs*).
- **S33 (whitespace inside a code span or link):** ``a ` b` c`` → `"a " c"b" " c"`, plain `a b c`. ``a ` ` b`` → ``"a ` ` b"`` (no code span). `[ x ](u)` → `l"x"`.
- **S34 (the row cut keeps graphemes whole):** `InlineText.literal("a👍🏽bc").prefix(characters: 3)` → `"a👍🏽…"`; `prefix(characters: 4)` → unchanged.
- **S35 (the row cut fits a width; D10):** with a fake measure of one unit a character and two for a code box, `"ab" c"cdef"` fits 8 unchanged; at 6 it is `"ab" c"c" "…"`; at 5 `"ab…"`; at 0 `"…"`; `a👍🏽bc` at 3 is `"a👍🏽…"`; `👍🏽👍🏽👍🏽👍🏽` at 2 is `"👍🏽…"` (the search counts Characters, not scalars).

- **S37 (what S36 does not change):** a fence of four backticks ````` ````\nx\n```` ````` → `c"x"`. Inside an open fence, a line that starts with ```` ``` ```` closes it, whatever follows: ```` ```\nx\n```y``` z\nw ```` → `c"x" " w"`.

### Error Scenarios

- **S24 (every cut of a real text):** the daemon cuts a report at 280 scalars, so a mark can arrive half-typed. Let `seed` be ````Need **OK** to _run_ `make qa` — see [log](u).\n* a *b*\n12) c\n## H\n```sh\nx  y\n```\n````. Let `t` be `seed` repeated, cut to its first 280 scalars. For every `p` that is the first `k` scalars of `t`, `k` from 0 to 280, `InlineMarkdown.line(p)`:
  - has no empty run and no two plain runs side by side;
  - has no runs if and only if `ChromeText.oneLine(p)` is empty;
  - has a `plain` with no more scalars than `ChromeText.oneLine(p)`;
  - has a `plain` with no whitespace at either end;
  - has `plain == ChromeText.oneLine(plain)`.

## Trade-offs and Limitations

- **Bold may not show** in a chosen family with no bold face (Monaco). The same is true of the inbox count today.
- **A hovered row's code box keeps `bg1`.** R5 names the selected row only; a hovered row gets the `bg3` background, and its box is not changed.
- **`__pycache__/` is bold `pycache`.** The `_` word test only treats letters, digits, `_` and a `.` before a letter or digit as inside a word; a `/` is not.
- **No nesting, no escapes, no blockquotes.** A report that uses them shows those marks as typed.
- **Each run is drawn on its own.** Kerning across a run boundary is lost. All Tarmac fonts are fixed-pitch, so this has no visible effect.
