# 2610.0012 Read a doc's path off the runtime, with a time limit

**Date:** 2026-10-29
**Status:** implemented
**Author:** EP Lin
**Issue:** [#267](https://github.com/pingeplin/tarmac/issues/267) `fix(daemon): a doc on a hung volume freezes the daemon`
**Design doc:** [2610.0012](../../docs/designs/2610.0012_doc_path_reads_off_the_runtime.md) (approved 2026-10-29, merged in #273)
**Builds on:** #265 (`reader::FileReader`, the look's time limit), #268, #253

## Gate

Written from `main` at `62ceb93`. The approach, the 1 s limit and the seven
decisions are settled in the design doc (*Decisions*). This spec turns them into
a contract, split into four PRs (*Delivery*).

**Decided by the user on 2026-10-29**, after the spec review (the design doc's
*Decisions* 8–10 record them):

- **D8. A failed watch is retried by the next open.** Every open sends
  `Reconcile(dir)`; only an open that counts the first doc of `dir` waits for
  the answer. So a dir whose watch failed at startup is watched by the next
  open in it, as today.
- **D9. A new dir whose `.git` walk is out fails the open.** The stuck walk
  makes the dir out, the watch is skipped, and the open fails with
  `cannot watch …: did not answer …`. "No repo" applies only in a dir that is
  already watched.
- **D10. Three readings:** a dir is out only when an out key is the dir itself
  or a direct child of it; an `unread` doc whose first reading finds no file
  is gone, as today; a `doc_refresh` of an `unread` doc works as today and
  ends `unread`.

## Context

Every file-system call on a doc's path, except the look's stamps, runs today with
no time limit, and most run on a tokio core worker:

| Call | Where | Thread today |
|---|---|---|
| `canonicalize` + `metadata` of an opened path | `tarmac-cli/src/main.rs:191-197` | the cli process, before it connects |
| `canonicalize` + `metadata` | `docs::handle_open`, `tarmacd/src/docs.rs:53-57` | tokio worker |
| `derive_repo` (`.git` walk) for a new doc | `docs::upsert_doc`, `docs.rs:100`, under the `boards` lock | tokio worker |
| `reader::stamp` of the opened doc | `Daemon::open_doc`, `state.rs:207` | tokio worker |
| notify `watch` / `unwatch` (canonicalizes the dir) | `acquire_watch` / `release_watch`, `state.rs:158-180`, under the watcher `std::sync::Mutex` | tokio worker |
| `derive_repo` + `stamp` per restored doc, then `acquire_watch` per dir | `persist::hydrate` (`persist.rs:106,116`) and `Daemon::with_reader` (`state.rs:118-122`) | main thread, before `accept` |

On a volume that stops answering, each of these blocks for 4–6 minutes in an
uninterruptible state. The ones on a worker freeze **every** connection, because
the worker that holds the I/O driver is the one in `stat` (6 of 6 trials,
measured on a WebDAV mount: [#267 comment](https://github.com/pingeplin/tarmac/issues/267#issuecomment-6490720115)).
The look is bounded since #265 by `reader::FileReader` (`reader.rs`).

## Motivation

A doc on an SMB/NFS/WebDAV share or an external disk that drops makes the whole
cockpit stop answering, and closing the doc's card is one of the calls that
hangs, so the user cannot even give up. The cli hangs too, prints nothing, and
Ctrl-C does not end it.

## Proposed Solution

### Overview

`reader::FileReader` becomes `reader::PathGate`: every call on a doc's path runs
on a blocking thread, the caller waits at most `READ_LIMIT` (1 s), and a path
whose call is still out is answered `Out` at once and never read again until
that call returns. notify moves to one watcher thread that owns the existing
`Box<dyn WakeSource>`; the callers keep only `doc_counts`. Startup reads run
concurrently on the gate and wait at most 2 × limit. The cli stops touching the
path. The design doc has the full argument; this spec does not repeat it.

### Key Components

- **`reader::PathFs`** (new trait, `tarmacd/src/reader.rs`) — the three
  file-system calls: `resolve` (canonicalize + stat, refusing a non-regular
  file), `stamp`, `repo_of`. `RealFs` implements it with `std::fs` and
  `docs::derive_repo`. The test seam that `FileReader::new(read, limit)` is
  today: a double holds a call until released.
- **`reader::PathGate`** (replaces `FileReader`) — `run(key, op)`, `stamps`
  (unchanged behaviour), `is_out_dir`. One shared `out` set. When an out call
  returns, it removes the key and calls its `returned` hook. Keys: an open's
  resolve by the raw path, an open's walk and a look's stamp by the canonical
  doc path, a startup walk by the directory. `is_out_dir(dir)` is true while an
  out key is `dir` itself or has `dir` as its parent (not a deeper descendant).
- **The watcher thread** (`tarmacd/src/watch.rs` or `state.rs`) — one
  `std::thread` that owns `Box<dyn WakeSource>`, a `watched` set and a `retry`
  set; takes `Reconcile(dir)` (with an optional reply channel) and `Retry`.
- **`Daemon`** (`state.rs`) — `watcher: std::sync::Mutex<WatcherState>` keeps
  only `doc_counts`; `reader: FileReader` becomes `gate: PathGate`;
  `acquire_watch` / `release_watch` count and send `Reconcile`. `Daemon::new`
  becomes `async`.
- **`docs::handle_open` / `upsert_doc`** (`docs.rs`) — the resolve and the
  `.git` walk go through the gate; `upsert_doc` takes the repo as an argument
  instead of walking under the `boards` lock.
- **`persist::hydrate`** (`persist.rs`) — no file-system call; the stamps and
  walks are done by the daemon on the gate after `load`.
- **`DocInfo.unread`** (`boards.rs`) — in memory only, like `seen` and `untold`.
- **`tarmac-cli` `open`** (`tarmac-cli/src/main.rs`) — `std::path::absolute`,
  no `canonicalize`, no `metadata`.

### Data Flow

**Open** (`cli_session` or `dispatch_app_msg` → `handle_open`):

1. Reject a non-absolute path (as today).
2. `gate.run(raw_path, |fs| fs.resolve(raw_path))`. `Out` → `Err`. An I/O error
   or a non-regular file → the same `Err` texts as today.
3. If the canonical path is not registered on the target board,
   `gate.run(canon, |fs| fs.repo_of(canon))`; `Out` → no repo.
4. `open_doc`: `acquire_watch(dir)` counts the doc and sends `Reconcile(dir)`
   (D8). For a first doc it waits for the reply with the limit; no reply, `Out`
   or a watch error → release the count and `Err("cannot watch …")`, as today.
   Any other open does not wait: a dir that is counted but not watched is
   watched by the thread, whose `wake` gives the look.
5. Upsert with the stamp from step 2 and the repo from step 3; `report_changes`
   after the upsert for an open that had its dir watched in step 4, as today.

**Close / board delete:** the count drops; for the last doc of a dir,
`Reconcile(dir)` is sent and the call returns at once. `close_doc` no longer
calls `report_changes`; the watcher thread's `wake` gives that look.

**Watcher thread, on `Reconcile(dir)`:** want = `doc_counts[dir] > 0`, have =
`dir ∈ watched`. Equal → reply `Ok`, nothing else. `gate.is_out_dir(dir)` →
`dir` into `retry`, reply `Out`. Otherwise call `watch` / `unwatch`, update
`watched` (a `watch` on success only; an `unwatch` always, because notify's
`remove_path` takes the path out of the stream before it can fail, notify 8.2.0
`fsevent.rs:371-383`), `wake.notify_one()` either way, reply with the result.
On `Retry`: reconcile every dir in `retry` again (each leaves `retry` first).

**Gate, when an out call returns:** remove the key from `out`, then call
`returned`, which the daemon wires to `wake.notify_one()` and sending `Retry`.

**Startup:** `persist::load` builds the boards with no file-system call. Then,
all at once on the gate: one `stamps` batch for every restored doc, and one
`repo_of` per distinct parent directory, keyed by that directory and called
with one of its docs (`derive_repo` starts at the doc's parent). A doc whose
stamp is out is `unread`; a dir whose walk is out leaves its docs with no repo.
Every dir with a doc gets a `Reconcile` that nobody waits for. Then `accept`
starts.

**An unread doc's first reading:** the first look that reads it takes the
reading as `seen` with no `FileEvent`, and `last_changed_ms` stays as
restored, as a restart does today. A reading of "no file" counts too: the doc
is then like a doc whose file is gone. A `doc_refresh` behaves as today (it
records and pushes) and also ends `unread`. After that the doc is like any
other.

### Interface Contract

Internal to `tarmacd`, except the cli's wire behaviour. No protocol change.

```rust
// reader.rs
pub const READ_LIMIT: Duration = Duration::from_secs(1);   // unchanged
pub struct Out;                                             // "did not answer in time"

pub trait PathFs: Send + Sync {
    /// canonicalize + stat. Err for a missing path, an I/O error, or a path
    /// that is not a regular file; the message is the one handle_open sends.
    fn resolve(&self, raw: &Path) -> Result<(PathBuf, FileStamp), String>;
    fn stamp(&self, path: &Path) -> Option<FileStamp>;
    fn repo_of(&self, doc: &Path) -> Option<RepoInfo>;
}

impl PathGate {
    pub fn new(fs: Arc<dyn PathFs>, limit: Duration, returned: Arc<dyn Fn() + Send + Sync>) -> Self;
    pub async fn run<T: Send + 'static>(&self, key: &Path,
        op: impl FnOnce(&dyn PathFs) -> T + Send + 'static) -> Result<T, Out>;
    pub async fn stamps(&self, paths: impl IntoIterator<Item = PathBuf>)
        -> HashMap<PathBuf, Option<FileStamp>>;             // as FileReader::stamps
    pub fn is_out_dir(&self, dir: &Path) -> bool;
}
```

Error replies (`Msg::Err { msg }` to the cli; pushed `Msg::Err` to the app, as
today):

| Case | `msg` |
|---|---|
| resolve did not answer, or its key is out | `cannot open {raw_path}: did not answer in {limit:?}` |
| watch did not answer, or its dir is out | `cannot watch {dir}: did not answer in {limit:?}` |
| missing file, I/O error, not a regular file | unchanged (`cannot open …: {e}`, `cannot stat …: {e}`, `not a regular file: …`) |

The cli prints any of them as `tarmac: {msg}` on stderr and exits 1 (unchanged).
On success it prints `opened {path}` where `{path}` is the path it sent (made
absolute, not canonical).

Shape names (`Reconcile`, `Retry`, `RealFs`, where the thread lives) may differ;
the behaviour in the scenarios may not.

## Delivery

Four PRs, in this order. Each is mergeable alone and leaves the daemon no worse:

| PR | Scope | Scenarios |
|---|---|---|
| **A. Gate and open** | `PathFs`, `PathGate`, `handle_open` resolve, the `.git` walk of a new doc, the open's stamp. `returned` is wired to `wake.notify_one()` only | S1–S8, S8b |
| **B. Watcher thread** | `Reconcile`, `Retry` (added to `returned`), `acquire_watch` / `release_watch`, close, board delete, the looks, and the startup watches as `Reconcile`s that nobody waits for (`Daemon::new` is still sync, so it cannot wait for a reply) | S5b, S9–S16, S21 |
| **C. Startup** | `async Daemon::new`, the concurrent stamps and walks, `unread` | S17–S20 |
| **D. cli** | `std::path::absolute`, no file-system call | S22–S25 |

**D must not merge before A.** Today the cli's own `stat` hangs first, so a hung
path never reaches the daemon. With D alone, it would, and `handle_open` would
freeze every connection.

## Alternatives Considered

The design doc's *Alternatives* (A–E) and the cleanup review's skipped
proposals (one combined resolve-and-walk op, notify as a gate lane, app opens
off the session loop, a clippy guard) stand. Nothing new is chosen here.

## Migration & Rollback

No state-file change: `unread` is in memory only, and `persist::save` writes the
same fields. Each PR reverts on its own. Reverting A while D is merged brings
the global freeze back for a hung open, so revert D with A.

## Acceptance Scenarios

Unit tests live in the `#[cfg(test)] mod tests` of `state.rs` (and of
`reader.rs` for gate-only tests), as the #265 tests do, with `LIMIT = 200 ms`. The `PathFs` double (the `StuckReads`
pattern) holds the calls the test names, by method and by path prefix, until
the test releases them; it answers a value the test names for a call the
test names (S20), and every other call with `RealFs`; and it counts the calls
of each method. The `WakeSource` double records each `watch`
and `unwatch` call and can hold the calls the test names in the same way.

Time margins are the existing tests' margins, never a sleep:

- "Waits the limit": `< 3 × LIMIT`, for a wait of one or two limits (as
  `a_look_waits_two_limits_at_most_for_all_its_stuck_reads` does).
- "At once": `< LIMIT` (as
  `a_doc_whose_read_is_out_is_read_again_only_when_it_returned` does). A call
  that waits for the limit takes at least `LIMIT`, so this tells the two apart.
- "Flushed" (before the act of any scenario that asserts a look follows, or
  counts looks): the setup's own opens wake `watch_loop` too, and its look,
  `BURST` later, could push the change the scenario expects from the act. So
  the test first changes a sentinel doc and waits for its `FileEvent`; only
  then does it act.
- "Eventually" (after a release): retry or receive with a deadline, as
  `a_doc_whose_read_is_out_is_read_again_only_when_it_returned` does.
- "The thread records no call": the test first makes a call that waits for
  the watcher thread's reply (an open in a new dir, or a test accessor that
  asks the thread), so the thread has handled every `Reconcile` sent before.

Paths: `std::env::temp_dir()` is under `/var`, which canonicalizes to
`/private/var`. A test that needs an open and a look to meet on one key passes
the canonical path. QA scenarios use the WebDAV harness from #267 and are run
by hand before the PR is opened.

### PR A — gate and open

- **S1 (unit):** Given a `PathFs` whose `resolve` of `gone/a.md` is held, when
  `handle_open` is called for it, then it returns
  `Err("cannot open {raw}: did not answer in …")` within `< 3 × LIMIT`, and
  nothing is registered on any board.
- **S2 (unit):** Given S1's open has timed out and the call is still held, when
  `handle_open` is called again for the same raw path, then it returns the same
  error at once (`< LIMIT`) and the double counts **one** `resolve` call, not
  two.
- **S3 (unit):** Given a held `resolve` of `gone/a.md`, when another task opens
  `d/b.md` (not held) at the same time, then that open succeeds and its
  `DocOpened` is pushed before the first open has answered.
- **S4 (unit):** Given S1 with an app connected, when the held call is
  released and the path has left `out` (`is_out_dir`, waited for with a
  deadline), then the board still has no such doc and the app got no
  `DocOpened` for it: the timed-out open is not finished on its own. The next
  `handle_open` of the same path then succeeds, the double counts **two**
  `resolve` calls, the doc is registered, and the app gets one `DocOpened` for
  it.
- **S5 (unit):** Given a doc dir with a `.git` above it that is already
  watched (another doc there is open), and a `PathFs` whose `repo_of` is held
  and whose `resolve` answers, when a new doc in that dir is opened, then the
  open succeeds within `< 3 × LIMIT` and the doc has `repo: None`,
  `repo_root: None`, `repo_color: None`.
- **S5b (unit, PR B):** Given a `PathFs` whose `repo_of` under a dir that is
  not watched yet is held, when a new doc there is opened, then the open fails
  with `cannot watch {dir}: did not answer …` within `< 3 × LIMIT`, nothing is
  registered, the dir's count is zero, and the source records no `watch` of
  that dir (D9).
- **S6 (unit):** Given a doc already registered with a repo, when it is opened
  again, then `repo_of` is not called (the double counts zero calls for that
  open) and its repo is unchanged. Given a doc registered with **no** repo (S5),
  once its held walk has returned (the test waits for `is_out_dir(dir)` to be
  false, with a deadline, as S4 does; else the gate would answer `Out` with no
  call), a re-open also does not call `repo_of` and the repo stays `None`
  (Decision 6).
- **S7 (unit):** Given a missing path, a directory, and a regular file, when
  each is opened through `handle_open` with `RealFs`, then the replies are
  exactly today's: `cannot open …: …`, `not a regular file: …`, and success.
- **S8 (unit, existing):** The #265 look tests
  (`a_read_that_does_not_return_costs_only_its_own_doc` …
  `a_doc_whose_read_is_out_is_read_again_only_when_it_returned`) pass against
  `PathGate::stamps`, rewritten only to build the gate through the new seam.
  An open and a look of the same held path share the `out` entry, in both
  directions. Given `gone/a.md` is registered under its canonical path and its
  calls are then held: a re-open by that path times out (one call out), and a
  look after it gets no entry for the path and adds no call (the double still
  counts one). Given instead that a look left the path out, an open of the
  same canonical path answers `cannot open …: did not answer …` at once and
  the double counts no `resolve` call.
- **S8b (unit):** Given a `Silent` source, `gone/a.md` registered with its
  stamp out after a look, and `d/b.md` registered, when `d/b.md` is changed
  and then the held call is released, then a `FileEvent` for `d/b.md` is
  pushed with no look called by the test: `returned` notifies `wake`.

### PR C — startup

- **S17 (unit):** Given a `.git` above both `gone/` and `d/`, a state file
  with a doc under each, and a `PathFs` whose calls under `gone/` are held from
  the start, when the daemon is built, then the constructor returns within
  `< 3 × LIMIT`, both docs are on their board, the doc in `d/` has its repo
  (in its `DocEntry`), and the doc under `gone/` has no repo. A look then pushes
  nothing for the doc in `d/` until its file changes.
- **S18 (unit):** Given S17, when the held calls are released and the file was
  not changed, then a look that reads the doc (the double counts the new
  `stamp` call) pushes **no** `FileEvent` for it, and its `last_changed_ms` is
  still the one in the state file. When the file is then changed, the next
  look pushes one. The source records exactly one `watch(gone/)`, at once or
  after the release (whichever the timing gives).
- **S19 (unit):** Given S17 and the doc's file deleted while held, when the calls are
  released, then the look that reads it pushes nothing, and when the file is
  written again the next look pushes a `FileEvent` (the reading of "no file"
  ended `unread`). Given S17 and the calls released, a `doc_refresh` of the doc
  pushes as today, and a later change is pushed by the next look. A doc whose
  file is really missing at startup (no hold) still behaves as today: a
  `FileEvent` when it comes back.
- **S20 (unit):** Given a state file with five docs in one dir and two in
  another, and a `PathFs` whose `repo_of` answers a repo that is not on disk
  (no `.git`), when the daemon is built, then `repo_of` is called twice (once
  per dir) and every doc has the double's repo of its dir. This proves the
  repo came through the gate, not from a walk in `persist`.

## For the Implementing Agent

> **Your job:** make every acceptance scenario above pass with tests that would
> *fail if the behaviour were wrong*. A green suite that passes for the wrong
> reason does not satisfy this contract — `/verify` will hunt for vacuous tests
> by asking, of each behaviour, "what is the smallest change that breaks this,
> and would any test catch it?"

Project rules that bind this work:

- **TDD.** Watch each new test fail on the unmodified tree first
  (`CLAUDE.md`, `docs/coding-style.md`).
- **Lock discipline.** No `std::sync::Mutex` across `.await`; no file-system
  call or notify call under any lock; `looking` before `boards`.
- **No sleeping for an outcome.** Hold calls with channels, as `StuckReads`
  does. Every test holds its release sender to its end: a runtime waits for its
  blocking threads when it is dropped.
- **Never run `tarmacd` or a binary under `target/` by hand.** Daemons only
  through the test harness. Never `pkill` anything.
- **Do not `cargo fmt`.** Match the surrounding style.
- **Report every changed assertion** of an existing test (S8, S13, S15, S25
  name the expected ones). Any other changed assertion is a finding.
- `make test` green before each PR. `docs/architecture.md` is updated in the PR
  that changes what it says (the look's reader, the watcher, startup, the cli's
  open).

Behavioural over structural: assert what the daemon answers, pushes and calls
on its doubles, not private fields. Deterministic and isolated: per-test temp
dirs, no shared state.

## Definition of Done

Done is when `/verify` passes against this spec, for each PR's scenarios:

- [ ] `make test` is green.
- [ ] Every scenario of the PR maps to at least one test (Q1–Q5 to a QA record
      in the PR body).
- [ ] No covered-but-vacuous scenario: each test fails under the smallest break
      of its behaviour (thought-mutation).
- [ ] Tests meet the Desiderata bar; no AP-1…AP-8 violations.
- [ ] No implementation-quality blockers (stubs, dead code, stale doc comments,
      a `FileReader` name left behind).

## Trade-offs and Limitations

From the design doc, unchanged: a slow but live volume can fail an open (1 s);
a stuck call holds one blocking thread per dead path for minutes; a dead dir
stays in the FSEvents stream until it answers; a hung notify fails opens that
need a new watch; an app open of a hung doc stalls the app's session for up to
1 s; startup can wait up to 2 s with a restored doc on a dead volume; a board
delete gets one more look than today. New here: with the cli no longer
statting, `tarmac open` of a missing file with no daemon running says "no
daemon", not "cannot open" (S25).
