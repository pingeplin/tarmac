## Context

The ⌘Q guard is the native Quit item retargeted onto `tarmacQuit:`
(`desktop/src-tauri/src/quit_intercept.rs`). A keyboard ⌘Q shows the notice. A
~500 ms hold hides the window and quits on release, and two taps within 1 s
quit. Release is read by a 50 ms main-run-loop timer that polls
`CGEventSource::key_state(CombinedSessionState, key)`.

Every change to that path owes Q1, Q11, Q12 and Q16 of
`desktop/qa/hold-to-quit-qa.md` by hand (the rows #179 names). The driver cannot
help today:
- **DOM events only.** `tarmac dev key` and `type` dispatch DOM events.
  WebKit never forwards an untrusted event to the native menu, so nothing the
  driver sends reaches AppKit.
- **No ⌘ chords.** `key` refuses them on purpose (`devKeyPlan.ts`,
  `unsupported_combo`). 2609.0015 records that ⌘C and ⌘V cannot be driven
  either, for the same reason.
- **No holds.** No verb can make a key read as held: the poller reads the
  physical key state.
- **No visibility into the guard.** `make qa`'s only guard check, D11, reads
  whether the Quit item is retargeted. It presses nothing and cannot see what the
  guard decided.

**Measured before writing this spec.** Four spikes ran on 2026-09-19. Their
tools and logs are in the main checkout's `.dev/`, which is gitignored and
machine-local.

       `activeElement` on BODY (`r-md2-from-iframe.json`).

     - The same select step.

       `borrowed` class.

       (`r-h-3-focus.json`). This matches what spike 2 reported for its run
       A10; `a10-html-watch.log` does not record `activeElement` either.

       (variants V1–V5, `r-var-*.json`): the select sets `focused_card`, the
       `dblclick` the borrow, and `.focus()` the IFRAME. `.focus()` works with
       the shield still up and with no select (V4, V5). So all three are
       needed to match a native double-click, not for focus alone.
     - Untrusted mouse events on the iframe cannot replace `.focus()`
       (`r-mousepair-iframe.json`).
     - The frame is cross-origin (`sandbox="allow-scripts"`,
       `tarmac-card://`), so its document is unreachable except by
       `postMessage`.

     plan's steps back to back and settles once, so React has not yet
     unmounted the shield when `.focus()` runs. V4 shows the shield does not
     block `.focus()`. D17 and D18 check the end state this ordering produces.
   - **A culled HTML card cannot take focus.** Its wrapper is
     `visibility: hidden`, and `iframe.focus()` silently does nothing
     (`r-hplan-culled.json`). The markdown plan still works on a culled card.
   - **No link can be followed.** No `click` is dispatched, and `DocCard` opens
     links only from `onClick`. `location.href` never changed.
   - **Side effects.** Every call raises the card's z-index, as `focus` on a
     terminal already does. A borrowed card stays borrowed after focus moves
     away (`r-md2-from-iframe.json`). While it does, `App.tsx`'s Esc ladder
     spends the next Esc that no toast or fly-back claims on un-borrowing it,
     and that Esc never reaches the terminal.
   - **Not measurable while locked:** whether a native ⌘Q with the IFRAME
     focused reaches the menu. Spike 2's A10 already showed a ⌘Q taking the page
     path with an HTML card focused by a native click (`inapp-spike-183/run1.log`,
     121170190). D18 is the first run with the iframe focused by a DOM
     `.focus()` call.

## Motivation

#179 needed a hand run (2026-09-19), and every release-path change will owe the
same run again. Q1's tap/hold/double tap across focus contexts, Q12's freshness
and Q16's re-show are mechanical. Holds, double taps and stale presses end the
app, which is exactly why nobody re-runs them casually.

The missing capability is general: the driver cannot press a native ⌘ chord at
all. That is why ⌘C, ⌘V, ⌘H, ⌘M and the switcher's rows (Q6, Q13) are manual
too. A verb that posts a real ⌘ chord, plus snapshot fields that show what the
guard did, turns the guard rows into a repeatable check an agent can run
unattended. The same verb is the base for those other rows later. The rows that
depend on the input source (Q11) stay manual, and the QA doc says so.

## Proposed Solution

### Overview

A new debug-only verb, `tarmac dev press <combo> [--hold <ms>] [--age <ms>]`,
presses any **⌘ chord** natively:
1. parses the combo into modifier flags, characters and an ANSI key code;
2. refuses a chord that a native `terminate:` menu item would take;
3. makes the main window key, activating the app if needed;
4. arms a debug-only key-held override for that key code;
5. posts a constructed keyDown in-process, then the keyUp when the hold ends;
6. replies with what it did. It does **not** report what the key caused.

Observation stays in the snapshot. `quit_guard` gains:
- `phase`;
- `notice: { visible, alpha }`;
- `last_press: { press_ms, route, age_ms }`, what the Quit handler recorded for
  the most recent keyboard press it saw.

A scenario presses, then waits with
`--until 'quit_guard.last_press.press_ms ~= <reply's press_ms>'`. `~=` allows
±1, which absorbs the float truncation in `press_ms`, and the snapshot that the
wait returns carries the route.

`focus` learns doc cards, with DOM dispatch as for terminals:
- a markdown card is selected and focus drops to the page body;
- an HTML card is selected, borrowed (its shield lifted), and its iframe
  focused.

Q1's markdown and HTML cells become scenarios.

`make qa` gains the scenarios that leave the app running. That includes one
that proves the verb is general: ⌘T opens a terminal and ⌘W closes it, both
through the page's own shortcuts. A new `make qa-quit CASE=<hold|double|stale>`
runs one scenario that ends the app, so it needs a fresh `make run` each time.

### Key Components

- **`core/crates/tarmac-protocol/src/lib.rs`, `dev` module.**
  - `DevRequest::Press { combo: String, hold_ms: Option<u32>, age_ms: Option<u32> }`,
    tagged `press`; `None` fields are skipped.
  - `HOLD_MS_MAX = 10_000` and `AGE_MS_MAX = 60_000`, the only definitions of
    the verb's ranges.
  - `timeout_ms()` stays `None` for `Press`. The verb's longest wait is
    `KEY_WAIT_MS` (1000) plus hops, well inside `BACKEND_SLACK_MS` (2000), and
    the CLI's `read_deadline_ms(None)` (3000) outlasts both. The verb never
    waits for the hold: the keyUp is a spawned task (step 4.5).
    - `timeout_ms()`'s doc comment ("Only `snapshot` waits on anything") is
      updated: `press` waits too, inside the backend's slack.
    - If the first implementation step (*For the Implementing Agent*) needs
      `KEY_WAIT_MS` above 1500, the slack no longer covers it with margin, and
      `timeout_ms()` must return a budget for `Press` instead.
- **`core/crates/tarmac-cli/src/dev.rs`.**
  - `parse_verb` gains `press <combo>` and its two flags, and `USAGE` gains the
    line.
  - The CLI checks the flags' ranges but not the combo. The app parses it, as
    it does for `key`.
- **`desktop/src/devDriver.ts`.**
  - `handle` answers `press` before routing, like `snapshot`: it needs no card.
  - It awaits `invoke("dev_press", { combo, holdMs, ageMs })` and replies with
    the command's JSON, or its error JSON.
  - `IMPLEMENTED` gains `press`.
  - `quitGuardFacts`' type widens to the new `quit_guard` shape.
- **`desktop/src/kit/devKeyPlan.ts`.** The `unsupported_combo` message for a
  `cmd`/`meta` chord now names `tarmac dev press` as the verb to use for a
  letter or digit, spelled with `cmd` (`press cmd+<letter or digit>`), because
  `press` refuses `meta` and named keys.
- **`desktop/src/kit/devSnapshot.ts`.** The `quitGuard` input type widens.
  - `buildSnapshot` copies the object, except that it reports `notice.alpha`
    as `0` whenever `notice.visible` is false.
  - The reason: `hide_notice` resets a hidden panel's `alphaValue` to 1.0,
    which would read as a notice at full opacity.
  - This is a decision, so it lives here, as `selection`'s `""` → `null` does.
  - `DevSnapshotInput` gains `borrowedId: string | null`: App's `borrowedCardId`,
    prefixed like every internal id.
  - A doc card's object gains `borrowed: boolean`, true iff its id is
    `borrowedId`. A terminal card carries no `borrowed` key, just as a doc card
    carries no `term`.
  - `devDriver.ts`'s deps gain `borrowedId()`. `App.tsx` supplies it from
    `borrowedCardIdRef`, a one-line production touch like 2609.0015's
    `termProcRef`.
  - This key was added after the gate. The spec-evaluator found that nothing
    else observes the borrow, so without it the `doc-shield` step would have no
    knockout that can fail. It is additive, `v` stays 1, and it is easy to drop
    if the human prefers a by-eye check.
- **`desktop/src-tauri/src/dev_press.rs`** (new, pure,
  `#[cfg(any(test, debug_assertions))]`).
  - `parse_chord(combo) -> Result<Chord, ChordError>`.
  - `Chord { flags: u64, chars: String, key_code: u16 }` uses raw
    `NSEventModifierFlags` bits. It imports `SHIFT`, `CONTROL`, `OPTION` and
    `COMMAND` from `quit_guard.rs`, which become `pub(crate)`, rather than
    restating them a third time. So this module needs no AppKit.
  - An ANSI key-code table for `a`–`z` and `0`–`9` (`kVK_ANSI_*`).
  - `matches_item(chord, key_equivalent, item_mask) -> bool`, step 4.2's refusal
    predicate (rule under *Interface Contract*).
- **`desktop/src-tauri/src/quit_intercept.rs`.** Everything below is
  `#[cfg(debug_assertions)]`.
  - `QuitIvars` gains `held: Cell<Option<(u16, u64)>>`: a key code and the time
    it is held until. When `on_poll` samples that key code, its read becomes
    `key_state(…) || now_ms() < until`.
  - `QuitIvars` gains `last_press: Cell<Option<(u64, Route, i64)>>`: the
    handler's `press_ms`, route and `age_ms`.
    - `on_quit` writes it for every keyDown it routes, after `route` and before
      applying it. `terminate:` never returns, so the write must come first.
    - A non-key `on_quit` (a menu click) leaves it alone.
  - `async fn dev_press(app, combo, hold_ms, age_ms) -> Result<Value, Value>`.
    It must never block the main thread: every AppKit step is a
    `run_on_main_thread` hop, and every wait is an async sleep between hops.
  - `dev_quit_guard` also reports `phase`, `notice` and `last_press`.
    - Until the first `ShowHud` the `notice` ivar is `None`, and
      `dev_quit_guard` reports it as `{ visible: false, alpha: 0 }`.
    - With no `QuitTarget` at all (`TARGET` is `None`, as under 2609.0016's
      S37 knockout, which S33 reuses), it reports `phase: "idle"`, that same
      `notice` and `last_press: null`. `retargeted: false` is what carries the
      meaning.
- **`desktop/src-tauri/src/quit_guard.rs`.**
  - `SHIFT`, `CONTROL`, `OPTION` and `COMMAND` become `pub(crate)`, so
    `dev_press.rs` imports them.
  - `Route` gains `Clone, Copy`. It has two unit variants, and `Cell::get`
    needs `Copy`.
  - `pub fn phase_name(&Phase) -> &'static str` returns `"idle"`, `"showing"`
    or `"confirming"`.
  - `pub fn route_name(&Route) -> &'static str` returns `"guard"` or
    `"terminate"`.
  - `expected_modifiers` becomes `pub(crate)`, so `matches_item` applies the
    guard's own modifier rule rather than a second copy of it.
  - Only tests and debug-only code read `phase()`, `phase_name` or
    `route_name`, so all three carry
    `cfg_attr(not(any(test, debug_assertions)), allow(dead_code))`. `phase()`
    carries `cfg_attr(not(test), …)` today.
- **`desktop/src-tauri/src/quit_notice.rs`.** `Notice` gains `is_visible()`
  and `alpha()` (the panel's `isVisible` and `alphaValue`), read on the main
  thread. Only the debug-only `dev_quit_guard` calls them, so both are
  `#[cfg(debug_assertions)]`; otherwise a release build warns `dead_code`.
- **`desktop/src-tauri/src/lib.rs`.** `dev_press` joins the
  `#[cfg(debug_assertions)]` command list beside `dev_quit_guard`, and the
  `dev_press` module is declared under the same `cfg(any(test,
  debug_assertions))`.
- **`desktop/src-tauri/Cargo.toml`.** `objc2-app-kit` gains the feature
  `NSGraphicsContext`, the type of `keyEventWithType…`'s `context` argument.
  The features there carry no per-line comments; the block comment above the
  dependency covers them.
- **`desktop/src/kit/devRouting.ts`** (pure).
  - `focus <doc card>` routes instead of refusing.
    - **markdown** (per `kit/docKind`): `card-body` `pointerdown`/`pointerup`,
      then a `page-body` step.
    - **HTML**: `card-body` `pointerdown`/`pointerup`, then `doc-shield`
      `dblclick`, then `doc-iframe` `focus`.
  - `DevTarget` gains `page-body`, `doc-shield` and `doc-iframe`.
    `RouteStep.card`'s comment ("null for the board itself") also names
    `page-body`, whose step has no card either.
  - Its test helper `ctx()` and `devSnapshot.test.ts`'s `input()` gain
    defaults for the new required fields (`viewport`, `viewSize`,
    `borrowedId`). `npm test` runs `tsc --noEmit` over the tests too, so
    without defaults every existing test fails to compile. That is not red in
    the §1 sense. S8's and S9's red shows under `npx vitest run`.
  - `RouteContext` gains `viewport: Viewport` and
    `viewSize: { w: number; h: number }`.
  - An HTML card that `kit/cull`'s `isCardVisible` reports off-screen is
    refused with the new code `card_hidden`, before any event. This is the same
    predicate `BoardEngine` culls with, so the refusal and the paint agree.
    `card_hidden` is `focus`'s alone: `resize`, `type` and `key` on a culled

  - `type` / `key` on a doc card stay `unsupported_card_kind`. Its message
    becomes "doc cards take `focus`, but cannot be typed into or keyed".
- **`desktop/src/devDriver.ts`.** `dispatchStep` implements the three new
  targets:
  - `page-body`: focus a temporary `tabIndex=-1` div (`preventScroll`), then
    remove it. This is only needed when `activeElement` is not already BODY.
  - `doc-shield`: dispatch a `dblclick` `MouseEvent` (`detail: 2`) on the
    card's `.html-shield`. It does nothing when the shield is gone, because the
    card is already borrowed.
  - `doc-iframe`: call `.focus()` on the card's `<iframe>`.

  These three branch before the generic path (`requireElement`, then one
  dispatched event per name). In a plan, `focus` names a `.focus()` call, not
  an event to dispatch, and `page-body` has no card element to resolve. A
  missing shield is the one deliberate exception to `dispatchStep`'s
  throw-on-missing rule, because every re-run meets a card that is already
  borrowed.

  The reply stays `{ focused_card, active_element }`, as observed. The
  frontend supplies `viewport` and `viewSize` from the engine
  (`viewport`, `viewportSize`).

### Data Flow

1. **CLI.** `tarmac dev press cmd+q --hold 1000` becomes
   `Press { combo: "cmd+q", hold_ms: Some(1000), age_ms: None }`.
2. **Backend relay.** `DevDriver::dispatch` emits `dev-request` as for every
   verb.
3. **Frontend.** `handle` sees `t === "press"` and awaits
   `invoke("dev_press", …)`. The page's event loop stays free while it waits,
   which is what lets the page receive the posted key.
4. **`dev_press`**, with `hold = hold_ms.unwrap_or(TAP_HOLD_MS)` and
   `age = age_ms.unwrap_or(0)`:

   The command re-checks the ranges, because the wire accepts any `u32`. A
   `hold` outside `1..=HOLD_MS_MAX` or an `age` above `AGE_MS_MAX` replies
   error `bad_request` without posting. The bounds come from
   `tarmac_protocol::dev`, so S20 and S30 pin the only definition. The
   app-side re-check itself is untested defensive wiring.

   If `run_on_main_thread` returns `Err` in any step, the event loop is
   exiting, and the reply is error `app_unresponsive`.

   `TARGET` being `None` matters in two steps. Step 4.2 refuses the Quit
   chord. Step 4.4 has no `QuitIvars` to arm `held` in, so it posts without
   the override; no poller exists to read it.

   1. **Parse.** `parse_chord(combo)` → `Chord`, or reply its error:
      - `unsupported_combo` for a combo without `cmd` (the message points at
        `key` / `type`);
      - `bad_combo` for anything outside the grammar.
   2. **On main: refuse a real quit.** Walk the menu tree the way
      `is_retargeted` does. Reply error `not_retargeted` without posting when
      `matches_item(chord, item.keyEquivalent(), item.keyEquivalentModifierMask())`
      is true for:
      - an item whose action is still native `terminate:`, because posting
        would quit for real; or
      - an item whose action is `tarmacQuit:` while `TARGET` is `None`. Its
        target is gone, AppKit disables the item, and no handler could see the
        press.

      Every other chord is posted, whatever the menu does with it.
   3. **Make the window key.** Start the step with a single "already key?"
      test (one line), so that S21's knockout can short-circuit it. If the main
      window is not key:
      - call `NSApplication::activate()` and set `activated = true`;
      - poll `isActive && isKeyWindow` with hops about every 20 ms;
      - if it is still false after `KEY_WAIT_MS`, reply error `not_key`.

      **Never call `deactivate`.**
   4. **On main: arm the override and post.**
      - Take `now = now_ms()`, set `held = Some((chord.key_code, now + hold))`
        (when `TARGET` is `Some`), and set `stamp_ms = now.saturating_sub(age)`.
      - Build a keyDown:
        - `characters` and `charactersIgnoringModifiers` both `chord.chars`;
        - `modifierFlags` = `chord.flags`, `keyCode` = `chord.key_code`;
        - `isARepeat` false;
        - the main window's `windowNumber`;
        - a timestamp of `stamp_ms / 1000` seconds.
      - Post it with `postEvent_atStart(false)`.
      - Reply `{ "combo": …, "press_ms": stamp_ms, "hold_ms": hold,
        "activated": … }`.

      The verb does not wait for anything the key causes. A scenario observes
      that through the snapshot.
   5. **Afterwards, post the keyUp.** A spawned task captures `now + hold`.
      The next press may re-arm `held`, so the task must not re-read it. It
      sleeps until that time, then posts the matching keyUp on main (same
      chord, same window). By then the app may already be exiting; any hop
      failure is ignored.
5. **The guard sees an ordinary gesture.**
   - `tarmacQuit:` runs for a keyDown whose chord matches the Quit item. It
     routes, records `last_press` (which carries the route), and on `Guard`
     starts the poller on the event's key code.
   - The poller reads `held` until it expires, so the guard sees a release at
     `now + hold`. The tap default of 100 ms means a double tap quits on
     release, as a real one does, not on the first poll.
   - A press the page swallows never reaches `tarmacQuit:`, and `last_press`
     does not move. S11's knockout relies on this.
   - **Stale override (known, accepted).** If a press never reaches the
     handler (a swallowed ⌘Q, or any chord that is not Quit's), `held` stays
     armed until it expires, at most `HOLD_MS_MAX`. A real ⌘Q tap on the same
     key code inside that window reads as held. It is debug-only, needs such a
     `press` on Quit's key code just before a real ⌘Q, and costs at most a
     dev-app quit.
6. **Snapshot.** `dev_quit_guard` returns `{ retargeted, enabled, phase,
   notice: { visible, alpha }, last_press }`, read on the main thread in the
   same hop. `alpha` is the panel's raw `alphaValue`; `buildSnapshot` zeroes it
   when `visible` is false.
7. **`focus <doc card>`.** `routeVerb` returns the plan for the card's kind, or
   `card_hidden` for a culled HTML card. `dispatchStep` runs the steps in order,
   then `settle()`, then the reply reports `focused_card` and
   `active_element` as observed. Nothing native is involved, so the window does
   not have to be key.

### Interface Contract

```text
tarmac dev press <combo> [--hold <ms>] [--age <ms>]
  <combo>  the first argument after `press`, before any flag. cmd plus any of shift, alt, ctrl,
           each at most once and in any order, then one ASCII lowercase letter a-z or digit 0-9:
           cmd+q, cmd+shift+z, alt+cmd+q, cmd+1. An argument starting with `--` in that position
           is a usage error naming it.
  --hold   1..=10000, default 100 (TAP_HOLD_MS)   how long the key reads as held
  --age    0..=60000, default 0                    stamp the press this many ms in the past
  usage errors (exit 2): missing combo, missing flag value, not an integer, out of range,
  repeated flag, unknown flag, extra positional argument — the message's first
  line names the flag or argument (`usage()` appends the full USAGE after it)
```

```rust
// tarmac_protocol::dev
DevRequest::Press {
    combo: String,
    #[serde(default, skip_serializing_if = "Option::is_none")] hold_ms: Option<u32>,
    #[serde(default, skip_serializing_if = "Option::is_none")] age_ms: Option<u32>,
}                                  // wire tag "press"
pub const HOLD_MS_MAX: u32 = 10_000;         // --hold is 1..=HOLD_MS_MAX
pub const AGE_MS_MAX: u32 = 60_000;          // --age is 0..=AGE_MS_MAX

// dev_press.rs
pub struct Chord { pub flags: u64, pub chars: String, pub key_code: u16 }
pub enum ChordError { Unsupported(String), Bad(String) }   // → unsupported_combo / bad_combo
pub fn parse_chord(combo: &str) -> Result<Chord, ChordError>;
pub fn matches_item(chord: &Chord, key_equivalent: &str, item_mask: u64) -> bool;  // step 4.2

// quit_guard.rs
pub fn phase_name(phase: &Phase) -> &'static str;   // "idle" | "showing" | "confirming"
pub fn route_name(route: &Route) -> &'static str;   // "guard" | "terminate"
pub(crate) fn expected_modifiers(key_equivalent: &str, mask: u64) -> u64;  // was private
```

`parse_chord` rules:
- **Flags.** `cmd` → `COMMAND` (1<<20), `shift` → `SHIFT` (1<<17), `alt` →
  `OPTION` (1<<19), `ctrl` → `CONTROL` (1<<18).
- **Characters.** `chars` is the base, uppercased under `shift` for a letter.
  A digit stays the digit: its shifted symbol depends on the layout, the same
  rule `devKeyPlan` follows.
- **Key code.** The ANSI key code of the base.
- **`unsupported_combo`:** a combo with no `cmd`.
- **`bad_combo`:**
  - an unknown modifier, including `meta`;
  - a repeated modifier;
  - an empty or missing base;
  - an uppercase base;
  - a base outside ASCII `a`–`z` and `0`–`9` (so `é`, `enter` and `qq`);
  - any empty `+` segment.
- **Order.** Every `bad_combo` rule is checked before `cmd` is looked for, so
  `unsupported_combo` means a well-formed chord without `cmd`. That is why `""`,
  `"cmd"` and `"meta+q"` are `bad_combo`. `devKeyPlan` checks in the other
  order: it refuses any `cmd`/`meta` modifier first.

⌥ does not alter `chars`. A real ⌥⌘Q carries `œ` in `characters`, but menu
matching uses `charactersIgnoringModifiers`.

`matches_item` rule (step 4.2's refusal). It is true iff both hold:
- `key_equivalent` equals `chord.chars`, ignoring ASCII case;
- `chord.flags` equals `quit_guard::expected_modifiers(key_equivalent,
  item_mask)`: the item's mask restricted to Shift, Control, Option and
  Command, plus Shift when `key_equivalent` is an uppercase letter.

The modifier half is the rule `is_keyboard_quit` already applies to an event.
The character half is the comparison AppKit makes before the handler runs.

Reply body (`ok: true`):

```json
{ "combo": "cmd+q", "press_ms": 121268655, "hold_ms": 100, "activated": false }
```

Errors (`ok: false`, the 2609.0015 JSON error shape):
- New codes: `not_retargeted` and `not_key`.
- Reused with their 2609.0015 meaning: `unsupported_combo` and `bad_combo`.
- Existing codes with an added meaning:
  - `bad_request` also covers a `hold` or `age` out of range on the wire;
  - `app_unresponsive` also covers a failed main-thread hop.
- `app_not_ready` is unchanged.
- An app built before this verb answers `unsupported_verb`.

`focus` gains one new error code:
- `card_hidden`: an HTML doc card culled off-screen. Its message tells the
  caller to zoom out, or pan by hand: no verb pans.

`unsupported_card_kind` now applies only to `type` and `key` on a doc card.

The verb does not read *Warn Before Quitting*. With the toggle off, a ⌘Q press
routes `terminate` and the app quits, as Q3 requires of a real tap. The scenario
scripts check `enabled == true` before they press ⌘Q.

Snapshot (`v` stays 1; additive keys inside `quit_guard`):

```ts
quit_guard: {
  retargeted: boolean;
  enabled: boolean;
  phase: "idle" | "showing" | "confirming";
  notice: { visible: boolean; alpha: number };    // alpha 0 when not visible (buildSnapshot)
  last_press: { press_ms: number; route: "guard" | "terminate"; age_ms: number } | null;
} | null

cards[i].borrowed: boolean   // doc cards only (additive); true iff App's borrowedCardId is this card
```

Constants:
- in `quit_intercept.rs`: `TAP_HOLD_MS = 100` and `KEY_WAIT_MS = 1000`;
- in `tarmac-protocol`: `HOLD_MS_MAX = 10_000` and `AGE_MS_MAX = 60_000`.

**Release builds.** None of the verb's command, `dev_press.rs`, the override or
`last_press` exists in a release build. The CLI side keeps 2609.0015's gate: a
release binary still exits 1 with `driver unavailable in release builds`.

## Alternatives Considered

### A dedicated `quit-key` verb

Reading the live Quit chord from the menu, and reporting the route in the reply,
fits the guard exactly.

It was the first draft of this spec, and it was not chosen: it adds a verb that
can press only one key. The generic verb costs a combo parser and an ANSI table.
In exchange it drives any ⌘ chord (⌘C, ⌘V, ⌘H, ⌘M and the page's ⌘T/⌘W/⌘K), and
it keeps observation in the snapshot, where every other scenario already reads
it.

Q9, a remapped Quit, now presses the remapped chord explicitly, for example
`press alt+cmd+q`.

### Extend `key` to post native events for ⌘ chords

`key`'s contract is DOM-level. It is scoped to a card, it requires that card to
have focus, and it plans a keydown/keyup pair that it dispatches into the page.
A native post has none of that. It targets the key window and passes through
AppKit and WebKit, and it needs `--hold` and `--age`. One verb with two delivery
paths would make its replies and errors mean different things depending on the
combo. `key` keeps its contract and now points at `press`.

### Post from outside with `CGEventPostToPid`

Spike 1 shows it works for taps, and it would need no app code for posting. It
was not chosen for three reasons:
- the std-only CLI would need CoreGraphics FFI;
- it still cannot drive a hold, because `key_state` never reads a posted key;
- it cannot choose the key window. An in-process post can, and that choice is
  what decides whether the page sees the key.

### A debug switch that suppresses `Exit`

This would let the quitting cases join `make qa` without ending the app. It
was rejected because it forks the behaviour under test: the scenario would pass
while `app.exit(0)` from the timer callback broke. A separate entry point that
lets the app really quit keeps the check honest.

### Drive holds with a real key-state source

No event source makes `key_state` read a posted key as down (spike 1). The
remaining global `CGEventPost` taps reach the frontmost app, and a ⌘Q there
could quit the user's other apps. The override is the only safe route. It tests
everything except the physical key read, which Q8 and the hand-run rows keep
covering.

### Focus doc cards with posted native clicks

Spike 2 focused both doc kinds with native clicks. The approach needs a key
window, a CSS-to-window coordinate conversion, and a safe click point:
- The conversion is off by the 32 pt title bar if done naively (spike 3,
  unverified).
- A second click inside a borrowed HTML card could land on a link.

Spike 4 reaches the same end states with DOM dispatch alone: no coordinates,
no key window, no click inside content. That is also how `focus` already
reaches terminals. The one thing only a native click would add is that
intermediate states match: a native click drops focus to BODY immediately.
No scenario observes the intermediate states.

## Security Considerations

- **Debug builds only.** The command, the parser, the override and
  `last_press` are compiled out of release builds, and a release build is
  checked for the command's name (S35).
- **No event leaves the process.** Posting stays in-process (`postEvent`), so
  no event can reach another app. That is the reason `CGEventPostToPid` and
  `CGEventPost` were not used.
- **Menu actions can.** A posted chord still fires whatever native menu action
  it maps to, and step 4.2 refuses only `terminate:`. For example,
  `press alt+cmd+h` runs Hide Others, which hides the user's other apps.
  `SKILL.md` says so beside the verb.
- **The verb activates the app**, taking focus from whatever the user was
  using. That is the price of taking the real path, and it is stated in
  `SKILL.md`.
- **A real quit is refused** (step 4.2) while the chord would reach native
  `terminate:`.

## Acceptance Scenarios

Automated scenarios name their test home. Rust tests go in the file's
`#[cfg(test)] mod tests`, and TS tests go beside the module. `[D]` scenarios run
against a live `make run` app, in `make qa` or `make qa-quit`. Each `[D]`
scenario names a **knockout**, a one-line temporary change that must make it
fail. Record each knockout run in `desktop/qa/hold-to-quit-qa.md`, and revert
the line, never the file.

**Matching a press.** After each ⌘Q `press` except S17's, whose app is gone
before a snapshot can answer, a scenario reads `press_ms` from the reply and
waits with
`--until 'quit_guard.last_press.press_ms ~= <press_ms>' --timeout 1000`. It then
reads `route` and `age_ms` off the snapshot that the wait returns. `~=` allows
±1. The handler reads the press back as `quit_guard::press_ms(timestamp)`, which
truncates, and `(x / 1000.0) * 1000.0` lands just under `x` for stamps just
above a power of two in seconds. For example, 754,974 of the integers from
131,072,001 to 134,217,724 ms do (about 36–37 h of uptime).

**Before every ⌘Q press.** Each ⌘Q `press` in D12–D15, D17, D18 and in `quit.mjs` is
preceded by these checks. If one fails, the script fails without pressing.
- `quit_guard.enabled == true` and `quit_guard.retargeted == true`. The toggle
  belongs to the user (`.dev/app-prefs.json`, and D11 asserts only its type).
  With it off, a tap routes `terminate` and ends the app mid-run, and S17 would
  pass for the wrong reason.
- `--until 'quit_guard.phase == "idle"'`, then
  `--until 'quit_guard.notice.visible == false'`, each with `--timeout 3000`.
  A press within 1 s of the previous press is a second tap, and it would quit
  the app in the middle of `make qa`. A notice is never gone sooner than
  1200 ms (`LINGER_MS` + `FADE_MS`) after the release that ended its tap, so
  once it is gone, more than 1 s has passed since the press.
- At least 1000 ms since the previous ⌘Q `press` reply arrived. This is the
  backstop for when no notice was shown at all: under S10's knockout, for
  example, "notice gone" says nothing about elapsed time.

The deliberate second presses in S13 and S16 are the only exceptions.

**Timing.** A script cannot read the app's clock. Times below are measured from
when a reply *arrives*, which is before its key has been handled: the reply
leaves right after the post, and in spike 2 the handler ran 1–111 ms after the
post. `press_ms` differences come from the replies themselves.

  - `dev_press` never blocks the main thread. It is an `async` command; every AppKit call is a
    `run_on_main_thread` hop; every wait is an async sleep.
  - **Never post a chord that a native `terminate:` item would take** (step 4.2).
  - Never call `NSApp.deactivate()`.
  - Never `CGEventPost` or `CGEventPostToPid`.
  - Never query `CGEventSourceKeyState(.privateState, …)`.
  - Never `pkill`. Stop a dev app by pid, and the daemon with `make kill-daemon`.
  - Never press ⌘W while an HTML card's IFRAME has focus. It hides the window (Q14).
- **Don'ts:**
  - Don't `cargo fmt`.
  - Don't touch `Msg`, `docs/protocol.md` or the V1–V13 vectors.
  - Add no crate versions to `Cargo.lock`: only the `NSGraphicsContext` feature.
  - Serialize heavy builds while a dev app is up.

Test principles: assert on returned values, replies and snapshot fields, never on private state.
Write every expected value out literally. `[D]` scenarios wait with `--until`, never with a fixed
sleep. There are four exceptions:
- S15's probe, 1500 ms after its reply;
- the 1000 ms spacing in *Before every ⌘Q press*;
- S14's new-id and gone-id polls, which the grammar cannot express;
- the "app is gone" checks in S15–S17. `--until` cannot express those, because the app is not
  there to evaluate it.

The last two poll `snapshot` about every 100 ms, up to the scenario's bound, and fail if the
bound passes first. The "app is gone" poll stops when `snapshot` exits 1 with
`no tarmac app driver`.

`--until` supports only `==`, `!=`, `~=` (within 1) and `contains`, one comparison per
expression (`kit/devUntil.ts`). To check several fields at one moment, read them off the
snapshot that `--until` returns.

- [ ] Every automated scenario (S1–S9, S20, S30–S32) maps to at least one test. Every `[D]`
  scenario (S10–S19, and S21 unless the activation fallback in *Open Questions* applies) has been
  run against a live app, and its result and knockout run are
  recorded. S22 and S33–S35 are recorded in `desktop/qa/hold-to-quit-qa.md`; S36, a driver

- [ ] No covered-but-vacuous scenarios: each automated test fails under the smallest break of

- [ ] Tests meet the Desiderata bar, with no AP-1…AP-8 violations.
- [ ] No implementation-quality blockers. `make docs-check` is green. `SKILL.md`, the two QA docs,

  driver-covered and which stay manual.

## Trade-offs and Limitations

- **Not a real key.**
  - The input source and IME play no part, because the characters are supplied. Q11 stays manual.
  - ⌥ does not alter `characters` either.
  - A shifted digit carries the digit, not its layout's symbol. A menu item or page handler keyed
    to `!` does not take `press cmd+shift+1`.
  - The physical `key_state` read is bypassed by the override. Q8 and the hand-run Q1 hold keep
    covering it.
  - `--age` backdates the press for the whole gesture, not only for freshness. The hold threshold
    counts from `press_ms` (`sampled − started_ms ≥ HOLD_MS`), so an `--age` plus `--hold` that
    reaches about 500 ms can commit a hold and quit. `--age 450` with the default hold can.
- **Only ⌘ chords.** Letters and digits with `cmd`, and no named keys (⌘⌫, ⌘←, ⌘Enter). Adding
  them later is additive.
- **The verb steals focus** when the window is not key. That is the only way the key takes the
  page's path.
- **The reply does not say what the key did.** Scenarios read the snapshot.
  - ⌘H and ⌘M already flip `visibility` to `"hidden"`.
  - ⌘C and ⌘V have no snapshot field (the clipboard, the paste), and they need one before a
    scenario can assert on them.

  Those rows (Q6, Q13) are follow-ups.
- **Each quitting case costs a relaunch.** Hold, double tap and stale each end the app, so
  `make qa-quit` runs one case per `make run`.
- **Q12's busy half is not covered.** The driver serves one request at a time, so nothing can
  freeze the page while `press` runs. See *Open Questions*.
- **Doc-card focus is DOM-level.**
  - The end states match a native click. The intermediate ones do not: focus stays on the old
    element until the plan's last step.
  - A culled HTML card is refused (`card_hidden`) rather than scrolled into view.
  - A borrowed HTML card stays borrowed after focus moves away, and takes the next Esc.
  - The borrow is observed through the new `cards[].borrowed` key (S9), not through the DOM.
  - Focus moving from one borrowed HTML card straight to another was not measured.
- **A stale press's reply races its terminate.** S17 asserts the exit. The route is recorded
  from the `make run` output, which `quit.mjs` cannot see.

## Open Questions

The gate settled the four questions (see *Gate*). One is still pending a
measurement:

- [ ] **Q12's busy half.** The user's decision was "measure first, then decide".
  - Spike 3 showed that the page freeze works (`eval` of a busy loop).
  - It could not show whether a press on the page path reports an `age_ms` close to the freeze
    left, because the locked screen kept the window from becoming key.
  - Re-run `.dev/spike3-183/runB.sh` with the screen unlocked and the dev window key.
    `spike.patch`, `t.sh` and `runB.sh` hardcode the original session's scratchpad
    (`/private/tmp/…/scratchpad/spike3`), which a reboot deletes. Repoint them at
    `.dev/spike3-183/` first, and tee the patched `make run`'s output to its `run.log`, which
    `t.sh` and `runB.sh` read.
  - Until then, the busy half stays manual and outside this spec.
  - If it is added later, a `--busy` press must be refused unless the window is key. Otherwise
    it bypasses the frozen page and passes vacuously.

The activation measurement (Gate item 2) is the first implementation step, not
an open question. Its fallback is decided: if activation is refused, D12
reports `not_key`, and `make qa` needs the dev window key before it runs.
