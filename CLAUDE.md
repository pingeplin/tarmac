# Tarmac

Tarmac is a terminal-first macOS cockpit for working alongside CLI coding agents. You run an agent (or anything) in a real terminal inside Tarmac; when that process — or you, a Makefile, a git hook, CI — runs `tarmac open <path>`, the file surfaces as a live card (HTML as a page, anything else as markdown) on an infinite, pannable, zoomable **board**, placed next to the terminal that opened it and tied by a dashed provenance edge. It is deliberately **not an agent harness**: every on-screen mark is backed by an observable OS fact (a running process, an mtime change, a `tarmac open` socket call, a terminal bell), never by parsing agent output. Status: shipped as notarized macOS releases (GitHub Releases + a Homebrew cask, `make release`); work is per-issue (`docs/workflow.md`).

## Dev builds and the installed Tarmac

The Mac you work on may run an installed Tarmac with real work in its terminals. A dev build must never reach it.

- **Never `pkill`/kill a daemon by name — the dev and installed apps coexist on purpose.** `make run` pins `TARMAC_SOCKET`/`TARMAC_STATE` (and `TARMAC_CONFIG_DIR`, where the theme files and `app-prefs.json` are) to a per-worktree `.dev/` path, so the dev app and an installed Tarmac use separate sockets, state, preferences and theme files and don't collide. To stop only the dev daemon, use `make kill-daemon` (resolves the pid via `lsof` on the dev socket, so it can only ever touch this worktree's daemon). A name-based kill (`pkill tarmacd`, `pkill -f tarmac-app`) can instead take down the user's real installed app and every terminal it owns. A `make bundle` build has the installed app's executable name (`tarmac-app`) and bundle id (`com.tarmac.desktop`, `packaging/Info.plist`), and the `make run` binary (`TarmacApp`) has no bundle id at all, so when driving any of them with a GUI/automation tool, address the specific window by PID, never by name.
- **Never launch a built `dist/Tarmac.app` or a release binary without `TARMAC_SOCKET`/`TARMAC_STATE` pinned, and pin `TARMAC_CONFIG_DIR` with them.** A release build resolves the *installed* channel: it attaches to the user's real daemon and, on a version mismatch, SIGTERMs and replaces it — taking every terminal the user has open with it. Without its own `TARMAC_CONFIG_DIR` it reads the user's theme files, or uses the config directory that its shell inherited (`docs/architecture.md`, *A theme from a file*). `make run` is the only launch that pins them for you.
- **Dev-channel work has a skill: `.claude/skills/dev-channel/SKILL.md`** — bringing the app up, driving it with `tarmac dev`, `make qa`, and what to check when it does not answer. The two rules above are the short form.

## Architecture

Two processes that share nothing in-process, plus a tiny CLI, talking over **one Unix stream socket** (`~/Library/Application Support/tarmac/tarmacd.sock`, override `TARMAC_SOCKET`) with **length-prefixed MessagePack** frames (4-byte big-endian u32 length + msgpack map with string keys; `"t"` field tags the type; 16 MiB max frame).

- **`tarmacd`** (Rust / Tokio) — the PTY owner + observatory. Spawns and owns every terminal (`portable-pty`), watches opened docs (`notify` on the parent dir), tracks OS facts (foreground process name, file changes, bells, exits), holds all boards, persists to atomic JSON (`state.json`, override `TARMAC_STATE`). In `core/` (Cargo workspace, edition 2024): crates `tarmacd`, `tarmac-cli`, `tarmac-protocol`.
- **`TarmacApp`** (Swift 6 / AppKit, macOS 26+) — the cockpit glass. Renders boards/cards, hosts terminal cards and doc/HTML cards, turns input into daemon requests. In `app/` (a SwiftPM package), three layers: **`TarmacKit`** (no AppKit: the msgpack codec, `DaemonClient`, and every pure decision — where the tests are), **`TarmacTerm`** (the terminal card: `TerminalEngine` over libghostty-vt, `FrameReader`, a CoreText `TerminalRenderer`, and `TerminalView`, which does its own IME and translates AppKit key/mouse events for libghostty-vt's encoders), **`TarmacApp`** (the AppKit shell: wiring, views, event routing). Doc and HTML cards are `WKWebView`s; terminals are not.
- **`tarmac` CLI** (Rust; beside the protocol crate it depends only on `serde`/`serde_json`, to merge agent settings and read hook input) — the universal doorbell. `tarmac open <path>` connects, names a doc, exits. Inside a Tarmac PTY it reads `TARMAC_TERM_ID` (the daemon sets it per PTY) to attribute a call to the calling terminal. Only the CLI knows an agent: the daemon and app see plain `report` and `resume` frames. `tarmac dev <verb>` is a **dev-builds-only** family that talks to the *app* over its own socket (`tarmac-dev.sock`, override `TARMAC_DEV_SOCKET`) — the in-app QA driver; a release binary exits 1 with `driver unavailable in release builds`. What each verb does is not listed here, so it cannot drift: `tarmac --help` (`core/crates/tarmac-cli/src/help.rs`), the agent guide `tarmac skill` prints (`core/crates/tarmac-cli/src/GUIDE.md`), and the opening of `docs/architecture.md`.

The wire contract has two implementations: `core/crates/tarmac-protocol` (the single `Msg` serde enum) and the hand-written Swift codec in `TarmacKit` (`MsgPack`, `Message`). Protocol grows **additive-only** (new optional keys / new message types; unknown keys and types ignored). Authoritative spec: `docs/protocol.md`; full engineering overview: `docs/architecture.md`.

## Build, run, test

Everything goes through the root `Makefile`:

- `make setup` — once per clone: installs the git hooks of `lefthook.yml` (it needs `lefthook`: `brew install lefthook`; worktrees of the clone share them) and sets `blame.ignoreRevsFile`, so `git blame` skips the commits listed in `.git-blame-ignore-revs` (the two formatter baselines; GitHub's blame view reads the file by itself). A commit goes on that list only when a formatter wrote it. In a checkout older than the file, `git blame` then stops with "could not open object name list"; `git blame --no-ignore-revs-file <file>` gets round it (an empty `--ignore-revs-file=` does not: git opens the configured file first).
- `make core` — `cargo build` the Rust workspace (daemon + CLI + protocol).
- `make ghostty-vt` — stage the pinned libghostty-vt XCFramework into the gitignored `app/Vendor/` (`scripts/fetch-ghostty-vt.sh`; a no-op once staged).
- `make app` — `swift build` the native package (depends on `ghostty-vt`).
- `make test` — `make docs-check` + `make arch-check` + `make check-test` (the check scripts' own tests, `node --test`) + `make ghostty-vt` + `cd core && cargo test` + `cd app && swift test`. CI runs the same suites (`.github/workflows/test.yml`: `core (cargo test)`, `app (swift test)`; `.github/workflows/lint.yml`: `check scripts`), but `make test` stays the local entry point.
- `make fmt` / `make fmt-check` — the formatter (`scripts/check/fmt.mjs`): `fmt` rewrites every tracked Rust file with rustfmt (`core/rustfmt.toml`) and every tracked Swift file with `swift format` (`.swift-format`, at the repo root so that it also covers the Swift scripts in `scripts/qa/`); `fmt-check` changes nothing and names the files `fmt` would rewrite; `ONLY=rust` or `ONLY=swift` limits either one. The script hands each tracked file to the formatter by itself, so it does not depend on `cargo fmt`, which follows `mod` lines to untracked files. `lint.yml` runs the check on every PR (`fmt (rust)`, `fmt (swift)`); a job fails the run, and blocks a merge only once the `Protect main` ruleset lists it. A failed check prints the rule, the files, and the command to run next (`scripts/check/report.mjs`); a new check uses the same reporter.
- `make lint` — the lint check (`scripts/check/lint.mjs`), where any finding is a failure; `ONLY=rust`, `ONLY=swift` or `ONLY=swiftc` limits a run. **Swift compiler (`swiftc`):** a build of the package into an empty directory, about 22 seconds, because an incremental build prints a warning only for a file it compiles again. Every warning must be an entry of `scripts/check/swiftc-known-warnings.json` (file, message, issue, reason; three today, #478), and every entry must still be seen: the list shrinks when the code is fixed. Warnings as errors are deliberately not in `app/Package.swift`: the Swift compiler is not pinned (CI and a current Xcode differ), and a new warning must fail the lint job, not `make run`, `make bundle` or the test job. `Package.swift` does hold `MemberImportVisibility` and `ExistentialAny` for the three product targets: a file uses only what it imports itself. **Swift:** `swift format lint` over the tracked Swift files with the rules of `.swift-format` — no force unwrap, `try!` or implicitly unwrapped optional (a file that imports `XCTest` or `Testing` is not checked for these three, wherever it is; a `#!` script is not linted). A finding is fixed, or kept under a `//` reason comment and `// swift-format-ignore: <Rule>` on the two lines before it (above the `///` doc comment, if there is one); the script refuses every other form of that comment, and it cannot tell a stale one. It also refuses to run when `.swift-format` turns on a rule the running swift-format lacks, or when a second `.swift-format` sits in a directory above a linted file (tracked or not), so that a rule is not silently off. **Rust:** clippy over the workspace: it prints clippy's own text, then the rule, the places and the next command. The lint table is `[workspace.lints]` in `core/Cargo.toml` (with `core/clippy.toml`, and a `#![warn(...)]` at a crate root for a rule that belongs to one crate); it is at `warn`, so `cargo test` still runs a `todo!()` stub and only `make lint` and the `lint (rust)` CI job fail. Not part of `make test`. What it holds: `to_vec_named` only (`disallowed_methods`), a `std::sync::Mutex` guard in a local across `.await` (not one in a struct field), no `.unwrap()` and no printing in `tarmacd` outside test code, a `SAFETY:` comment on every `unsafe` block, no `todo!()` in a commit and no `dbg!()` outside a test, and no new integer `as` cast that can truncate, wrap or lose a sign without a reason (a cast to a float is not checked). A finding is fixed, or carries `#[expect(lint, reason = "…")]` on the narrowest item — never `#[allow]`. A toolchain update can add findings; the commit that moves the pin clears them.
- **Hooks run the same checks earlier** (spec 2611.0031). A hook file holds no rule: `.claude/settings.json` and `lefthook.yml` only say when a script under `scripts/check/` runs, and CI stays the gate that cannot be skipped. **Claude Code** (`scripts/check/hook.mjs`, which runs the check scripts of the repository that holds the file, so a worktree is judged by its own branch): after an `Edit` or `Write` of a Rust or Swift file it formats the file in place, lints it (Swift only: clippy needs the whole build) and runs `arch-check`, and a finding goes to the agent while the edit stays; at the end of a turn it runs the format check and the Swift lint on the files that differ from `HEAD` or are new, then `arch-check` and `docs-check`, and a set of findings blocks the stop **once** in a session (the same set again is reported and does not block, so that an agent is not held on another agent's files; a check that cannot run is reported and never blocks; no clippy, because a red test starts with a `todo!()`); before a Bash call it refuses `pkill` or `killall` with a name that holds `tarmac` (`scripts/check/kill-guard.mjs`: it reads quotes, `$(…)`, here-documents, `sh -c`, wrappers such as `sudo` or `xargs`, and a `kill` of what `pgrep` found, but it reads text: a variable, an alias, a script file or another way to end a process (`osascript`) hides a kill from it, so the rule above about a kill by name still stands in words). There is no `SubagentStop` hook, and a file that Bash or another program changed gets no edit hook. **git** (`lefthook.yml`): `pre-commit` runs `scripts/check/staged.mjs` (format check and Swift lint on the staged files as they are in the working tree, clippy when a Rust file is staged, `arch-check`, `docs-check`); `commit-msg` runs `scripts/check/commit-msg.mjs` (the subject form below and a `Signed-off-by:` of the author or committer, read as `dco-check` reads it; CI does not check the subject form); `pre-push` runs `make test`. `git commit --no-verify` skips the commit hooks, and a clone with no `make setup` has none.
- `make arch-check` — rules about the tree that no formatter, linter or compiler setting holds (`scripts/check/arch.mjs`, plain node, sub-second, part of `make test` and of `lint.yml`): no `import` of AppKit, Cocoa, WebKit, SwiftUI or a sibling in `TarmacKit`, and of a sibling in `TarmacTerm`; `Bundle.module` only in `BundledResource.swift`; `libc::kill` under a crate's `src/` only in `core/crates/tarmacd/src/term.rs` (test code under `tests/` is not read); no profile that sets `debug-assertions`; `serde`, `rmp-serde` and `serde_bytes` pinned with `=`; a `<Module>Tests.swift` for each `TarmacKit` module (a `<Module>+<Part>.swift` slice needs none), or an entry in `scripts/check/arch-exceptions.json` (which must shrink: an entry no longer needed fails). It reads tracked files as text, so it names a line and does not parse the language: it does not see a signal sent another way (`use libc::{kill, killpg}` then a bare `kill(…)`), a second `import` after a `;`, or what a test file tests. The three copies of `socket_path()` are not checked.
- `make docs-check` — deterministic doc tripwires (`scripts/docs-check.mjs`, plain node, sub-second): status banners, link rot, ACTIVE docs citing paths that don't exist, and `Msg` variants missing from `architecture.md`/`protocol.md`. Runs on every PR as its own workflow (`.github/workflows/docs-check.yml`), kept separate from `test.yml` so it never queues behind a cargo build.
- `make run` — launches the native dev app with `TARMAC_SOCKET`/`TARMAC_STATE`/`TARMAC_DEV_SOCKET`/`TARMAC_CONFIG_DIR` pinned to this worktree's `.dev/`. `DEV_DIR=<dir>` moves all four to another directory: a second channel (`make qa`, `make qa-quit`, `make qa-resume` and `make kill-daemon` take it too).
- `make qa` — `scripts/qa/smoke.mjs`: the in-app QA driver's own scenario suite (#166), driven through `tarmac dev` against a **live `make run` app**. Deliberately **not** part of `make test` or CI — every scenario needs a window. It exits non-zero with a clear message if no app is listening. `make qa-quit` (`scripts/qa/quit.mjs`) holds the cases that end the app, and `make qa-resume` (`scripts/qa/resume.mjs`, spec 2611.0011) the one that kills the dev daemon by its socket's pid.
- `make bundle` — `scripts/bundle.sh`: an unsigned `dist/Tarmac.app` from the Swift release build plus the two Rust binaries. `make dmg` (`scripts/dmg.sh`; needs `VERSION`, `DEVID_IDENTITY`, `NOTARY_PROFILE`) stamps `core/Cargo.toml` and its lockfile, rebuilds the bundle, signs it, builds the `.dmg`, notarizes and staples — and publishes nothing. `make release` (`scripts/release.sh`, same variables plus an optional `SUMMARY`) is the whole release from this Mac: `dmg`, the cask stamp, the version-bump PR, the GitHub release, the Homebrew tap PR and a check of what was published; every step is skipped once it has landed, so a failed run is resumed by running it again. Releases are local-only — there is no release workflow in CI.

## Docs

- `docs/` — **read [`docs/README.md`](docs/README.md) first**: it classifies every doc as ACTIVE / PROPOSED / HISTORICAL. ACTIVE (trust as current): `architecture.md`, `protocol.md` (wire contract + conformance vectors), `backlog.md` (the audited *unbuilt* list), `workflow.md`, `coding-style.md`. PROPOSED (**zero lines implemented**): `proposed/`. HISTORICAL (frozen): `archive/`, which describes two earlier apps (see Gotchas). `designs/` holds one record per change, for the earlier apps and for this one; go by each record's banner — a record of a change that was not built is PROPOSED.

## Conventions

- **Work per issue** ([`docs/workflow.md`](docs/workflow.md)): one branch `type/N-slug` per issue, never work on `main` (a release is the exception: the `/release` skill), and a worktree at `../tarmac-worktrees/N-slug/` (outside the repo) when something else holds `main` or an agent runs unattended.
- **Commits: Conventional Commits.** `type(scope): summary` (whole history conforms). Types in use: `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `chore`, plus bare `release:` for version bumps. Scopes are area tags, not paths (`feat(terminal)`, `fix(board)`, `feat(protocol)`, …). PRs are squash-merged with `(#N)` suffix.
- **Where tests live.** Rust: inline `#[test]`/`#[tokio::test]` in `src/` + subject-named integration suites under each crate's `tests/`. Swift: XCTest in `app/Tests/` — `TarmacKitTests` (a kit module's tests are its paired `<Module>Tests.swift`) and `TarmacTermTests`. The `TarmacApp` shell has no unit tests by design.
- **Layout belongs to the formatters.** Run `make fmt` before a commit; `make fmt-check` and the `fmt (rust)` and `fmt (swift)` CI jobs fail on a file that rustfmt or swift-format would rewrite. Do not lay code out by hand. There is no `.editorconfig`. `make test` must pass before opening a PR.
- **Commit trailers: both.** A DCO `Signed-off-by:` (`git commit -s`) is required by `CONTRIBUTING.md` and enforced on PRs by `.github/workflows/dco.yml`; the `Co-Authored-By:` trailer the history uses is attribution and is kept alongside it. `make dco-check` verifies the branch. (Commits before that workflow are unsigned and were not rewritten.)
- **TDD is mandatory.** Red → green → refactor: write the failing test, *watch it fail on the unmodified tree*, then make it pass with the smallest change. A test that would pass before your change is not a test of your change. For the AppKit shell (`TarmacApp`) — which has no unit tests by design — extract the decision into `TarmacKit` and TDD that, leaving the view or controller as wiring. Placement table, the closed exception list, and what each exception owes instead: [`docs/coding-style.md`](docs/coding-style.md).
- **Coding style: SOLID, ultra-concise, no line-noise comments.** Keep modules/functions single-responsibility and depend on narrow interfaces (protocol types, plain function signatures) rather than reaching across layers. Prefer the smallest correct diff over a more "thorough" one. Don't add comments that restate what the code already says line-by-line; a comment earns its place only by explaining a non-obvious *why* (a hidden constraint, a workaround, an invariant) — see the Gotchas below for the kind of thing that's worth a comment. The full reference — naming, error handling, lock discipline, the `TarmacKit` layering, per-language test idioms — is [`docs/coding-style.md`](docs/coding-style.md).

## Gotchas

- **Milestone names are history, not a roadmap.** `M0`–`M3` and `v4` are *closed*; they survive as archived plans only — the integration suites that carried their names are now subject-named (`tests/{daemon_basics,restore,honest_signals,boards}_integration.rs`). `v4c` (editable docs) is a **proposal that was never started** — doc cards are read-only, and none of its chrome (`.edit`, `.tm-caret`, `.tm-homechip`, `.tm-conflict`) exists in the code. There is no `M4`/`M4c`/`v5`. Work since M3 is per-issue (`docs/workflow.md`).
- **Archived docs describe two apps that no longer exist — and the current one is Swift again.** Anything naming `desktop/`, Tauri, React, xterm.js, a WKWebView-hosted terminal, npm/Vite or Vitest is the deleted Tauri app (2026-06 → 2026-10). Its hand-run QA records and probe pages survive, moved from `desktop/qa/` to `qa/`. Anything naming `SwiftTerm`, `ShelfView` or `PeekPanel` is the *pre-Tauri* Swift app that #27 replaced. Today's app lives in `app/Sources/` like that older one and reuses some of its file names (`DocWebView`, `BoardView`), so a `.swift` path in `docs/archive/`, `docs/designs/` or `.blueprint/specs/` proves nothing: go by the doc's banner and date. A code comment citing a file under `desktop/` names the Tauri original a rule was ported from, not a current path. Also gone on purpose (`docs/backlog.md` §4 — don't re-file these as missing): the **shelf**, the terminal **dock pane**, **peek (`⌘P`)**, and the **`⌥Tab` terminal cycle**; `doc_read` still exists on the wire but has no caller in the app.
- **`make` is the source of truth, not the editor.** Always verify compilation with `make`, not IDE diagnostics.
- **The app's version must be the daemon's exact `CARGO_PKG_VERSION`, never a guess** (`AppVersion`): a bundle reads `CFBundleShortVersionString` (stamped by `scripts/bundle.sh`), `make run` passes `TARMAC_APP_VERSION` from `core/Cargo.toml`. A wrong one makes every launch replace the daemon; an app with none names no version and restarts nothing.
- **`app/Vendor/` must be staged before the Swift package builds.** It is gitignored and `app/Package.swift` names the XCFramework there as a binary target, so a bare `swift build`/`swift test` in a fresh worktree — or an editor opening the package — fails until `make ghostty-vt` has run (it downloads; `make app`, `make test`, `make run` and `make bundle` do it for you). The libghostty-vt C API is declared unstable: `GHOSTTY_COMMIT` and `GHOSTTY_VT_SHA256` in `scripts/fetch-ghostty-vt.sh` are bumped together, and a bump can break `TarmacTerm`.
- **Bundled resources are looked up in `Bundle.main` first.** `scripts/bundle.sh` flattens the SwiftPM resource bundle into `Contents/Resources`, where `Bundle.module` finds no package bundle and traps; `BundledResource` therefore asks the main bundle first and falls back to `Bundle.module` only for an unbundled build. A new resource lookup must do the same. `make arch-check` refuses `Bundle.module` anywhere else.
- **swift-format is checked by version, not pinned.** The check refuses a `swift format` whose minor version is not one seen to give this tree the same bytes (`version.expect` in `scripts/check/fmt.mjs`: 6.3 and 6.4 today — 6.4 formatted it, and the `macos-26` CI image has 6.3). With another version `make fmt-check` and `make check-test`, and so `make test`, stop with "cannot run swift-format". To add a version, run `make fmt` with it; add it to the list only if nothing changes, else commit what changed and drop the versions that now disagree. A Swift script that starts with `#!` is not formatted: swift-format 6.4 joins the comment lines under that line onto it.
- **The Rust toolchain is pinned** (`rust-toolchain.toml`, at the repo root: rustup takes the toolchain from the current directory, so the pin covers every cargo command run from inside the repo, `make bundle` included): rustfmt's output changes between releases, and CI must format exactly as a local run does. A toolchain update is its own commit, together with whatever `make fmt` then rewrites. A bare `rustfmt <file>` needs `--edition 2024`; without it most files come out different from `cargo fmt`.
- **Wire protocol is additive-keys-only and conformance-gated, in two codecs.** Never change/remove a key or alter encoding without regenerating the hex conformance vectors, which are mandatory tests on both sides: `core/crates/tarmac-protocol/src/tests.rs`, and `app/Tests/TarmacKitTests/ConformanceTests.swift` for the Swift codec, whose encoder is also pinned byte-for-byte to Rust's output (`RustEncoderParityTests.swift`). A new key or message type lands in both codecs in the same change. Rust must encode with `rmp_serde::to_vec_named` (plain `to_vec` emits arrays and breaks the contract); binary payloads use msgpack `bin` via `serde_bytes`.
- **Serde stack is pinned with `=`** (`serde =1.0.228`, `rmp-serde =1.3.1`, `serde_bytes =0.11.19`) — the tagged-enum + serde_bytes interaction is verified only on those versions. `make arch-check` fails when one of the three is not pinned.
- **`repo_color_index` (Rust, FNV-1a 64 mod 4) is the only source of a doc's repo colour** — the app hashes nothing and maps the index onto its four-colour palette (`Theme.repoColors`), so changing the hash alters colors users already saw.
- **`socket_path()` is duplicated in THREE places** (not shared) — `core/crates/tarmacd/src/main.rs`, `core/crates/tarmac-cli/src/main.rs`, and `ChannelPaths` in `app/Sources/TarmacKit/ChannelPaths.swift`. Keep all three in sync. The dev driver's socket resolver is the same shape again in `tarmac-cli/src/dev.rs`, which calls `tarmac-protocol`'s `resolve_dev_socket_path`, and `ChannelPaths.devSocketPath`, which mirrors it.
- **Daemon lock discipline is load-bearing.** `std::sync::Mutex`es (watcher, term master, scrollback) are never held across `.await`; board-delete clones PTY handles and drops the lock before `kill()`. PTY kill signals the whole process group (`SIGHUP`).
- Tarmac is **not MCP / not an agent harness** on purpose — `tarmac open` is a plain CLI over a Unix socket so any caller can ring the doorbell. Don't propose MCP-based coupling.
