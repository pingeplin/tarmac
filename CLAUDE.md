# Tarmac

Tarmac is a terminal-first macOS cockpit for working alongside CLI coding agents. You run an agent (or anything) in a real terminal inside Tarmac; when that process — or you, a Makefile, a git hook, CI — runs `tarmac open <path>`, the referenced markdown doc surfaces as a live card on an infinite, pannable, zoomable **board**, placed next to the terminal that opened it and tied by a dashed provenance edge. It is deliberately **not an agent harness**: every on-screen mark is backed by an observable OS fact (a running process, an mtime change, a `tarmac open` socket call, a terminal bell), never by parsing agent output. Status: working prototype (M0–M3 + the v4 whiteboard migration complete on `main`).

## Architecture

Two processes that share nothing in-process, plus a tiny CLI, talking over **one Unix stream socket** (`~/Library/Application Support/tarmac/tarmacd.sock`, override `TARMAC_SOCKET`) with **length-prefixed MessagePack** frames (4-byte big-endian u32 length + msgpack map with string keys; `"t"` field tags the type; 16 MiB max frame).

- **`tarmacd`** (Rust / Tokio) — the PTY owner + observatory. Spawns and owns every terminal (`portable-pty`), watches opened docs (`notify` on the parent dir), tracks OS facts (foreground process name, file changes, bells, exits), holds all boards, persists to atomic JSON (`state.json`, override `TARMAC_STATE`). In `core/` (Cargo workspace, edition 2024): crates `tarmacd`, `tarmac-cli`, `tarmac-protocol`.
- **`TarmacApp`** (Swift 6 / AppKit, macOS 26+) — the cockpit glass. Renders boards/cards, hosts terminal cards and doc/HTML cards, turns input into daemon requests. In `app/` (a SwiftPM package), three layers: **`TarmacKit`** (no AppKit: the msgpack codec, `DaemonClient`, and every pure decision — where the tests are), **`TarmacTerm`** (the terminal card: `TerminalEngine` over libghostty-vt, `FrameReader`, a CoreText `TerminalRenderer`, and `TerminalView`, which does its own IME and translates AppKit key/mouse events for libghostty-vt's encoders), **`TarmacApp`** (the AppKit shell: wiring, views, event routing). Doc and HTML cards are `WKWebView`s; terminals are not.
- **`tarmac` CLI** (Rust, std-only) — the universal doorbell. `tarmac open <path>` connects, names a doc, exits. Inside a Tarmac PTY it reads `TARMAC_TERM_ID` (the daemon sets it per PTY) to attribute the doc to the calling terminal. `open` and `--version` are the two verbs that talk to the daemon — `--version` completes the handshake only, to report the cli, daemon, and connected-app versions plus the resolved channel and socket; `tarmac dev <verb>` is a **dev-builds-only** fourth family that talks to the *app* over its own socket (`tarmac-dev.sock` beside the daemon's, override `TARMAC_DEV_SOCKET`) — the in-app QA driver from #166, so an agent can drive and inspect the running cockpit without a keyboard; a release binary exits 1 with `driver unavailable in release builds`. `tarmac skill` is a purely local third verb that prints `core/crates/tarmac-cli/src/SKILL.md` — the agent-facing guide, embedded verbatim; `tarmac skill install` copies it into each supported agent's skills directory.

The wire contract has two implementations: `core/crates/tarmac-protocol` (the single `Msg` serde enum) and the hand-written Swift codec in `TarmacKit` (`MsgPack`, `Message`). Protocol grows **additive-only** (new optional keys / new message types; unknown keys and types ignored). Authoritative spec: `docs/protocol.md`; full engineering overview: `docs/architecture.md`.

## Build, run, test

Everything goes through the root `Makefile`:

- `make core` — `cargo build` the Rust workspace (daemon + CLI + protocol).
- `make ghostty-vt` — stage the pinned libghostty-vt XCFramework into the gitignored `app/Vendor/` (`scripts/fetch-ghostty-vt.sh`; a no-op once staged).
- `make app` — `swift build` the native package (depends on `ghostty-vt`).
- `make test` — `make docs-check` + `make ghostty-vt` + `cd core && cargo test` + `cd app && swift test`. CI runs the same suites (`.github/workflows/test.yml`: `core (cargo test)`, `app (swift test)`), but `make test` stays the local entry point.
- `make docs-check` — deterministic doc tripwires (`scripts/docs-check.mjs`, plain node, sub-second): status banners, link rot, ACTIVE docs citing paths that don't exist, and `Msg` variants missing from `architecture.md`/`protocol.md`. Runs on every PR as its own workflow (`.github/workflows/docs-check.yml`), kept separate from `test.yml` so it never queues behind a cargo build.
- `make run` — launches the native dev app with `TARMAC_SOCKET`/`TARMAC_STATE`/`TARMAC_DEV_SOCKET`/`TARMAC_CONFIG_DIR` pinned to this worktree's `.dev/`.
- `make qa` — `scripts/qa/smoke.mjs`: the in-app QA driver's own scenario suite (#166), driven through `tarmac dev` against a **live `make run` app**. Deliberately **not** part of `make test` or CI — every scenario needs a window. It exits non-zero with a clear message if no app is listening. `make qa-quit` (`scripts/qa/quit.mjs`) holds the cases that end the app.
- `make bundle` — `scripts/bundle.sh`: an unsigned `dist/Tarmac.app` from the Swift release build plus the two Rust binaries. `make dmg` (`scripts/dmg.sh`; needs `VERSION`, `DEVID_IDENTITY`, `NOTARY_PROFILE`) stamps `core/Cargo.toml` and its lockfile, rebuilds the bundle, signs it, builds the `.dmg`, notarizes and staples — and publishes nothing. `make release` (`scripts/release.sh`, same variables plus an optional `SUMMARY`) is the whole release from this Mac: `dmg`, the cask stamp, the version-bump PR, the GitHub release, the Homebrew tap PR and a check of what was published; every step is skipped once it has landed, so a failed run is resumed by running it again. Releases are local-only — there is no release workflow in CI.

## Docs

## Conventions

- **Commits: Conventional Commits.** `type(scope): summary` (whole history conforms). Types in use: `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `chore`, plus bare `release:` for version bumps. Scopes are area tags, not paths (`feat(terminal)`, `fix(board)`, `feat(protocol)`, …). PRs are squash-merged with `(#N)` suffix.
- **Where tests live.** Rust: inline `#[test]`/`#[tokio::test]` in `src/` + subject-named integration suites under each crate's `tests/`. Swift: XCTest in `app/Tests/` — `TarmacKitTests` (a kit module's tests are its paired `<Module>Tests.swift`) and `TarmacTermTests`. The `TarmacApp` shell has no unit tests by design.
- **Formatting is convention-by-imitation.** No `rustfmt.toml`/`.swiftformat`/`.editorconfig`, no formatter command, and no CI check on style — the CI workflows run docs-check, the DCO check and the test suites only. Match surrounding code. `make test` must pass before opening a PR.
- **Commit trailers: both.** A DCO `Signed-off-by:` (`git commit -s`) is required by `CONTRIBUTING.md` and enforced on PRs by `.github/workflows/dco.yml`; the `Co-Authored-By:` trailer the history uses is attribution and is kept alongside it. `make dco-check` verifies the branch. (Commits before that workflow are unsigned and were not rewritten.)
- **TDD is mandatory.** Red → green → refactor: write the failing test, *watch it fail on the unmodified tree*, then make it pass with the smallest change. A test that would pass before your change is not a test of your change. For the AppKit shell (`TarmacApp`) — which has no unit tests by design — extract the decision into `TarmacKit` and TDD that, leaving the view or controller as wiring. Placement table, the closed exception list, and what each exception owes instead: [`docs/coding-style.md`](docs/coding-style.md).
- **Coding style: SOLID, ultra-concise, no line-noise comments.** Keep modules/functions single-responsibility and depend on narrow interfaces (protocol types, plain function signatures) rather than reaching across layers. Prefer the smallest correct diff over a more "thorough" one. Don't add comments that restate what the code already says line-by-line; a comment earns its place only by explaining a non-obvious *why* (a hidden constraint, a workaround, an invariant) — see the Gotchas below for the kind of thing that's worth a comment. The full reference — naming, error handling, lock discipline, the `TarmacKit` layering, per-language test idioms — is [`docs/coding-style.md`](docs/coding-style.md).

## Gotchas

- **Milestone names are history, not a roadmap.** `M0`–`M3` and `v4` are *closed*; they survive as archived plans only — the integration suites that carried their names are now subject-named (`tests/{daemon_basics,restore,honest_signals,boards}_integration.rs`). `v4c` (editable docs) is a **proposal that was never started** — doc cards are read-only, and none of its chrome (`.edit`, `.tm-caret`, `.tm-homechip`, `.tm-conflict`) exists in the code. There is no `M4`/`M4c`/`v5`. Work since M3 is per-issue (`docs/workflow.md`).
- **Archived docs describe two apps that no longer exist — and the current one is Swift again.** Anything naming `desktop/`, Tauri, React, xterm.js, a WKWebView-hosted terminal, npm/Vite or Vitest is the deleted Tauri app (2026-06 → 2026-10). Its hand-run QA records and probe pages survive, moved from `desktop/qa/` to `qa/`. Anything naming `SwiftTerm`, `ShelfView` or `PeekPanel` is the *pre-Tauri* Swift app that #27 replaced. Today's app lives in `app/Sources/` like that older one and reuses some of its file names (`DocWebView`, `BoardView`), so a `.swift` path in `docs/archive/`, `docs/designs/` or `.blueprint/specs/` proves nothing: go by the doc's banner and date. A code comment citing a file under `desktop/` names the Tauri original a rule was ported from, not a current path. Also gone on purpose (`docs/backlog.md` §4 — don't re-file these as missing): the **shelf**, the terminal **dock pane**, **peek (`⌘P`)**, and the **`⌥Tab` terminal cycle**; `doc_read` still exists on the wire but has no caller in the app.
- **`make` is the source of truth, not the editor.** Always verify compilation with `make`, not IDE diagnostics.
- **Dev-channel work has a skill: `.claude/skills/dev-channel/SKILL.md`** — bringing the app up, driving it with `tarmac dev`, `make qa`, and what to check when it does not answer. The gotchas below are the short form.
- **Never `pkill`/kill a daemon by name — the dev and installed apps coexist on purpose.** `make run` pins `TARMAC_SOCKET`/`TARMAC_STATE` (and `TARMAC_CONFIG_DIR`, where the theme files are) to a per-worktree `.dev/` path, so the dev app and an installed Tarmac use separate sockets, state and theme files and don't collide. To stop only the dev daemon, use `make kill-daemon` (resolves the pid via `lsof` on the dev socket, so it can only ever touch this worktree's daemon). A name-based kill (`pkill tarmacd`, `pkill -f tarmac-app`) can instead take down the user's real installed app and every terminal it owns. A `make bundle` build has the installed app's executable name (`tarmac-app`) and bundle id (`com.tarmac.desktop`, `packaging/Info.plist`), and the `make run` binary (`TarmacApp`) has no bundle id at all, so when driving any of them with a GUI/automation tool, address the specific window by PID, never by name.
- **Never launch a built `dist/Tarmac.app` or a release binary without `TARMAC_SOCKET`/`TARMAC_STATE` pinned.** A release build resolves the *installed* channel: it attaches to the user's real daemon and, on a version mismatch, SIGTERMs and replaces it — taking every terminal the user has open with it. `make run` is the only launch that pins them for you.
- **The app's version must be the daemon's exact `CARGO_PKG_VERSION`, never a guess** (`AppVersion`): a bundle reads `CFBundleShortVersionString` (stamped by `scripts/bundle.sh`), `make run` passes `TARMAC_APP_VERSION` from `core/Cargo.toml`. A wrong one makes every launch replace the daemon; an app with none names no version and restarts nothing.
- **`app/Vendor/` must be staged before the Swift package builds.** It is gitignored and `app/Package.swift` names the XCFramework there as a binary target, so a bare `swift build`/`swift test` in a fresh worktree — or an editor opening the package — fails until `make ghostty-vt` has run (it downloads; `make app`, `make test`, `make run` and `make bundle` do it for you). The libghostty-vt C API is declared unstable: `GHOSTTY_COMMIT` and `GHOSTTY_VT_SHA256` in `scripts/fetch-ghostty-vt.sh` are bumped together, and a bump can break `TarmacTerm`.
- **Bundled resources are looked up in `Bundle.main` first.** `scripts/bundle.sh` flattens the SwiftPM resource bundle into `Contents/Resources`, where `Bundle.module` finds no package bundle and traps; `BundledResource` therefore asks the main bundle first and falls back to `Bundle.module` only for an unbundled build. A new resource lookup must do the same.
- **Do NOT `cargo fmt` the Rust crates.** Local rustfmt disagrees with the whole committed repo and would create spurious churn.
- **Wire protocol is additive-keys-only and conformance-gated, in two codecs.** Never change/remove a key or alter encoding without regenerating the hex conformance vectors (V1–V13), which are mandatory tests on both sides: inline in `tarmac-protocol`, and `app/Tests/TarmacKitTests/ConformanceTests.swift` for the Swift codec, whose encoder is also pinned byte-for-byte to Rust's output (`RustEncoderParityTests.swift`). A new key or message type lands in both codecs in the same change. Rust must encode with `rmp_serde::to_vec_named` (plain `to_vec` emits arrays and breaks the contract); binary payloads use msgpack `bin` via `serde_bytes`.
- **Serde stack is pinned with `=`** (`serde =1.0.228`, `rmp-serde =1.3.1`, `serde_bytes =0.11.19`) — the tagged-enum + serde_bytes interaction is verified only on those versions.
- **`repo_color_index` (Rust, FNV-1a 64 mod 4) is the only source of a doc's repo colour** — the app hashes nothing and maps the index onto its four-colour palette (`Theme.repoColors`), so changing the hash alters colors users already saw.
- **`socket_path()` is duplicated in THREE places** (not shared) — `core/crates/tarmacd/src/main.rs`, `core/crates/tarmac-cli/src/main.rs`, and `ChannelPaths` in `app/Sources/TarmacKit/ChannelPaths.swift`. Keep all three in sync. The dev driver's socket resolver is the same shape again in `tarmac-cli/src/dev.rs`, which calls `tarmac-protocol`'s `resolve_dev_socket_path`, and `ChannelPaths.devSocketPath`, which mirrors it.
- **Daemon lock discipline is load-bearing.** `std::sync::Mutex`es (watcher, term master, scrollback) are never held across `.await`; board-delete clones PTY handles and drops the lock before `kill()`. PTY kill signals the whole process group (`SIGHUP`).
- Tarmac is **not MCP / not an agent harness** on purpose — `tarmac open` is a plain CLI over a Unix socket so any caller can ring the doorbell. Don't propose MCP-based coupling.
