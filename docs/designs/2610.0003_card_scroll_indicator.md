**Date:** 2026-10-03
**Status:** implemented
**Author:** EP Lin
**Doc type:** Mini RFC
**Issue:** [#191](https://github.com/pingeplin/tarmac/issues/191)
**Companion:** [2610.0002 Native wheel for HTML cards](2610.0002_native_html_card_wheel.md) — lands first; this design uses its probe and gesture poster

## Decision

Every card kind reports where its content is scrolled to as one value,
`ScrollMetrics {offset, visible, total}`, and the card draws one Tarmac-owned
thumb from it: the same look and the same rule for a terminal's scrollback, a
markdown doc and an HTML document. WebKit's own root scrollbar is hidden in
both web kinds.

The thumb appears while the wheel is on the card and fades one second after
the last wheel. It is an indicator: it takes no pointer.

We draw our own rather than restyle WebKit's, because we value one look across
three engines more than we value the draggable scrollbar the two web kinds have
today.

## Problem

| Card | What shows the scroll position today |
| --- | --- |
| Terminal | nothing — `TerminalEngine.scrollbar` has the numbers, no view draws them |
| Markdown | WebKit's scrollbar on `.doc-scroll`, at native width |
| HTML | WebKit's scrollbar on the document, scaled by `zoom/3` |

1. **A terminal shows nothing.** 5000 lines of scrollback and no mark of where
   the viewport is in them.
2. **The two web kinds do not match each other.** Measured with legacy
   scrollbars forced (`-AppleShowScrollBars Always`): at board zoom 0.25 a
   markdown card's scrollbar track is 15 pt wide and a magnified HTML card's
   about 1 pt; at zoom 1 the HTML card's is about 5 pt. The markdown scroller
   is laid out at its on-screen size; the HTML document is laid out at 3× and
   shown scaled by `zoom/3`, and its scrollbar with it.
3. **Both follow the system's *Show scroll bars* setting**, so the same board
   looks different on two machines, and an untrusted HTML document can restyle
   or hide its own.

## Constraints

- **`TarmacTerm` depends on nothing of `TarmacKit`** (`Package.swift`): the
  terminal can report only its own type, `TerminalScrollbar`.
- **An HTML card's document is untrusted and opaque-origin.** The host page
  cannot read its scroll position; only the shim, which runs inside the
  document's world, can — and whatever the shim sends, the document can forge.
- **A culled HTML card must leave no native frame request pending** (spec
  [2609.0002](../../.blueprint/specs/2609.0002_offscreen_html_card_throttle.md):
  an unserviced one is a standing CPU charge). `CardShimTests` pins how many
  native frames the shim asks for.
- **The `TarmacApp` shell has no unit tests**, and nothing runs
  `doc-render.js` under test. `card_shim.js` is run by `CardShimTests` and
  `card-host.js` by `CardHostScriptTests`, each in a stand-in page with no
  layout behind it.
- A board holds many cards. A mark on every one of them, always, is noise.
- No wire or daemon change, and no CLI code change: the agent guide the CLI
  embeds gains a line (plan, step 5).

## Proposed change

### One value, one drawing

```swift
// TarmacKit
/// Where a card's content is scrolled to, in any one unit of that content.
public struct ScrollMetrics: Equatable, Sendable {
    public let offset: Double    // of the first visible unit, from the start
    public let visible: Double
    public let total: Double
    /// nil unless all three are finite, `visible > 0` and `total >= visible`.
    /// `offset` is clamped into `0...(total - visible)`: an overscroll is the
    /// nearest edge, not a refusal.
    public init?(offset: Double, visible: Double, total: Double)
    /// A web card's report, `{offset, visible, total}` as a script message
    /// carries it; nil for anything else.
    public init?(report: Any)
    public var overflows: Bool { get }   // total > visible
}

public enum ScrollIndicator {
    public static let width: CGFloat = 10      // world units, as the header's 30 is
    public static let inset: CGFloat = 2       // from the body's right edge, and from the track's top
    public static let minLength: CGFloat = 24

    public struct Thumb: Equatable, Sendable { public var y: CGFloat; public var length: CGFloat }
    /// The thumb on a track `track` world units long; nil when the content
    /// fits, nothing has been reported, or the track is shorter than `minLength`.
    public static func thumb(_ metrics: ScrollMetrics?, track: CGFloat) -> Thumb?

    /// The thumb's frame on screen, in the coordinates `body` is given in and
    /// on whole device pixels. `body` is the card body's on-screen rect as it
    /// shows (`CardBox.Screen.shownBody`); `covered` is the height, in world units, an
    /// overlay of the body's own hides at its bottom.
    public static func frame(_ metrics: ScrollMetrics?, body: CGRect, covered: CGFloat, scale: CardScale) -> CGRect?

    /// When the thumb shows: from a wheel on the card until `holdMs` after the
    /// last one, then a fade of `fadeMs`.
    public struct Visibility: Equatable, Sendable {
        public static let holdMs: UInt64 = 1000
        public static let fadeMs: UInt64 = 200
        public init()
        public mutating func wheeled(atMs now: UInt64)
        public mutating func reset()                    // the card was deselected
        public func alpha(atMs now: UInt64) -> CGFloat   // 1, a ramp, then 0
    }
}
```

`thumb`: `length = max(minLength, track × visible / total)`,
`y = (track − length) × offset / (total − visible)`.

`frame`: the track starts `inset` below the body's top and stops clear of the
card's rounded bottom corner (`CardBox.cornerRadius`), or `inset` above the
overlay when `covered` reaches higher than that. Every on-screen coordinate is
`frame`'s; the view only assigns it.

### Who reports, and when

| Card | Reads | Reports through | When |
| --- | --- | --- | --- |
| Terminal | `TerminalEngine.scrollbar` (rows) | `TerminalView.onScrollChanged: ((TerminalScrollbar) -> Void)?` | whenever the value differs from the last reported, checked after each frame read and each relayout |
| Markdown | `.doc-scroll` `scrollTop`, `clientHeight`, `scrollHeight` | a `docScroll` script message from `doc-render.js` | after every `relayout()` and on every `scroll` |
| HTML | the root: `window.scrollY`, and `document.scrollingElement`'s `clientHeight`, `scrollHeight` | `{tarmac: "scrolled", offset, visible, total}` from the shim → host page → `CardConsole.parse` | when the root's size observer fires, on a root `scroll`, on `resize` |

- **The terminal's mapping** to `ScrollMetrics` is three field copies in the
  shell — wiring, not a decision. Reporting only a changed value is
  `TerminalView`'s, and `TerminalViewTests` covers it.
- **Both web reports are parsed in Kit**, by `ScrollMetrics.init?(report:)`. A
  malformed one is nothing: `CardConsole.parse` returns nil for it, as for any
  message it cannot read, and the card keeps the metrics it had.
  `CardConsole.Message` gains `.scrolled(ScrollMetrics)`, and
  `HTMLCardSession.handle` answers it with a `.scrollChanged(ScrollMetrics)`
  effect. The session holds no scroll state.
- **`DocCardBody` gains** `var onScrollChanged: ((ScrollMetrics?) -> Void)?`.
  A body sends nil when what it reported is gone: an HTML reload, a markdown
  page reload, a web content process that terminated.
- **The web pages post as the event happens**: no frame is requested, no timer
  is set, nothing is remembered between posts. A `scroll`, a `resize` and a
  size observation each fire at most once a frame by themselves. So a culled
  card's shim schedules nothing, and the scheduler gate has nothing of this to
  hold. `doc-render.js` has no condition to test: it posts three numbers.
- **No rate cap.** A document can already post any number of `escape`, `ready`
  or console messages; a `scrolled` costs the app one parse and one
  `needsLayout`, which AppKit folds into the next display pass.
- **The size observer** is a `ResizeObserver` on the root element. Measured in
  a sandboxed, magnified document: it fires when the root zoom lands (so the
  first, pre-zoom numbers are replaced) and when content grows with no scroll.
  Not measured: a root pinned to the viewport's height
  (`html { height: 100% }`), whose box does not change when its content grows.
  Its `total` is then stale until its next `scroll` or `resize` — and a wheel
  that moves it is a `scroll`.

### The thumb

`CardView` owns one indicator view, a sibling of the body's container inside
the card's clip — chrome, laid out on screen through `CardScale` as the header
and border are, so it is sharp at every zoom and grows with the card. It lies
over the body's right edge: 10 wide, 2 in, a dark fill with a light hairline,
both opaque, so it is the same thumb on a terminal, on the markdown page and
on a white HTML document. It answers no hit test: an event reaches what lies under it — the
content, or, in the card's outer 6 screen points, the resize strip that already
takes them (`CardHandles`).

An HTML card's open console covers the bottom of its body, and the track ends
above it. `DocCardBody` gains `var scrollCover: CGFloat { get }` — the height
its own overlay hides, in the body's own (world) units, 0 for a markdown card
and for a closed console — and `var onScrollCoverChanged: (() -> Void)?`,
which the HTML body calls when its console opens, closes or changes height.
The document's `visible` stays its whole viewport: the console lies over the
document, it does not shorten it.

### The rule

The thumb is drawn when the card's content **overflows** and its `Visibility`
says so. `Visibility.wheeled` is called when the wheel router gives the card a
wheel (`BoardWheel.Route.card`), which it does only over the body of the
selected card; `Visibility.reset` is called when the card is deselected. So at
most one card on a board shows a thumb: the selected one, from a wheel over its
body until one second after the last.

The rule keys on the wheel reaching the card, not on the content having moved.
The thumb says where the card's content is whenever the card takes a wheel:

- **A terminal printing at the bottom** changes its metrics on every line and
  shows nothing: output is not a wheel.
- **The alternate screen** reports `total == visible` (measured: `3, 0, 3` on a
  3-row grid with 10 lines of history behind it), so a full-screen program has
  no thumb.
- **A wheel that scrolls something else shows the thumb, unmoved**: over an
  open HTML console, over a nested scroller, in a document that cancels the
  wheel, across a document that only scrolls down, in a terminal whose program
  tracks the mouse. Each is a true reading of where the root is.
- **The resize strip** takes the card's outer 6 screen points: 3 of the
  thumb's 10 at zoom 1, all of it at about zoom 0.4 and below. A wheel there
  is not over the body and pans the board, as it does today.
- **A board switch** clears the selection, so the wheel pans until a card is
  pressed. A card borrowed before the switch stays borrowed and is in the same
  position: no thumb until it is selected again.
- **A culled card** is hidden, thumb and all, and keeps its metrics.
- **A reload** sends nil; a wheel shows the thumb again once a document has
  reported. A report the old document posted late — a magnified card's does,
  as its frame is resized for the reload — is replaced by the new one's first.

### WebKit's root scrollbar goes

`.doc-scroll { scrollbar-width: none }` in the markdown page. In an HTML
document the shim sets `documentElement.style.scrollbarWidth = "none"`, as it
sets `zoom`: an inline style through the CSSOM, which a card's content policy
does not gate. Both measured with legacy scrollbars forced: the markdown card's
15 pt track and the sandboxed document's gutter are gone, and the content runs
to the edge. A nested scroller keeps its own; that is the document's content,
not the card's.

### The driver sees it

`tarmac dev snapshot` gains `cards[].scroll` — `{offset, visible, total,
shown}` or `null` — built by `DevSnapshot` from the value the thumb is drawn
from. `shown` is true when a thumb is laid out — the card has a thumb frame and
is not culled — and its `Visibility` alpha at the time of the snapshot is above
0, so a card whose content fits reads `false` whatever its `Visibility` says.
(The spec settled this on `Visibility`'s alpha, not the view's: under an
animated fade the view's own alpha is already 0 while the thumb is still on
screen.) The snapshot is JSON the app builds; no Rust change.

## Why this and not the alternatives

**Restyle WebKit's scrollbar and draw a look-alike on terminals.** No message
from the document, and the web kinds keep a draggable bar. But the HTML card's
bar is scaled by `zoom/3`, so the three match at one zoom at most, and all of it
still follows the system setting.

**Shown whenever the card is selected and overflows.** No timer: a pure
function of two facts, and it marks the one card a wheel will scroll. It puts a
permanent mark on the terminal being worked in, which overflows almost always.

**Shown while the pointer is over the selected card's body.** No timer either.
The tracking is already there: the cursor router hit-tests every pointer move
before it is dispatched (`HoverCursorRouter`), web views included. But the
pointer rests on the terminal being typed into, so in practice this is the
permanent mark again.

**Shown when the card's own content scrolls**, each source saying why its
metrics changed. It would cover a key in a borrowed document and a selection
drag past a terminal's edge, and drop the unmoved-thumb cases above. It costs
a cause in every report: the terminal has its `scrollViewport` call sites, but
`doc-render.js` would have to tell its own `relayout()` from the reader's
scroll in an event that arrives later and looks the same, with no test to hold
it, and the shim cannot tell a document that scrolls itself from a reader at
all. One fact in one tested place — the router gave this card a wheel — is
worth the cases it misses.

**Shown on any change of the metrics.** A printing terminal changes its metrics
every line, and a board zoom re-lays out every markdown card, so the whole
board would flash.

**Shown on a wheel, and kept on while a terminal is scrolled back from the
bottom.** The chosen rule plus the one case it hides: a terminal left in its
history, which today looks exactly like a live one. The most useful of these
and the least unified — only a terminal has a live edge — and it would show on
unselected cards. Offered at review and not taken; see *Confirmed*.

**The indicator inside each body view** rather than the card's chrome. The
HTML console would order above it for free, with no `scrollCover`. But the body
is drawn at world size and scaled, so the thumb would be scaled with it instead
of laid out sharp, and three views would each own one.

## Trade-offs accepted

- **Markdown cards, and HTML cards while borrowed, lose a scrollbar that can be
  dragged.** The thumb takes no pointer.
- **An HTML card's thumb is drawn from what its document says.** The shim runs
  in the document's world, so the document can forge the report, as it can
  already forge a console line. The damage is one wrong thumb on its own card;
  `ScrollMetrics` refuses what is not finite and ordered.
- **An HTML document can bring WebKit's scrollbar back** — a stylesheet rule
  with `!important`, or clearing the inline style. Then it shows both. Problem
  3 is fixed for a document that leaves the root's style alone.
- **Only the root scroller is indicated.** A document whose root fits and whose
  content scrolls in a full-size inner element — an app shell — gets no thumb,
  and its inner scroller keeps WebKit's scaled scrollbar.
- **A scroll that is not a wheel shows nothing**: a selection drag past a
  terminal's edge, a key in a borrowed document. In the web kinds WebKit's bar
  shows such a scroll today.
- **The system's *Show scroll bars* setting stops applying to a card's root.**
  A user who set *Always* gets the wheel-only thumb like everyone else.
- **A web card's thumb trails its content** by the trip from the page to the
  app: a frame or two. Not measured.
- **A timer per shown thumb**, in the untested shell. The timing is
  `Visibility`'s, which is tested; the shell takes its two durations.
- Three sources stay three. Only the value and the drawing are shared: the
  contents scroll in three engines.

## Riskiest assumption

**That an HTML document's root is what scrolls.** [ASSUMPTION — not measured]
The cards agents write are mostly documents that grow past the viewport, which
scroll at the root. The agent guide does not tell them to; this change adds
that line. If app-shell layouts turn out common anyway, HTML cards have no
thumb where a markdown card or terminal has one, and the fix is for the shim to
report the element that last scrolled — a larger message and a second scrollbar
to hide.

Measured, each a claim the proposal rests on (harness in `.dev/spike-wheel/`,
not tracked):

- `scrollbarWidth = "none"` removes the root scrollbar of a sandboxed document,
  and `scrollbar-width: none` on `.doc-scroll` the markdown card's.
- A capture listener on `document`, in the document's world, sees every root
  `scroll` and can tell it from a nested element's.
- A magnified root's `scrollY`, `scrollTop`, `clientHeight` and `scrollHeight`
  share one unit, iframe pixels (`scrollTop` and `scrollY` both read 150 after
  the same gesture). A nested element's `scrollTop` is in CSS pixels, a third
  of that — one more reason the report is the root's.
- A `ResizeObserver` on the root fires for the zoom landing and for content
  growth.
- The terminal engine's numbers on the alternate screen.

## Success criteria

*Probe* and *poster* are 2610.0002's (`qa/wheel-travel-probe.html`, which
paints the document's own `scrollY`, `innerHeight` and `scrollHeight`, and
`scripts/qa/wheel-gesture.swift`). Baseline for every row: no Tarmac thumb
exists today.

1. **Geometry.** `ScrollIndicator.thumb`: nil when the content fits, nothing is
   reported or the track is under 24; at the top `y = 0`; at the end
   `y + length = track`; never shorter than 24. `ScrollIndicator.frame`: 10
   world units wide and 2 in from the body's right edge at zoom 0.5, 1 and 2,
   on whole device pixels, ending clear of the corner radius, or above
   `covered`. *`ScrollIndicatorTests`.*
2. **Timing.** `Visibility.alpha` is 1 until 1000 ms after the last wheel, 0
   from 1200 ms, a wheel during the fade restores 1, and `reset` gives 0 at
   once. *`ScrollIndicatorTests`.*
3. **Validation.** `ScrollMetrics.init?` refuses NaN, infinity, `visible <= 0`
   and `total < visible`, and clamps an offset outside its range;
   `init?(report:)` refuses a missing key, a non-number and anything that is
   not a dictionary. *`ScrollMetricsTests`; `CardConsoleTests` for the
   `scrolled` message.*
4. **The shim's report.** Posted when the size observer fires, on a root
   scroll and on resize, and not on a nested element's scroll; no native frame
   and no timer is requested for it, paused or not, so the pinned counts of
   2609.0002 stand. *`CardShimTests`.*
5. **Metrics are true, per kind** — the snapshot's `scroll` against a second
   reading:
   - HTML: equals the `scrollY`, `innerHeight` and `scrollHeight` the probe
     paints, at the top, after a 100 pt gesture and at the end. `innerHeight`
     is a second API for `visible`: it and the root's `clientHeight` both read
     840 in the spike.
   - Terminal: the engine's numbers against known content are
     `TerminalEngineTests`' already. Live, `visible` equals the snapshot's
     `rows`; at the bottom `offset + visible = total`; after a notched wheel of
     *k* lines `offset` is *k* less.
   - Markdown, on a fixture whose last line is marked: `visible` equals the
     body's on-screen height (its `screen_rect` less the header and both
     borders) ± 1 pt; `offset` is 0 at the top; scrolled until `offset` stops
     growing, `offset + visible = total` ± 1 (the three are whole numbers of a
     fractional layout) and a capture shows the marked line.
6. **The rule.** On each kind: a wheel on a selected, overflowing card turns
   `scroll.shown` true and a capture shows the thumb; 1.5 s after the gesture's
   last event `shown` is false; selecting another card inside the hold turns it
   false at once; a card whose content fits never shows one; a terminal
   printing 500 lines with no wheel never shows one. *The snapshot, polled with
   `--until`, and captures, by the QA sheet.*
7. **No WebKit root scrollbar** in a markdown card or in an HTML card that
   leaves its root's style alone, with the app started
   `-AppleShowScrollBars Always`. *Region captures, beside the same capture on
   `main`.*
8. **Console.** With an HTML card's console open, the thumb ends above it.
   *`ScrollIndicatorTests` for `covered`; a capture for the wiring.*
9. **Alternate screen.** `TerminalEngine.scrollbar` reports `total == visible`
   on the alternate screen with history behind it, and the primary screen's
   numbers again on leaving it. *`TerminalEngineTests`* — a pin, green on
   `main`: it guards a `GHOSTTY_COMMIT` bump, not this change.
10. `make test` passes; `make qa` passes with no scenario changed.

## Out of scope

- A thumb that can be dragged or clicked.
- A horizontal thumb.
- A thumb for a nested scroller, or for a document whose root does not scroll.
- Showing a scroll that did not come from the wheel.
- The persistent mark on a terminal scrolled back — the sixth alternative.

## Confirmed (2026-10-03)

1. **The rule.** Shown while the wheel is on the card and for a second after.
   The two alternatives — always on the selected card, and the wheel rule plus
   a mark that stays while a terminal is scrolled back — were offered and not
   taken.
2. **Passive.** The thumb is not draggable, and the two web kinds lose the
   scrollbar they can drag today.
3. **Root scroller only** for an HTML document.
4. **The look**: 6 wide, 2 in, never under 24, dark fill with a light hairline.
   Widened to 10 on 2026-10-04, at the user's word on seeing it.
5. Vertical only.
