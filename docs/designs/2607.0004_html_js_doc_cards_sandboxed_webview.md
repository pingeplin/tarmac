# 2607.0004 HTML/JS doc cards in a sandboxed iframe

> **Doc status: HISTORICAL** — a design record for the change it accompanied.
> It describes the system *as of that change*, not as it is today. Its zoom
> semantics in particular were superseded twice: by magnify (2607.0006), then
> by frozen-K magnify, which drops the settle-time relayout entirely.
> For current behaviour see [`../architecture.md`](../architecture.md).

**Date:** 2026-07-02
**Status:** draft
**Author:** EP Lin
**Doc type:** RFC
**Issue:** [#49](https://github.com/pingeplin/tarmac/issues/49)

## TL;DR

Render `.html` docs as live, script-executing cards using a **sandboxed `<iframe>` inside the existing main webview**, loaded from a **new Tauri custom URI scheme (`tarmac-card://`)** whose Rust handler serves the file with a strict `Content-Security-Policy` response header and a prepended console-capture shim. Routing is a frontend-only extension check; the daemon, CLI, and wire protocol change **not at all**. Pointer/keyboard input is gated behind an explicit "interactive borrow" (a transparent shield overlay, on by default), extending v4c's *focus's home is the terminal* rule to HTML content. We reject the child-webview-per-card route (Tauri `unstable` multiwebview) because it is demonstrably broken for many positioned, z-ordered surfaces today.

We accept **one WKWebView process shared between host and card JS** (softer isolation than an OS-level webview sandbox) in order to keep cards cheap, composable with the board's transform/z-order model, and shippable now.

## Problem

Agents already produce files that `tarmac open <path>` surfaces as cards. But `DocCard` treats every file as Markdown source: `marked.parse()` straight into `.doc-prose` (`desktop/src/cards/DocCard.tsx:84`), no extension dispatch anywhere in the frontend, daemon, or protocol. An agent that writes a D3 dashboard or a Canvas visualization and rings the doorbell gets its HTML rendered as escaped text soup. The file-as-pipe model stops exactly where it would get most interesting: live, agent-generated UI.

The constraint that makes this hard: the content is machine-written and effectively untrusted, and it would run inside the app's own WKWebView — which today has **no CSP at all** (`security.csp: null` in `tauri.conf.json`) and a frontend that holds Tauri invoke rights. "Just put it in the DOM" is an XSS-shaped hole; "just don't run scripts" defeats the purpose.

## Constraints

- **`tarmac open` stays a plain doorbell.** No new agent-facing protocol, no manifest, no broker. The file is the whole interface.
- **Wire protocol is additive-only and conformance-gated.** Happily, doc bytes never cross the socket — the daemon sends only path + mtime (`doc_opened`/`file_event`), and the frontend reads the file itself (`read_doc`, `desktop/src-tauri/src/commands.rs:106-112`). Doc-type routing can live entirely client-side with zero protocol change.
- **Focus discipline is load-bearing.** `CardShell` is deliberately not focusable; clicking a card must never steal keys from the prime terminal (`CardShell.tsx:5-6`). Interactive HTML must not violate this by default.
- **Sandbox requirements (issue acceptance):** block outbound network (`fetch`/XHR) and arbitrary Tauri `invoke` by default; allow DOM/Canvas/WebGL; capture `console.log` in the host.
- **Crispness model:** doc cards live in a real-device-px wrapper (`docWrapperBox()`, translate-only) with prose oversampled at K=3 and downscaled. That trick is DOM-reflow-specific and does not transfer to live iframe content.
- **Testing convention:** only pure `kit/` logic is unit-tested; the React/Tauri shell is QA'd. Sandbox enforcement must therefore be verifiable by a *runnable probe*, not just unit tests.

## Proposed design

### Routing (frontend only)

A pure function `docKind(path): "markdown" | "html"` in `kit/` keys off the extension (`.html`, `.htm`). `Board.tsx` branches at the existing doc-card mount point (`Board.tsx:188-219`): same `docWrapperBox()` wrapper, same `CardShell` chrome, new `HtmlCard` body instead of `DocCard`. `DocCardModel` and the protocol are untouched — kind is derived, never stored. [ASSUMPTION: extension sniffing is sufficient; no content sniffing, no front-matter override.]

### Delivery: `tarmac-card://` custom scheme

The Tauri backend registers `register_uri_scheme_protocol("tarmac-card", …)`. The handler:

1. Resolves `tarmac-card://doc/<url-encoded-abs-path>?v=<mtime_ms>` to the canonical path, reads the bytes (the HTML analogue of `read_doc` — same trust: the user's own filesystem).
2. Prepends the **console/escape shim** (below) to the document as string composition — the only way to guarantee the shim runs before any card script.
3. Returns an `http::Response` with:

```
Content-Type: text/html; charset=utf-8
Content-Security-Policy: default-src 'none';
  script-src 'unsafe-inline';
  style-src 'unsafe-inline';
  img-src data: blob:;
  font-src data:;
  media-src data: blob:
```

`connect-src` is covered by `default-src 'none'` — `fetch`, XHR, WebSockets, and `sendBeacon` are all blocked. External `<script src>` (CDN D3 etc.) is also blocked: **agents must inline their JS into the file.** That is a feature, not a bug — the file stays the complete, self-contained pipe.

The custom-protocol route is chosen over `srcdoc` because a **response header CSP** is the strongest, least-quirky enforcement point (meta-tag CSP has directive gaps and parser-ordering caveats), because the custom scheme gives the content a non-app origin that Tauri's capability system has never granted anything to, and because it avoids the WKWebView "outside the sandbox" failure mode of `file://` iframe loads.

### The iframe and its sandbox layers

```html
<iframe sandbox="allow-scripts"
        src="tarmac-card://doc/<path>?v=<mtime>"
        allow="">  <!-- no permissions-policy grants -->
```

Blocking Tauri `invoke` is defense-in-depth, three independent layers:

1. `sandbox="allow-scripts"` **without** `allow-same-origin` → opaque origin: no cookies, no storage, no same-origin reach into the parent.
2. Tauri 2 (≥ 2.0.0-beta.20, GHSA-57fm-592m-34r7) does not inject `__TAURI_INTERNALS__` into iframes on macOS, and `__TAURI_INVOKE_KEY__` rejects `ipc.postMessage` from frames core didn't initialize.
3. `tarmac-card://` appears in no capability file (`capabilities/default.json` grants only `windows: ["main"]`).

Layer 2 is a security-patch behavior, not a documented contract — hence the probe card below.

### Console capture + escape hatch (the shim)

The prepended shim (a single inline `<script>`) overrides `console.log/info/warn/error`, hooks `window.onerror` and `unhandledrejection`, and relays each event via `window.parent.postMessage({tarmac: "console", level, args: safeSerialize(args)}, "*")`. It also listens for `Escape` keydown and posts `{tarmac: "escape"}` — without this, Esc pressed inside a focused iframe would never reach the board's Esc-goes-home handling.

The host listens on `window` `message` events and routes by `event.source === iframe.contentWindow` to a **per-card ring buffer** (app-side, capped ~500 entries). MVP surfaces it as a count in the card meta row plus a toggleable console strip in the card body. This buffer is the designated future root of card→Tarmac communication; anything beyond capture-and-display (feeding it back to agents, structured channels) is explicitly out of scope here.

The shim is assembled in `kit/` as a pure string builder → unit-testable (shim-before-content ordering, serialization edge cases) per the repo's kit-only testing convention.

### Interaction: shield by default, interactivity is a borrow

By default a transparent **shield overlay** sits over the iframe. The card then behaves *exactly* like every other card: press selects/grabs, drag moves, the prime terminal keeps the keyboard, and CardShell's wheel routing works (DOM events never enter the iframe). The content still renders and animates live — you just can't poke it.

An explicit affordance (double-click the body, or a `⌥⏎`-style chrome control — exact gesture to settle with v4c's edit-entry design) drops the shield: pointer and keyboard now go to the card content, the card shows borrowed-focus chrome (reuse v4c's `.edit`-style ring), and **Esc always goes home** — via the shim's escape relay when focus is inside the iframe, via the board handler otherwise. `⌥tab` still cycles terminals only. This is v4c's rule applied unchanged: *focus's home is the terminal; interaction is a borrow.*

Consequence we accept: a **shielded** card cannot be scrolled or hovered. For dashboards (the target use case) that's fine; for scrollable HTML you borrow first.

### Zoom & crispness

The iframe is sized in **real device pixels** inside the untransformed `docWrapperBox()` — the terminal-canvas model, not the prose oversample model. Content lays out at true resolution at every zoom, so it is always crisp, and responsive/canvas content gets honest viewport dimensions. During a pinch/zoom gesture the iframe keeps its size and takes a temporary CSS scale (cheap, momentarily soft); on settle (reuse the existing ~150ms rasterScale debounce) the scale resets to 1 and the iframe is resized to the new real-px box. [ASSUMPTION: resize-on-settle is acceptable for card content — pages see a `resize` event per settle, not per frame.]

### Live reload

On `file_event` for an `.html` path, the host swaps the iframe `src` to the new `?v=<mtime_ms>` — a full reload. **All in-page JS state is lost by design**: the file is the pipe, a rewrite *is* the new content. No hot-patching, no state preservation. (Markdown cards keep their scroll-fraction behavior; HTML cards get none in MVP.)

### What each layer changes

| Layer | Change |
|---|---|
| CLI, daemon, protocol | **Nothing.** |
| Tauri backend | `tarmac-card://` protocol handler (~1 small module); no capability changes. |
| Frontend | `docKind()` + shim builder in `kit/` (tested); `HtmlCard` component; shield/borrow state; console buffer; `file_event` → src-swap hook. |

## Alternatives considered

**`srcdoc` iframe + injected `<meta>` CSP.** No Rust changes at all; frontend reads the file (existing `read_doc`), wraps it with shim + meta CSP, escapes into `srcdoc`. Rejected as primary because meta CSP is the weaker enforcement point (directive gaps, applies only from parse-time, no header semantics) and WKWebView's enforcement of meta CSP inside `srcdoc` is less certain than header CSP on a real response. It survives as the **designated fallback** if the spike falsifies header enforcement (below) — the frontend seams (`HtmlCard`, shim, shield) are identical either way.

**Child Tauri webview per card (multiwebview / `WebviewWindow`).** The "real" sandbox: separate webview, OS-level isolation, native console hooks closer to reach. Rejected on evidence: the feature is behind the `unstable` Cargo flag with open issues for broken positioning after resize/maximize (#10420, #11170, #10131), only-last-webview-renders (#11376), transparency not applied (#12450), and platform-inverted z-order (#9798). A pannable, zoomable board with N cards is precisely the worst case for all of those. Also directly contradicts the codebase's deliberate no-nested-WKWebView stance (`DocCard.tsx:1-4` — the about:blank suspend/restore hack this app was built to avoid). Revisit if/when multiwebview stabilizes.

**Sanitized static HTML into the host DOM (DOMPurify, scripts stripped).** Cheapest and safest; renders pretty HTML. Rejected because it fails the entire point of #49 — no JS, no Canvas/WebGL, no dashboards. Worth doing someday as a *renderer* for `.html` in peek/shelf contexts, but it is not this feature.

## Trade-offs accepted

- **Process-shared isolation, not OS isolation.** Card JS runs in the same WKWebView content process as the host UI. We are trusting (a) the iframe origin boundary and CSP, (b) Tauri's iframe-injection exclusion — not a process boundary. In exchange: cards are cheap DOM nodes that compose with the board transform, z-order, and screenshot/raster pipeline for free. A malicious-content threat model stronger than "agent wrote a weird file onto your own disk" is out of scope.
- **No external resources, ever, in MVP.** Inline-everything is a real authoring constraint on agents (D3 must be embedded, ~280 KB). We gain: the network-blocking guarantee stays absolute and legible. The issue's "how does a card declare it needs network?" question is deliberately not answered here.
- **A runaway card can still burn CPU/GPU in the shared process.** `while(true)` or a heavy WebGL loop degrades the whole app. Accepted for MVP (same trust argument); throttling/`display:none`-on-offscreen is future work.
- **Shielded cards are look-don't-touch; borrowing is a mode.** One more mode for users to learn, in exchange for keeping the never-steal-focus invariant intact.
- **Reload loses card state.** Simplicity and honest file-as-pipe semantics over continuity.

## Riskiest assumption

**WKWebView enforces the CSP header served by Tauri's custom-protocol handler on sandboxed-iframe content, and Tauri's IPC really is unreachable from that frame on macOS.** Both came out of this design's research as *strongly indicated but not documented contracts* (the IPC exclusion is a CVE fix, not an API promise; no macOS-specific confirmation of custom-scheme CSP header enforcement was found).

Mitigation: **spike first.** Before any card UI work, build the protocol handler plus a throwaway iframe and load a **probe card** — an `.html` file whose script attempts `fetch()` (http + custom scheme), XHR, `WebSocket`, `sendBeacon`, `import()`, reads `window.__TAURI__`/`__TAURI_INTERNALS__`, and calls `window.ipc?.postMessage` — and reports every result through the console shim. All attempts must fail and all failures must arrive in the host buffer. The probe card stays in the repo as the permanent QA artifact for this sandbox.

Note the primary and the srcdoc fallback share a premise — *WKWebView enforces CSP on iframe content at all* — so the spike must distinguish three outcomes, not two:

1. **Header CSP enforced** → proceed as designed.
2. **Header CSP not enforced, meta CSP enforced** → srcdoc fallback; re-probe.
3. **Neither enforced** → CSP-based network blocking is unviable in this webview; the live-JS feature is blocked (the honest remainder is the sanitized-static alternative, which is a different feature). Do not ship with shim-level `fetch`/XHR monkeypatching as a substitute — it is trivially defeatable and would fake the guarantee.

Independently of CSP: if Tauri IPC is reachable from the sandboxed frame → stop; the feature is blocked until a real boundary exists.

## Success criteria

1. **Live render:** an agent writes `dashboard.html` (inline D3/Canvas/WebGL) and runs `tarmac open`; an animating card appears on the board next to the opening terminal with a provenance edge, and survives pan/zoom at full crispness after settle.
2. **Sandbox (probe card):** 0 of the probe's escape attempts succeed — no outbound request observed (verifiable with a local listener), `__TAURI__` undefined, IPC postMessage rejected — on the pinned Tauri 2 version.
3. **Console capture:** every `console.*` call and uncaught error in card JS appears in the host per-card buffer, in order, including calls issued during initial script execution (proves shim-before-content ordering).
4. **Invariants hold:** with a shielded HTML card selected, typing goes to the prime terminal; Esc from a borrowed card returns focus home in one keypress; `⌥tab` never lands on the card.
5. **Live reload:** rewriting the file yields a fresh render within the existing 100ms-debounce + fetch path, with the new `?v=` observed.

## Out of scope

- Network opt-in for cards (allowlist/manifest design — the issue's third open question).
- Forwarding captured console output to agents or the daemon (buffer + display only).
- HTML rendering in peek and shelf (placeholder chip: name + "open on board to run"); dock behavior unchanged.
- `.svg`, `.png`, or other non-markdown, non-html doc kinds.
- Multi-file HTML apps (relative asset resolution) — blocked by CSP anyway; single self-contained file only.
- Any daemon/protocol `doc_kind` field. If a future need appears (e.g. dock badges by kind), it's a textbook additive optional key with one new conformance vector.
- v4c editable docs — orthogonal milestone; this design only borrows its focus rules.

---

**Decisions (confirmed 2026-07-02):**

1. **Shield-by-default, interactivity is a borrow** — confirmed. Shielded cards are look-don't-touch (no scroll, no wheel forwarding); the never-steal-focus invariant stands.
2. **Inline-everything** — confirmed. No CDN/external scripts; agents embed their libs. `default-src 'none'` stays absolute.
3. **Borrow gesture: double-click now** — confirmed. Double-click body borrows, Esc goes home; revisit for consistency in the v4c edit-entry design round (cheap to change).
4. **Console surfacing: meta-row count + toggleable strip** — confirmed. Per-card ring buffer capped ~500 entries.

Unobjected defaults (raise before /spec if wrong): extension-only routing (`.html`/`.htm`, including on restore); reload loses in-page JS state.
